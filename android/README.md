# Wynd для Android — каркас

Решения: [план 50](../docs/plans/50-android-wrapper.plan.md). Java, системный
WebView, без Capacitor и Google-зависимостей во время исполнения.

Сейчас это отладочная основа: сборка APK, существующий интерфейс сервера в
WebView, системная «Назад», восстановление истории при пересоздании Activity,
ограничение главного документа выбранным origin и открытие чужих HTTP(S)-ссылок
в браузере по нажатию. Сессии и очередь принадлежат профилю WebView приложения;
входы браузера телефона и PWA автоматически не переносятся.

Выбор сервера человеком, приглашения/QR, обработка недоступного сервера,
нативные возможности и реакция системных полос на тему ещё не реализованы.
Адрес для этого шага задаётся при dev-сборке, а не является новым экраном продукта.
Без адреса Activity завершает запуск с диагностикой в logcat. Release-вариант
выключен до выбора ключа владельца и реализации первого запуска.

## Среда и сборка на Windows

Среда в `D:\android-env`: распакованные Liberica JDK 17, Android SDK 36,
Build Tools 35.0.0, SDK Command-line Tools 19.0 и Gradle 8.13.
AGP 8.13.2 совместим с JDK 17 и Gradle 8.13:
[таблица Android](https://developer.android.com/build/releases/agp-8-13-0-release-notes).
Command-line Tools 19.0 закреплены для работы под согласованным JDK 17.

```powershell
.\scripts\build-android.ps1 -ServerUrl 'https://home.example.org'
```

По умолчанию скрипт выполняет `testDebugUnitTest`, `lintDebug`, `assembleDebug`.
Для локального сервера допустим HTTP **только** на `localhost`, `127.0.0.1`
и `[::1]` в отладочной сборке:

```powershell
.\scripts\build-android.ps1 -ServerUrl 'http://127.0.0.1:7696'
& 'D:\android-env\sdk\platform-tools\adb.exe' devices -l
# Если телефонов несколько, добавить -s <serial> в каждую команду ADB.
& 'D:\android-env\sdk\platform-tools\adb.exe' reverse tcp:7696 tcp:7696
& 'D:\android-env\sdk\platform-tools\adb.exe' install -r .\android\app\build\outputs\apk\debug\app-debug.apk
& 'D:\android-env\sdk\platform-tools\adb.exe' shell am start -n mixeme.wynd.debug/mixeme.wynd.MainActivity
```

Сервер на компьютере должен быть запущен отдельно. `adb reverse` даёт ему
USB-доступ с телефона без публикации порта в локальную сеть.

Проверка работающего отладочного пакета (Node с встроенным WebSocket):

```powershell
node scripts/test-android-webview.mjs <serial> http://127.0.0.1:7696 dev/screens/shots
```

Заменить `<serial>` номером из `adb devices -l`. Проверка не входит в учётку
и не отправляет записи: открывает приглашение, нажимает системную «Назад»,
проверяет отмену чужого перехода и сохранение собственного временного маркера
localStorage после полного перезапуска. Затем убирает маркер, делает настоящий
снимок через `adb exec-out screencap -p` и закрывает созданные CDP-порты.
Добавление `--inspect` даёт только диагностику текущего тестового экрана.

Скрипт временно задаёт `JAVA_HOME`, `PATH`, `ANDROID_HOME`, `ANDROID_USER_HOME`
и `GRADLE_USER_HOME`, затем восстанавливает прежние значения. Кэши Gradle,
включая кэш проекта, находятся внутри `D:\android-env`. Для другого пути
передать `-EnvironmentRoot`. При сборке без скрипта задавать эти переменные
процессу самостоятельно, а также `-PwyndEnvironmentRoot` и `--project-cache-dir`.

APK: `android/app/build/outputs/apk/debug/app-debug.apk`, пакет
`mixeme.wynd.debug`. Будущий пакет выпуска — `mixeme.wynd`.
Отладочный ключ — `D:\android-env\keys\wynd-debug.keystore`, alias
`androiddebugkey`, стандартные отладочные пароли `android`. Это отдельный ключ,
который не годится для выпуска. Ключи и машинные пути не включать в Git.

Минимум каркаса — Android 5.0 / API 21: во время исполнения внешних библиотек
пока нет. Это не подтверждение всех функций этапов 1–5 на Android 5. Новые
библиотеки могут потребовать пересмотра минимума по правилам плана 50.
Компиляция и target — API 36. На API 30+ учтены системные отступы и клавиатура;
проверка на современном Android остаётся отдельным пунктом.

## Что учтено из настольной оболочки

Осмотрены `internal/desktop/{address,instance,store,proxy}.go`,
`cmd/wynd-desktop`, `$lib/desktop/bridge.ts`, справочник и планы 55, 61, 62.

- **Две роли сервера.** Настольный план 62 уже разделяет источник интерфейса
  и постоянные учётные записи. Каркас хранит только источник в конфигурации
  dev-сборки; он не создаёт вход и не копирует список сессий в Java.
- **Настоящий origin.** Android открывает сервер напрямую. Здесь не нужны
  `wails.localhost`, iframe, переписывание адресов или `apiBase` локального
  прокси. Проверка адреса повторяет ограничения настольного нормализатора:
  сервер в корне, без userinfo, query и fragment. Для телефона добавлено
  требование HTTPS с исключением для отладочной USB-петли.
- **SSE.** Настольный обход буферизации asset-сервера Wails не переносится:
  `shouldInterceptRequest` не подменяет допустимые запросы и не читает их
  ответы целиком. Доставку событий нужно отдельно проверить после входа.
- **Кэш и обновления.** У настольного окна был старый интерфейс из SW.
  Android не объявляется настольным, не отключает SW и не стирает данные при
  старте: план 50 требует сохранённый интерфейс без сети. При следующем шаге
  отдельно проверить обновление оболочки, восстановление без сети и queue.
- **Возможности по факту.** `__wyndDesktop` не выставляется: он включил бы
  настольные настройки и поведение. Нативного JavaScript-моста пока нет;
  будущий мост должен проверять origin и объявлять только готовые возможности.
- **Чужие ссылки.** Главный документ ограничен выбранными схемой, хостом и
  портом. `file:`, `content:`, `intent:`, `data:` не открываются по ссылкам;
  Java не выдаёт WebView доступ к локальным файлам. Ошибки TLS не обходятся.
