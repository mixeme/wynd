# Wynd Android — каркас и обновления APK

Решения: [план 50](../docs/plans/50-android-wrapper.plan.md). Java, системный
WebView, без Capacitor и Google-зависимостей во время исполнения.

Сейчас это отладочная основа: сборка APK, существующий интерфейс сервера в
WebView, системная «Назад», восстановление истории при пересоздании Activity,
ограничение главного документа выбранным origin и открытие чужих HTTP(S)-ссылок
в браузере по нажатию. Сессии и очередь принадлежат профилю WebView приложения;
входы браузера телефона и PWA автоматически не переносятся.

Первый запуск без источника использует локальный старт: единое поле адреса или
приглашения, QR камерой/из фото, ответ и состояние в ServerRow. Проверка не меняет
выбор; после успешного ответа «Дальше» атомарно сохраняет источник и открывает
серверный экран входа либо исходное приглашение. Токен и параметры приглашения
не сохраняются в каталоге. При ошибке главного документа открывается принятый
локальный экран недоступности; при возврате к форме прежний выбор сохраняется.
Сборка и браузерный стенд проверены; актуальная проверка на телефоне ещё нужна:
[протокол](../docs/testing/android-startup-implementation-2026-11-17.md).
Скачивания сохраняются системным
ACTION_CREATE_DOCUMENT; «Открыть в…» доступно из уведомления о готовом файле.
Системные полосы связаны с темой Wynd;
на OPPO проверены обе темы и полный перезапуск.
Файловый выбор и доступ WebView к камере/микрофону добавлены; внешняя
фотосъёмка требует отдельного устойчивого сценария возврата в приложение.
Начальный адрес задаётся при dev-сборке, если сохранённого выбора ещё нет.
Дальше источник выбирается через «Настройки → Приложение → Интерфейс»:
список, проверка адреса до добавления, добавление без переключения и входа,
подтверждение удаления неактивного источника. Выбор сохраняется атомарно
в private `interface-servers.json` и переживает перезапуск и обновление APK.
Каждый выбранный origin получает новый WebView с собственными мостами;
входы, очередь и кэш прежнего адреса остаются на месте и не копируются.
Пока есть входящий Share или незавершённый системный выбор/экспорт, смена блокируется.
Раздел требует актуального серверного интерфейса; старый сервер его не покажет.
Без начального или сохранённого адреса открывается локальная стартовая форма.
Release-вариант
собирается unsigned для CI; публичная публикация заблокирована `releaseReady=false`
до реализации первого запуска/вшитого интерфейса и выбора ключа владельца.

Стартовый пакет собирается Gradle-задачей `prepareStartupAssets` из того же
Svelte-исходника, который утверждён на стенде (`a1d1e3ee`), с существующими Wynd UI,
шрифтами и общими стилями. Перед Android-сборкой нужен `npm ci` в `web`.
В APK входят только старт/QR/недоступность; маршруты основного клиента не вшиты.
`WebViewAssetLoader` обслуживает пакет с отдельного HTTPS origin;
`__wyndStartup` выдаётся только его главному документу. Сеть локальной страницы
закрыта CSP и перехватчиком; проверку `/api/v1/instance` выполняет Java.
Существующие системные файловый выбор и права камеры используются и на старте.

## Файлы, камера и микрофон

WebChromeClient открывает системный выбор документов с MIME-фильтром и режимом
один/несколько файлов. Обычный выбор не запрашивает доступ ко всему хранилищу:
проверяются конкретные content URI и их чтение; свои provider/UID и file URI
не принимаются из результата системного выбора.
Отмена завершает callback, повторный выбор работает. Файловые флаги WebView
`allowFileAccess`/`allowContentAccess` остаются false.

Камера QR/видео и запись микрофона используют существующий getUserMedia клиента.
Runtime-права CAMERA/RECORD_AUDIO запрашиваются по действию на выбранном сервере;
чужие/неизвестные ресурсы не разрешаются. Normal-разрешение MODIFY_AUDIO_SETTINGS
нужно Chromium для записи. Android-подсказки отправляют в настройки Wynd телефона.
Внешний ACTION_IMAGE_CAPTURE пока не включён: надёжный возврат в WebView после
его выгрузки требует отдельного сценария. HTML capture остаётся базовым выбором файла.

Повторяемая проверка на телефоне — `scripts/test-android-media.mjs`; команды,
реальные кадры и границы проверки — [протокол](../docs/testing/android-media-2026-11-16.md).

## Исходные геоданные фотографий записи

`FilePicker` с `preservePhotoLocation` использует отдельный origin-bound мост
`__wyndPhotoLocation`: главный документ получает одноразовый маркер, затем
открывает обычный системный выбор. Фотографии из ленты, редактора и через кнопку
«Файл» получают этот режим. Аватары, QR и обычные вложения других экранов его
не включают. На старой оболочке и в браузере остаётся прежний файловый выбор.

После выбора локального изображения Android 10+ запрашивает
ACCESS_MEDIA_LOCATION; Android 10–11 также READ_EXTERNAL_STORAGE для чтения
эквивалентного MediaStore URI. Местоположение устройства не запрашивается.
`MediaStore.setRequireOriginal` открывается только для выбранного изображения.
Закрытый read-only ContentProvider передаёт дескриптор в обычный File API WebView;
нет копии файла, HTTP-прокси, произвольных путей или передачи байтов через мост.
Новые временные persisted grants освобождаются после сопоставления URI,
существующие права не отзываются. Реестр выбранных источников очищается при
переходе главного документа и уничтожении Activity.

При отказе возвращается обычный выбранный файл; клиент сохраняет дату и не
подставляет GPS в место записи. Это **не удаление EXIF из байтов оригинала**:
некоторые SAF-провайдеры отдают полный JPEG даже без media-location. Прежний
контракт отправки файла с исходным EXIF сохраняется. Неизвестный провайдер или
недоступный MediaStore-оригинал оставляет обычный файл; утраченные координаты
не восстанавливаются и не заменяются текущим положением.

`scripts/test-android-photo-location.mjs` проверяет только синтетический JPEG из
репозитория через настоящий системный выбор. [Протокол, команды и ограничения](../docs/testing/android-photo-location-2026-11-16.md).
OPPO Android 10 проверен; realme, старые API и Android 13+ ещё требуют устройств.

## «Поделиться» из других приложений

SEND принимает обычный текст, фото и видео; SEND_MULTIPLE — набор фото/видео.
Смешанный набор с MIME `*/*` тоже сопоставляется Android с этими фильтрами.
Каждый фактический тип отдельно проверяется:
другие файлы отклоняются целиком. Произвольные URL не открываются как документы,
HTML остаётся текстом; file URI, свои provider/UID и источники без явного URI
read grant не принимаются. Новые системные разрешения для Share не нужны.

Данные копируются потоком в private `files/incoming-share`: до 32 файлов,
суммарно до 512 МиБ, текст до 32 КиБ UTF-8. Это предел приёма на устройстве;
лимиты выбранного сервера дополнительно действуют в редакторе. Метаданные
фиксируются после файлов, недописанные копии очищаются при следующем запуске.
Готовый набор остаётся до передачи в редактор или отмены. Второй Share не
заменяет первый. Текст/URI/координаты не выводятся в logcat.

`singleTask` сохраняет одно окно; `onNewIntent` не перезагружает WebView.
`__wyndIncomingShare` доступен только главному документу выбранного origin.
Страница читает метаданные, затем получает private-копии через строго
ограниченные same-origin subresource GET с UUID набора, `no-store` и `nosniff`.
Локального HTTP-сервера нет; пути/URI отправителя в запросы страницы не попадают.
JS получает Blob/File по одному, без base64 в мосте. После успешного чтения
редактор подтверждает приём и убирает native-копии. Далее действует прежнее
сжатие/подготовка Wynd; устойчивое продолжение после закрытия редактора ещё
относится к этапу 5.

После входа открывается `/share` с выбором доступного для записи круга.
В открытом редакторе автоматического перехода нет: его можно сначала завершить.
Системная «Назад», стрелка и «Отмена» отменяют выбор и удаляют набор.
Существующий текст черновика сохраняется; полученный текст добавляется через
пустую строку, без обрезания при переполнении. До выбора круга ничего не
отправляется. Само получение/подготовка не загружает медиа и не публикует запись.

Геоданные и байты сохраняются такими, какими их передал отправитель. Уже
вырезанный отправителем GPS не восстанавливается. Реальные источники облачной
галереи и старые/новые версии Android требуют отдельных прогонов.

Локальный `android/share-fixture` подключается **только** с
`-PwyndShareFixture=true`, release-вариант отключён. Он не входит в APK Wynd и
служит отправителем синтетических JPEG/WebM. Команды и осмотр настоящего
Svelte/WebView — [протокол](../docs/testing/android-share-2026-11-16.md).

## Сохранение и открытие файлов

Медиа Blob передаются native-мосту частями по 32 KiB с подтверждением записи;
архивы по одноразовой HTTPS-ссылке идут прямо с сервера в выбранный документ.
Целый файл не собирается в ArrayBuffer JavaScript. В debug разрешён HTTP только
на выбранном USB loopback origin. Повторные redirect проверяются; авторизационные
заголовки, cookies WebView и локальные пути мосту скачиваний не передаются.

После записи появляется тихое системное уведомление «Файл сохранён» с действием
«Открыть в…». Стороннее приложение запускается по нажатию; URI выдаётся на чтение.
На Android 13+ уведомления запрашиваются только после первого сохранения. При
отказе файл остаётся в выбранном месте. Постоянные read grants ограничены
16 последними документами. Отказ провайдера от постоянного grant может ограничить
время работы действия в уведомлении.

Скачивания пока не возобновляются после гибели процесса; прерванный документ
может остаться неполным. Автоматического удаления нет: ACTION_CREATE_DOCUMENT
может вернуть существующий документ. Это не реализация нативной очереди этапа 5.
[Проверки, реальные кадры и команды](../docs/testing/android-exports-2026-11-16.md).

## Среда и сборка на Windows

Среда в `D:\android-env`: распакованные Liberica JDK 17, Android SDK 36,
Build Tools 35.0.0, SDK Command-line Tools 19.0 и Gradle 8.13.
AGP 8.13.2 совместим с JDK 17 и Gradle 8.13:
[таблица Android](https://developer.android.com/build/releases/agp-8-13-0-release-notes).
Command-line Tools 19.0 закреплены для работы под согласованным JDK 17.

```powershell
.\scripts\build-android.ps1 -ServerUrl 'https://home.example.org'
```

По умолчанию скрипт выполняет `testStandardDebugUnitTest`, `lintStandardDebug`,
`assembleStandardDebug`.
Для локального сервера допустим HTTP **только** на `localhost`, `127.0.0.1`
и `[::1]` в отладочной сборке:

```powershell
.\scripts\build-android.ps1 -ServerUrl 'http://127.0.0.1:7696'
& 'D:\android-env\sdk\platform-tools\adb.exe' devices -l
# Если телефонов несколько, добавить -s <serial> в каждую команду ADB.
& 'D:\android-env\sdk\platform-tools\adb.exe' reverse tcp:7696 tcp:7696
& 'D:\android-env\sdk\platform-tools\adb.exe' install -r .\android\app\build\outputs\apk\standard\debug\app-standard-debug.apk
& 'D:\android-env\sdk\platform-tools\adb.exe' shell am start -n mixeme.wynd.debug/mixeme.wynd.MainActivity
```

Сервер на компьютере должен быть запущен отдельно. `adb reverse` даёт ему
USB-доступ с телефона без публикации порта в локальную сеть.

Проверка работающего отладочного пакета (Node с встроенным WebSocket):

```powershell
node scripts/test-android-webview.mjs <serial> http://127.0.0.1:7696 dev/screens/shots
```

Заменить `<serial>` номером из `adb devices -l`. Проверка не входит в учётку
и не отправляет записи: открывает приглашение, нажимает системную «Назад»,
проверяет отмену чужого перехода и сохранение собственного временного маркера
localStorage после полного перезапуска. Затем убирает маркер, делает настоящий
снимок через `adb exec-out screencap -p` и закрывает созданные CDP-порты.
Добавление `--inspect` даёт только диагностику текущего тестового экрана.

Скрипт временно задаёт `JAVA_HOME`, `PATH`, `ANDROID_HOME`, `ANDROID_USER_HOME`
и `GRADLE_USER_HOME`, затем восстанавливает прежние значения. Кэши Gradle,
включая кэш проекта, находятся внутри `D:\android-env`. Для другого пути
передать `-EnvironmentRoot`. При сборке без скрипта задавать эти переменные
процессу самостоятельно, а также `-PwyndEnvironmentRoot` и `--project-cache-dir`.

APK: `android/app/build/outputs/apk/standard/debug/app-standard-debug.apk`, пакет
`mixeme.wynd.debug`. Будущий пакет выпуска — `mixeme.wynd`.
Отладочный ключ — `D:\android-env\keys\wynd-debug.keystore`, alias
`androiddebugkey`, стандартные отладочные пароли `android`. Это отдельный ключ,
который не годится для выпуска. Ключи и машинные пути не включать в Git.

Минимум — Android 5.0 / API 21. Для привязанного к origin моста используется
AndroidX WebKit 1.14.0: последняя стабильная ветка с minSdk 21; более новые
ветки поднимают минимум. Google Play Services не используются. Это не
подтверждение всех функций этапов 1–5 на Android 5. Новые
библиотеки могут потребовать пересмотра минимума по правилам плана 50.
Компиляция и target — API 36. На API 30+ учтены системные отступы и клавиатура;
проверка на современном Android остаётся отдельным пунктом.

## Редакции standard и fdroid

Приложение собирается в двух редакциях — product-флейворы `standard` и `fdroid`
(dimension `distribution`, [план 67](../plans/67-fdroid-android.plan.md)):

- `standard` — редакция владельца: самообновление из GitHub-выпусков
  (раздел «Канал обновлений»).
- `fdroid` — редакция для f-droid.org: реализация самообновления (`UpdateController`,
  `UpdatePolicy`, `UpdateTransport`, `ReleaseCatalog`, `ApkVerifier`) не входит
  в APK — живёт в `app/src/standard/java`. Слитый манифест редакции теряет
  `REQUEST_INSTALL_PACKAGES` через `app/src/fdroid/AndroidManifest.xml`;
  `UpdateController` заменён заглушкой (`app/src/fdroid/java`), отвечающей
  веб-странице `updates: false` — клиент сам не показывает полосу обновления.
  Общий `InstallResultReceiver` остаётся в обеих редакциях: он только пересылает
  результат системного установщика контроллеру, а заглушка его игнорирует.
  API заглушки обязан совпадать с настоящим классом: общие `AndroidBridge`
  и `MainActivity` собираются без флейворных веток, расхождение ловится
  компиляцией. Тесты обновления — в `src/testStandard/java`, охраняющий тест
  заглушки — в `src/testFdroid/java`.

Задачи Gradle получают приставку редакции: `assembleStandardRelease`,
`assembleFdroidRelease`, `testFdroidDebugUnitTest` и тому подобное. Пути APK:

- `android/app/build/outputs/apk/standard/release/app-standard-release-unsigned.apk`
- `android/app/build/outputs/apk/fdroid/release/app-fdroid-release-unsigned.apk`

CI собирает обе редакции и кладёт обе в Actions artifacts; в черновик релиза
попадает только standard — f-droid.org собирает приложение из исходников сам
и подписывает своим ключом. Редакция не меняет package (`mixeme.wynd`)
и номер версии.

## Нативная очередь (этап 5.1)

Записи без вложений — текст, комментарии, реакции и снятие реакции — уходят
после закрытия окна. Страница отдаёт `__wyndQueue` запись и токен; `NativeQueue`
хранит их в private `native-queue.json`, `NativeQueueWorker` на WorkManager
отправляет тот же API, что и очередь страницы (включая `client_id`), и
возвращает `sent`/`failed`/`unauthorized`. Страница хранит `native_id`, не
сливает такую запись и сверяет статусы через `reconcileNativeQueue`; правка,
удаление, повтор и выход снимают native-копию. Токен и тело в журнал не
пишутся и дальше private-файла не уходят. 401 возвращает запись странице для
повтора после входа, 507 и сеть WorkManager повторяет с паузой, остальные 4xx
показываются как обычная ошибка очереди.

Файлы, постеры и обложки передаются в native через `begin → chunk → commit`;
native грузит порциями по 1 МиБ, считает SHA, продолжает по `Upload-Offset`
после обрыва и удаляет каталог после успеха. Офлайн-видео в приложении
сжимается нативно после закрытия окна: `VideoCompressor` на Media3 Transformer
(H.264/AAC, ограничение высоты) заменяет оригинал до загрузки; при ошибке
уходит оригинал. Фото и звук пока сжимаются страницей в foreground. Выбранный
`.wynd` помнится постоянным правом URI: `ArchiveStore` отдаёт его странице
через `/__wynd_archive/<token>`, и `accept` сам открывает файл после
перезапуска; пароль по-прежнему вводится заново. Если у ролика нет
клиентского кадра, `PosterExtractor` снимает первый кадр через
`MediaMetadataRetriever` и очередь грузит его отдельным постером; серверная
съёмка кадра (C48) удалена. Media3 добавляет к APK около 7 МБ;
лицензии Apache-2.0, Google Play Services нет. Ворота и живые прогоны —
[5.1](../docs/testing/android-native-queue-2026-11-24.md),
[5.2](../docs/testing/android-native-queue-files-2026-11-24.md) и
[5.3](../docs/testing/android-native-queue-compress-2026-11-24.md).

## Вшитый интерфейс (подготовка, план 50)

По решению владельца 23.11 — схема Настольного: клиент вшивается в APK, но
по умолчанию интерфейс по-прежнему приходит с сервера. Вшитый включается
только сборкой с `-PwyndEmbeddedUi=true` (`BuildConfig.EMBEDDED_UI`), обычные
APK его не содержат и не растут. В этом режиме страницы и статика выбранного
сервера отдаются из `www/` APK с SPA-фолбэком, а `/api/`, `/health`, `/ready`,
SSE, медиа, докачка и скачивания идут обычной сетью на сервер. Origin остаётся
адресом сервера, поэтому сессии, снимки и очередь в IndexedDB остаются на
месте. Сервис-воркер вшитого клиента встаёт на тот же origin и кэширует
вшитые файлы. Каталог `_app` лежит в APK как `app/` (aapt не пакует каталоги,
начинающиеся с `_`), наружу URL остаётся `/_app/…`. При смене сборки APK
старый Service Worker и CacheStorage снимаются один раз; IndexedDB не
трогается.

```powershell
.\scripts\build-android.ps1 -ServerUrl 'http://127.0.0.1:7676' -EmbeddedUi
```

Перед первой такой сборкой нужен `npm ci` в `web`: задача Gradle собирает
полный клиент (`vite build`), а не только стартовые экраны. Переключение
вшитого интерфейса по умолчанию (роль «встроенный», откат на серверный,
кадры и приёмка) — после стабилизации интерфейса, отдельным решением
владельца. Подача F-Droid — после этого переключения (план 67).

## Что учтено из настольной оболочки

Осмотрены `internal/desktop/{address,instance,store,proxy}.go`,
`cmd/wynd-desktop`, `$lib/desktop/bridge.ts`, справочник и планы 55, 61, 62.

- **Две роли сервера.** Настольный план 62 уже разделяет источник интерфейса
  и постоянные учётные записи. Каркас хранит только источник в конфигурации
  dev-сборки; он не создаёт вход и не копирует список сессий в Java.
- **Настоящий origin.** Android открывает сервер напрямую. Здесь не нужны
  `wails.localhost`, iframe, переписывание адресов или `apiBase` локального
  прокси. Проверка адреса повторяет ограничения настольного нормализатора:
  сервер в корне, без userinfo, query и fragment. Для телефона добавлено
  требование HTTPS с исключением для отладочной USB-петли.
- **SSE.** Настольный обход буферизации asset-сервера Wails не переносится:
  `shouldInterceptRequest` не подменяет допустимые запросы и не читает их
  ответы целиком. Доставку событий нужно отдельно проверить после входа.
- **Кэш и обновления.** У настольного окна был старый интерфейс из SW.
  Android не объявляется настольным, не отключает SW и не стирает данные при
  старте: план 50 требует сохранённый интерфейс без сети. При следующем шаге
  отдельно проверить обновление оболочки, восстановление без сети и queue.
- **Возможности по факту.** `__wyndDesktop` не выставляется: он включил бы
  настольные настройки и поведение. `__wyndAndroid` объявляет только готовое
  обновление APK: AndroidX `addWebMessageListener`, точный origin и главный
  фрейм. Объект не выдаётся чужим источникам, сообщения подфрейма отклоняются.
  `addJavascriptInterface` не используется; URL и путь APK страница не задаёт.
- **Чужие ссылки.** Главный документ ограничен выбранными схемой, хостом и
  портом. `file:`, `content:`, `intent:`, `data:` не открываются по ссылкам;
  Java не выдаёт WebView доступ к локальным файлам. Ошибки TLS не обходятся.

## Канал обновлений

Канал есть только в редакции `standard`; редакция `fdroid` обновляется
магазином приложений (план 67).

- Источник — публичные GitHub Releases `mixeme/wynd`, теги `android-vX.Y.Z`.
  Нужны `wynd-android.apk` и `wynd-android.apk.sha256`. Черновики, prerelease,
  неправильные метки, одинаковые/меньшие версии и чужие адреса assets не подходят.
- Выдержка **72 часа** действует по умолчанию. Время берётся из HTTP `Date`
  сервера каталога; неверные часы телефона не превращают выпуск в «будущий».
  Нет времени или ответа сервера — ошибка проверки, а не «последняя версия».
- «Приложение → Разработка → Скачивать сразу» доступно в debug и при включённых
  системных настройках разработчика Android. По умолчанию выключено. Настройка
  хранится в приложении и может применяться к обычным APK того же пакета/ключа;
  без режима разработки обход не действует даже при сохранённом значении.
- Автопроверка выполняется при запуске; активный клиент проверяет повторно
  при возврате в окно с интервалом 15 минут. Загрузка/установка — по действию
  человека. «Скачивать сразу» отменяет выдержку, а не системное подтверждение.
- Транспорт ограничивает HTTPS-хосты GitHub, перенаправления, размер ответа
  и APK. Локальный HTTP fixture возможен только в debug; release его не содержит.
- SHA-256 проверяет целостность скачанного файла, **не** авторство. Android
  проверяет подпись APK; сертификаты должны совпасть с установленным приложением,
  пакет — с текущим, `versionCode` — с тегом и быть больше установленного.
  Подпись `.sig` Ed25519 Windows-программ здесь не заменяет Android-подпись.
- Установка — через `PackageInstaller.Session` с обязательным действием
  пользователя. Разрешение источника спрашивается только после «Установить».
  Дополнительный запрос Play Protect может появиться позже основного окна;
  автоматизация не должна закрывать его запуском Wynd. Передача APK на внешнюю
  проверку требует отдельного согласия владельца телефона.
- Неуспешный `STATUS_FAILURE_ABORTED` не обязательно означает нажатие «Отмена»:
  так возвращается и отказ проверяющей системы. Поздние ответы отделены по ID
  сеанса, текущая ошибка очищается перед повторной установкой. Сеанс сохраняется
  до результата; данные WebView при обновлении не очищаются.

Версия — `version.properties`. Код: `major * 1000000 + minor * 1000 + patch`,
minor/patch 0–999, итог 1…2100000000. У приложения свой номер, отдельно от сервера.

## Подпись и GitHub

`.github/workflows/android.yaml` запускает тесты и lint обеих редакций и сборку
unsigned APK на изменениях Android/значков/самого workflow в `main` и pull
request, вручную и по `android-v*`. APK обеих редакций с SHA-256 сохраняются
в Actions artifacts на 14 дней, отчёты тестов/lint — на 7 дней, в том числе
при неуспешной сборке.
Сборочная задача имеет только `contents: read`. Отдельная задача с правами
записи запускается только по Android-тегу после успешной сборки: проверяет
сумму скачанного артефакта, удостоверяет происхождение и создаёт **черновик**
с `wynd-android-unsigned.apk` и SHA-256. Существующий релиз не заменяется.
Ключа APK на GitHub нет. Это не возобновление отложенного канала обновлений.

Проверка и подпись Android-выпуска — в окне «Wynd Подпись»
([план 65](../plans/65-signer-android.plan.md)): список выпусков, проверка
SHA-256, удостоверения `android.yaml` и тега, пакета, версии, debug-флага и
выравнивания, подпись apksigner и публикация по `releaseReady`. Отдельного
CLI-скрипта подписи нет: `scripts/sign-android-release.ps1` удалён 24.11 по
решению владельца; окно само создаёт ключ Android. В описание выпуска окно
добавляет пояснение к файлам: ставить `wynd-android.apk`;
`wynd-android-unsigned.apk` — тот же APK до подписи, для проверки удостоверения
сборки.

Постоянный ключ создаёт владелец в обычном локальном терминале:

```powershell
.\scripts\new-android-signing-key.ps1
```

По решению владельца от 2026-11-16 постоянный PKCS12 keystore хранится в
`D:\Local\Git\myenv\wynd\wynd-android.p12`, alias `wynd-android`.
Ключ создан и закоммичен отдельно в репозитории `myenv` (`b35f845`);
в репозиторий приложения его не добавляют. Скрипт создания ключа и окно
используют этот путь по умолчанию; для другой машины указать `-KeyStore` явно.

Пароль спрашивает `keytool`; в чат, аргументы скрипта или CI его не передавать.
Keystore, alias и пароль сохранить отдельно и в резервной копии. Debug-ключ
не годится для публичного канала.

Подпись и публикация — в окне «Wynd Подпись». Оно скачивает unsigned APK,
сверяет сумму, удостоверение именно `android.yaml` и тега, пакет/номер/
debug-флаги, подписывает и проверяет APK, готовит финальную сумму и описание
из `android/whatsnew.md` в теге. Уже подписанные assets не перезаписываются;
публикация — только если в теге `releaseReady=true`. Проверено 19–23.11 на
0.1.0 и 0.1.1; запасной путь создания ключа — `new-android-signing-key.ps1`.
[Протокол 0.1.1](../testing/android-release-0.1.1-2026-11-23.md).

Эталонный сертификат подписи — открытая часть ключа — лежит в теге
(`android/wynd-android.cert.pem`): окно «Wynd Подписи» сверяет с ним
подписанный APK и отказывается подписывать чужим ключом. Экспортирует владелец
один раз (пароль keystore вводит локально, в чат не передаётся):

```powershell
& (Get-ChildItem D:\android-env\jdk\jdk-17*\bin\keytool.exe | Select-Object -First 1).FullName `
  -exportcert -rfc -keystore D:\Local\Git\myenv\wynd\wynd-android.p12 -alias wynd-android `
  | Set-Content -NoNewline android\wynd-android.cert.pem
```

## Повторяемый прогон двух APK

`scripts/serve-android-update-fixture.mjs` отдаёт формат GitHub Releases только
на loopback 7697. Файлы и результаты — `D:\android-env\test-releases`.
Собрать одну и ту же реализацию как 0.1.0 и 0.1.1, подписанную одним debug-ключом;
дополнительно подготовить APK с чужой подписью и изменённым `classes.dex`.

```powershell
.\scripts\build-android.ps1 -ServerUrl http://127.0.0.1:7696 -UpdateFixtureOrigin http://127.0.0.1:7697
# Скопировать app-standard-debug.apk как base-0.1.0.apk в папку тестовых выпусков.
.\scripts\build-android.ps1 -ServerUrl http://127.0.0.1:7696 -UpdateFixtureOrigin http://127.0.0.1:7697 -VersionName 0.1.1
# Скопировать app-standard-debug.apk как candidate-0.1.1.apk и подготовить отрицательные файлы.
node scripts/serve-android-update-fixture.mjs D:/android-env/test-releases
node scripts/test-android-update.mjs SERIAL prepare
node scripts/test-android-update.mjs SERIAL install
# Дождаться всех системных запросов, включая проверяющую систему.
node scripts/test-android-update.mjs SERIAL finish
```

`prepare` проверяет выдержку, переключатель, подпись и сумму и сохраняет тестовые
маркеры localStorage/IndexedDB. Только исходная установка debug через ADB;
само обновление обязано пройти `PackageInstaller`. `finish` не открывает Wynd
до фактической смены номера, затем проверяет сохранность маркеров и удаляет их.
Этот прогон не является проверкой публикации на настоящем GitHub.
