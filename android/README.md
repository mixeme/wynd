# Wynd для Android — каркас и обновления APK

Решения: [план 50](../docs/plans/50-android-wrapper.plan.md). Java, системный
WebView, без Capacitor и Google-зависимостей во время исполнения.

Сейчас это отладочная основа: сборка APK, существующий интерфейс сервера в
WebView, системная «Назад», восстановление истории при пересоздании Activity,
ограничение главного документа выбранным origin и открытие чужих HTTP(S)-ссылок
в браузере по нажатию. Сессии и очередь принадлежат профилю WebView приложения;
входы браузера телефона и PWA автоматически не переносятся.

Первый запуск с выбором сервера, в том числе через приглашение/QR, обработка недоступного сервера
и сохранение скачанного ещё не реализованы. Системные полосы связаны с темой Wynd;
на OPPO проверены обе темы и полный перезапуск.
Файловый выбор и доступ WebView к камере/микрофону добавлены; внешняя
фотосъёмка требует отдельного устойчивого сценария возврата в приложение.
Адрес для этого шага задаётся при dev-сборке, а не является новым экраном продукта.
Без адреса Activity завершает запуск с диагностикой в logcat. Release-вариант
собирается unsigned для CI; публичная публикация заблокирована `releaseReady=false`
до реализации первого запуска/вшитого интерфейса и выбора ключа владельца.

## Файлы, камера и микрофон

WebChromeClient открывает системный выбор документов с MIME-фильтром и режимом
один/несколько файлов. Разрешений на всё хранилище нет: проверяются конкретные
content URI и их чтение; свои provider/UID и file URI не передаются странице.
Отмена завершает callback, повторный выбор работает. Файловые флаги WebView
`allowFileAccess`/`allowContentAccess` остаются false.

Камера QR/видео и запись микрофона используют существующий getUserMedia клиента.
Runtime-права CAMERA/RECORD_AUDIO запрашиваются по действию на выбранном сервере;
чужие/неизвестные ресурсы не разрешаются. Normal-разрешение MODIFY_AUDIO_SETTINGS
нужно Chromium для записи. Android-подсказки отправляют в настройки Wynd телефона.
Внешний ACTION_IMAGE_CAPTURE пока не включён: надёжный возврат в WebView после
его выгрузки требует отдельного сценария. HTML capture остаётся базовым выбором файла.

Повторяемая проверка на телефоне — `scripts/test-android-media.mjs`; команды,
реальные кадры и границы проверки — [протокол](../docs/testing/android-media-2026-11-16.md).

## Среда и сборка на Windows

Среда в `D:\android-env`: распакованные Liberica JDK 17, Android SDK 36,
Build Tools 35.0.0, SDK Command-line Tools 19.0 и Gradle 8.13.
AGP 8.13.2 совместим с JDK 17 и Gradle 8.13:
[таблица Android](https://developer.android.com/build/releases/agp-8-13-0-release-notes).
Command-line Tools 19.0 закреплены для работы под согласованным JDK 17.

```powershell
.\scripts\build-android.ps1 -ServerUrl 'https://home.example.org'
```

По умолчанию скрипт выполняет `testDebugUnitTest`, `lintDebug`, `assembleDebug`.
Для локального сервера допустим HTTP **только** на `localhost`, `127.0.0.1`
и `[::1]` в отладочной сборке:

```powershell
.\scripts\build-android.ps1 -ServerUrl 'http://127.0.0.1:7696'
& 'D:\android-env\sdk\platform-tools\adb.exe' devices -l
# Если телефонов несколько, добавить -s <serial> в каждую команду ADB.
& 'D:\android-env\sdk\platform-tools\adb.exe' reverse tcp:7696 tcp:7696
& 'D:\android-env\sdk\platform-tools\adb.exe' install -r .\android\app\build\outputs\apk\debug\app-debug.apk
& 'D:\android-env\sdk\platform-tools\adb.exe' shell am start -n mixeme.wynd.debug/mixeme.wynd.MainActivity
```

Сервер на компьютере должен быть запущен отдельно. `adb reverse` даёт ему
USB-доступ с телефона без публикации порта в локальную сеть.

Проверка работающего отладочного пакета (Node с встроенным WebSocket):

```powershell
node scripts/test-android-webview.mjs <serial> http://127.0.0.1:7696 dev/screens/shots
```

Заменить `<serial>` номером из `adb devices -l`. Проверка не входит в учётку
и не отправляет записи: открывает приглашение, нажимает системную «Назад»,
проверяет отмену чужого перехода и сохранение собственного временного маркера
localStorage после полного перезапуска. Затем убирает маркер, делает настоящий
снимок через `adb exec-out screencap -p` и закрывает созданные CDP-порты.
Добавление `--inspect` даёт только диагностику текущего тестового экрана.

Скрипт временно задаёт `JAVA_HOME`, `PATH`, `ANDROID_HOME`, `ANDROID_USER_HOME`
и `GRADLE_USER_HOME`, затем восстанавливает прежние значения. Кэши Gradle,
включая кэш проекта, находятся внутри `D:\android-env`. Для другого пути
передать `-EnvironmentRoot`. При сборке без скрипта задавать эти переменные
процессу самостоятельно, а также `-PwyndEnvironmentRoot` и `--project-cache-dir`.

APK: `android/app/build/outputs/apk/debug/app-debug.apk`, пакет
`mixeme.wynd.debug`. Будущий пакет выпуска — `mixeme.wynd`.
Отладочный ключ — `D:\android-env\keys\wynd-debug.keystore`, alias
`androiddebugkey`, стандартные отладочные пароли `android`. Это отдельный ключ,
который не годится для выпуска. Ключи и машинные пути не включать в Git.

Минимум — Android 5.0 / API 21. Для привязанного к origin моста используется
AndroidX WebKit 1.14.0: последняя стабильная ветка с minSdk 21; более новые
ветки поднимают минимум. Google Play Services не используются. Это не
подтверждение всех функций этапов 1–5 на Android 5. Новые
библиотеки могут потребовать пересмотра минимума по правилам плана 50.
Компиляция и target — API 36. На API 30+ учтены системные отступы и клавиатура;
проверка на современном Android остаётся отдельным пунктом.

## Что учтено из настольной оболочки

Осмотрены `internal/desktop/{address,instance,store,proxy}.go`,
`cmd/wynd-desktop`, `$lib/desktop/bridge.ts`, справочник и планы 55, 61, 62.

- **Две роли сервера.** Настольный план 62 уже разделяет источник интерфейса
  и постоянные учётные записи. Каркас хранит только источник в конфигурации
  dev-сборки; он не создаёт вход и не копирует список сессий в Java.
- **Настоящий origin.** Android открывает сервер напрямую. Здесь не нужны
  `wails.localhost`, iframe, переписывание адресов или `apiBase` локального
  прокси. Проверка адреса повторяет ограничения настольного нормализатора:
  сервер в корне, без userinfo, query и fragment. Для телефона добавлено
  требование HTTPS с исключением для отладочной USB-петли.
- **SSE.** Настольный обход буферизации asset-сервера Wails не переносится:
  `shouldInterceptRequest` не подменяет допустимые запросы и не читает их
  ответы целиком. Доставку событий нужно отдельно проверить после входа.
- **Кэш и обновления.** У настольного окна был старый интерфейс из SW.
  Android не объявляется настольным, не отключает SW и не стирает данные при
  старте: план 50 требует сохранённый интерфейс без сети. При следующем шаге
  отдельно проверить обновление оболочки, восстановление без сети и queue.
- **Возможности по факту.** `__wyndDesktop` не выставляется: он включил бы
  настольные настройки и поведение. `__wyndAndroid` объявляет только готовое
  обновление APK: AndroidX `addWebMessageListener`, точный origin и главный
  фрейм. Объект не выдаётся чужим источникам, сообщения подфрейма отклоняются.
  `addJavascriptInterface` не используется; URL и путь APK страница не задаёт.
- **Чужие ссылки.** Главный документ ограничен выбранными схемой, хостом и
  портом. `file:`, `content:`, `intent:`, `data:` не открываются по ссылкам;
  Java не выдаёт WebView доступ к локальным файлам. Ошибки TLS не обходятся.

## Граница интерфейса

Принятая основа Android: `docs/visual/screens.html`, `#e7-41`–`#e7-47`,
коммит `825921cc100f5cd8b793b5a245fa916d14ba426f`. Правила новых экранов —
`.cursor/rules/wynd-ui-screens.mdc` и `docs/testing/ui-review-protocol.md`.
Обновление использует существующие `NewsBanner` (#e7-7), `SettingsRow`, `Switch`,
`SectionLabel` и `Hint`. В `NewsBanner` добавлены только опциональные тексты,
прежний вид по умолчанию сохранён. Новые элементы Android ещё не приняты
владельцем по вёрстке. Подтверждение запуска WebView не закрывает этап 1.

## Канал обновлений

- Источник — публичные GitHub Releases `mixeme/wynd`, теги `android-vX.Y.Z`.
  Нужны `wynd-android.apk` и `wynd-android.apk.sha256`. Черновики, prerelease,
  неправильные метки, одинаковые/меньшие версии и чужие адреса assets не подходят.
- Выдержка **72 часа** действует по умолчанию. Время берётся из HTTP `Date`
  сервера каталога; неверные часы телефона не превращают выпуск в «будущий».
  Нет времени или ответа сервера — ошибка проверки, а не «последняя версия».
- «Приложение → Разработка → Скачивать сразу» доступно в debug и при включённых
  системных настройках разработчика Android. По умолчанию выключено. Настройка
  хранится в приложении и может применяться к обычным APK того же пакета/ключа;
  без режима разработки обход не действует даже при сохранённом значении.
- Автопроверка выполняется при запуске; активный клиент проверяет повторно
  при возврате в окно с интервалом 15 минут. Загрузка/установка — по действию
  человека. «Скачивать сразу» отменяет выдержку, а не системное подтверждение.
- Транспорт ограничивает HTTPS-хосты GitHub, перенаправления, размер ответа
  и APK. Локальный HTTP fixture возможен только в debug; release его не содержит.
- SHA-256 проверяет целостность скачанного файла, **не** авторство. Android
  проверяет подпись APK; сертификаты должны совпасть с установленным приложением,
  пакет — с текущим, `versionCode` — с тегом и быть больше установленного.
  Подпись `.sig` Ed25519 Windows-программ здесь не заменяет Android-подпись.
- Установка — через `PackageInstaller.Session` с обязательным действием
  пользователя. Разрешение источника спрашивается только после «Установить».
  Дополнительный запрос Play Protect может появиться позже основного окна;
  автоматизация не должна закрывать его запуском Wynd. Передача APK на внешнюю
  проверку требует отдельного согласия владельца телефона.
- Неуспешный `STATUS_FAILURE_ABORTED` не обязательно означает нажатие «Отмена»:
  так возвращается и отказ проверяющей системы. Поздние ответы отделены по ID
  сеанса, текущая ошибка очищается перед повторной установкой. Сеанс сохраняется
  до результата; данные WebView при обновлении не очищаются.

Версия — `version.properties`. Код: `major * 1000000 + minor * 1000 + patch`,
minor/patch 0–999, итог 1…2100000000. У приложения свой номер, отдельно от сервера.

## Подпись и GitHub

`.github/workflows/android.yaml` проверяет tag/version, тесты и lint, собирает
unsigned APK и удостоверяет его происхождение. Только от тега создаётся
**черновик** с `wynd-android-unsigned.apk` и SHA-256. Ключа APK на GitHub нет.

Проверить unsigned APK черновика без ключа и запроса пароля:

```powershell
.\scripts\sign-android-release.ps1 -Tag android-v0.1.0 -VerifyOnly
```

Проверяются SHA-256, attestation нужного workflow и тега, пакет, версия,
debug-флаг, выравнивание и заметки. Отчёт `verification.json` остаётся в
`D:\android-env\releases\…`. Подпись, загрузка и публикация в этом режиме
не выполняются; `-VerifyOnly` нельзя совместить с `-Upload`/`-Publish`.
Проверка unsigned работает и после добавления подписанного APK; существующие
подписанные файлы при обычном запуске скрипт по-прежнему не заменяет.

Постоянный ключ создаёт владелец в обычном локальном терминале:

```powershell
.\scripts\new-android-signing-key.ps1
```

По решению владельца от 2026-11-16 постоянный PKCS12 keystore хранится в
`D:\Local\Git\myenv\wynd\wynd-android.p12`, alias `wynd-android`.
Ключ создан и закоммичен отдельно в репозитории `myenv` (`b35f845`);
в репозиторий приложения его не добавляют. Скрипты используют этот путь
по умолчанию; для другой машины указать `-KeyStore` явно.

Пароль спрашивает `keytool`; в чат, аргументы скрипта или CI его не передавать.
Keystore, alias и пароль сохранить отдельно и в резервной копии. Debug-ключ
не годится для публичного канала.

```powershell
.\scripts\sign-android-release.ps1 -Tag android-v0.1.0 -KeyStore D:\Local\Git\myenv\wynd\wynd-android.p12
```

Скрипт скачивает unsigned APK, сверяет сумму, attestation именно `android.yaml`
и тега, пакет/номер/debug-флаги, локально подписывает и проверяет APK и готовит
финальную сумму/описание из `android/whatsnew.md` в теге. По умолчанию готовит
файлы **локально**. `-Upload` добавляет подписанные файлы в черновик; `-Publish`
дополнительно публикует, только если в теге `releaseReady=true`. Уже подписанные
assets не перезаписываются. В окно «Wynd Подпись» Android пока не добавлен:
отдельный локальный сценарий подготовлен, GUI остаётся следующим шагом. Публикация
этим скриптом ещё не проверена. Черновик `android-v0.1.0`, его attestation и
локальная подпись постоянным ключом проверены 2026-11-16. Подписанный APK
добавлен в черновик, скачан заново, подпись и SHA-256 сверены; системное обновление
остаётся незавершённым. Все сетевые проверки и условия публикации выполняются
до запроса пароля ключа. [Протокол](../docs/testing/android-updates-2026-11-16.md).

## Повторяемый прогон двух APK

`scripts/serve-android-update-fixture.mjs` отдаёт формат GitHub Releases только
на loopback 7697. Файлы и результаты — `D:\android-env\test-releases`.
Собрать одну и ту же реализацию как 0.1.0 и 0.1.1, подписанную одним debug-ключом;
дополнительно подготовить APK с чужой подписью и изменённым `classes.dex`.

```powershell
.\scripts\build-android.ps1 -ServerUrl http://127.0.0.1:7696 -UpdateFixtureOrigin http://127.0.0.1:7697
# Скопировать app-debug.apk как base-0.1.0.apk в папку тестовых выпусков.
.\scripts\build-android.ps1 -ServerUrl http://127.0.0.1:7696 -UpdateFixtureOrigin http://127.0.0.1:7697 -VersionName 0.1.1
# Скопировать app-debug.apk как candidate-0.1.1.apk и подготовить отрицательные файлы.
node scripts/serve-android-update-fixture.mjs D:/android-env/test-releases
node scripts/test-android-update.mjs SERIAL prepare
node scripts/test-android-update.mjs SERIAL install
# Дождаться всех системных запросов, включая проверяющую систему.
node scripts/test-android-update.mjs SERIAL finish
```

`prepare` проверяет выдержку, переключатель, подпись и сумму и сохраняет тестовые
маркеры localStorage/IndexedDB. Только исходная установка debug через ADB;
само обновление обязано пройти `PackageInstaller`. `finish` не открывает Wynd
до фактической смены номера, затем проверяет сохранность маркеров и удаляет их.
Этот прогон не является проверкой публикации на настоящем GitHub.
