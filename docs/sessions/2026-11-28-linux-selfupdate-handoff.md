Сессия по слову владельца: «Linux: механизм обновления. Linux: кнопка
„Открыть в приложении“ в браузере. Делаем.» Работа шла поверх 0.5.7 и
сервера 0.58.2; новых выпусков в этой сессии не было.

  `canOpenInApp` показывает принятую кнопку на странице приглашения в

- **Путь AppImage** (`d677cc93`, `09edcee1`): `SelfPath()` возвращает сам
  `.AppImage` из `APPIMAGE`, а не временный бинарник `/tmp/.mount_…`.
  Используется схемой `wynd:`, автозапуском, очисткой `.old` и подменой
  обновления. Живая проверка 28.11: CI-сборка записала
  `Exec="/tmp/wynd-0.5.7-ci.AppImage" %u`; официальная 0.5.7 перезаписывала
  на путь монтирования (старый дефект).

  заданного файла) и `FetchVerified` (скачивание + проверка подписи) с

- **Linux-самообновление** (`963c3935`): вид сборки — AppImage (`APPIMAGE`,
  симлинки раскрываются), `.deb` (`/var/lib/dpkg/info/wynd-desktop.list`),
  локальная сборка — без обновлений. Файлы выпуска `Wynd-*-x86_64.AppImage`
  и `wynd-desktop_*_amd64.deb` + `.sig`; выпуск без своего файла/подписи не
  предлагается. AppImage подменяет сам файл (`.old`), `.deb` ставится
  `pkexec dpkg -i` после проверки подписи. Новый процесс получает
  `WYND_UPDATE_FROM_PID`, ждёт выхода прежнего до `application.New`;

## Открыто и дальше

1. **Следующий выпуск Настольного** — единственный способ доставить это
   владельцу: поднять `desktop.Version` и `build/windows/info.json`, дописать
   `cmd/wynd-desktop/whatsnew.md`, перенести строки из `[Unreleased]` в раздел
   версии, прогнать `scripts\test.bat`/`test-desktop.bat`, собрать, подписать,
   опубликовать. В Linux-бинарник ключ уже вшивается.
2. **Живой `.deb` через pkexec** — после этого выпуска на машине с агентом
   PolicyKit: полоса → системный пароль → `dpkg -i` → окно новой версии;
   отмена пароля оставляет прежнюю версию и текст в полосе. Сейчас проверены
   только юнит-тесты `installDeb`/`debInstallCommand`. Реестр §12.
3. **Кнопка «Открыть в приложении» в Linux-браузере** — после следующего
   серверного выпуска (правка в web). Проверить Firefox/Chrome на Linux:
   кнопка есть, нажатие открывает окно на приглашении; на Android/iPhone и в
   окне её нет. Реестр §12.
4. **Схема и автозапуск AppImage после нового выпуска** — проверить, что
   `~/.local/share/applications/wynd.desktop` и
   `~/.config/autostart/wynd.desktop` указывают на файл AppImage, а не на
   `/tmp/.mount_…`; заодно `.old` после обновления убирается при старте (в
   официальной 0.5.7 этого ещё нет — старый `CleanOldSelf`).
5. **Остальные проверки Linux:** камера/микрофон (нужна другая машина),
   Wayland, HiDPI — реестр §12.
6. **Официальные 0.5.7 Linux-пакеты** собраны без ключа и этот механизм на
   себя не получат; это ожидаемо, перевыпускать 0.5.7 не нужно.

## Решения

- Принято: AppImage обновляется подменой своего файла (прежний `.old`);
  `.deb` — `pkexec dpkg -i` после проверки подписи; локальная сборка без
  установки обновлений не предлагает.
- Принято: подпись проверяется до установки; отказ/отмена — в существующей
  полосе обновления, без нового экрана.
- Принято: у AppImage схема `wynd:` и автозапуск используют `SelfPath`
  (сам файл AppImage); `os.Executable()` внутри образа для этого не годится.
- Не принималось: новых кадров вёрстки. Кнопка приглашения — тот же принятый
  компонент, что на Windows; полоса обновления — принятая полоса окна.

## Грабли

- **Тестовый AppImage должен лежать в каталоге, доступном на запись своему
  пользователю.** Первый прогон из каталога другого владельца дал
  `open …AppImage.new: permission denied` — это ошибка стенда, не дефект;
  кадр `update-error.png` показывает, что текст отказа виден в полосе.
- **`APPIMAGE` есть и при FUSE, и при `APPIMAGE_EXTRACT_AND_RUN=1`**, а
  `os.Executable()` в обоих случаях — временный смонтированный/распакованный
  бинарник. Для схемы, автозапуска, `.old` и подмены нужен `SelfPath`.
- **Официальная 0.5.7 старше правки `SelfPath`:** после живого обновления
  она перезаписала схему старым путём `/tmp/.mount_…` и не убрала `.old`.
  Это ожидаемо; проверять чистое поведение — на следующем выпуске.
- **Linux-машина не имеет Go/npm/GTK dev.** Linux-тесты гонялись
  кросс-собранным на Windows ELF-бинарником (`GOOS=linux go test -c`) через
  SSH; сборка и CI — в GitHub `desktop.yaml`.
- **Параллельная сессия.** В дереве были чужие правки (F-Droid, поиск,
  `search-memory`); коммиты делались только своими pathspec-путями. Не
  включать `web/src/lib/journal/search-memory*` в свои коммиты.
- **Auth Gitea** иногда отвечает `Failed to authenticate`; повтор через
  несколько секунд проходит.
