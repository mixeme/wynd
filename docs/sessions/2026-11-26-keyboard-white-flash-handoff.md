# Передача сессии 26.11: белая вспышка клавиатуры (C144)

Сессия по записи владельца: «Экран продолжает мигать. Сколько можно уже это
чинить?! Можно решить это системно?» — запись `Record_2026-11-26-15-56-35.mp4`.

## Сделано

- **Диагноз по записи** (`docs/testing/phone-flicker-2026-11-26.md`): при
  закрытии клавиатуры в поиске круга под бумагой на 0,3–0,7 с появляется
  полоса чистого `#FFFFFF` (до 36 % экрана), за одно закрытие — два импульса.
  Бумага `(244, 240, 232)` и её нижняя граница стоят на месте: содержимое
  готово, растёт «дырка» под ним. Это не APK: полосы системы не окрашены в
  цвет круга, как их красит `AppearanceBridge`. По поведению — Chromium
  (Chrome/Vivaldi/PWA): только он применяет `resizes-content`.
- **Причина:** `interactive-widget=resizes-content` в `app.html` отдавал
  сжатие layout viewport браузеру. Пока клавиатура уезжает, viewport ещё
  старый, клавиатура уже ниже — полоса между ними вне холста страницы, фон
  `body` туда не достаёт, и оболочка красит её своим фоном. Правка 0.25.10
  («страница в цвет темы») помогала только Firefox и тёмной теме.
- **Исправление** (`46588b5f`): метка убрана в `web/src/app.html` и
  `web/src/android-startup/index.html`; высоту окна считает только
  `visualViewport` (`--app-h`, `session/viewport.ts`) — тот же механизм, что
  уже работает в Firefox и в Chromium до 108. Холст `html` красится в
  бумагу/тёмную вместе с `body` — страховка.
- **Сторож** (`58660c4f`): `web/scripts/viewport-guard.mjs` + тест (2) в
  `check:ui` — `resizes-content` не вернуть.
- **Документы** (`11139d71`): протокол с кадрами
  (`docs/testing/phone-flicker-2026-11-26.md`, 4 снимка), реестр §16 (C144),
  план 46 (C144), `client-reference.md`, CHANGELOG.
- **Ворота:** svelte-check 0/0; `check:ui` — `viewport-guard: OK`,
  `chrome-guard: OK`, `check-spacing: OK`; 716 тестов, exit 0; prettier и
  eslint по изменённым файлам; `npm run build` — «done».

## Открыто и дальше

1. **Живая проверка C144** — реестр §16: на телефоне в Chromium (Chrome,
   Vivaldi, установленное веб-приложение) поиск в круге → «Назад» без белой
   полосы ни в одном кадре; повторить в «Написать в журнал…», в Firefox и в
   APK. **Визуально на устройстве не проверено** — устройства в сессии нет;
   не выдавать за приёмку.
2. **Серверный выпуск** — правка уезжает на телефон только с ним (интерфейс
   отдаёт сервер; APK и PWA тянут его же). Вместе с ней — накопленное:
   C136–C141, планы 73/74, C143, C144.
3. **C138** — в записи владельца имя в шапке круга появляется на 3,19 с
   (вход в круг на 1,56 с). Правка `f188c1e8` в main есть, но не выпущена;
   после выпуска — проверка по реестру §10.
4. Если владелец увидит вспышку ещё раз — фиксировать оболочку (APK, PWA,
   Chrome, Vivaldi, Firefox), версию сервера и запись с той же частотой;
   при `resizes-content` в HTML быть не должно (сторож), следующий шаг —
   фон окна конкретной оболочки, а не страница.

## Решения

- Принято: layout viewport не сжимает никто, кроме страницы; высота окна —
  только `--app-h` из `visualViewport` во всех оболочках; холст `html` —
  бумага/тёмная; метку сторожит `check:ui`.
- Отклонено: оставить `resizes-content` и лечить фоном `body` — белая полоса
  лежит вне холста страницы, фон её не покрывает.

## Грабли

- Запись 41,7 кадра/с; кадры разбирались `cv2` (ffmpeg в окружении нет):
  мерить цвета (бумага против белого) и неподвижную нижнюю границу бумаги, а
  не «на глаз» по снимку.
- Оболочку не определять по виду: у APK полосы красит `AppearanceBridge`
  (в снимках APK верх — цвет шапки круга, низ — бумага), у записи они
  системные `(246, 245, 250)`.
- `interactive-widget` встречался только в двух HTML; других потребителей
  метки в коде нет.
