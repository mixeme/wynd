# Передача сессии 26.11: полосы-подложка в окне Настольного (C143)

Сессия началась с вопроса владельца «поля где-то есть, где-то нет» по двум снимкам окна. Я ошибочно понял «поля» как поля ввода, сделал и выпустил правку C142 — владелец поправил: речь про вертикальные полосы на втором снимке. Правка откачена, тема сделана как C143.

- **Разбор полос** (по коду и снимкам): окно по умолчанию 760 × 780 (`cmd/wynd-desktop/main.go:838`), колонка интерфейса 720 (`--app-max-width`), iframe 720, а 20 px по бокам красила оболочка `--app-gutter` `#e0dbd2` (`.server-host`, `.page-host`, `body`). Экраны оболочки (ПК1, ошибки) подложки не имели — отсюда разнобой. В браузере/PWA шире 720 клиент рисует те же поля сам.

- **Кадры:** `docs/visual/reviews/window-no-gutter-2026-11-26/` — до (снимок окна владельца 760 × 780 и край крупно) и после (настоящий рендер shell + клиент, 760 × 780 и 1000 × 660), README с методом и SHA-256. **Вёрстка принята 26.11 («Принимаем»); кадры ПК5/ПК6/ПК6а/ПК7 обновлены.**

## Решения

- Принято владельцем: «Убрать в окне» — окно целиком бумажное, колонка 720 без видимых краёв; браузер/PWA не меняем.
- Отклонено: правка C142 (рамки полей) — была ошибкой понимания, откачена; в чате владельцу показан разбор полос.
- Не предлагать: «полосы везде» (подложка на экранах оболочки) и «убрать везде» — не выбраны.

## Грабли

- **Параллельные сессии.** В дереве одновременно работали C140/C141 и PWA-баннер: `internal/api/sessions.go`, `web/src/routes/+page.svelte`, `web/src/lib/pwa/`, `web/src/lib/session/pwaHint.ts`. Коммиты делать только с явным pathspec; `plan 46` и `CHANGELOG` правились конкурентно — при конфликте брать HEAD и удалять только свои строки (сделано для откката C142).
- **Чужие стенды/серверы.** На 7676 работал чужой стенд: свой поднял на 7678 (`dev/wynd-stand-72.exe`, данные `dev/frame72-data`). По невнимательности остановлен чужой сервер галереи на `:8899` (PID 32308) — та сессия при необходимости перезапустит; впредь проверять, чей порт, перед `taskkill`.
- **Съёмка окна с клиентом.** Сервер отдаёт `X-Frame-Options` — в iframe напрямую не вставить. Для кадров: shell mock `?screen=app` грузит клиент с vite 5173 (без XFO), а API клиента — через временный proxy `web/vite.config.ts` на стенд 7678 (`/api`). Прокси после съёмки возвращён; в коммит не попал.
- **Ожидание текста в iframe.** `waitText` из `dev/c120/cdp.mjs` не видит текст кросс-доменного iframe — снимок делать после фиксированной паузы, ориентироваться по картинке.
- **`--app-gutter`** остаётся для клиента/браузера; в окне больше не используется. Не менять токен глобально ради окна.
