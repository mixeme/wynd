## Решения

- C150 чинится в общем прокси, а не обходом в оболочке: класс «ответ отменён
  клиентом» и «сервер недоступен» различается по контексту запроса, поведение
  C66 (сетевой сбой для очереди) сохранено.
- Linux-меню трея — системное (GTK/DBusMenu), своей вёрстки нет; кадр нужен
  для приёмки, менять оформление не требуется.
- Ubuntu 24.04 не обязательна (слово владельца): прогон на MX Linux (база
  Debian 12) считается живой проверкой; чистый Debian/Ubuntu остаётся в CI.
- Ветку «без трея крестик закрывает» живьём не изображали: на машине есть
  StatusNotifierWatcher; политика закрыта тестом.

## Грабли

- **Asset-сервер Wails v3 не перехватывает панику** `http.ErrAbortHandler`:
  любой `panic` в обработчике запроса убивает всё окно. В обработчиках
  запросов окна нельзя рассчитывать на восстановление, как в `net/http`.
- `pkill` из SSH-пользователя `mix` не убивает процесс `mx`: `sudo -n -u mx
  pkill wynd-desktop`.
- Для одного экземпляра приложению нужен адрес сеансовой шины
  (`DBUS_SESSION_BUS_ADDRESS=unix:path=/tmp/dbus-…` из окружения панели);
  без него `gio open` запускает второй экземпляр, и это не дефект.
- Проверка «сервер недоступен» делается обрывом обратного туннеля: остановка
  стенда тоже годится, но туннель возвращается одной командой.
- IMAP-поиск imaplib не принимает кириллицу в `SEARCH`; код ищется по
  последним письмам с разбором заголовка локально. В `credentials.txt` две
  строки `Password` (ящик и панель wynd2) — парсер обязан остановиться на
  пустой строке блока.
- Окно, сдвинутое ниже экрана (760×780 при y=60 на 1280×800), обрезает низ
  страницы: «ТЕМА» была недоступна не из-за вёрстки, а из-за положения окна.
