## C95 — отзывчивость чтения кругов (план 46)

Три кандидата реализованы и замерены; контрольный проход на OPPO пройден. Числа и метод — [docs/testing/responsiveness-baseline-c95-2026-11-19.md](../testing/responsiveness-baseline-c95-2026-11-19.md):

1. **Лента на время чтения** — общий контроллер `web/src/lib/journal/reading.svelte.ts` (`CircleReading`: FeedData + общие словари обложек и лиц); запись открывается из загруженного, обновление фоном, возврат в ленту без перечитывания; сброс при уходе со круга. `FeedData` получил `rebind` и дедупликацию `load` (`inFlight`). Тесты — `reading.svelte.test.ts`.
2. **Лента параллельно с доступом** — в макете круга запрос ленты стартует после определения сервера; сведения о круге параллельно списку; аватар шапки после открытия экрана; `redrawDivider` пересчитывает границу непрочитанного.
3. **Оплата в фоне** — на списке кругов статус оплаты берётся фоном, строки нажимаются сразу; защита от устаревшего ответа по номеру обновления.

Итог по сети (net 150 мс/1,5 Мбит, CPU×6): список → лента 961 → 475 мс, нажатие → текст записи 344 → 145 мс, «Назад» → карточка 409 → 200 мс, «Назад» → список 756 → 530 мс. OPPO: те же эффекты, но медленнее (запуск 2355 мс, лента 462, запись 117, назад 314, список 236) — числа стенда читать как минимальную оценку.

**Осталось по C95:** «Поиск — позже» (строки без миниатюр, результаты по мере ответов серверов); остаток «Назад» (~0,3 с на OPPO) — пересоздание экрана ленты роутером, отдельного кандидата не заводили; телефонная проверка выпущенного PWA — на устройстве владельца (SW обновит клиент сам, «Что новое?» покажет 4 строки).

## Грабли метода замера (для следующего раза)

- **Протухший `web/.svelte-kit`** давал цикл full-reload посреди сценария (vite перегенерировал `.svelte-kit/generated` каждые пару минут) — лечится `rm -rf web/.svelte-kit` + перезапуск vite; в release-дереве зависимости ставить и в три фронтенда окон (`cmd/wynd-{workshop,signer,desktop}/frontend`), не только в `web`.
- **Затворённое окно Edge** останавливает rAF — метки отрисовки (`markPainted`) не приходят; запуск с `--disable-backgrounding-occluded-windows --disable-background-timer-throttling --disable-renderer-backgrounding` + `Browser.bringToFront` из CDP.
- **Координатные клики CDP** (`Input.dispatchMouseEvent`) по кнопкам не доходили до обработчиков — в драйвере JS-клик по элементу (`el.click()`); метка ставится в обработчике, так что это допустимо для замера.
- **На телефоне CDP нет** — метки рисуются отладочной плашкой на экране (`web/src/lib/dev/marks.ts`, крупный текст, `adb screencap`); «Назад» — кнопками шапки, системная back идёт мимо обработчиков с метками; порог «свежей страницы» для S4 — 20 с (холодный старт телефона дольше 3 с).
- **Сеялка данных** (`dev/c95/seed.mjs`, `avatars.mjs`, `more-posts.mjs`): вход по коду с сохранением токенов в `dev/c95/tokens.json` (лимит кодов 10/час на IP — чистится строками `code_request_log` в живой БД), приглашение = POST `/invites/{token}/claim` потом `/join` с `name`, аватары — PUT `/circles/{id}/identity` с `avatar_blob_id` (размер PNG делает блобы разными).
- **adb**: `svc power stayon usb` возвращает 137 и не применяется (настройки телефона не менялись); экран будить `input keyevent 224` перед каждым блоком.
