## Решения

- Сервер — минор **0.54.0** по прямому указанию владельца; клиенты — патчи.
- Android-иконка — adaptive с обязательным `<monochrome>` (требование lint
  Android 13+); тег 0.1.4 переставлен до создания черновика, опубликованных
  выпусков это не затронуло.
- Эталон `assets/icon.svg` и maskable остаются квадратными; скругление — в
  производных файлах.
- Набор реакций: ❤️ 😄 😮 😠 👍 😢 🎉; ключи `like`, `sad`, `party`.
- Опубликованные выпуски не перетегируем: исправление точек шагов уходит в
  следующую Мастерскую, а не в уже подписанную 0.4.9.

## Грабли

- Android lint: `MonochromeLauncherIcon` валит сборку, если в adaptive-icon нет
  `<monochrome>`; слой — тот же `wynd_icon_foreground`.
- Тег `android-v0.1.4` переставлялся force до черновика; зеркало GitHub
  обновило тег, прогоны перезапустились. Второй прогон того же тега остаётся
  лишним («Release already exists») — это ожидаемо.
- Gradle требует JDK 17 из `D:\android-env\jdk\jdk-17.0.21.0.3` и переменные
  `ANDROID_HOME`, `ANDROID_USER_HOME`, `GRADLE_USER_HOME`.
- Зеркало GitHub синхронизирует main и теги с задержкой ~1–2 мин; image workflow
  идёт на push main, клиентские — на теги.
- `gh api` иногда отдаёт HTTP 500 на списки прогонов — повторить или смотреть
  по `databaseId`.
- Публикация Android — последний шаг подписи. Если загрузка APK прошла, а
  публикация нет, окно 25.11 (`ae8e4aa0`) не бросает выпуск: при уже подписанном
  APK сверяет сумму, подпись с эталоном, пакет и версию и публикует без новой
  подписи. До этой правки состояние чинилось только вручную.
- `gh release view <тег>` видит черновик, а REST `releases/tags/<тег>` для
  черновика отдаёт 404 — не принимать 404 за «выпуска нет».
