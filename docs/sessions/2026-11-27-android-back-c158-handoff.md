# Передача сессии 27.11: «Назад» из списка кругов в APK закрывает приложение (C158)

Сессия — ответ на замечание владельца: «Android. Системная кнопка Назад из
списка кругов должна, как обычно на платформе, закрывать/сворачивать
приложение. Сейчас ничего не происходит.» Уточнено владельцем: речь в первую
очередь об **приложении для Android (APK)**, не о PWA.

## Сделано

- **Правка C158** (`71d0abdb`, уточнение `bdbced2b`): оболочка спрашивает
  страницу, что значит «Назад». `MainActivity.goBack()` шлёт
  `CustomEvent('wynd:android-back')` с `detail.exit` и читает ответ: `2` —
  выйти из приложения, `1` — страница справилась сама (оверлей, экран входа),
  `0` — обычный шаг истории. Выход повторяет платформу (`MainActivity.leaveApp()`):
  с Android 12 задача сворачивается в фон, как по Home (приложение остаётся в
  недавних тёплым), на Android 11 и ниже — `finish()`. Корневой макет
  (`web/src/routes/+layout.svelte`) ставит `exit` после закрытия верхнего
  оверлея и только на улице, за которой нет настоящего экрана:
  `androidBackClosesApp()` в `web/src/lib/navigation/up.ts` — тот же разбор,
  что у записи-копии C157 (позади вход `/`, копия улицы или пусто). Назад в
  настройки, поиск, другой круг, на шлюз `?closed=` — обычный шаг. Браузер и
  PWA не тронуты; окно Настольного не тронуто.
- **Почему разные версии Android.** Официальная документация
  ([tasks-and-back-stack](https://developer.android.com/guide/components/activities/tasks-and-back-stack)):
  на Android 11 и ниже системный Back на корневой launcher-activity завершает
  её, с Android 12 — переводит activity и задачу в фон, как Home, ради тёплого
  возврата; там же советуют не вызывать `finish()`, а отдавать корневой Back
  системе. Мы перехватываем событие (оверлеи и история WebView), поэтому
  повторяем оба случая сами.
- **Причина, почему раньше «ничего»:** запись-копия улицы (C157) делает
  `webView.canGoBack()` истинным всегда; `goBackWithoutOverlay()` →
  `webView.goBack()` уходил на копию, `popstate` возвращал улицу на место, а
  `finish()` вызывался только при пустой истории WebView.
- **Тесты/ворота:** `up.test.ts` — 40 (5 новых для C158); svelte-check 0/0;
  `check:ui` — OK; полный web-прогон — 753 теста, 153 файла, зелёные;
  prettier/eslint по изменённым файлам — чисто.
- **Совместимость:** старая оболочка шлёт `Event` без `detail` — новый клиент
  не падает и ведёт себя по-прежнему; новый APK со старым клиентом сервера
  тоже работает (ответ `0` — прежний путь). Правка активируется, когда новая
  оболочка и новый клиент встретятся.
- **Записано:** C158 — [план 46](../plans/46-open-questions-and-debt.plan.md)
  (`8bf52663`); раздел «C158: в APK „Назад“ с улочки закрывает приложение» —
  [протокол](../testing/street-back-2026-11-27.md#c158-в-apk-назад-с-улочки-закрывает-приложение);
  живая проверка — [реестр](../testing/pending-device-checks.md), §21;
  CHANGELOG — строка в `[Unreleased]` (`53603539`). Решение из открытого
  вопроса C157 («Назад на улице ничего не делает; если нужно выходить —
  отдельное решение») этим закрыто для APK.

## C159: аудит платформы Android (та же сессия)

Вопрос владельца после C158: «Есть ли ещё аспекты, где следовало опираться на
документацию Android?» Найдено пять расхождений; разбор, цитаты и границы —
[протокол](../testing/android-platform-audit-2026-11-27.md), C159 в
[плане 46](../plans/46-open-questions-and-debt.plan.md).

- **Сделано** (`b54ef3cd` — новые файлы, `2fe552f6` — правки оболочки,
  `71fb2db1` — документы): `onRenderProcessGone` — при гибели рендерера
  приложение не падает, а собирает новый WebView на том же адресе
  (`MainActivity.recoverPage`); полноэкранное видео —
  `onShowCustomView`/`onHideCustomView`, «Назад» сначала выходит из него;
  «Поделиться» — origin-bound мост `__wyndShare` (`ShareBridge`,
  `$lib/android/share.ts`), лист открывается, «Отправлено» не показываем —
  результат знает только система; `tel:`, `mailto:`, `sms:`, `mms:`, `geo:` —
  `ACTION_VIEW` по жесту (`ServerOrigin.isExternalAppLink`).
- **Геолокация (№2) включена по слову владельца «Включаем»** (коммиты — ниже):
  в манифесте `ACCESS_COARSE_LOCATION` и `ACCESS_FINE_LOCATION`, GPS-фичи
  `required=false`; `onGeolocationPermissionsShowPrompt` показывает системное
  объяснение «Место на карте» с «Разрешить»/«Не сейчас», затем системный
  запрос обеих точностей (Android 12+ предлагает приблизительное место).
  Отказ и «Не сейчас» оставляют карту с видом на все точки; «Не сейчас» — до
  конца запуска; после постоянного отказа объяснение не повторяется. Карточка
  приложения в магазинах меняется — владелец принял.
- **Проверки:** `share.test.ts` — 3; полный web-прогон — 756 тестов
  (154 файла); svelte-check — 0/0; `check:ui` — OK; prettier/eslint по
  изменённым файлам — чисто. Android локально не собирался (нет SDK/JDK 17) —
  Java в CI следующего APK; в 0.1.10 правок нет. Живые проверки — реестр, §27.

## Открыто и дальше

2. **Выпуск.** В черновик Android 0.1.10 правка не входит. Нужен следующий APK

   проверки на телефоне нужны оба; CHANGELOG-строка ждёт в `[Unreleased]`.
3. **Живая проверка на телефоне** — реестр, §21, новый пункт: улица → «Назад»
   выходит из приложения; оверлей закрывается первым; из настроек/поиска на
   улицу — обычный шаг. Отдельно по версиям: на Android 12+ задача остаётся в
   недавних и открывается тёплой, на 11 и ниже приложение закрывается.
   Проверять на сборке с обеими частями.
4. **C159 в следующем APK** — восстановление после гибели рендерера, полный

5. **Геолокация — сделана** по слову владельца «Включаем» (см. выше); открытых

## Решения

- Принято: «Назад» с улицы в APK выходит из приложения **как на платформе**:
  Android 12+ — `moveTaskToBack(true)` (задача в недавних, тёплый возврат),
  Android 11 и ниже — `finish()` (документация Android,
  [tasks-and-back-stack](https://developer.android.com/guide/components/activities/tasks-and-back-stack)).
  В браузере/PWA остаётся запись-копия (страница не может закрыть себя).
- Принято: оверлеи закрываются первыми, затем выход — как на платформе.
- Принято: протокол ответа числом (`2`/`1`/`0`) через `detail.exit`; старые
  оболочки шлют `Event` без `detail`.
- Принято (C159): при гибели рендерера — новый WebView на том же адресе, без
  закрытия приложения; полный экран видео закрывается системной «Назад»
  первым; системный лист «Поделиться» не помечает «Отправлено» — результат
  знает только система; `tel:`/`mailto:` и подобные — только по жесту
  пользователя, не по редиректу.
- Принято (C159): геолокация в APK включена по слову владельца «Включаем» —
  разрешения места в манифесте (карточка в магазинах меняется, принято),
  системное объяснение до запроса, «Не сейчас» действует до конца запуска.
- Отклонено (не предлагать): всегда `finish()` — на Android 12+ это расходится
  с платформой (задача исчезает из недавних); всегда `moveTaskToBack` — на
  Android 11 и ниже платформа закрывает activity; выход из браузера/PWA;
  переносить решение в `blockedHomeBack` (шаг истории) — там шаг не должен
  уходить с адреса.

## Грабли

- **Параллельная сессия.** Пока шла работа, соседний чат закоммитил
  `cabace87` + `9feefa9d` (0.58.1 и клиенты 0.5.7/0.1.10) и оставил
  незакоммиченными статусы C155–C157 в плане 46 и реестре (плюс
  `docs/plans/66-desktop-functions.plan.md`). Мои правки в этих файлах
  закоммичены через временный индекс (`GIT_INDEX_FILE` + `git update-index
  --cacheinfo` + `commit-tree`), чтобы не забрать чужие строки. Оставшийся
  `git status` в этих файлах — **чужие** правки, не включать.
- **HEAD и рабочее дерево расходятся в документах.** В HEAD план/реестр без
  свежих статусов C155–C157 (они не были закоммичены соседом), в рабочем
  дереве — со статусами. После коммита соседа это сойдётся; проверять
  `git show HEAD:…` и `git diff`, а не только рабочее дерево.
- **Окружение не собирает Android.** `ANDROID_HOME` пуст, `local.properties`
  нет, SDK не найден, Java 11; Gradle 8.13 требует 17. Не пытаться собирать
  локально — только CI. `javac`-проверку MainActivity без SDK тоже не сделать.
- **Кириллица в argv Windows-Python.** Путь `C:\Users\Микс\…` при передаче в
  `python` через Git Bash искажается (ENOENT). Скрипты и временные файлы —
  в ASCII-пути (`D:/Local/c158-docs-tmp`, можно удалить) и `python -I`.
- **Протокол — JSON-строка.** `evaluateJavascript` вернёт `"2"` как строку без
  кавычек (число), поэтому сравнение `"2".equals(result)`; для строковых
  ответов пришлось бы сравнивать с кавычками.
- **Общий индекс снова сработал (C159).** Соседний чат закоммитил
  `1d03419c` («Живые проверки настольных приложений») и вобрал в него мои
  правки оболочки — но **без новых файлов** (`ShareBridge.java`,
  `share.ts`/`share.test.ts`), из-за чего HEAD на минуту стал неполным
  (страницы импортируют несуществующий модуль). Затем сосед переписал историю
  (`7651e75b`), и мои правки вернулись в рабочее дерево. Довёл двумя
  коммитами: `b54ef3cd` (новые файлы) и `2fe552f6` (правки). После каждого
  чужого коммита проверять `git show HEAD:<путь>` и собирать ли
  ссылки/импорты; общие документы — только своими путями.
