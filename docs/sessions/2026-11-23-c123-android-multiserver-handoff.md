# Передача сессии 23.11 — C69/C123: многосерверность Android

Сессия 23.11.2026: решение C69, механизм C123, серверный CORS, флаг клиента,
кадры экрана «Серверы» и их приёмка. Все коммиты в `main`, запушены в Gitea
параллельными сессиями по мере работы.

## Решение

- **C69 закрыт окончательно.** Владелец: «Оставляем многосерверность только
  настольному и мобильному приложению. В PWA её не будет.» В браузере и PWA
  второй сервер не предлагается — это продуктовое правило, не заглушка.
- **C123 (Android): механизм — ограниченный CORS на сервере.** Владелец:
  «Принимаем твою рекомендацию.» Страница Android-клиента открыта с сервера A
  и напрямую обращается к API сервера B; B разрешает читать ответы только на
  маршрутах участника. Прямая сеть Android сохраняется — SSE, медиа-блобы и
  чанковые загрузки работают как раньше, mixed content не ослабляется.
  Резерв, если CORS не примут на проверке безопасности, — локальный прокси в
  оболочке Android (дороже: mixed content, SSE и медиа через прокси).

### Устройство CORS

`internal/api/cors.go`:

- только `/api/v1/` участника; **закрыты** `/api/v1/admin/*`, bootstrap и вход
  администратора, одноразовые ссылки `/api/v1/archive/…` и
  `/api/v1/full_archive_stream/…`;
- `Vary: Origin`; `Access-Control-Allow-Origin` — эхо проверенного origin
  (`http(s)://host[:port]`, без пути/запроса/фрагмента/userinfo);
- `Access-Control-Allow-Credentials` не выставляется — вход по Bearer-токену,
  cookie нет;
- preflight `OPTIONS` → 204; методы GET/POST/PUT/PATCH/DELETE; заголовки
  `Authorization`, `Content-Type`, `Range`, `Content-Range`, `Upload-Offset`,
  `If-Range`, `If-None-Match`, `If-Modified-Since`; `Max-Age: 600`;
- наружу: `Retry-After`, `Content-Range`, `Content-Disposition`, `ETag`,
  `Upload-Offset`, `Accept-Ranges`, `Location`.

Клиент: `ADD_SERVER_IN_APP` истинен при `__wyndDesktop` или `__wyndAndroid`;
в браузере ложен, кнопка не показывается. Настольное окно по-прежнему ходит
через Go-прокси `/__srv` — CORS там не нужен.

## Как повторить кадр

Инструменты — `dev/c123-frame/` (каталог `dev/` в `.gitignore`):

- `wynd.exe` — сборка `main`; **перед `go build` обязательно `npm run build`**
  в `web/`: интерфейс вшивается в бинарник. Данные — копия `dev/c92/data`,
  токен anya — `dev/c92/seedA.json`.
- Запуск стенда:
  `WYND_DATA_DIR=dev/c123-frame/data WYND_LISTEN=127.0.0.1:7676
  WYND_PUBLIC_URL=http://127.0.0.1:7676 ./dev/c123-frame/wynd.exe`.
- Edge headless: `msedge.exe --headless=new --disable-gpu
  --remote-debugging-port=9333 --user-data-dir=<новый профиль> about:blank`.
- `node dev/c123-frame/capture.mjs <out.png>`: CDP, 360×728 DPR 2,
  `Page.addScriptToEvaluateOnNewDocument` с
  `window.__wyndAndroid={postMessage:function(){},onmessage:null};`, затем
  навигация, посев сессии в IndexedDB, `/settings/servers`, снимок.
- `node dev/c123-frame/measure.mjs` — центры значков (`getBoundingClientRect`
  у `svg` и `use`).

Грабли:

- после пересборки интерфейса старый service worker отдаёт кэш — каждый раз
  новый профиль Edge (или чистить SW);
- старый стенд держит 7676: убить по PID из `netstat`, а не `taskkill /IM`;
- `git commit -- <path>` не берёт новые файлы: сначала `git add` новых;
- полный lint на HEAD красный из-за C120 (C124), не из-за C123.
