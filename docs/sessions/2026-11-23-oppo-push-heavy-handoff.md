# Передача сессии: OPPO — UnifiedPush и тяжёлые ветки (22–23.11)

Сессия агента 22.11 (вечер) — 23.11 (утро), телефон OPPO CPH1931 по USB чёрным ящиком. Всё записано в протоколы [phone-push-unifiedpush-2026-11-22](../testing/phone-push-unifiedpush-2026-11-22/README.md) и [phone-heavy-2026-11-23](../testing/phone-heavy-2026-11-23/README.md); отметки перенесены в [реестр](../testing/pending-device-checks.md) и [план 50](../plans/50-android-wrapper.plan.md). Среда на конец сессии погашена (стенды 7676/7677, reverse, SMTP-приёмник, будильный цикл экрана).

## Закрыто

- **§5 реестра — целиком:** системные пуши оплаты всех четырёх текстов (продление без заявки, отказ, утверждение с сроком — срок продлевался от прежнего, бессрочность) через ntfy на OPPO; шапка — имя сервера.
- **§0.1 уточнено:** на OPPO установлен внешний доставщик ntfy 1.25.2 (F-Droid-сборка, SHA-256 в протоколе) — прежний блокер «доставщика нет» снят.
- **§8.2/§9 UnifiedPush:** регистрация подписки тоглом, доставка учётке с двух стендов (свои VAPID — риск A8 не воспроизвёлся), замена endpoint тоглом, снятие при выходе, смена источника со снятием прежней регистрации, открытие правильного круга по тапу из уведомления. При остановленном процессе сигнал не догоняется (свойство UnifiedPush, ntfy хранит сообщение в теме).
- **0.39.3:** «Читаем файл…» на архиве 94,5 МБ; оживление до «сверено с файлом».
- **0.30.2:** все виды медиа в одном новом читаемом архиве (img/video/audio×2/файл, SHA-256 сходятся).
- **0.32.0:** приглашение участника в оживлённый круг; **большой файл и обрыв** («Не удалось выполнить запрос» при живой карточке; повтор = заново, обрыв не оставляет круга).
- **0.36.0:** просьба места — «Своё…» МБ, отказ в строке, валидация «больше занятого», меньшая просьба 95 МБ.
- **0.30.0:** «+» реакций скрыты в заполненном круге (Аня + Боб, 1 Б).
- **0.33.x:** меню участника («Дать право менять настройки», «Исключить»), «кэш очищен», упоминания над клавиатурой без себя.
- **0.25.x:** правка записи («Правится без ограничения», «Сохранить» гасится до ответа), мерцание старым текстом не воспроизводится (8 кадров, шаг 0,3 с).
- **C44:** узкая панель — семь названий разделов, карточка заявки с миниатюрой, снимок на весь экран с пресетами «Продлить на».
- **§5 письмо панели:** «Просят место» с ссылкой `/admin#requests` → вход → сразу раздел заявки.

## Новые дефекты и наблюдения (план 46)

- **C119:** комментарий из очереди с файлом 94 МБ сервер отверг после полной передачи («blob: invalid» — SHA-256 не сошёлся); 1 МБ прошёл. Порог не найден; повторить на ПК.
- **C114, экземпляр:** панель «Оплата» — «1 заявок ждут».
- Наблюдения: «вместо 0 ГБ» для круга без квоты в заявке; формулировка «это последняя версия» (веб) против «это последняя доступная версия» (APK); при остановленном процессе push-сигнал не догоняется; экран «Доступ закрыт» держится как устаревший снимок WebView до перезапуска.

## Хвосты (не исполнимы на стенде / не формализованы)

- Письмо о просрочке архива: нужен цикл с истёкшим сроком (минимум 24 ч); свидетельство wynd2 от 15.11 уже есть, телефонная сторона не показана.
- Цифра процента отправки в обсуждении (состояние «отправляется» поймано).
- «Вместо 0 ГБ» — мелкая подпись, решать с C114-классом.
- Детали карточек списка серверов и текущей почты — не формализованы владельцем.
- Две одновременные подписки UnifiedPush — блокирует C69.
- Установленная PWA для «Проверить обновления» — владелец ставит заново с действующего сервера.
- Повторы после правок кода: C99/C108, прокрутка ленты при возврате (2 сбоя), большой перенос «повторный вход», C98 при 1,35, потеря MP4 при ранней публикации.

## Грабли сессии (в памяти `phone-usb-checks`, `iphone-device-testing-limits`)

- После полуночи shell сессии начал отдавать кириллицу не в UTF-8: curl-тела записали битые имена на стенде. Правило: кириллические API-тела только через python-urllib; после артефактов сверять имена в кадрах.
- Keep-awake: `keyevent 224` раз в 60 с сбрасывает таймер сам; свайп по открытой клавиатуре печатает буквы — свайп из цикла убран.
- Обёртка требует `http://` в адресе локального стенда; `am force-stop` доставщика блокирует broadcast `REGISTER`; просить место может только владелец и только у заполненного круга; смена URL в Firefox — крестик «×» в поле; в loopback-режиме сервер дублирует письма целиком в журнал; «Письма администратору» на стенде пусты — письма не уходят вовсе.
- Съёмка кадров и pull-файлов: device-пути только с `MSYS_NO_PATHCONV=1`, локальные пути для push — Windows-вид; pull по одному файлу (в цикле с `\\$var` файлы терялись).
