# Передача сессии 26.11: поле ввода с акцентной рамкой (C142)

Сессия — разбор вопроса владельца «поля где-то есть, где-то нет» по двум снимкам: окно Настольного 0.4.2 («Адрес сервера») и клиент («Почта»). Владелец просил разобраться, как делать; выбор из вариантов в чате остался без ответа — сделан минимальный по утверждённым кадрам вариант, вёрстка показана и ждёт приёмки.

## Сделано

- **Разбор** (без коммита, по снимкам и коду): фон у полей один — `#fcfaf6` (`--card`) на бумаге `#f4f0e9`; отличается только рамка 1 px. Причина — статичный проп `Input.active` → `.fld.act` (`web/src/lib/styles/ui.css:1757`, `:1892`). В клиенте `active` стоял на 31 поле из 34, в оболочках почти нигде: окно — 3 из 4, стартовый экран Android — без него; отставали «Разделить круг» и приём переноса. Внутри одного окна соседние экраны показывали разные поля.
- **Правило и правка** (`48206d82`): поле, которое можно менять, — с акцентной рамкой (`.fld.act`, цвет `--c` экрана); мягкая `.fld` — у статики (`FieldDisplay`) и в админке `.inp`. `active` добавлен 3 полям клиента и 3 полям окна (адрес на первом запуске, интервал, число копий). Сторож `checkEditableFieldAccent` в `check-ui` роняет `Input` без `active`/`admin` в экранах, тест в `ui-guard.test.ts`, правило в `docs/reference/ui-components.md`, пункт C142 в плане 46 и CHANGELOG.
- **Кадры** (`48206d82`): `docs/visual/reviews/field-accent-2026-11-26/` — настоящий рендер окна 760 × 780, до/после и увеличенные фрагменты; README с основой, методом, SHA-256 и границами. Оба кадра сняты с одного дерева (у «до» временно убран `active`).
- **Проверки:** `check:ui` зелёный (включая chrome-guard параллельной сессии), svelte-check 0/0, 695 тестов, prettier по своим файлам, `npm run check` и `npm run build` в `cmd/wynd-desktop/frontend`.
- **Приёмка:** нет. Показан кадр `welcome-after.png`; ждёт «принимаем» владельца.

## Открыто и дальше

1. **Приёмка вёрстки окна и правила** — кадр и разбор: [README проверки](../visual/reviews/field-accent-2026-11-26/README.md), локальная галерея была на `http://127.0.0.1:8896/` (сервер мог остаться в фоне). Если принято — обновить кадры ПК1/ПК4 в `docs/visual/desktop.html` (сейчас рисуют мягкое поле) и убрать пометку «ждёт приёмки» из C142.
2. **Если отклонено в пользу мягкой рамки** — снять `active` с ~31 поля клиента, сделать акцент только на фокусе (как `.ins input.fld:focus` в Мастерской) и переутвердить кадры клиента. Это большая переделка утверждённых кадров, не начинать без явного слова.
3. **Стартовый экран Android** — поле адреса стало акцентным (`web/src/routes/dev/smoke/android-startup/+page.svelte`); визуально проверяется только в следующей сборке APK. Запись — реестр, §14 «Поля ввода — акцентная рамка (C142)».
4. **Живой прогон** — открыть окно Настольного (сборка после `48206d82`) и пройти «Адрес сервера → Почта»: рамки должны совпасть. Сейчас проверено рендером исходника, не установленным окном.

## Решения

- Принято правило (по разбору, не владельцем): фон у всех полей один, акцентная рамка — у редактируемых. Мягкая — статика и админка.
- Выбран минимальный вариант — акцентная рамка везде: он не трогает 39 мест утверждённых кадров клиента и правит 6 полей в оболочках. Мягкая рамка у всех (с акцентом только в фокусе) не отклонена как идея, а отложена: это переделка ~31 поля и переутверждение кадров.
- Кадры ПК1/ПК4 окна **пока не правились** — утверждённую основу меняет только владелец; код после C142 расходится с ними до приёмки.
