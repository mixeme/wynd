# Передача сессии 25.11: уведомления Android — встроенный канал и форк доставщика

Сессия — разбор пути обычного пользователя после отказа Sunup. Код не менялся:
записаны два клиентских варианта в план, проверены готовые форки ntfy.

## Сделано

- **Разобран путь обычного пользователя.** Доставщик обязателен и обычно один
  на телефон; свой push-сервер сам по себе порог не снижает, пока адрес
  вводится в доставщике. «Ноль действий» без Google даёт только встроенный
  канал; с чужим доставщиком остаётся установка второго приложения. ntfy.sh
  держится на авторе проекта и платных тарифах, SLA и гарантий нет.
- **Встроенный канал записан** в [план 50](../plans/50-android-wrapper.plan.md),
  раздел «Встроенный канал»: собственное постоянное соединение Wynd,
  foreground service, без второго APK. Коммит `275158c1`.
- **Готовые форки проверены** (`3e6a9e36`): `TheBlusky/ntfy-android-builder` —
  preset `NTFY_APP_BASE_URL`, Play/FCM, тег 1.16.0, не обновлялся с 2023;
  `mptfire/axon-android` — `axon://pair/<code>?auto=1&server=…` и
  provision-файл, но это канал своего сервиса, не UP-доставщик;
  `SaitoTech/saito-ntfy-android` — preset `app_base_url`, 2024. Общего форка
  с deep link для default server нет: upstream #440 открыт с 2022, PR #67/#91
  не смержены.
- **Форк доставщика записан** по слову владельца (`53a0f2b0`): второй APK на
  базе `ntfy-android`, **без преднастроенного адреса**; Wynd передаёт адрес
  push-сервера через защищённый компонент, сервер Wynd сообщает адрес.
  Обновлены [план 50](../plans/50-android-wrapper.plan.md) и
  [план 45](../plans/45-workshop.plan.md).
- **Приёмок, выпусков и телефонных проверок нет** — код не менялся. CHANGELOG
  и реестр проверок не трогались: кода и новых проверок нет.

## Открыто и дальше

1. **Решение о начале.** Встроенный канал и форк доставщика записаны как
   кандидаты этапа 4; срок, объём и основной путь не выбраны. План 50, разделы
   «Встроенный канал» и «Форк доставщика».
2. **Адрес push-сервера.** Сервер Wynd должен сообщать приложению адрес своего
   push-сервера (ntfy из плана 45) в данных сервера/приглашения. Если адреса
   нет — поведение отдельным решением; ntfy.sh молча не подставляем. План 50.
3. **Один `DefaultBaseURL` у доставщика.** При нескольких входах Wynd на разных
   серверах с разными push-серверами нужен общий push-сервер или доработка
   форка на адрес для каждой регистрации; смена адреса затрагивает все
   UP-подписки, не только Wynd. План 50, «Что проверить до решения».
4. **Защита компонента настройки.** Signature-разрешение при общей подписи APK
   или одноразовый код; exported-компонент не должен позволять чужому
   приложению перенастроить доставщик.
5. **Мастерская: опциональный push-сервер** — без изменений, ждёт выбора
   autopush-rs или ntfy и слова владельца. [План 45](../plans/45-workshop.plan.md).
6. **Остальные открытые** — без изменений: Android 0.1.2 ждёт подписи;
   Настольный 0.4.4/0.4.5, Мастерская 0.4.8 — по реестру и передачам 24.11.

## Решения

- Принято 24.11: встроенный канал записать в план; не начато.
- Принято 24.11: форк доставщика записать; **предустановленного адреса не
  будет**, Wynd настраивает адрес сервера.
- Отклонено: preset-адрес в сборке (builder/ребренды) как наш путь — работает
  для одного сервиса, не даёт Wynd настраивать адрес и ломается при переезде.
  Эти проекты остаются ориентирами по сборке и provisioning, не основой.
- Отклонено: молчаливая подстановка ntfy.sh при отсутствии адреса; без адреса —
  отдельное решение.
- Не решено: какой из двух путей основной и начинать ли сейчас.
- Напоминание: upstream #440 не реализован; не рассчитывать на него.

## Грабли

- UP-регистрация в ntfy берёт `repository.getDefaultBaseUrl() ?: app_base_url`
  (`up/BroadcastReceiver.kt`, ~строка 78). Ссылка `ntfy://host/topic`
  подписывает на тему, но default server не меняет; документированного способа
  передать адрес извне нет.
- `TheBlusky/ntfy-android-builder` собирает Play/FCM (нужен
  `google-services.json`), тег 1.16.0; для F-Droid/no-Firebase его надо править.
- `mptfire/axon-android` — свой канал axon, не UP-доставщик; брать оттуда можно
  образец защищённой настройки (`autoPairServerAllowed`) и provisioning.
- Параллельные сессии: между нашими коммитами появился чужой `bbdb3587`
  (Linux/подпись); свои правки коммитились только pathspec. Push в Gitea один
  раз отказал по auth — повтор прошёл.
- В документах нет идентификаторов тем и адресов подписок (SEC-7).
