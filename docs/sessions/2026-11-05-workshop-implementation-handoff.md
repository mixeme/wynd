## Задача владельца и ближайшее продолжение

Владелец поручил реализовывать утверждённые **список серверов и пульт**, каждый законченный шаг сохранять отдельным коммитом, в конце сделать выпуск. На уточнение «Ты будешь потом проверять по экрана настоящего приложения?» дан ответ: да, браузерный стенд не заменяет проверку exe.

**Следующее действие — завершить проверку настоящего исправленного приложения**, включая штатное компактное окно. Основные браузерные кадры уже осмотрены, найденные расхождения исправлены. Однако снимок exe получить не удалось: после выбора и активации окна оба штатных захвата Computer Use завершились таймаутом. Не объявлять нативную проверку выполненной и не выпускать старый отклонённый кандидат.

Не начинать заново реализацию профилей и не возвращаться к ручным картинкам. Не запрашивать заново принятие неизменённых утверждённых кадров. Смысл, принятие исходного макета, проверка его реализации и готовность выпуска — отдельные факты.

## Что реализовано

- `internal/installer/workshop.go`: профили в `os.UserConfigDir()/Wynd/workshop/servers.json` (Windows — `%APPDATA%`), атомарная запись, без паролей и сырых SSH-журналов. Сессии по стабильному ID; блокировки операций, обоих участников переезда и совпадающих реальных SSH-адресов. Самообновление блокируется при работе любого сервера.
- `cmd/wynd-installer/profiles.go`, `main.go`: Wails API с явными ID; ошибка открытия/повреждения списка показывается, файл не затирается пустым списком. Общие вспомогательные методы приватные.
- `frontend/src/Window.svelte`: вкладки, список, формы профиля, постоянные экземпляры `App.svelte`. Переключение сервера, архивов или сведений об обновлении не размонтирует выполняющиеся операции.
- `frontend/src/App.svelte`, `api.ts`: состояние и вызовы привязаны к профилю, отдельные автоподключения, сохранённые сведения, переезд между профилями. После переезда исходное соединение сохраняется, новое передаётся назначению, оба сервера проверяются заново.
- Изменённый SSH-ключ требует старого/нового отпечатков и отдельного явного подтверждения; wildcard/CA и устаревшее подтверждение не перезаписываются. Реальные ключи владельца не использовались.

Пути `frontend/...` в этом разделе относительны `cmd/wynd-installer/`. Основные UI-компоненты — `web/src/lib/components/workshop/`; общие поля — `forms/Input.svelte`, кнопки — существующие Wynd UI.

## Причина провала и последние исправления

В `2a7e7450` потеряны `.ins-content`, `.ins-workspace`, `.ins-profile-view`, `.ins-archive-view`, `.ins-hidden`, `.ins-pane`, формы/нижние панели и responsive-правила. В результате скрытые разделы становились видимыми, каркас распадался. Старые jsdom-тесты не подключали `app.css` и фильтровали скрытые панели по имени класса, поэтому дефект не обнаружили.

`03ab3f65` восстановил блок из `a0f12cf7`; тест с настоящим CSS сначала воспроизвёл отказ, затем прошёл. Первый запуск возвращён к `s0`: текст пустого списка и основное действие внизу.

Настоящие браузерные снимки выявили дополнительные ошибки. `98cef915` исправляет:

- Scoped-стиль `FootBar` перекрывал `margin-top:auto`: нижнее действие первого запуска оставалось посередине окна. Уточнена специфичность каркаса и расположение разделителя.
- Возвращены путь формы, интервалы полей, размеры/вес шапки, вкладок и заголовка списка, рамка принятого окна. Новые правила ограничены `.ins-win.ins-servers`; «Подпись» не должна получать оформление списка серверов.
- Основное действие обновления возвращено под пояснение `Notice` через существующий `FootBar`; строки бэкапа и переезда — к виду/подписям `7а`. `MarkRow mark=""` не рисует необязательный значок.
- В ходе операции бейдж рядом с именем показывает связь («Подключён»); название операции/этап остаётся в списке. Есть путь операции, нижняя панель занятой операции без ссылок профиля, шкала через существующий `Meter`.
- `StepList meter` показывает **долю завершённых этапов**, не процент оставшегося времени. Он не реализует C71. По умолчанию опция выключена.
- Форма резервирует пароль и пояснение; смена ключа/пароля не сдвигает подключение и отмену.
