# Передача сессии 28.11: метка карты (C161)

Сессия — вопрос владельца по снимку «Мигание → Карта»: «Почему на карте
фотографии — это круги? И почему справа в круге пустое место?».

## Сделано

- **Разбор** (`cbc45ac1` — правка): круг — стиль метки из первой версии
  интерфейса (`map.css`: 44 px, `border-radius: 50%`, кольцо 2 px цветом
  бумаги), введён в `d9fd0221`. Пустое место справа — дефект: Leaflet
  сбрасывает ширину картинок маркерного слоя
  (`.leaflet-container .leaflet-marker-pane img { width: auto }`) с той же
  специфичностью, что у `.ph .map-pin-thumb img { width: 100% }`, а в
  собранном бандле CSS Leaflet идёт **после** `map.css` (порядок зависимостей
  маршрута: `assets/map.*.css`, затем `assets/41.*.css`). Портретное фото
  получало ширину по высоте — 33 × 44 в кружке 48 × 48, справа полоса 11 px;
  квадратные и горизонтальные заполняли. В dev порядок обратный, поэтому
  дефект был виден только в сборке и APK.
- **Правка** (`cbc45ac1`): селектор усилен до
  `.ph .map-wrap .leaflet-container .map-pin-thumb img` — сильнее сброса
  Leaflet при любом порядке файлов. Вид и размер метки не менялись: в
  приложении метка 44 px (общий `box-sizing: border-box` из `+layout.svelte`),
  фото 40 px; стенд без этого сброса показывает 48 и 44 px.
- **Форма метки по слову владельца 28.11** («Форма метки - квадрат в белой
  рамке»; `2594c040`): `map.css` — радиус 0, рамка `#fff` 2 px, метка
  44 × 44, фото 40 × 40.
  Настоящий рендер собранного клиента (сервер стенда на копии `dev/data`,
  круг «Наш дом», 412 × 915, DPR 2, скопление раскрыто нажатием): до — круг,
  после — квадрат; кадры — `docs/testing/map-pin-shape-2026-11-28/`.
  **Вёрстка ждёт приёмки владельца; в CHANGELOG не вносилась.**
- **Настоящий рендер** (`e7e19366` — протокол и кадры): Edge headless, DPR 3,
  собранные CSS в порядке бандла, DOM маркера как у Leaflet. До — портретное
  33 × 44, квадратное 44 × 44, горизонтальное 58,7 × 44; после — 44 × 44 у
  всех. Кадры — `docs/testing/map-pin-fill-2026-11-28/` (метки на стенде, не
  полный экран и не телефон).
- **Документы** (`e7e19366`, `3c0262c7`): протокол заполнения, протокол формы
  с настоящими кадрами, пункт C161 в плане 46, реестр §29,
  CHANGELOG `[Unreleased]` (только заполнение).
- Сборка `npm run build` — зелёная (2 м 20 с), `check:ui` — OK, prettier по
  `map.css` — чисто. Тесты не трогались: правка только CSS.

## Открыто и дальше

   круга с портретным фото — кружок заполнен целиком, полосы справа нет;
   квадратные и горизонтальные обрезаны по кругу как раньше. **Телефона в
   сессии не было; полный экран приложения не снимался.**
2. **Приёмка формы метки** — владелец задал форму 28.11 («квадрат в белой
   рамке»), настоящий кадр снят: `docs/testing/map-pin-shape-2026-11-28/`,
   галерея на `http://127.0.0.1:8902/` (каталог `dev/map-pin-check/`).
   Ждёт слова «принимаем» или правки (скругление, толщина/цвет рамки, размер).
   Кадр [5.6](../visual/screens.html#e5-6) не перерисовывался: слово владельца

3. **Выпуск** — C160 и C161 лежат в `[Unreleased]` CHANGELOG (пункт про

   следующим серверным выпуском (клиент — сервер). Android APK правку получит
   с серверным клиентом; отдельная сборка не нужна, если интерфейс берётся с
   сервера.

## Решения

- Принято: первая правка меняла только заполнение фотографией; форму и размер
  метки не трогала.
- Принято владельцем 28.11: форма метки — **квадрат в белой рамке**. Точные
  пиксели (44 × 44, радиус 0, рамка `#fff` 2 px) предложены и ждут приёмки;
  если владелец поправит — меняется одно правило в `map.css`.
- Отклонено в первой правке: `box-sizing: border-box` на `.map-pin-thumb` —
  в приложении общий сброс из `+layout.svelte` уже даёт border-box; добавлять
  его к метке не нужно.
- Не переоткрывать без слова владельца: тень метки, кружки скоплений
  `leaflet.markercluster` со счётчиком, лист записи.

## Грабли

- Дефект порядка CSS **не воспроизводится в dev**: там `map.css` грузится
  после Leaflet. Проверять только на собранных файлах и в порядке из
  `__vite__mapDeps` (`assets/map.*.css` → `assets/41.*.css`).
- Специфичность: `.leaflet-container .leaflet-marker-pane img` — (0,2,1), как
  и прежний `.ph .map-pin-thumb img`; порядок файлов решал исход. Новый
  селектор (0,4,1) выигрывает независимо от порядка.
- Стенд проверки — `dev/map-pin-check/capture.mjs` (каталог `dev/` в
  `.gitignore`): сам поднимает headless Edge с CDP, снимает метки и печатает
  размеры картинок; CSS-файлы передаются аргументами, чтобы гонять «до» и
  «после» на одной сборке. Кадры для репозитория скопированы в
  `docs/testing/map-pin-fill-2026-11-28/`.
- `npm run build` пишет в `web/dist`; в git это не попадает. После правки CSS
  имена файлов бандла меняются (`map.*.css`), не искать старый.
- **Общий `box-sizing: border-box`** задан в `web/src/routes/+layout.svelte`
  (`:global(*)`), а не в `ui.css`. Стенд меток без этого сброса показывает
  48 px снаружи и фото 44 px; в приложении — 44 / 40. Для кадров «как в
  приложении» снимать настоящий экран, а не только метку.
- **Настоящий экран карты на стенде:** `cd web && npm run build` → вшить
  `web/dist` в бинарник (`go build ./cmd/wynd`) → запустить с
  `WYND_DATA_DIR=<копия dev/data>`, `WYND_LISTEN`, `WYND_PUBLIC_URL`; код входа
  сервер печатает в stdout, `POST /api/v1/auth/code` + `/auth/verify` дают
  токен; в Edge положить сессию в IndexedDB `wynd`/`sessions` (`origin: ''`) и
  открыть `/circles/<id>/map`. Все точки круга «Наш дом» в скоплениях —
  одиночные метки появляются после нажатия на скопление (спайдерфай). Плитки
  ждать отдельно (`.leaflet-tile-loaded`), иначе кадр без карты.
- **Галерея показа** — `dev/map-pin-check/serve.mjs`, слушает
  `127.0.0.1:8902` (в этой сессии оставлена запущенной для владельца). Каталог
  `dev/` в `.gitignore`; кадры для репозитория скопированы в
  `docs/testing/map-pin-shape-2026-11-28/`.
