Сессия: по слову владельца «По вшиванию интерфейса делаем по той же схеме, как

## Сделано

### 1. Вшитый интерфейс Android — подготовка по схеме Настольного (`b15e18cd`)

- `web/dist` собирается в `assets/www` только под `-PwyndEmbeddedUi=true`
  (`BuildConfig.EMBEDDED_UI`); по умолчанию интерфейс с сервера, обычные APK
  не растут. `scripts/build-android.ps1 -EmbeddedUi`; CI-сторож
  `assembleStandardDebug -PwyndEmbeddedUi=true`.
- `EmbeddedAssets` отдаёт страницы и статику выбранного origin из APK с
  SPA-фолбэком; `/api/`, `/health`, `/ready`, SSE, медиа и докачка — сетью.
  Origin не меняется, данные IndexedDB остаются.
- Грабли: aapt выкидывает каталоги с `_` — `_app` в APK лежит как `app/`,
  `storagePath` возвращает URL; старый Service Worker и CacheStorage
  снимаются один раз при смене сборки APK, IndexedDB не трогается.
- Живой OPPO: интерфейс из APK, список кругов, офлайн-запуск с сохранёнными
  кругами; APK без флага — серверный. [Протокол](../testing/android-embedded-ui-2026-11-24.md).

### 2. Нативная очередь 5.1 — записи без вложений (`da4abd32`)

- `NativeQueue` (private `native-queue.json`, AtomicFile), мост `__wyndQueue`
  (enqueue/cancel/status/clear), `NativeQueueWorker` на WorkManager,
  `NativeQueueSender` (POST записи/комментария, PUT/DELETE реакции).
- Страница: `native_id` в `QueueRecord`, `handOffToNative` для записей без
  файлов, `reconcileNativeQueue`, отмена при правке/удалении/повторе и выходе
  (`nativeClear`). Токен и тело — только в private-файле и в памяти native.
- Ворота: Go `go build ./...` и `go test ./internal/api`; Android-тесты
  (ArchiveStore 1, NativeQueue 10, NativeQueueSender 6), lint, сборка; web
  135 файлов / 652 теста, svelte-check 0/0. Полный `npm run lint` красный на
  чужом `src/lib/circles/first-frame.svelte.test.ts` — не трогал.
- Живой OPPO: запись, поставленная при выключенном стенде, ушла после
  сворачивания приложения; запись пережила гибель процесса и ушла после
  открытия. Автоматический перезапуск процесса JobScheduler'ом без открытия
  приложения на OPPO не подтверждён (задание висело `waiting`).
  [Протокол](../testing/android-native-queue-2026-11-24.md).

### 3. Нативная очередь 5.2 — вложения

- Файлы, постеры и обложки передаются в native через `begin → chunk →
  commit`; native грузит порциями по 1 МиБ, считает SHA по ушедшим байтам,
  продолжает по `Upload-Offset` после обрыва, собирает media и удаляет
  каталог после успеха.
- Страница: `native_pending`, фоновая передача после `enqueue`, сверка
  подхватывает native-запись по `client_id`, правка/удаление/повтор снимают
  native-копию; незавершённые каталоги чистятся при следующем запуске.
- Живой OPPO: PNG 68 байт через мост, стенд выключен, приложение свёрнуто,
  стенд поднят — вложение `test.png` 68 байт в ленте, SHA скачанного блоба
  совпал. Видео/постер/обложка и resume большого файла — unit-тесты; UI-путь
  и авто-WorkManager после гибели процесса остаются телефонными проверками.
  [Протокол](../testing/android-native-queue-files-2026-11-24.md).

### 4. Нативная очередь 5.3 — фоновое сжатие видео

- Офлайн-видео в compose больше не ждётся в foreground: страница кладёт
  оригинал в очередь с `media_meta.native_compress`, native сжимает его через
  Media3 Transformer 1.5.1 (H.264/AAC, ограничение высоты) и подменяет файл
  до загрузки; при ошибке уходит оригинал. Фото и звук пока сжимаются
  страницей в foreground.
- Мост отвечает `capabilities {compress:true}`; старый APK получает `false`
  и работает по-старому.
- Живой OPPO: MP4 960×540, 3 766 394 байта → 640×360, 958 664 байта за ~5 с,
  ушёл при невидимой активности; в ленте `video.mp4` 937 КБ, скачанный блоб —
  валидный MP4 640×360, 375 кадров, 25 fps. Битрейт пока не применяется
  (только высота), прогресса/foreground нет, UI-путь — веб-тесты. APK debug
  вырос до ~11 МБ из-за Media3; при необходимости заменить на прямой
  MediaCodec. [Протокол](../testing/android-native-queue-compress-2026-11-24.md).

### 5. Постоянный `.wynd` (`45dd969b`)

- Выбор `.wynd` берёт постоянное право URI; `ArchiveStore` хранит origin, URI,
  имя, размер и токен, мост `__wyndArchive` отдаёт файл через
  `/__wynd_archive/<token>`, `accept` сам открывает его после перезапуска.
  Пароль не сохраняется; «Назад» и успех очищают, отказ оставляет для повтора.
- Живой OPPO: системно выбран `A12.wynd`, после `force-stop` страница снова
  открыла файл без выбора и показала пароль; `forget` очистил prefs.
  [Протокол](../testing/android-native-archive-2026-11-24.md).

### 6. Кадр ролика и снятие C48 (`92857e1e`)

- Ролику без клиентского кадра native снимает первый кадр
  `MediaMetadataRetriever` (JPEG до 1024 px) и грузит его aux-постером;
  клиентский кадр не заменяется. Серверная съёмка удалена: `internal/poster`,
  ffmpeg из Dockerfile, поле `Server.Posters`, исключение в ARCHITECTURE,
  stack и server-reference. **C48 закрыт.**
- Живой OPPO: ролик 960×540 без кадра → native JPEG 960×540 36 789 байт →
  media `video_poster_blob_id`; серверный код кадров в сборке отсутствует.
  [Протокол](../testing/android-native-poster-2026-11-24.md).

## Грабли сессии

- aapt игнорирует `<dir>_*`: `_app` в APK обязателен как `app/`; иначе 404 на
  все модули клиента (было пустым экраном).
- Старый Service Worker от предыдущей сборки отдаёт index и чанки, которых в
  APK уже нет; сброс воркера/кэшей один раз по `lastUpdateTime` APK, IndexedDB
  не трогается.
- `am crash` на OPPO убил и WebView-песочницу, и основной процесс — сбил
  первый прогон нативной очереди; для «гибели процесса» это сработало, но
  WorkManager тогда остался `waiting`. `run-as kill` на OPPO не сработал.
- Для фоновой проверки помогло `am set-standby-bucket mixeme.wynd.debug
  active`; после — вернул `working_set`. Нативная запись ушла при невидимой
  активности, процесс жив.
- Токен, тело записи и `client_id` в отчёты не выводить: в протоколе только
  тела записей и статусы.
