# Передача сессии 28.11. Ядро пульта Wynd Push

После «Дальше» выполнена часть шага 2 плана 76, отвечающая за состояние и
команды отдельного сервиса уведомлений.

## Сделано

- `955924d7` — `ServerPage.push` отдаёт адрес, версию, срок хранения,
  запуск, состояние HTTPS и признаки незавершённой операции. Метод Wails
  `PushControl(id, action, cache)` выполняет `start`, `stop`, `restart`,
  `cache`, `remove` в выбранном профиле. Ручной запуск Wynd и возобновление
  работы на источнике переезда сохраняют остановленный Push.
- У работающего Push изменение срока пересоздаёт только его контейнер и
  проверяет HTTPS. У остановленного записывает файлы для следующего запуска.
  После ошибки можно повторно применить `pending_cache`. При `removing`
  повторяется удаление с сохранённым состоянием Wynd и Caddy.
- При удалении команда Compose адресована сервису `push`. Применение
  конфигурации может кратковременно перезапустить запущенные Wynd и Caddy.
  Остановленные контейнеры остаются остановленными, работавший Wynd
  проходит проверку здоровья. Файлы данных Wynd, сертификаты, другие
  контейнеры и тома сохраняются.
- Прошли `go test ./internal/config ./internal/workshop/...` и
  `go test -tags desktop ./cmd/wynd-workshop`. Подставной SSH проверил
  раздельные команды, срок у запущенного и остановленного Push, повтор
  после ошибки, сохранение остального `.env` и Caddyfile, отказ при
  вручную изменённом блоке. Выпусков, тегов и развёртываний не было.

## Открыто и дальше

1. Подключить утверждённые кадры к операциям из окна. В Go уже есть
   `Wizard.MakePlanWithPush` и Wails `PushControl`. Мост планирования
   установки ещё не принимает Push-домен. В пульте нужны фактические
   данные `push`, ошибка `push_error` и повтор `pending_cache` или
   `removing`. Отдельно остаётся добавление Push к существующей
   установке. [План 76](../plans/76-wynd-push.plan.md#шаг-2-мастерская-установка-и-пульт).
2. Сверить рендеры из рабочей вёрстки на одинаковых размерах и теме.
   Ориентиры — [установка](../visual/reviews/wynd-push-install-2026-11-28/README.md),
   [строка пульта](../visual/reviews/wynd-push-pult-2026-11-28/README.md)
   и [панель настроек из `67a92fcd`](../visual/reviews/wynd-push-cache-2026-11-28/README.md).
   Текущий шаг меняет Go-часть. Новых визуальных кадров здесь нет.
3. Пройти Docker Compose, Caddy, HTTPS, обновление, откат, удаление и
   доставку на отдельном стенде и телефоне. В этой Windows-сессии Docker
   и дистрибутив WSL недоступны. [Реестр живых проверок](../testing/pending-device-checks.md#32-wynd-push-в-мастерской-план-76).

## Решения

- Владелец принял компактное поле хранения, ручные команды над ним и
  удаление справа внизу с подтверждением. Вариант с меню на всю ширину
  отклонён. [Протокол кадра](../visual/reviews/wynd-push-cache-2026-11-28/README.md).
- Для удаления выбран адресный `compose rm --stop --force push`.
  Ранее предложенный `--remove-orphans` мог охватить другие контейнеры
  проекта. В командах Push явно задано `COMPOSE_REMOVE_ORPHANS=false`.
  [Команда удаления Compose](https://docs.docker.com/reference/cli/docker/compose/rm/).

## Грабли

- `ntfy.yml` и Caddyfile примонтированы отдельными файлами. После
  атомарной замены файла управляемый контейнер пересоздаётся, чтобы
  Docker примонтировал новый файл.
- `push.json` удаляется последним. При частичном удалении `.env` и
  Caddyfile могут уже быть очищены. Повтор разрешён только для своей
  установки и её ожидаемых файлов.
