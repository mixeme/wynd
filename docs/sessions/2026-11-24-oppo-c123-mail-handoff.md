## Решения

- Многосерверность — только окно для компьютера и приложение Android; в PWA её
  нет (C69).
- Продуктовое правило: выпускное приложение принимает только https вне
  отладочной петли (`ServerOrigin.parse`), поэтому защита оболочки от чужого
  http не ослабляется. Для локальных http-стендов в отладочном APK было
  временное послабление только для http→http; откачено, чистый debug-APK
  собран и установлен заново.
- На wynd2: `admin_email` возвращён в пусто; SMTP оставлен настроенным
  (API не принимает пустой host, тестовому серверу полезно).
- Сессию Firefox с учёткой владельца на wynd2 не выходили; тестовый аккаунт
  проверялся отдельно.
- Отклонено: считать `http`-стенд доказательством блокировки C123 — на https
  ограничение не срабатывает.

## Грабли

- Старый процесс `wynd.exe --version` держал 7676 и мешал стенду; убивать по
  PID из `netstat`, а не `taskkill /IM`.
- Клиент дополняет голый адрес до `https://`; для http-стенда вводить
  `http://127.0.0.1:7677` явно.
- `shouldInterceptRequest` (MainActivity.java:220-225) режет любой чужой http;
  для отладки петли снимать точечно и не выдавать за продуктовую правку.
- Приватная вкладка Firefox = `FLAG_SECURE`: `screencap` отдаёт 0 байт, в
  `uiautomator dump` только заголовок и адрес.
- `adb exec-out screencap` изредка отдаёт 0 байт; помогает
  `adb shell screencap -p /sdcard/...` + `adb pull` (device-пути только с
  `MSYS_NO_PATHCONV=1`).
- Python на Windows пишет stdout в cp1251: файлы-доказательства создавать с
  `encoding='utf-8'`, а не перенаправлением print.
- API wynd2 `PUT /admin/smtp` не принимает пустой host — полностью «стереть»
  SMTP через API нельзя.
- Параллельные сессии меняют тот же checkout: план 46 перестроен, C125 занят,
  C119 исправлен, plan 50 обновлён. Стейджить и коммитить только свои пути;
  `git commit -- <paths>`; чужие `cmd/wynd-desktop/*` не трогать.
- `MEMORY.md` перерос лимит (25,5 КБ): индекс надо сокращать, подробности — в
  файлах памяти.
