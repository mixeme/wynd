# Передача сессии 23.11 — «Назад» в окне 0.4.1, подписанные выпуски и неподписанный APK

Владелец 23.11 показал окно «Wynd Настольный [0.4.1]» на экране «Войти»:
«Кнопка Назад теперь есть, но не работает». Затем спросил, почему в
Android-выпуске остаётся неподписанный APK; на предложение оставить его и
добавить в описание выпуска строку-пояснение ответил «Да».

## 1. «Назад»: это расхождение версий, а не дефект кода

- Стрелку на экране входа рисует **веб-клиент с сервера** (0.53.4/0.53.5):
  `web/src/routes/+page.svelte:183-190` показывает `BackBar`, когда есть мост
  или Android-оболочка; нажатие шлёт окну `wynd:return-to-address`
  (`web/src/lib/desktop/servers.ts:41-44`).
- Оболочка понимает этот сигнал только с **Настольного 0.4.2**: обработчик
  добавлен в `b8792abd`, в теге `desktop-v0.4.2` и в main
  (`cmd/wynd-desktop/frontend/src/App.svelte:212`). В теге `desktop-v0.4.1`
  принимается только `wynd:open-interface` — нажатие уходит в пустоту.
- Установленное окно на машине владельца — **0.4.1**, хотя 0.4.2/0.4.3 уже
  опубликованы. Менять код не нужно.
- Самообновление предлагает выпуск не раньше 72 часов после публикации
  (`UpdateDelay`, `internal/desktop/selfupdate.go:35`): полоса «Вышла версия
  0.4.3» появится после **26.11, 13:30 МСК**. До этого — установка вручную из
  выпуска: <https://github.com/mixeme/wynd/releases/tag/desktop-v0.4.3>
  (`wynd-desktop.exe`, окно перед заменой закрыть, «Выход» из значка).
- Класс на будущее: элемент веба, требующий умения оболочки, показывается по
  наличию моста `__wyndDesktop`, а не по версии/возможностям оболочки. Поэтому
  старые оболочки показывают мёртвую стрелку. Заведено кандидатом **C122**
  плана 46; делать не обязательно — лечится обновлением, признак возможностей
  в мосте нужен только по нужде.

## 4. Неподписанный APK: оставляем, выпуск объясняет файлы — коммит `dad043fa`

**Почему остаётся.** CI без ключа собирает unsigned APK, считает SHA-256 и
кладёт в черновик вместе с удостоверением сборки
(`.github/workflows/android.yaml:128-151`). «Подпись» скачивает именно
`wynd-android-unsigned.apk` (`internal/signing/release.go:62,297`), проверяет
сумму, attestation нужного workflow и тега, пакет/версию/debug-флаг и
подписывает локально. Подпись APK **встраивается в файл**, то есть подписанный
APK — уже другой файл; исходный остаётся единственным объектом проверки
происхождения и повторной подписи (`-VerifyOnly` работает и после публикации).
Удалить его — потерять проверку attestation и возможность переподписать.
Установить unsigned APK нельзя (Android требует подпись), а автообновление
берёт строго `wynd-android.apk` (`android/app/src/standard/java/mixeme/wynd/UpdatePolicy.java:12`).

**Что сделано, чтобы не выглядело выбором из двух файлов:**

| Файл | Что изменилось |
| --- | --- |
| `internal/signing/android.go` | `androidAssetNote` + `androidReleaseBody`: к «Что нового» добавляется абзац «Устанавливать нужно **`wynd-android.apk`**. Файл `wynd-android-unsigned.apk` — тот же APK до подписи, для проверки удостоверения сборки; установить его нельзя.» |
| `internal/signing/android_test.go` | `TestAndroidReleaseBodyExplainsAssets` — «Что нового» в начале, оба имени файла и «установить его нельзя», один завершающий перевод строки |
| `scripts/sign-android-release.ps1` | та же строка дописывается в `release-notes.md` перед публикацией |
| `android/README.md`, `docs/DEVELOPMENT.md` | описание правила для следующих выпусков |
| `docs/testing/android-release-0.1.1-2026-11-23.md` | пункт «подписать» отмечен сделанным; раздел «23.11 — пояснение к файлам выпуска» с причиной и решением |

Описание уже опубликованного **0.1.1 исправлено на GitHub тем же днём**
(`gh release edit android-v0.1.1 --notes-file`), ассеты не трогались. Со
следующего выпуска строка пишется автоматически «Подписью»; запасной скрипт —
тоже.

## Проверено

- `gh release list/view`: даты, Latest, ассеты, наличие `.sig` и подписанного
  APK.
- Тег `desktop-v0.4.1` против `desktop-v0.4.2`/main: в 0.4.1 обработчика
  `wynd:return-to-address` нет, в 0.4.2 есть.
- `go vet ./internal/signing/` — чисто; `go test ./internal/signing/` — ok
  (26,35 с, включая новый тест).
- `scripts\build-signer.bat` — собрался; `dist\wynd-signer.exe` 15 211 520
  байт, 23.11 14:51 (версия окна остаётся 0.3.0).
- Тело выпуска 0.1.1 прочитано после правки: «Что нового» и строка про файлы.

**Не проверено:** живая стрелка в установленном 0.4.3 (нужна установка),
полная `gh attestation verify` для Android 0.1.1 — упирается в DNS роутера
(`tmaproduction.blob.core.windows.net`), повторять при живом DNS.

## Осталось

1. **Владелец:** поставить Настольный 0.4.3 вручную (или дождаться полосы
   после 26.11, 13:30 МСК) и проверить стрелку «Назад» — реестр §7, окно
   должно стать «[0.4.3]».
2. **Attestation Android 0.1.1** — повторить `gh attestation verify` при живом
   DNS (C118 не при чём; отмечено в протоколе 0.1.1).
3. **C121** — живая проверка прокрутки «Подписи» на пересобранном exe остаётся
   за владельцем (реестр §7).
4. `main` впереди Gitea на 5 коммитов (включая `f828526c`, `dad043fa`); push —
   по решению владельца, только Gitea.
5. **C122 плана 46** — кандидат: скрывать стрелку у старых оболочек через
   признак возможностей моста; сейчас не делается, лечится обновлением окна.
