## Правило применения

- Единица — зазор между соседними блоками контейнера; `padding` блока и
  высоты строк — не зазор.
- Зазор задаёт нижний отступ верхнего блока, ровно один шаг; верхний отступ
  следующего равен нулю, чтобы шаги не складывались. `auto` у прижатого низа —
  не шаг.
- Роли по порядку: **4** — части одного блока (заголовок→подзаголовок,
  подпись→своё поле); **8** — соседние блоки раздела, действие/пояснение к
  блоку, элементы одного списка; **16** — новая роль, содержимое раздела,
  поля окна.
- Новый размер не вводим: если пара не попадает в роль, пересобираем блок.
- Допустимо: 0 у строк с разделителями, `auto`, оптика ≤ 2 px, нахлёст −1 px.

## Грабли

1. **Проверять CSS парсером после массовых правок.** `postcss.parse` поймал
   осиротевшие строки и потерянные `}`; браузер молча теряет стили. После
   миграции: `node -e "postcss.parse(...)"`.
2. **«До»-кадры — из чистого дерева.** Веб-стенд на 5173/5179 бывает занят
   параллельной сессией и умирает; для «до» создан worktree на HEAD с
   junction на `web/node_modules` и vite 5174. Junction снимать `rmdir` до
   `git worktree remove`.
3. **Служебные классы живут в трёх фронтендах.** После удаления `mt-10` и др.
   из `ui.css` остались их использования в `cmd/wynd-signer`,
   `cmd/wynd-workshop`, `cmd/wynd-desktop` — переведены на `mt-8`/`mb-16`.
   Ищите по всем фронтендам, не только `web/src`.
4. **Утилиты — по значению и роли.** 6–12 → 8, 14 и больше → 16, 3 → 2
   (оптика); `mb-5 → 4`. Классы с именами-px после миграции не оставлять.
5. **Пустые состояния — не ритм.** Крупные 80/48/220/28 и центровка ворот
   оплаты остаются исключениями с комментарием и записью в стороже.
6. **Сторож и утверждённые кадры.** Новый экран с инлайн-отступами не
   добавляйте в `FILES`, пока его кадр не показан и не принят; иначе сторож
   упадёт или заставит менять принятое.
