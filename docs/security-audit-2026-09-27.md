## Что было в порядке

- **Шлюз прав (B1).** `internal/chronicle/gate.go` собрал проверки в одну цепочку: `membership` → `requireReader` (не `gone` и есть `can_read`-отрезок) → `requireWriter` (`CanWrite`: `active` и открытый `can_write`-отрезок, начавшийся не позже `now`) → `requireAuthor` (своя identity и `CanWrite`); `requireSettingsTx` — `active` и (`can_settings` или владелец); `RequireCanInvite` — при `invite_who=owner` только владелец, иначе любой `active`. Каждая эквивалентна тому, что было разбросано по пакету в 0.7.1. Новые методы, читающие хронику (`DayPostsSnapshot`, `ArchiveSnapshot`, `RequireReader` в поиске и `notify_prefs`), идут через `requireReader` и `newReadScope`; тестовые помощники (`ErasePersonalData`, `PostBody`, …) живут в `export_test.go` и в бинарник не попадают. Шлюз оплаты одним запросом (`PaymentRequired`: `instance_settings × accounts`) даёт то же правило `required && trim(requisites) != "" && expired`, что четыре запроса `PayStatus`; безлимит `9999-12-31` разбирается одинаково. `CanAccessBlob` без изменений; `IdentityAvatarBlobIDs` только собирает id для ответа, доступ к блобу по-прежнему решает `CanAccessBlob`. Пробники 2026-09-22 (`TestClearDaySaidRequiresWriteAccess`, `TestClientIDReplayIsScopedToAuthor`, `TestSearchHidesCommentWrittenAfterLeaving`, `TestPaidGateBlocksJournalButNotPayRoutes`) на месте и зелёные.
- **Отдача файлов (B2).** Архив собирается во временный файл `<data>/tmp/archive-*.zip` (`CreateTemp` → 0600 в каталоге 0700), удаляется в `defer`, каталог чистится при старте сервера; отдаёт `http.ServeContent` (Range, `If-Range` по началу цикла). Отсечка (`LockCutoff`) запирается только `GET`-запросом, дошедшим до последнего байта (200 с `written == size` или 206 с `last == size−1`), и только если `archive_cutoff_date` не сдвинули во время сборки; `HEAD`, обрыв и частичный диапазон её не трогают. Одна сборка на учётку (429 + `Retry-After`), после срока — 403, исключённому — 403 (`TestArchiveDownloadForbiddenForExcluded`). Состав — по отрезкам читателя (`newReadScope`), комментарии и реакции до отсечки; названия дней — только у дней с видимой записью, в HTML через `html.EscapeString`; сниппет режется по рунам. Имя файла в `Content-Disposition` — только UUID круга. Письма о purge и напоминания — только `status != 'gone'`. `blobs.go`, `admin_storage.go` — механический перенос на `requireSession`/`bindJSON`.
- **Секреты (B3).** `wynd admin-password` читает пароль первой строкой stdin (README: `read -rs` + труба, `sudo -u wynd`), не логирует его, `LoadExisting` ничего не создаёт при опечатке в `WYND_DATA_DIR`; сброс по токену удалён. Бэкап: цель внутри `blobs/`/`keys/` отклоняется, каталог 0700, `wynd.db` через `VACUUM INTO` → 0600, `keys/*` копируются с сохранением 0600, blobs — 0640 внутри 0700, инкрементальный режим прав не расширяет. В журнале сервера из секретов — только bootstrap-URL с токеном до установки (это и есть канал доставки); ошибки push пишутся с хостом endpoint'а, не с полным адресом; отказ SMTP наружу уходит кодом причины (`dial|tls|starttls_required|auth|protocol`), сырой баннер — только в журнал.
- **Исходящие запросы (B4).** Push: свой `DialContext` (`internal/push/endpoint.go`) проверяет каждый IP при каждом соединении (DNS-rebinding из очереди закрыт), loopback/private/link-local/CGNAT/`0.0.0.0`/multicast отвергаются, редиректы запрещены, таймауты 5/10 с; `SendTestTo` на произвольный endpoint — только `admin` и через `validateEndpoint`. Проверки инстанса (`internal/check`): TLS-проба и HTTP-редирект только на `public_url` админа, общий таймаут 15 с, `InsecureSkipVerify` нигде; DNS — `LookupIPAddr`, NTP — `pool.ntp.org`, «исходящий адрес» — UDP-сокет к `8.8.8.8:80` без отправки. SMTP: `Start`/`Next` AUTH LOGIN отказывает в открытом тексте вне localhost (без изменений), ошибки классифицированы.
- **Публичные маршруты и лимиты (B5).** Публичных маршрутов не прибавилось. `/auth/verify` — лимитер по IP (10 неудач / 15 мин, `TestVerifyAttemptsLimitedPerClientIP`); глобальный ключ `*` у `/admin/login` и `/bootstrap` замедляет на 2 с вместо запрета; `chargeRate` атомарен (`INSERT … SELECT … WHERE COUNT(*) < N` + `RowsAffected`); индекс `(email, requested_at)` (миграция 0015). Открытая регистрация отвечает 200 без письма и заблокированному — иначе endpoint был справочником учёток. Приглашения: `max_uses ≤ 1000`, `ttl ≤ 365 д`, «без ограничений»/«без срока» только из панели админа; peek проверяет `ValidateInvite` (отзыв, срок, остаток); отложенное вступление живёт 24 ч (или срок личного приглашения), связано со ссылкой (миграция 0016) и снимается при отзыве ссылки, исключении, блокировке и удалении пригласившего.
- **Клиент (B7).** Ссылка-приглашение из вставки или QR (`$lib/auth/links.ts`) принимается только со своего origin — чужой сервер называется словами, токен на этот сервер не уходит; путь после разбора — всегда `/invite/…` или `/join/…`. `{@html}` — по-прежнему только SVG QR-кода; `Math.random` — только в задержке повтора sync; `Authorization` — токен того origin, к которому запрос (админский — только к origin админской сессии). Запасные пути без secure context: `sha256Hex` (FIPS-реализация), `uuid` (`getRandomValues`), `copyText`. IndexedDB v3 (`media_meta`, потолок кэша) — локальные данные без новых входов с сервера.
- **Развёртывание.** `compose.own-proxy.yaml` публикует Wynd только на `127.0.0.1:7676`; юнит systemd получил `ProtectProc`, `ProtectKernel*`, `ProtectClock`, `ProtectHostname`, `PrivateDevices`; шаблон Apache снимает клиентский `X-Forwarded-For` до прокси, ставит HSTS и `LimitRequestBody`.

## Очередь 2026-09-22: что стало

Сделано (где): DNS-rebinding push — `dialPublicOnly`; лимит `/auth/verify` по IP — `verifyLimiter`; глобальный `*` — замедление вместо запрета; `chargeRate` — атомарный `INSERT … WHERE COUNT < N`; `pending_circle_joins` — срок 24 ч и `invite_id` (0016); SMTP-проба — код причины; `EstimateArchivePersonal` — один пакет запросов и только в карточке круга, не в списке; архив — временный файл и Range; инвайты заблокированного/удалённого создателя — отзываются вместе с отложенными вступлениями; peek — `ValidateInvite`; `max_uses`/`ttl_sec` — потолки; endpoint push в журнале — только хост; `account_id` участников — только владельцу и `can_settings`; `writeFileConfig` — удалён; отрицательный `edit_window_sec` — 400; число медиа на запись — `MaxPostMedia = 50`; `client_id` ≤ 64.

Открыто (низкое, переносится):

- **Нет `ReadTimeout` на чанк загрузки** — медленный клиент держит соединение сколько угодно; перед сервером стоит прокси с `read_timeout 300 с`, без прокси (loopback/lan) это только локальная сеть. Принято.
- **Упоминание и mute** — `notify_prefs.mentions` всегда `true`, отдельного обхода mute в коде нет; продуктовый вопрос, не безопасность.
- **Строка `blobs.pending` при сбое между `Rename` и коммитом** — по коду не проверялось в этом проходе; остаётся заметкой для плана хранения.

## Не подтвердилось

Ничего: обе серверные гипотезы (карточка круга исключённому, отсутствие предупреждения `lan`) и клиентская (`javascript:` в `href`) подтвердились пробниками.

## Принятые риски

Все из [2026-09-22](security-audit-2026-09-22.md#принятые-риски) остаются в силе (текущее состояние видимых записей, плитки OSM, `http://` для удалённого сервера, CSP без `script-src`, секреты в БД открытым текстом, 404 в режимах invite/closed). Добавлено:

- **`GET …/archive/download` до проверки членства** читает цикл круга: не-участник по UUID круга получает 404 без цикла и 403 после срока — оракул «в круге есть просроченный цикл». UUID v7 не угадывается; принято.
- **`validateEndpoint` при недоступном DNS пропускает подписку** (`LookupIPAddr` с ошибкой → `nil`): доставка всё равно пойдёт через `dialPublicOnly`, который приватный адрес отвергнет. Принято — лишний отказ при мигающем DNS хуже.
- **NAT64 (`64:ff9b::/96`) и IPv4-mapped адреса** в `isPublicIP`: mapped `::ffff:127.0.0.1` ловится `IsLoopback` (Go разворачивает `To4`), NAT64-префикс к приватному IPv4 — нет. На сервере без NAT64 недостижимо; не исправляем.
- **Режим `lan` в доверенной сети** — после предупреждения при старте остаётся на совести запускающего: сосед по сети видит инстанс без TLS, но коды входа ему недоступны (журнал сервера), `X-Forwarded-For` от него не принимается.

## Что стоит помнить при развёртывании

- `wynd admin-password` и `wynd backup` запускать от пользователя службы (`sudo -u wynd`, как в README): от root они создают `wynd.db-wal`/`-shm`, которые служба потом не сможет открыть.
- Каталог `<data>/tmp` — временные архивы; после аварийного останова он чистится при следующем старте, руками трогать не надо.
- Исключённые участники после 0.10.1 получают 403 на `GET /circles/{id}`; старый клиент (до 0.10.1) карточку для `gone` тоже не запрашивал, поведение экрана не меняется.
- В режиме `lan` в журнале появляется `WARNING …trusted LAN only` — это ожидаемо.
