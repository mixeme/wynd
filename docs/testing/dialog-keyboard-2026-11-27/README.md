# Диалог удаления круга под клавиатурой (C156)

27 ноября 2026. Две записи владельца (13:45 и 13:50) с подписью «Опять
мигает»: на телефоне диалог «Удалить «Мигание»?» появляется и исчезает, а
«Отмена»/«Удалить» уходят под клавиатуру. Вёрстка кадра не менялась;
исправлено положение диалога в видимой области.

- Основа: [кадр 6.40 «Удаление круга»](../visual/screens.html#e6-40),
  реализация — `web/src/routes/circles/[id]/settings/+page.svelte`
  (диалог `ConfirmDialog`, `?delete=1`), общий стиль — `body .dlg` в
  `web/src/lib/styles/ui.css`, коммит до правки `07c482e4`.

## Что видно в записях

Разбор кадров (cv2, 43–48 кадров/с): диалог при открытии получает фокус в
поле (модальность, `focusFirst`), клавиатура выезжает через 0,2 с и накрывает
нижнюю часть карточки. По тёмной кнопке: её видимая высота 47 CSS px в покое
и 5 px при клавиатуре — остальное под клавиатурой. Обе кнопки недоступны.

Чтобы убрать клавиатуру, владелец жмёт системную «Назад» (клавиатура уезжает,
фокус в поле остаётся), затем ещё раз — и диалог закрывается (наша «Назад»
закрывает верхний оверлей, C13). Дальше снова нажатие на «Удалить круг и все
записи»: диалог открывается, клавиатура снова накрывает кнопки. За 13 секунд
записи — три таких цикла; со стороны это и есть «мигание».

## Причина

`body .dlg` ставил диалог жёстко: `top: 250px`, без ограничения высоты.
Высоту видимой области знает только `--app-h` из `session/viewport.ts`
(C144: layout viewport под клавиатуру не сжимается). Вписывание в видимую
область было отдельным исключением `dlg-fit-viewport` — его включал только
выбор файлов (`FilePicker`), удаление круга его не включало.

Проверка на записи: страница 360 × 800 CSS (кадр 864 × 1920, масштаб 2,4,
верх страницы на 88 px), верх карточки (688 − 88) / 2,4 = 250 CSS — совпадает
с `top: 250px`; верх клавиатуры (1195 − 88) / 2,4 ≈ 461 CSS. Кнопки диалога
455–505 CSS: при клавиатуре видно только 6 px.

## Правка

`web/src/lib/styles/ui.css`, правило `body .dlg` (было у `dlg-fit-viewport`,
теперь у всех диалогов):

```css
--dialog-top: clamp(12px, calc(var(--app-h, 100dvh) - 400px), 250px);
top: var(--dialog-top);
max-height: calc(var(--app-h, 100dvh) - var(--dialog-top) - 12px);
overflow-y: auto;
```

Флаг `fitViewport` у `ConfirmDialog` и его использование в `FilePicker`
сняты — правило теперь общее. Сторож `web/scripts/dialog-guard.mjs` (в
`npm run check:ui`) не даёт вернуть диалог без `--app-h`; тест
`web/src/test/dialog-guard.test.ts` — 2.

## Рендер

Настоящий рендер клиента: vite dev (`npm run dev -- --port 5183`), headless
Edge через CDP (`dev/screens/cdp.mjs`), viewport 360 × 800, DPR 2,4, светлая
тема. На странице — диалог с разметкой из настроек круга (те же
`ConfirmDialog`, `Hint`, `Label`, `Input`) поверх дымового экрана 6.2
(`/dev/smoke/e6-2`). Клавиатура не эмулируется браузером: выставлено
`document.documentElement.style.setProperty('--app-h', '461px')` — то же
значение, что сообщает телефон в записи; на кадрах с клавиатурой её граница

  клавиатурой вместе с кнопками; в Firefox и APK — то же.

  поэтому обычный вид диалогов не меняется (верх 250 px, пока окно выше
  650 px).
