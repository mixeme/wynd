# Проверки видео и фото на OPPO, 21 ноября 2026

OPPO CPH1931, Android 10 (API 29). Веб и локальный сервер Wynd 0.53.4
собраны из `807ba203` и доступны по USB через `adb reverse`. Для прогонов
созданы отдельные тестовые круги. Снимки сняты с телефона через
`adb exec-out screencap -p` (720 × 1600, портрет, светлая тема).

## C107. Кадры WebM и MP4 в офлайн-очереди

**Пройдено в Firefox 132.0.** В круге «Видео OPPO» добавили WebM (VP8,
8 секунд) через «Фото и видео» → «Файлы» и MP4 (H.264, 15 секунд)
из [альбома Movies в приложении OPPO «Фотоснимки»](fx-gallery-movies.png).
Оба кадра были видны [в редакторе](fx-both-ready.png) до публикации.

| Прогон | Карточка без сети | После возврата сети |
| --- | --- | --- |
| WebM и MP4 | [Кадр WebM, длительность 0:08, два вложения](c107-queued.png) | [Одна запись с обоими роликами](c107-result.json) |
| MP4 отдельной записью | [Кадр MP4, длительность 0:15](c107-mp4-queued.png) | [Одна запись с MP4](c107-mp4-result.json) |

В каждом прогоне выключили Wi-Fi и мобильные данные и перекрыли доступ к API
через USB на время постановки в очередь. Записи с контрольными подписями
отсутствовали на сервере до восстановления сети. После возврата сети
каждая запись опубликовалась автоматически. Журнал локального прокси показал
по одному успешному POST публикации на прогон.

Локальный сервер работал без ffmpeg. В первом прогоне сервер сохранил оба
видеофайла без постеров. После публикации на плитке WebM
[появилась заглушка](c107-published-settled.png). Кадры в редакторе и
офлайн-очереди подтверждены отдельно для обоих форматов.

## C22. Импорт JPEG, дата и координаты

Android WebView 157.0.8103.50, отдельный тестовый APK с тем же исходным кодом.
На Android 10 обе кнопки открывали системные «Файлы». Использован
[контрольный JPEG](Wynd-QA-20261121-C22-GPS.jpg) с EXIF от 17 мая 2024 года,
12:34:56 (UTC+03:00), и GPS 55.75166667, 37.62000000. Значение «Места со снимков»
переключали через API только для круга «Места OPPO».

«Фото и видео» из ленты открыло Android DocumentsUI. Системная кнопка «Назад»
[вернула в пустую ленту](c22-cancelled.png). В повторе выбрали JPEG и
отклонили [запрос Android на доступ к фото](c22-android-permission.png).
Снимок остался [в редакторе](c22-denied-editor.png) с датой из EXIF.

| Вход | «Места со снимков» и доступ Android | Точка записи на карте | GPS в скачанном файле |
| --- | --- | --- | --- |
| «Фото и видео» из ленты | Включены, доступ отклонён | Нет | Нет, WebP |
| «Фото и видео» из редактора | Включены, доступ разрешён | [Совпадает с EXIF](c22-map.png) | Нет, WebP |
| [«Файл» из редактора](c22-file-on-editor.png) | Включены, доступ ранее разрешён | Совпадает с EXIF | Есть, исходный JPEG |
| [«Файл» из редактора](c22-file-off-editor.png) | Выключены, доступ ранее разрешён | Нет | **Есть, исходный JPEG** |
| [«Фото и видео» из редактора](c22-plus-off-editor.png) | Выключены, доступ ранее разрешён | Нет | Нет, WebP |

Во всех пяти прогонах опубликована одна запись с одним фото, дата записи
`2024-05-17`, серверное время съёмки `2024-05-17T09:34:56Z`. При разрешении
Android выдал тестовому APK `READ_EXTERNAL_STORAGE` и `ACCESS_MEDIA_LOCATION`.
[Ответы ленты и карты, EXIF и SHA-256 скачанных файлов](c22-result.json).

**Открыт дефект C22 в пути «Файл».** На OPPO с ранее выданным разрешением
выключили «Места со снимков», выбрали JPEG из DCIM через «Файл» и
опубликовали запись. В её метаданных и на карте координат нет. Скачанный
через API JPEG побайтно совпал с контрольным исходником и содержит его GPS
в EXIF. Для повтора после исправления сверять и карту, и EXIF скачанного JPEG.

Проверка выбора «Галерея», отмены диалога выбора источника в Wynd,
разового и запомненного выбора остаётся для устройства с поддерживаемым
Android Photo Picker.
