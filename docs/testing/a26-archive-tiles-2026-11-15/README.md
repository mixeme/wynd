# A26 — плитки фото записи и путь «лента → запись» в архиве: кадр

**Вёрстка ждёт приёмки владельца.** Решения владельца 2026-11-15 (план 46, A26): путь «лента → запись» нужен в любом случае; спрятанные за «ещё N» фото раскрываются на месте, без перехода. Кадр показывает, как это легло.

Рендер — настоящий HTML генератора (`internal/archive`) в браузере, окно 375 × 812 (снимок удвоен), тема светлая. Архив собран `go run ./dev/archive-frame dev/archive-frame/out dev/screens/dacha.jpg dev/archive-frame/sample.mp4`; в пробных данных есть пост «фото и ролик рядом» (плитка + ролик во всю ширину), пост с двенадцатью фото («ещё 6»), голосовое, звуки, файл и комментарий.

## Что на кадре

- **a26-tiles-top** — пост «фото и ролик рядом»: фото — плиткой 88 × 88 (как `.thumbs` приложения: радиус 8, зазор 8, `object-fit: cover`), ролик остался во всю ширину; сетка двенадцати фото тремя в ряд.
- **a26-tiles-closed** — в ленте видны первые шесть плиток, седьмая позиция — плитка «ещё 6» (тонированный квадрат, размер плитки).
- **a26-tiles-open** — после нажатия «ещё 6» скрытые плитки раскрылись на месте и продолжают сетку прямо за плиткой «ещё N» (проверено на живом рендере: раскрытие — `<details>` без JS, офлайн-читаемость сохраняется).
- **a26-post-page** — страница записи (`posts/<ID>.html`): фото остались столбиком во всю ширину, как принято 13.11; шапка не ссылка.
- Путь «лента → запись»: шапка карточки в единой ленте — ссылка на страницу записи (снимок ссылки не показывает; разметка проверена тестом `TestFeedTilesAndPostLink`).

Ролик в плитку не превращается — остаётся плеером во всю ширину. Клик по плитке открывает сам файл: просмотрщика в статичном архиве нет.
