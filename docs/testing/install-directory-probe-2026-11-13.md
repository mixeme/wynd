## Найденные и исправленные дефекты

Первый прогон по пути `/srv/Мой wynd` упал на шаге «Настройка»: пути подставлялись в команды без экранирования (`mkdir -p`, `sha256sum`, `grep`, `cat >`, `cp -p`, `rm -rf`, `test -f`, `sed` по `compose.yaml`, отзыв сертификата). Половина мест жила на `/opt/wynd`, где экранирование не нужно, и потому не проявлялась. Исправлено в тот же день: общий `ShellPath` (`internal/installer/layout.go`) и его использование в записи файлов, шаге настройки, обновлении, откате и отзыве сертификата. После правок путь с пробелом и нелатинскими буквами прошёл установку и удаление целиком.

Чужой `compose.yaml` в целевом каталоге сначала считался «своим»: проверка смотрела только на наличие файла. Исправлено тем же днём: установка узнаётся по подписи «установщик Wynd» в `compose.yaml`, папка с чужим файлом получает отказ, и та же проверка повторяется перед удалением с данными.

Отдельно: имя проекта Docker Compose выводится из имени каталога. `/srv/wynd-probe` дал проект `wynd-probe`, `«/srv/Мой wynd»` и `/opt/wynd` — проект `wynd`. Значит две установки Wynd на одной машине могут стоять только в папках с разными именами; одну машину с каталогами `…/wynd` в разных местах Compose не различит. Это ограничение пробы, а не дефект кода; в плане отмечено.

## Что не проверено

- занятый том и смена точки монтирования между осмотром и записью;
- переезд на назначение с другим каталогом (оба сервера переезда считаются с одним каталогом);
- окно Мастерской на живом сервере (поле уже принято по кадру, живой проход — отдельно).
