# Wynd Push. Локальная проверка ntfy 2.38.3

28 ноября 2026. Проверен Windows-бинарник официального выпуска ntfy 2.38.3. SHA-256 ZIP сверен с `checksums.txt` из того же [выпуска](https://github.com/binwiederhier/ntfy/releases/tag/v2.38.3).

Бинарник запущен на `127.0.0.1:18873` с шаблоном из коммита `b7dc61ce`. Для локального запуска адрес и прослушиваемый порт заменены на loopback, SQLite авторизации размещена во временном каталоге, срок хранения 12 ч. Отправитель и подписчик представлены разными тестовыми адресами в `X-Forwarded-For`. Сообщение синтетическое, с тем же заголовком `Content-Encoding: aes128gcm`, который выставляет Wynd.

| Проверка | Результат |
| --- | --- |
| `GET /v1/health` | 200, `healthy: true` |
| `GET /` | 404 |
| Анонимная публикация и чтение обычной темы | 403 |
| Публикация в новую UP-тему до подписки | 507 |
| Публикация после открытия анонимного JSON-потока той же темы | 200, сообщение получено |
| `GET /_matrix/push/v1/notify` | 200, объявлен встроенный шлюз Matrix |
| `GET` темы с `?up=1` | 404 при `web-root: disable` |

На первом прогоне обычный POST без признака UnifiedPush получил 200 на разрешённой теме. Для проверки лимита доставки нужен параметр UnifiedPush или заголовок `Content-Encoding: aes128gcm`. Регистрация подписчика для этого лимита в v2.38.3 действует для темы из 14 символов, включая префикс `up`. Эти условия сверены с [обработчиком публикации](https://github.com/binwiederhier/ntfy/blob/v2.38.3/server/server.go) и [кодом учёта подписчиков](https://github.com/binwiederhier/ntfy/blob/v2.38.3/server/server_rate_visitor.go). Спецификация обнаружения Matrix использует [отдельный адрес](https://unifiedpush.org/users/gateway/).

Приёмка контейнера остаётся в [шаге 3 плана 76](../plans/76-wynd-push.plan.md#шаг-3-проверка-контейнера-ntfy). На стенде предстоит пройти Docker Compose, проксирование Caddy, TLS, отсутствие тем в журналах, истечение подписки с ответом 410 и реальное зашифрованное сообщение от Wynd на телефон.
