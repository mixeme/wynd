# Android: нативная очередь 5.1 — записи без вложений (24.11.2026)

Этап 5 плана [50](../plans/50-android-wrapper.plan.md): записи и сжатие должны
продолжаться после закрытия окна. Первый шаг — **5.1, без вложений и без
фонового сжатия**: текст записи, комментарии, реакции и снятие реакции;
отправляются уже подготовленные байты. Вложения — 5.2, фоновое сжатие —
5.3 (native-транскодирование оригинала), `.wynd` — 5.4, кадр ролика и C48 —
5.5.

## Что сделано

- **Хранилище.** `NativeQueue` — private-файл `native-queue.json` (AtomicFile):
  записи с типом, origin, кругом, `client_id`, payload, токеном, попытками;
  статусы `sent`/`failed`/`unauthorized` живут 7 дней. Ограничения: 100
  записей, payload 64 КиБ, токен 4 КиБ, файл 8 МиБ. `client_id` — ключ
  идемпотентности; повтор после перезагрузки не создаёт вторую запись.
- **Мост `__wyndQueue`.** Только главный фрейм выбранного origin; операции
  `enqueue`, `cancel`, `status`, `clear`. Токен и тело дальше private-файла
  не уходят, в журнал не пишутся. Страница без моста работает как раньше.
- **Отправка.** `NativeQueueSender` повторяет API очереди страницы: POST
  записи/комментария, PUT/DELETE реакции; `Authorization: Bearer`; 401 —
  `unauthorized`, 507/408/429/5xx и сеть — повтор, остальные 4xx — `failed`.
  `NativeQueueWorker` на WorkManager (сеть, экспоненциальный повтор 30 с);
  без Google Play Services, работает и в редакции fdroid.
- **Страница.** В `QueueRecord` добавлен `native_id`: запись без файлов
  отдаётся native, страница её не сливает и не назначает ей повтор.
  `reconcileNativeQueue()` по событию `wynd:native-queue` и на входе снимает
  отправленное, показывает отказ, возвращает странице потерянную native-запись.
  Правка/удаление/повтор и выход из учётной записи отменяют native-копию
  (`nativeClear` в `dropParticipantSession`).
- **Зависимость.** `androidx.work:work-runtime:2.10.0` в обеих редакциях.

## Живой прогон на OPPO

OPPO CPH1931, Android 10, `mixeme.wynd.debug` 0.1.1-debug из текущего дерева;
стенд 7676 — `dev/native-queue/wynd.exe`, собранный из текущего клиента;
данные `dev/c92/data`. Отладочный APK и стенд соединены `adb reverse`.

1. **Отправка после простоя.** Через `__wyndQueue` (CDP) поставлена запись
   «native queue live…», стенд был остановлен. Попытки дошли до 3, процесс
   приложения погиб (проверка `am crash` затронула и основной процесс).
   Запись осталась в private-файле. После следующего открытия приложения
   WorkManager отправил её; в ленте круга появился текст, файл очереди
   содержит `state: sent`. Это доказывает, что запись переживает гибель
   процесса и уходит при следующем запуске.
2. **Отправка при закрытом окне.** Вторая запись «native queue background…»
   поставлена при остановленном стенде, приложение свёрнуто кнопкой «Домой».
   Стенд поднят снова; через ~20 с запись ушла **при невидимой активности**
   (процесс жив, WorkManager отработал в фоне), в ленте появился второй текст.
   Это ожидаемое поведение этапа: окно закрыто — запись ушла.
3. **Ограничение проверки.** Автоматический перезапуск процесса
   JobScheduler'ом без открытия приложения на OPPO не подтверждён: после
   гибели процесса задание висело `waiting`, принудительный `jobscheduler run
   -f` процесс не поднял; отправка прошла после открытия приложения. Вопрос
   остаётся для отдельного прогона (энергосбережение OPPO / Android 13+).
4. **Граница.** Живой прогон ставил запись прямо в мост; путь «текст из
   интерфейса → enqueue → native» покрыт веб-тестами, но не повторён руками
   в UI. Следующий телефонный повтор — с обычной публикацией текста офлайн.

## Осталось

1. **5.2 — вложения:** передача файлов/постеров/обложек в native, чанковая
   дозагрузка с SHA и возобновлением, сверка; большие ролики.
2. **5.3 — фоновое сжатие:** native получает оригинал (5.2) и транскодирует
   видео/звук/фото после закрытия окна, с прогрессом; видео —
   MediaCodec/MediaMuxer, без ffmpeg. 5.1 этого не делает.
3. **5.4 — `.wynd`** с постоянным правом доступа: после ответа о месте и
   обрыва продолжать без повторного выбора файла.
4. **5.5 — кадр ролика в native** и снятие серверной съёмки кадра (C48).
4. Проверить автоматический WorkManager после гибели процесса, Android 13+,
   энергосбережение производителей.
5. Телефонный повтор публикации текста из UI, а не через мост.

## Повтор

```powershell
# стенд из текущего клиента
cd web; npm run build
cd ..; go build -o dev/native-queue/wynd.exe ./cmd/wynd
$env:WYND_DATA_DIR='dev/c92/data'; $env:WYND_LISTEN='127.0.0.1:7676'
$env:WYND_PUBLIC_URL='http://127.0.0.1:7676'; .\dev\native-queue\wynd.exe

# APK с нативной очередью
.\scripts\build-android.ps1
adb install -r .\android\app\build\outputs\apk\standard\debug\app-standard-debug.apk
adb reverse tcp:7676 tcp:7676
```

Файл очереди на телефоне: `run-as mixeme.wynd.debug cat
files/native-queue.json`. Для CDP — отладочный APK, порт
`webview_devtools_remote_<pid>`; токен и тело в отчёт не выводить.
