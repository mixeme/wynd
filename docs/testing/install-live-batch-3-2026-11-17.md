# Живые проверки установок — батч 3: занятый том, кандидаты, корень/родитель — 17 ноября 2026

Прогоны ядром Мастерской (`dev/probe-dir`, вне git) на wynd2 на фальшивых установках (подпись «установщик Wynd» в `compose.yaml`, файл-жертва); стенд `/opt/wynd` не тронут. Правка из находки — `removeVolumesGuarded` в `internal/workshop/install.go`, тест `TestRollbackReportsBusyVolume`.

## 1. Занятый том при откате «с данными» — найдено и исправлено

Фальшивая установка `/srv/wynd-vol` + том `wynd-vol-caddy-data` с метками проекта, который держит контейнер-пустышка.

**До правки:** откат удалил каталог, `docker volume rm` ответил «volume is in use» посреди журнала, скрипт дошёл до конца — откат считался успешным, причина терялась.

**После правки:** откат останавливается до `rm -rf` шагом **«Том занят»** («Какой-то контейнер держит том этой установки — каталог и тома не тронуты…»).

| Шаг | Результат |
| --- | --- |
| Откат при занятом томе | ✓ шаг «Том занят»; файл-жертва, `compose.yaml`, каталог и том целы, контейнер-держатель работает |
| Контейнер убран, откат повторён | ✓ каталог удалён, том по метке проекта удалён, `/srv` пуст |
| Повтор на установке Б (том держал второй контейнер) | ✓ снова шаг «Том занят», ничего не удалено |
| После освобождения | ✓ полная очистка: каталог, том, метки |

Правка входит в следующий выпуск Мастерской после 0.4.5 (черновик 0.4.5 собран раньше).

Две фальшивые установки A (`/srv/wynd-a`) и Б (`/srv/wynd-b`), у каждой свой том по метке своего проекта; том Б занят контейнером.

| Шаг | Результат |
| --- | --- |
| Откат «с данными» установки A | ✓ каталог A и том A удалены; у Б файл-жертва, том и контейнер-держатель не тронуты — удаление по метке чужой проект не задевает |
| Откат установки Б (том занят) | ✓ шаг «Том занят» (см. 1) |
| Откат Б после освобождения | ✓ всё удалено |
