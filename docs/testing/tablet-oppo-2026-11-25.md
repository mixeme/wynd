# Планшет Android 11 и OPPO: запуск, реакции, PWA (ночь 25–26.11)

Владелец: «Прогони проверки на планшете и oppo, которые нам нужны. Особенно на
планшете будет полезно погонять приложение и pwa тоже.» Проверки шли по
[реестру](pending-device-checks.md); устройства — планшет **Samsung Galaxy Tab
S5e (SM-T725), Android 11 (API 30)** и **OPPO CPH1931, Android 10 (API 29)**.

## Стенд и данные

- Сервер **0.54.1** собран из `main` (`dev/wynd-stand-0541.exe`), данные
  `dev/data`, слушает `127.0.0.1:7676`; на оба устройства проброшен
  `adb reverse tcp:7676`. Приложение — отладочное **0.1.5-debug** (код с
  правкой C133) на планшете и OPPO; на планшете рядом осталась выпускная 0.1.3.
- Вход: `anya@example.com`, коды — из журнала стенда (`code_delivery: log`).
  Второй участник для проверки чужих откликов — `bob@example.com`.
- На OPPO в общем хранилище оболочки была только запись 7677, а каталог
  интерфейса указывал на 7676 со старым кэшем. Запись для 7676 добавлена в
  `secrets.json` токеном, полученным реальным входом на планшете; после
  перезапуска улица обновилась. Это подготовка данных, а не проверка входа.

## Результаты

### C133 — запуск на Android 11

- Выпускная **0.1.3** на планшете: нажатие значка в списке приложений
  возвращает в лаунчер (тихое закрытие); в журнале прежняя причина — NPE
  `SystemBarsFrame` (см. [протокол](android-11-launch-2026-11-25.md)).
- Отладочная **0.1.5**: стартовый экран, ввод адреса, проверка сервера
  («Дом Ани», «Сервер доступен»), вход по коду, улица, круг с записями и
  полосой «Написать в журнал…» — без закрытий и ошибок. Полностью отработал и
  путь интерфейса, и обе ветки `createPage`.
- Подписанный **0.1.5** на планшете ещё не проверялся — черновик ждёт подписи
  владельца (реестр §9).

### C127 — общие входы, OPPO

- «Серверы» в интерфейсе 7676 показывают **обе** записи: «Дом Ани»
  (127.0.0.1:7676, anya, 3 круга) и «Стенд OPPO Б» (127.0.0.1:7677, anya,
  «Сервер не отвечает»); улица показывает круги обоих серверов («Наш дом»,
  «Работа», «Дача», «Семья»).
- Оболочка хранит записи по абсолютному адресу (`secrets.json` →
  `http://127.0.0.1:7676`, `http://127.0.0.1:7677`).
- **Не проверено** (стенд Б не поднят): смена источника туда и обратно, выход
  из Б, находясь в A, перенос входов из IndexedDB после обновления старого APK.
  Проверки C126 (тогл и подписки при смене источника) требуют доставщика и
  двух живых серверов.

APK 0.1.5 проверяется после подписи и установки.

### Найден дефект: ключ реакции в служебной строке (C134)

Улица показывает служебную строку с **сырым ключом**: «Реакция like: Аня»
(планшет, приложение и PWA) и «Боб поставил реакцию party» (PWA до перезагрузки
улицы). Причина — серверный `summaryReactionSet` подставляет ключ как есть;
строка попадает и в новости улицы, и в читаемый архив. Подробности и
предложение правки — C134 в [плане 46](../plans/46-open-questions-and-debt.plan.md).

## Вторая партия (по вопросу владельца «ещё какие-то проверки»)

### fdroid со вшитым клиентом (§3.б) — планшет

Собрано `assembleFdroidDebug -PwyndEmbeddedUi=true` (9 327 966 байт),
установлено поверх отладочного пакета. В журнале `embedded ui: interface from
APK`. Стенд остановлен: интерфейс открылся из APK — улица с кругами, каждая
строка «localhost:7676 не отвечает». Выход из учётки и вход по коду прошли,
круги на месте, полосы обновления нет (редакция fdroid). Затем для остальных
проверок возвращена обычная отладочная сборка (standard).

### 5.1 — очередь из интерфейса и WorkManager без открытия приложения

Стенд остановлен, в круге «Наш дом» из интерфейса набрана и отправлена запись
«Офлайн-проверка очереди 26.11»: в ленте — «в очереди», в
`native-queue.json` — запись с payload и токеном. Приложение убито `am kill`
(процесса нет), стенд поднят — **WorkManager сам поднял процесс** и отправил
запись: `WM-WorkerWrapper: Worker result SUCCESS … NativeQueueWorker`, статус
`sent`, запись `01a2149b-10e0-74f4-b4dc-7768e5181310` на сервере, в ленте
«сегодня, 00:27». Оговорка: `am kill` — гибель процесса системой;
`force-stop` ставит приложение в stopped-состояние, и WorkManager до
следующего запуска не работает (поведение Android, не дефект).

### Архивный HTML (§1.8)

Архив круга «Наш дом» (4 355 453 байта) скачан с токеном участника через
`/api/v1/circles/{id}/archive/download`; в `index.html` чипы реакций —
`👍`, `😢`, `🎉`, `❤️`, ключи `like`/`party`/`heart`/`sad` — ноль вхождений.
Кнопку скачивания на устройстве не нажимали: проверялось содержимое архива.

### Проверить обновления (0.19.4–0.19.5) — OPPO

В приложении 0.1.5-debug (standard) «Настройки → Проверить обновления»:
действие завершилось, строка «Wynd 0.1.4 · это последняя доступная версия»
(0.1.4 опубликован, отладочная сборка новее).

## Границы

- Проверки шли на отладочной сборке 0.1.5 и стенде 0.54.1; выпускной
  подписанный APK и развёрнутый 0.54.x на VPS не проверялись.
- Пуш-проверки (C126, доставка, вход из уведомления) не запускались: нужны
  доставщик, два живых сервера и подписки.
- Нативная очередь проверена текстом; файлы/видео из интерфейса, `.wynd` и
  кадр ролика — не трогались.
