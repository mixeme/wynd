# Android: исходный снимок и место записи — 2026-11-16

Шаг C22 [плана 50](../plans/50-android-wrapper.plan.md). Код реализован, проверен
на OPPO CPH1931 / Android 10 API 29 / WebView 157.0.8103.38. Этап целиком не закрыт:
обязательная проверка на realme 8 отсутствует. Автообновление, публикация APK и
вшивание интерфейса остаются отложенными. Интерфейс загружается с dev-сервера.

## Что изменено

- Существующие кнопки фото в ленте/редакторе и «Файл» в редакторе используют
  необязательный `FilePicker.preservePhotoLocation`. Без нового моста работает
  обычный файловый выбор. Аватар, QR и прочие выборы не запрашивают геоданные.
- Главный документ выбранного origin получает одноразовый маркер протокола 1
  через AndroidX WebMessageListener. Маркер действует 10 секунд и погашается при
  открытии системного выбора; результат доступен один раз. Чужой origin и
  подфрейм не могут активировать режим. Общее `addJavascriptInterface` не добавлено.
- После выбора локального изображения запрашивается ACCESS_MEDIA_LOCATION;
  на Android 10–11 также READ_EXTERNAL_STORAGE. На старте разрешений нет;
  ACCESS_FINE_LOCATION/ACCESS_COARSE_LOCATION не добавлены. Не читается текущее
  положение телефона. Для текста/PDF/видео такой запрос не нужен.
- Только выбранный URI сопоставляется с MediaStore, затем используется
  `setRequireOriginal`. На Android 10–11 MediaDocuments `image:<id>` сопоставляется
  с Images URI. Для ExternalStorage временный persisted read grant нужен
  `getMediaUri` на Android 10: освобождается лишь вновь полученное право.
- Собственный ContentProvider не экспортирован, не выдаёт внешних grants,
  открывает только чтение зарегистрированного источника по случайному UUID.
  Путей `_data`, общей файловой системы, HTTP-прокси и копирования фото нет.
  WebView получает нормальный `File`; `allowFileAccess`/`allowContentAccess=false`
  сохранены. Реестр ограничен и очищается при навигации/уничтожении окна.
- Отказ не отменяет импорт: остаётся файл и дата, `readExif` не читает GPS для
  этого File и не предлагает место. Метка переживает передачу того же File из
  ленты в редактор. Байты EXIF **не переписываются**: обычный SAF на этом OPPO
  отдаёт GPS даже при отказе. Прежняя отправка оригинала сохраняет исходный EXIF.
  Это ограничение отделено от подстановки места записи.
- Если провайдер не поддерживает сопоставление или исходник недоступен,
  возвращается обычный выбранный файл. Потерянный GPS не придумывается.

Решение опирается на официальные контракты
[MediaStore](https://developer.android.com/reference/android/provider/MediaStore),
[доступа к медиа](https://developer.android.com/training/data-storage/shared/media)
и [SAF](https://developer.android.com/training/data-storage/shared/documents-files).
Поведение Android 10 сверено также по исходникам AOSP MediaStore/MediaProvider.

## Настоящий прогон

Отдельный debug-пакет `mixeme.wynd.debug`, сервер `http://127.0.0.1:7696` по USB
reverse. Установка через `adb install -r`, данные не очищались. В учётную запись
не входили, записи не отправляли. Использован только репозиторный образец
`web/src/test/fixtures/exif-gps.jpg` (16×16, 812 байт) с искусственными EXIF:

| Свойство | Проверенное значение |
| --- | --- |
| SHA-256 | `144acdd01b122c1690de594e3c152add162d7c96c39b6618d09031ef0296b5da` |
| DateTimeOriginal | `2026:08:14 09:21:33` |
| captured_at / entry_date | `2026-08-14T06:21:33.000Z` / `2026-08-14` |
| GPS | `59.93866666666666`, `30.309` |

На телефоне образец был в собственной папке
`/sdcard/Download/wynd-android-geo-test/wynd-android-exif-gps-fixture.jpg`.
Диагностика подставляет в настоящую страницу скрытый input и собирает **тот же
репозиторный** TS-код моста/`readExif`; это функциональная проверка, не макет
редактора и не подтверждение публикации записи.

1. Обычный SAF ещё до нового APK уже отдавал полный GPS на OPPO. Поэтому
   исходный дефект realme с вырезанным GPS здесь **не воспроизведён**.
2. Новый путь после системного разрешения вернул исходные 812 байт с тем же
   SHA-256, датой и GPS. Debug-log подтвердил подготовку источника через
   MediaStore/закрытый provider; в log не выводятся URI, имя или GPS.
3. Для проверки отказа в стандартных настройках **своего debug-приложения**
   отозван доступ к памяти (pm revoke запрещён прошивкой OPPO). Проверены
   фактические READ_EXTERNAL_STORAGE=false и ACCESS_MEDIA_LOCATION=false.
   В новом запросе нажато обычное «Отклонить». Импорт вернул дату и файл,
   `geo_lat`/`geo_lng` отсутствуют, SHA оригинала сохранился.
4. Повторный выбор с «Разрешить» восстановил оба права и вернул GPS.
   Повтор того же JPEG в том же input/WebView после сброса также прошёл.
5. Финальный APK проверен отдельно с `accept="*/*"` (кнопка «Файл»): совпали
   SHA, дата и GPS. В этой сборке дополнительно разрешён общий MIME-фильтр;
   запрос всё равно определяется по фактическому типу выбранного изображения.
6. На финальном APK/последнем серверном интерфейсе прошла регрессия: вход
   отрисован, same-origin приглашение/системная «Назад», отмена чужого документа,
   localStorage после полного перезапуска, отсутствие необработанных JS-ошибок.

Системный корень «Изображения» на этом OPPO не предложен даже при image-only
фильтре. Проверен ExternalStorage SAF → MediaStore; отдельная ветка
MediaDocumentsProvider, другие фотопровайдеры, HEIC/PNG и Android 13+ физически
не проверены. Доступ к личным фотографиям и текущему положению не использовался.

После прогона точная SHA-256 образца проверена ещё раз; удалены только этот
JPEG и его пустая тестовая папка. Сканирование подтвердило отсутствие его строки
в MediaStore. Разрешения debug-приложения восстановлены: оба выданы.
