## Настольный: CORS локального порта в настоящем окне

Правка CORS (`cmd/wynd-desktop/main.go`, [аудит](../security-audit-2026-11-17-desktop-shell.md)) до этого дня была подтверждена только модульным тестом. Окно собрано из текущего дерева (`scripts\build-desktop.bat`, `dist\wynd-desktop.exe`, ключ экосистемы вшит), запущено с настоящим профилем владельца (`%APPDATA%\Wynd\desktop`, выбранный сервер `https://wynd.mixfed.ru`).

- Окно открылось на сервере и показало живые данные: баннер «Что нового? Wynd 0.53», группы и круги с событиями — значит, запросы страницы к локальному порту (`apiBase`) проходят сужение CORS. Кадр — снимок сессии (не кадр утверждения; файл убран при чистке dev/).
- Прямые пробы порта окна (`netstat`, PID процесса; локальный адрес `127.0.0.1:51673`):

| Проба | Результат |
| --- | --- |
| `GET` с `Origin: https://evil.example` | `200`, **без** `Access-Control-Allow-Origin` — браузер такой ответ отбрасывает |
| `GET` с `Origin: http://wails.localhost` | `200`, `Access-Control-Allow-Origin: http://wails.localhost` |
| `OPTIONS` с чужим origin | `204`, служебные заголовки без `Access-Control-Allow-Origin` — preflight чужого сайта не проходит |
| `OPTIONS` с origin окна | `204`, полный набор с `Access-Control-Allow-Origin` |

Пункт «живой запуск с выбранным сервером» закрыт; из [реестра, раздел 7](../testing/pending-device-checks.md) и [плана 58, раздел 3а](../plans/58-review-and-tail-checks.plan.md) убран.

Ограничение: правка идёт в следующий выпуск Настольного; у установленного 0.3.0 поведение прежнее (не сломано — сужение только убирает чужие origin'ы).

## «Подпись»: диалоги ключа (C72)

Окно `dist\wynd-signer.exe` (пересобрано из текущего дерева, см. ниже), изолированный профиль: `WYND_SIGNER_SETTINGS` указывает на файл `dev\signer-live\tempB\Wynd\signer.json` с «ключом»-пустышкой; настоящий `signer.json` (путь к ключу владельца) и сам ключ не читаются и не меняются — проверено по содержимому файлов до и после. Инструменты прогона — `dev\signer-live\dialog.ps1` (поиск родного диалога, WM_CLOSE как «Отмена», нажатие кнопки подтверждения) и наблюдение дерева доступности; кадры — `dev\signer-live\shots\` (сессия, не кадры утверждения).

### Диалог нового ключа (12а)

Профиль без настроек — окно открывается на экране «Ключ подписи Wynd» с полем «Где хранить ключ» (путь по умолчанию `…\.wynd\workshop-signing.key`).

| Шаг | Результат |
| --- | --- |
| «Выбрать» → родной диалог «Где хранить ключ» | ✓ открывается, хотя папка по умолчанию (`.wynd`) не существует — тот самый исправленный случай: `keyDialogDirectory` поднимается до существующего родителя |
| «Отмена» (WM_CLOSE, эквивалент отмены) | ✓ диалог закрылся, поле пути не изменилось, настроек в изолированном профиле не появилось |
| «Сохранить» без правки имени | ✓ диалог вернул путь `C:\Users\<user>\workshop-signing.key`, поле «Где хранить ключ» обновилось — путь из диалога доходит до окна |

### Диалог «другой» для существующего ключа (12б)

Профиль с «ключом»-пустышкой — окно открывается списком «Выпуски» со строкой «Ключ — …tempB/dummy.key другой». Заодно видно выравнивание имён в собранном окне: «Wynd Мастерская 0.4.4 …», «Wynd Настольный 0.3.0 …».

| Шаг | Результат |
| --- | --- |
| «другой» → родной диалог «Файл ключа подписи» | ✓ открывается в папке профиля |
| «Отмена» (WM_CLOSE) | ✓ настройки не изменились (`signer.json` байт в байт — `dummy.key`) |
| Выбор конкретного файла из сеанса | не выполнен: ввести путь в родной диалог из сеанса автоматизации не удаётся (клавиатура требует переднего плана, `WM_SETTEXT` в поле имени диалога не проходит) — сам механизм «диалог вернул путь → настройки записаны» покрыт предыдущей строкой 12а и кодом `ChooseKey` (сохраняет только при непустом пути) |

**C72 закрыта**: оба диалога открываются (включая случай несуществующей папки по умолчанию), отмена ничего не меняет, путь из диалога доходит до окна. Ограничение записано здесь, в [плане 46](../plans/46-open-questions-and-debt.plan.md) не остаётся.

Первая проверка «содержит ли exe `WYND_SIGNER_SETTINGS`» дала ложный ноль: `grep` по бинарнику без `-a`.
