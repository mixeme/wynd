# Android · главный документ при холодном запуске без HTTPS

19 ноября 2026. OPPO CPH1931, Android 10, WebView 157.0.8103.50.
Диагностический APK `mixeme.wynd.debug.coldcheck` собран из `4b65fcce`.
SHA-256 APK `ef6a581fcea2d0e1dd335565ca2c2078fbe467eafea5d52e38849cd5b750cd2a`.
В `logcat` записаны события загрузки главного документа и коды ошибок.
Стартовые ресурсы взяты из рабочего APK с ПК3 из `bf248c97`.

Wynd 0.53.0 работал в локальной отдельной базе. Сессия получена через
обычные API входа, затем помещена в IndexedDB нового тестового профиля.
В приложении открыты список кругов и лента тестового круга. Использованы
имеющиеся production-ресурсы с SHA-256 `sw.js`
`2f14aa6121818423ea0a7696978255f34861ab2c1df27c166218e43f7d4ceee0`
и `index.html` `4a7ed22d935e270339ba26572e7f3212c5b109966bc6b295870c5f06fe340db9`.

Для тестового WebView доступен HTTPS через CONNECT-прокси USB и напрямую
через USB. Сертификату стенда доверял только изолированный APK. После
прогрева кэша связи перекрывались, пакет останавливался через
`am force-stop` и запускался заново. У Wynd на прокси-адресе воркер
регистрировался автоматически. На прямой петле `127.0.0.1` тот же `sw.js`
регистрировался вручную, поскольку обычная регистрация для петли отключена.

## Первый прогон через CONNECT

- Чистый профиль при обрыве до ответа прокси увидел штатный ПК3.
- После прогрева в Cache Storage было 372 ресурса, включая `index.html`.
  При обрыве до ответа прокси список кругов дважды открылся из кэша.
  С HTTP 503 список тоже открылся из кэша, этот статус получил только API.
- При закрытии транспорта сразу после ответа `200 Connection Established`
  WebView сообщил `ERR_CONNECTION_CLOSED` для `/` до `onPageCommitVisible`.
  Оболочка открыла ПК3. После возврата связи обнаружены те же 372 ресурса
  и активная регистрация воркера.
- В двух пробах с разрешённым повтором первая загрузка сразу открыла
  круги. Повтор в этих двух пробах не выполнялся.

## Чередование автоматического повтора

На том же адресе после `200 Connection Established` закрывали соединение
до TLS-ответа сервера. Без автоматического повтора три запуска из четырёх
показали ПК3 с `ERR_CONNECTION_CLOSED`. С одним повтором через 250 мс все
четыре запуска открыли круги. В трёх из них журнал подтвердил ошибку
первого запроса и фактический повтор, ни одно соединение до сервера не дошло.

В первом прямом USB-прогоне после ручной установки воркера не было
контроля навигации, и проверка остановилась. В повторном прогоне Cache
Storage сохранил 372 ресурса, но активной регистрации и контроллера при
открытии ленты уже не было. На прямой петле без работающего воркера запуск
с обрывом и запуск с HTTP 503 показали ПК3. Один пробный повтор тоже
привёл к ПК3. Этот контроль показывает обработку ошибки без воркера.

## Исправление в Android

При холодном запуске выбранного HTTPS-источника оболочка даёт первой
навигации GET один повтор через 250 мс при `ERROR_CONNECT`. Повтор идёт в
том же WebView. Страница ошибки Chromium скрыта до начала отрисовки нового
документа. Если повтор тоже завершается ошибкой, открывается ПК3. HTTP 503
главного документа по-прежнему ведёт на ПК3 сразу.

На OPPO чистый профиль после обрыва показал ПК3. В журнале были две ошибки
соединения и один повтор. В контроле с HTTP 503 повтора не было. После
прогрева Cache Storage шесть холодных запусков открыли круги из кэша с
первой попытки. В этой серии повторы с прогретым кэшем не потребовались.

В отдельной диагностической сборке начало первой навигации отложено на
6,5 секунды. Однократный повтор выполнял тот же рабочий код через 250 мс.
OPPO получил `ERR_CONNECTION_CLOSED` для `/`, журнал подтвердил один
повтор. `/sw.js` обслужил новую навигацию, `workerStart > 0`, и реальные
сохранённые круги были видны. Релей за этот запуск отклонил 32 соединения
и не пропустил запросы к серверу. Активная регистрация и 372 записи кэша
сохранились после восстановления связи.

Пиксели ПК3 до и после исправления совпали в области приложения.
Снимки 720 × 1600 сделаны через `adb screencap`, WebView 360 × 728 CSS px
при DPR 2 и светлой теме. Прошли 43 Android-теста.

Трассы и снимки сохранены в
`dev/screens/shots/android-cold-https-diagnosis-2026-11-19/`.
`observed.json` и `repeat-observed.json` относятся к сравнению до правки,
`fixed-observed.json` — к двум контрольным и шести успешным холодным
запускам с правкой, `forced-observed.json` — к успешному повтору с кэшем.
Тестовый пакет и USB-перенаправления удалены. Байты рабочего каталога
источников и путь рабочего APK совпали до и после прогона. Холодный
запуск по прямому HTTPS с активным воркером остаётся отдельной проверкой.
