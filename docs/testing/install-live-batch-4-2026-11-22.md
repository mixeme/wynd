# Живые проверки установок — батч 4: удаление с сохранением данных и повторная установка — 22 ноября 2026

Батч 4 живых проверок ([план 45](../plans/45-workshop.plan.md)) на выделенной машине `wynd2.mixfed.ru` ядром Мастерской (`dev/probe-dir`, вне git), как в [батчах 2–3](install-live-batch-2026-11-16.md). Стенд `/opt/wynd` (0.53.4) не тронут — контейнеры healthy, сайт 200 до и после прогонов; пробный корень `/srv/wynd-keep`, после прогонов убран, диск вернулся к 3,5 ГБ свободно.

Граница прогонов: на wynd2 порты 80/443 держит собственный Caddy стенда, поэтому установка доходит до шага «Запуск» и отказывает с понятным текстом («Порты 80 или 443 на сервере кто-то занял… Освободите их и нажмите „Повторить“») — этого достаточно для файловой части цикла, но шаги «Сертификат» и «Проверка» не исполняются. Сценарии, которым нужны свободные порты или перевод часов, остаются на изолированную машину: отказ сертификата при закрытых портах, исправление несинхронных часов, живой проход nginx с conf.d и чужим certbot ([62], [64], [65] плана).

## Удаление с сохранением данных, повторная установка, откат с данными

Прогон: установка в `/srv/wynd-keep` (образ 0.53.4 из реестра, тестовый сертификат) → контрольный файл `data/keep.txt` → удаление с сохранением данных → осмотр → повторная установка на те же данные → удаление с данными.

| Шаг | Результат |
| --- | --- |
| Установка | ✓ docker/place/image/files — done; **«Запуск» — failed** с текстом про занятые 80/443; каталог, `compose.yaml`, `Caddyfile` и пометка `.wynd-install` (устройство и inode) записаны; контейнер Wynd поднялся и создал базу (`wynd.db` + WAL), Caddy-контейнер остался Created — порт занят |
| Удаление с сохранением данных (`rollback keep`) | ✓ контейнеры и сеть сняты; **данные целы**: `data/` (база, blobs, keys, контрольный файл), `compose.yaml`, `Caddyfile` на месте; томов у установки нет (каталоги-монты) |
| Осмотр после удаления | ✓ штатный блок «На этот сервер Мастерская не поставит Wynd» (чужие порты) и заметка **«Wynd на этом сервере не запущен, его данные на месте»** с планом «поставим снова с ними» — ветка работает и для корня вне `/opt/wynd` |
| Повторная установка на те же данные | ✓ файлы перезаписаны (compose совпал по сумме — без `.bak`), **данные не тронуты**: база с WAL, blobs, keys и контрольный файл на месте; контейнер Wynd поднялся на тех же данных; «Запуск» снова отказал по портам |
| Удаление с данными (`rollback drop`) | ✓ охраняемая очистка: каталог удалён целиком (контрольный файл вместе с ним), контейнеров и томов нет, `/srv` чист |

**Вывод:** ветка «удаление с сохранением данных → осмотр → повторная установка на те же данные» и «удаление с данными» подтверждены живьём для корня вне `/opt/wynd`; данные, помеченные к сохранению, не стираются ни удалением, ни повторной установкой.
