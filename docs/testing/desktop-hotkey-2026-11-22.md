# Настольный: общая горячая клавиша — 22 ноября 2026

Функция 1 плана [66](../plans/66-desktop-functions.plan.md): `Ctrl+Alt+W` показывает и фокусирует окно из любого места Windows.

## Реализация

- `cmd/wynd-desktop/main.go`: `app.GlobalShortcut.Register("Ctrl+Alt+W", …)` до `app.Run()` — Wails v3.1.0 привязывает отложенную регистрацию при старте (`GlobalShortcutManager.flushPending`, Win32 `RegisterHotKey` на скрытом окне main thread). Колбэк — `win.Show()` + `win.Focus()`, как у второго запуска и значка трея. Комбинация занята другой программой → отказ в журнал, окно работает без горячей клавиши.
- Тот же коммит: `ErrorHandler` в `application.Options` — ошибки без экрана (отказ горячей клавиши и внутренние) идут в журнал; до правки молчали.

## Ворота

`scripts\test-desktop.bat` — зелёный целиком (`[desktop] OK`, svelte-check 0/0, тесты трёх окон и internal/desktop); exe пересобран `scripts\build-desktop.bat`.

## Живая проверка (пробники `dev/hotkey-check.ps1`, `hotkey-check2.ps1` — в git не входят)

1. **Старт и регистрация без ошибок.** `dist\wynd-desktop.exe` запущен с перехватом stderr: только строка `[WebView2] Environment created`; ни наш `global shortcut:`, ни `wails: failed to register global shortcut` — регистрация прошла (`flushPending` отказывает только через `handleError`).
2. **Диспетчеризация → показ окна.** Окно спрятано в трей (WM_CLOSE → хук прячет, `IsWindowVisible=false`), затем `PostMessage(WM_HOTKEY, id=0)` в скрытое окно `__wails_hidden_mainthread` — тот путь wndProc, куда ОС кладёт нажатие. Окно стало видимым, снимок — [window-after-dispatch.png](desktop-hotkey-2026-11-22/window-after-dispatch.png): `dispatch` находит колбэк, `Show`+`Focus` работают у спрятанного окна.
3. **Поздняя регистрация (тот же путь после старта).** Пробник `dev/hotkey-probe` (минимальное приложение Wails, в git не входит): `Register("Ctrl+Alt+X")` из goroutine через 2 с после `Run()` вернул nil — отказ в этом пути возможен только ошибкой `InvokeSyncWithError`, значит `RegisterHotKey` реально вернул успех.

## Ограничение проверки — физическое нажатие за владельцем

Синтетическая инъекция ввода (`keybd_event`) в этой среде недоказуема: она не дошла даже до хоткея чистого Win32 в пробнике PowerShell (`dev/hotkey-win32-probe.ps1`), а перекрёстные проверки «владения» комбинацией между процессами дали противоречивые результаты (ошибки 183/1400 у самих проб) — методу доверять нельзя. Прямой живой прогон нажатия не заменяется ничем из этого; проверка не выдаётся за выполненную. **Физическое нажатие Ctrl+Alt+W при видимом и при спрятанном в трей окне — ручной пункт реестра §7.**

## Решения

- Комбинация по умолчанию — `Ctrl+Alt+W` (план 66); смена — отдельное решение владельца, экрана настроек нет.
- Регистрация оставлена до `app.Run()` (документированный путь Wails) — «поздняя» регистрация не потребовалась: отказов нет, а более ранние сомнения в `flushPending` объяснились недостоверностью проб владения.
