# Настольный: вшитый интерфейс — подготовка без переключения (23.11.2026)

Функция 9 плана [66](../plans/66-desktop-functions.plan.md): клиент встраивается в exe, источник интерфейса перестаёт зависеть от версии сервера. **Решение владельца 23.11: подготовить полностью, переключение отложить — «нужно ещё получше стабилизировать интерфейс перед вшиванием».** По умолчанию окно, как и раньше, берёт интерфейс с сервера; вшитый включается флагом.

## Что сделано

- **Вшивание.** `web/embed.go` (`web.Build`, `//go:embed all:dist`) уже существовал для шрифтов архива; теперь его использует и окно: `cmd/wynd-desktop` собирается с клиентом внутри (exe 17,7 МБ). `scripts\build-desktop.bat` ставит web-зависимости при отсутствии и собирает клиент перед exe; `scripts\test-desktop.bat` собирает web, если dist нет (отдельный прогон ворот без `test.bat`).
- **Режим (`--embedded-ui`)**: `internal/desktop/embedded.go` — отдача файлов клиента с SPA-фолбэком на `index.html` и тем же мостом `window.__wyndDesktop` (настоящий адрес сервера и локальный порт API), что вставляется в HTML сервера. `proxy.go`: во вшитом режиме страницы и статика — из exe, а серверными остаются `/api/`, `/archive/`, `/admin/bootstrap` и `/__srv/…`; оболочка (`/__shell`) и запрос интерфейса сервера (`/?wynd=server` для iframe) не меняются.
- **Данные не переносятся.** Origin окна не меняется (страница отдаётся с того же origin, что и iframe раньше), поэтому сессии, снимки и очередь в IndexedDB остаются на месте — «перенос данных при смене origin» этой подготовкой не нужен. Отдельное дисковое хранилище кругов (бывшая функция 6) остаётся резервом: понадобится, только если у профиля WebView2 появится новая жизнь.
