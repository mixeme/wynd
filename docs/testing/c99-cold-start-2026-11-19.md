# Холодный запуск без ожидания сети — замер C99 (2026-11-19)

Задача C99 [плана 46](../plans/46-open-questions-and-debt.plan.md): холодный запуск
не должен ждать проверки входов. Владелец 19.11: «Делай замер». Ниже — метод,
числа «до/после» и ограничения.

## Метод

- Стенд: сервер `wynd.exe` из сборки на 127.0.0.1:7676 (данные — отдельный каталог стенда).
  Клиент — dev-сборка vite: **5174** — «после» (`main`, `f2c78442`),
  **5175** — «до» (worktree на `18fe8d4a`, C97 без C99).
- Браузер: Edge 157, выделенный профиль, CDP 9223, окно 412×915 DPR 2,
  `Emulation.setCPUThrottlingRate` ×6 и эмуляция фокуса (окно в фоне тормозит
  загрузку модулей).
- Сеть: эмуляция **только API** — `Fetch.enable` на `*://*/api/*`, каждый запрос
  продолжается через 150 мс (кроме `/api/v1/blobs/`); оболочка и модули грузятся
  локально. Это модель установленного PWA: клиент берётся из кэша воркера,
  данным нужен интернет. Полное `Network.emulateNetworkConditions`
  (150 мс / 1,5 Мбит) для запуска не годится: dev-клиент не собран в бандл,
  загрузка сотен модулей по сети даёт 5–18 с и шум в секунды — сравнивать
  нечего.
- Сценарий: в IndexedDB подкладывается сессия стенда (anya@example.com), затем
  `Page.navigate` на `/` (start_url манифеста) и на `/circles` (прямой вход,
  как в замере C95 S4). Метки ставятся `Page.addScriptToEvaluateOnNewDocument`:
  `pathAt` — смена пути на `/circles`, `rowsAt` — первая строка улочки
  (`button.r`), `loadAt` — событие `load`. Время — `performance.now()` от начала
  навигации.
- 7 зачётных прогонов на путь; прогон 1 — холодный (снимка улочки ещё нет),
  в медиану не входит. Выбросы стенда (зависание вкладки/перезагрузка vite,
  >10 с) отброшены и повторены — по одному на версию.
- Инструмент: `dev/stand-transition/launch.mjs <порт CDP> api150 <base>`
  (сессию и чистый IndexedDB готовит сам; `RUNS`, `CPU`, `API_DELAY` — из env).

## Числа

Медиана прогонов 2–7, миллисекунды от начала навигации; в скобках — разброс.

| Сценарий | до C99 | после C99 | разница |
| --- | --- | --- | --- |
| `/` → строки улочки | **1825** (1602–2746) | **1306** (1240–1415) | **−519 (−28%)** |
| `/` → смена маршрута на `/circles` | 1565 (1296–2513) | 1054 (969–1126) | −511 |
| `/`: маршрут → строки | ~289 | ~266 | в пределах шума |
| `/circles` → строки улочки | **1249** (1176–1622) | **1097** (1030–1391) | **−152 (−12%)** |
| первый прогон `/` (снимка нет) | 3569 | 2803 | — |

## Что из этого следует

- Чистый эффект C99 — один сетевой круг на сохранённый вход: на прямом
  `/circles` разница 152 мс ровно при задержке API 150 мс (в «до» `initSession`
  ждал `reconcileStoredSessions` — `GET /circles`; в «после» он идёт фоном).
- На пути `/` разница больше (~0,5 с): там к ожиданию добавлен второй вызов
  `initSession` (корневой макет и страница) — в «до» он не делился промисом и
  мог уходить в проверку повторно; в «после» оба вызова ждут одну локальную
  готовность, а проверка идёт одной фоновой сверкой.
- После смены маршрута до строк — те же ~0,2–0,3 с в обеих версиях: C99 убирает
  ожидание **до** улицы, а не саму отрисовку (её ускорил C97).
- При N сохранённых серверах сверка в «до» была последовательной (N × RTT), в
  «после» в критический путь не входит вовсе.

## Ограничения

- Dev-клиент, не бандл, SW нет: абсолютные значения — для сравнения версий, не
  для телефона. На реальном PWA оболочка уже в кэше воркера, база меньше, те же
  RTT дают бо́льшую относительную экономию.
- Пустые кадры здесь не считались — это C97 (`dev/stand-transition/probe.mjs`).
  Замер C99 отвечает только на вопрос «через сколько появились строки».
- Одно сохранённое подключение; поведение с несколькими серверами следует из
  кода (последовательный цикл убран из критического пути), отдельно не мерилось.
- Телефонная проверка — пункт C99 в [реестре](pending-device-checks.md).
