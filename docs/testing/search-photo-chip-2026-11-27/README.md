# Чип «С фото» и возврат в поиск — кадры проверки (27.11.2026)

Замечание владельца: «Выбрал чип с фото. Все результаты без фото. Возврат в поиск дал другую страницу, где нет результатов.» (телефон, 11:31, клиент 0.57.0).

## Причины

- **Строки под новым фильтром.** Общий поиск рисует ответы серверов по мере прихода (C95): `searchAllOrigins` зовёт обработчик только для серверов **с попаданиями**. Прогон без единого попадания не заменял `groups`, и на экране оставались строки прошлого запроса — под уже выбранным «С фото» висели записи без фото. Возврат на экран с чистым состоянием запускал поиск заново и показывал правильное «Ничего не найдено» — «другая страница».
- **Возврат без запроса.** `replaceSearchUrl` менял адрес записи через `history.replaceState`, но не обновлял `sveltekit:pageurl` в её состоянии. На шаге назад SvelteKit берёт адрес именно из состояния (`event.state[PAGE_URL_KEY] ?? location.href`), поэтому возврат открывал `/search` без запроса и фильтров.

## Изменение

- `SearchPane`: если поиск по всем серверам не дал попаданий, прежние строки и миниатюры убираются — экран показывает «Ничего не найдено» сразу под выбранным фильтром.
- `replaceSearchUrl`: состояние записи обновляется вместе с адресом (`sveltekit:pageurl`), остальные ключи состояния сохраняются. «Назад» из находки возвращает поиск с тем же запросом и фильтрами (C87).

## Рендер

- Стенд: `dev/wynd-stand-search.exe` — `go build ./cmd/wynd` из текущего `main` с клиентом `web/dist` после `npm run build`; `127.0.0.1:7685`, данные `dev/frame76-data`, вход `anya@example.com`, светлая тема.
- Браузер: headless Edge, CDP, `Emulation.setDeviceMetricsOverride` 400 × 900 CSS px, DPR 1, масштаб 100 %. Скрипт — `dev/probe-search-photo.mjs` (gitignored): запрос «семейный» (единственная запись без фото), чип «С фото»; затем «собрали», открыть найденное, «Назад» стрелкой шапки.

## Осмотр

- **Пусто под фильтром.** После чипа запрос ушёл с `has_photo=1`, строк не осталось, подсказка «Ничего не найдено»; прежняя строка «Собрали семейный альбом…» не висит.
- **Возврат.** После «Назад» адрес `/search?q=собрали&photo=1`, поле и чип на месте, в выдаче одна запись с фото и днём «23 ноября». Состояние истории: `sveltekit:pageurl` совпадает с адресом поиска.
- **Запросы в пробнике.** До чипа `/api/v1/search?q=семейный`, после — `…&has_photo=1`; на возврате поиск не перезапускается с пустым запросом.

## Автоматические проверки и границы

- `web/src/lib/journal/search.test.ts`: `replaceSearchUrl` обновляет `sveltekit:pageurl` и сохраняет `sveltekit:history`/`sveltekit:navigation` — 15 тестов файла зелёные.
- `npm run check` — 0/0; `npm run lint`, `npm run check:ui` — чисто; `npm run build` — собрался; `npm test` — полный прогон ниже.
- Границы: кадры сняты на стенде с демо-данными, не на телефоне владельца; телефонный повтор — после выпуска (реестр §23). Чип «С местом» и период используют тот же путь очистки, отдельно не снимались.
