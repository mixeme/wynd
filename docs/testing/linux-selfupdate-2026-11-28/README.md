# Самообновление Linux: живой цикл AppImage (2026-11-28)

Проверка на MX Linux 23.6 «Libretto» (база Debian 12), X11 `:1`, экран
1280 × 800, окно 1060 × 780. Проверялся AppImage-путь механизма
самообновления Linux (план 69, этап 5). Сборка — CI-артефакт
`wynd-linux-packages` прогона `46066569928` (коммит `2aec9655`): в бинарник
вшит открытый ключ из `signing-key.pub`, версия 0.5.7.

## Что именно запускалось

Чтобы окно увидело обновление, из CI-AppImage сделана **тестовая** сборка
0.5.6: AppImage распакован (`--appimage-extract`), в
`squashfs-root/usr/bin/wynd-desktop` все строки `0.5.7` заменены на `0.5.6`
(3 вхождения), AppDir собран обратно `appimagetool` 1.9.1. Размер тестовой
сборки — 7 043 576 байт. Это не выпуск и не подпись: проверялся только
механизм; скачивался и проверялся настоящий опубликованный выпуск 0.5.7.

Каталог запуска важен: первый прогон из `/tmp/wynd-live` (каталог принадлежал
другому пользователю) дал в полосе `open …AppImage.new: permission denied` —
это ошибка стенда, не дефект; она подтвердила, что текст отказа установки
виден в полосе (`update-error.png`). Успешный прогон — из
`/home/mx/wynd-live`, каталога пользователя.

## Шаги и результат

1. Запуск тестовой 0.5.6 как `mx` с сеансовой шиной и `DISPLAY=:1`:
   ```sh
   sudo -u mx env DISPLAY=:1 XAUTHORITY=/home/mx/.Xauthority HOME=/home/mx \
     DBUS_SESSION_BUS_ADDRESS="$BUS" \
     /home/mx/wynd-live/Wynd-0.5.6-test-x86_64.AppImage
   ```
2. Через ~10 с полоса обновления: «Вышла версия 0.5.7», «Обновить и
   перезапустить», «Позже», «Что нового»; заголовок окна — `[0.5.6]`.
   [Кадр](update-bar.png).
3. Нажатие «Обновить и перезапустить» (`xdotool mousemove 747 98 click 1`,
   координаты экрана 1280 × 800).
4. Окно скачало опубликованный AppImage 0.5.7 (7 035 384 байта), проверило
   `.sig` общим ключом и подменило файл: размер цели стал 7 035 384, прежний
   тестовый файл остался рядом `.old` (7 043 576).
5. Старый процесс закрылся, новый открыл окно с заголовком `[0.5.7]`; полосы
   обновления нет. [Кадр](updated-0.5.7.png). `pgrep` показал новый
   смонтированный процесс (`/tmp/.mount_Wynd-0jneGNH/…` вместо прежнего
   `/tmp/.mount_Wynd-0PBdOeN/…`).

## Что подтверждено

- Вид обновления определяется по `APPIMAGE`; подменяется сам файл AppImage, а
  не временный бинарник внутри образа.
- Подпись проверяется до установки: без совпадения `.sig` файл не был бы
  записан и запущен.
- Перезапуск переживает замок одного экземпляра Wails: новый процесс дождался
  выхода прежнего и открыл окно.
- Ошибка установки показывается в полосе тем же текстом, что и на Windows.

## Что осталось и границы

- **`.deb` через pkexec живьём не проверялся:** нужен интерактивный пароль
  PolicyKit. Юнит-тесты `installDeb` (подставной установщик) и
  `debInstallCommand` (`pkexec <dpkg> -i <файл>`) пройдены; живой прогон — на
  машине с агентом PolicyKit после следующего выпуска.
- **Опубликованные 0.5.7 собраны без ключа** и этот механизм на себя не
  получат: после обновления на них остался `.old`, потому что `CleanOldSelf` в
  0.5.7 ещё старый (смотрит на путь внутри образа). В следующем выпуске, где
  есть `SelfPath`, прежний файл убирается при старте.
- **Схема `wynd:` у AppImage.** CI-сборка (с правкой `SelfPath`) записала
  `Exec="/tmp/wynd-0.5.7-ci.AppImage" %u` — путь самого AppImage, а не
  `/tmp/.mount_…/usr/bin/wynd-desktop`. Официальная 0.5.7 при перезапуске
  перезаписала файл старым поведением — это и есть исправленный дефект.
- **Кнопка «Открыть в приложении» в Linux-браузере** проверена юнит-тестами
  `canOpenInApp` (Windows/Linux — да, Android/iOS/macOS/ChromeOS — нет). Живой
  браузер — после серверного выпуска с этой правкой.
- После прогона процессы, смонтированные образы, тестовые файлы и запись схемы
  в профиле `mx` убраны.
