# Certbot Stale: предупреждение и состояние «не продлевается» — 22 ноября 2026

Вариант «Б» (владелец: «Б. Используй wynd3 смело»): предупреждение в окне удаления **плюс** состояние «сертификат не продлевается» в осмотре сервера. Механика: при установке за nginx/Apache Мастерская ставит certbot и получает сертификат через webroot — папку на сайте Wynd; **откат (даже с сохранением данных) убирает сайт из веб-сервера** (`rollbackProxy` удаляет файл с меткой «установщик Wynd» и перечитывает nginx), а при сохранении данных сертификат с конфигом продления остаётся — продление начинает падать, и через ~60 дней сайт перестанет открываться.

## Что сделано

- **Осмотр** ([`internal/workshop/inspect.go`](../../internal/workshop/inspect.go)): секция `certrenew` читает `/etc/letsencrypt/renewal/*.conf` (домен, webroot, срок через `openssl x509 -enddate`) и находит сломанные продления: наш сертификат (каталог с пометкой установки) без файла сайта в nginx/Apache, или webroot-папка пропала. Находка — **note «Сертификат <домен> не продлевается — поставьте Wynd заново или уберите сертификат»**, полный совет и копируемая команда `certbot delete --cert-name <домен>` — отдельным блоком под списком находок (как блок чужих файлов сайта). Чужие сертификаты без webroot не трогаются.
- **Окно удаления** ([`App.svelte`](../../cmd/wynd-workshop/frontend/src/App.svelte)): в подтверждении удаления за nginx/Apache при сохранении данных добавлено: «Но сайт уйдёт из nginx: домен перестанет открываться, а сертификат перестанет продлеваться — примерно через два месяца он истечёт».
- Тест класса дефекта — `TestParseInspectionCertStale` (наш с убранным сайтом и пропавший webroot находятся; чужой без webroot и живой — нет; срок показан). Мастерские тесты 29/29, svelte-check 0/0, `go vet` чист.

## Живой прогон на wynd3 (82.114.228.93)

wynd3 — машина владельца для проверок переезда; на ней рабочий стенд Wynd (переехал 28.10, `wynd-caddy-1` на 80/443) и **чужой сервис selfpost** (порты 25/465 — не тронут). Сценарий окном с остановленным Caddy стенда:

| Установка за nginx (домен wynd3.mixfed.ru, DNS указывает на машину) | ✓ certbot выдал настоящий сертификат, сайт 200; осмотр — находки Stale нет |
| Удаление с сохранением данных | ✓ контейнеры сняты, данные на месте; сайт из nginx убран (nginx перечитался) |

| Доказательство сломанного продления | ✓ `certbot renew --cert-name wynd3.mixfed.ru --dry-run` — **1 renew failure** (папка проверки не обслуживается) |
| Уборка | ✓ удаление с данными отозвало сертификат (`WYND_REVOKED wynd3.mixfed.ru`), nginx удалён, Caddy стенда пересоздан через compose — сайт 200, цепочка сертификата валидна (`openssl s_client` Verify return 0), selfpost healthy |

## Находки прогона

- **certbot-хуки стенда**: на wynd3 лежат `/etc/letsencrypt/renewal-hooks/{pre,post}/stop|start-wynd-caddy.sh` — останавливают и запускают контейнер Caddy стенда на время certbot-операций. В коде репозитория их нет (история машины wynd3 вне репозитория); post-hook сам поднял остановленный мной контейнер во время dry-run. После пересоздания контейнера через compose всё вернулось. Кандидат на уборку при откате — записан здесь, решение владельца.
- **Пустой nginx после удаления сайта**: файл сайта удалён, reload выполнен — nginx остался без server-блоков и не слушает 80/443 вовсе (на чистом сервере это штатно: веб-сервер без сайтов). Если в этот момент рядом стоит наш же Caddy — docker-proxy не сможет перевязать порты и контейнер нужно пересоздавать (`docker compose up -d caddy`), простого restart мало.
- Детекция по файлам честна и для случая «nginx не перечитал настройку»: файл сайта удалён — находка появляется сразу, а после ближайшей перезагрузки/перечитывания продление действительно падает.
