# Certbot Stale: предупреждение и состояние «не продлевается» — 22 ноября 2026

Вариант «Б» (владелец: «Б. Используй wynd3 смело»): предупреждение в окне удаления **плюс** состояние «сертификат не продлевается» в осмотре сервера. Механика: при установке за nginx/Apache Мастерская ставит certbot и получает сертификат через webroot — папку на сайте Wynd; **откат (даже с сохранением данных) убирает сайт из веб-сервера** (`rollbackProxy` удаляет файл с меткой «установщик Wynd» и перечитывает nginx), а при сохранении данных сертификат с конфигом продления остаётся — продление начинает падать, и через ~60 дней сайт перестанет открываться.

## Что сделано

- **Осмотр** ([`internal/workshop/inspect.go`](../../internal/workshop/inspect.go)): секция `certrenew` читает `/etc/letsencrypt/renewal/*.conf` (домен, webroot, срок через `openssl x509 -enddate`) и находит сломанные продления: наш сертификат (каталог с пометкой установки) без файла сайта в nginx/Apache, или webroot-папка пропала. Находка — **note «Сертификат <домен> не продлевается — истечёт 26.01.2027»** (срок прямо в находке), короткий совет — «Поставьте Wynd заново — данные остались на месте, сайт и продление вернутся». Чужие сертификаты без webroot не трогаются.
- **Кнопка вместо консоли** (замечание владельца: команда противоречит замыслу Мастерской): у находки — кнопка **«Убрать сертификат»**, она вызывает `Wizard.DeleteStaleCert` → `CertbotDeleteAt` (`certbot delete --non-interactive --cert-name <домен>` через certbotWait; домен валидируется по символам, shQuote в команде); после успеха осмотр перечитывается — находка исчезает. Кнопка того же вида, что остальные в пульте (svcbar).
- **Окно удаления** ([`App.svelte`](../../cmd/wynd-workshop/frontend/src/App.svelte)): в подтверждении удаления за nginx/Apache при сохранении данных добавлено: «Но сайт уйдёт из nginx: домен перестанет открываться, а сертификат перестанет продлеваться — он истечёт 10.01.2027» — точной датой из осмотра (`Report.Certs`; без прочитанного срока — без даты, по замечанию владельца «примерно через два месяца» убрано).
- Тест класса дефекта — `TestParseInspectionCertStale` (наш с убранным сайтом и пропавший webroot находятся; чужой без webroot и живой — нет; срок показан). Мастерские тесты 29/29, svelte-check 0/0, `go vet` чист.

## Кнопка: живой прогон на wynd3 (23.11)

Второй полный прогон: установка за nginx → удаление с сохранением → осмотр (находка «истечёт 20.02.2027») → **кнопка** (`CertbotDeleteAt`): `certbot delete` стёр сертификат и конфиг продления («Deleted all files relating to certificate wynd3.mixfed.ru»), повторный осмотр — находки нет, чужой selfpost2 не тронут. Попутно найдено и исправлено: признак «своего» каталога в certrenew — compose за nginx имеет другую первую строку метки; теперь ищется инвариантная часть «установщик Wynd».

## Находки прогона

- **certbot-хуки стенда**: на wynd3 лежат `/etc/letsencrypt/renewal-hooks/{pre,post}/stop|start-wynd-caddy.sh` — останавливают и запускают контейнер Caddy стенда на время certbot-операций. В коде репозитория их нет (история машины wynd3 вне репозитория); post-hook сам поднял остановленный мной контейнер во время dry-run. После пересоздания контейнера через compose всё вернулось. Кандидат на уборку при откате — записан здесь, решение владельца.
- **Пустой nginx после удаления сайта**: файл сайта удалён, reload выполнен — nginx остался без server-блоков и не слушает 80/443 вовсе (на чистом сервере это штатно: веб-сервер без сайтов). Если в этот момент рядом стоит наш же Caddy — docker-proxy не сможет перевязать порты и контейнер нужно пересоздавать (`docker compose up -d caddy`), простого restart мало.
- Детекция по файлам честна и для случая «nginx не перечитал настройку»: файл сайта удалён — находка появляется сразу, а после ближайшей перезагрузки/перечитывания продление действительно падает.
