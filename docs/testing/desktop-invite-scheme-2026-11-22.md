# Настольный: приглашения из браузера, схема wynd: — 22 ноября 2026

Функция 4 плана [66](../plans/66-desktop-functions.plan.md), шаг «механизм»: браузер передаёт адрес приглашения окну через `wynd:open?url=<https-адрес приглашения>`.

## Реализация

- **Реестр** (`internal/desktop/scheme_windows.go`): `HKCU\Software\Classes\wynd` (только текущий пользователь, прецедент автозапуска) — `URL Protocol`, имя «URL:Wynd», команда `"<этот exe>" "%1"`; переписывается при каждом запуске, переживает обновления. Обычные кавычки, не `strconv.Quote` — он удваивал обратные слэши в пути (поймано тестом).
- **Разбор** (`inviteurl.go`, тестируется без Windows): регистронезависимые `wynd:`/`open?`, вариант `//open`, не-https и пустые значения отвергаются; лимит формы `wynd:open?url=…` против «прозрачной» части URI — шелл Windows приводит её к нижнему регистру и перекодирует проценты.
- **Доставка** (`main.go`): первый запуск — аргумент ждёт оболочку в `pendingInvite` (событие ушла бы до привязки JS); второй запуск — `SecondInstanceData.Args` → `DeliverInvite`: событие `wynd:invite` оболочке + показ и фокус окна. Оболочка слушает событие и при старте забирает отложенное (`TakePendingInvite`) — оба порядка загрузки покрыты.
- **Открытие** (`App.svelte openInvite`): свой сервер — iframe сразу на путь приглашения; чужой — интерфейс переключается проверкой адреса (тот же `CheckServer`, что при запуске); отказ проверки — утверждённый экран «Добавить сервер интерфейса» с адресом приглашения и словами об отказе — поправить связь или повторить можно там же.

## Ворота и тесты

Ворота desktop-контура зелёные; Go: таблица разбора (включая регистр, кодировки, `//open`, отказы — чужая схема, http, javascript, кривые проценты), регистр-тест переписывания команды, живой roundtrip; exe пересобран.

## Живая проверка (пробники `dev/invite-scheme-live.ps1`, `dev/invite-positive.ps1` — в git не входят)

1. Первый запуск регистрирует схему: команда в `HKCU\...\wynd\shell\open\command` — путь этого exe с `%1`.
2. Запуск через шелл (`start "" "wynd:open?url=…"`): второй процесс передал адрес и вышел, окно первого живо и показано.
3. **Позитивный случай** — приглашение на текущий сервер окна (`wynd.mixfed.ru`, пробный токен): окно открыло настоящий экран приглашения «Приглашение не действует» — адрес дошёл, интерфейс navigировался ([invite-screen.png](desktop-invite-scheme-2026-11-22/invite-screen.png)).
4. **Отказ** — несуществующий сервер: утверждённый экран адреса с подставленным адресом и строкой «Сервер приглашения не отвечает…» ([unreachable-server.png](desktop-invite-scheme-2026-11-22/unreachable-server.png)).

Окно прогона показывало настоящие данные этой машины (профиль общий) — чтение, изменений не было.
