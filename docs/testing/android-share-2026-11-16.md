# Android: «Поделиться» в новую запись — 2026-11-16

Этап 3 [плана 50](../plans/50-android-wrapper.plan.md). Код и протокол приёма
реализованы, проверены на OPPO CPH1931 / Android 10 API 29 / WebView
157.0.8103.38. Этап остаётся открытым до обязательного прогона на realme 8.
Обновления/публикация APK и вшивание интерфейса по-прежнему отложены.

## Сценарий и границы

1. В Android Sharesheet Wynd принимает SEND (text/plain, image/*, video/*) и
   SEND_MULTIPLE (image/*, video/*). Смешанный фото/видео `*/*` сопоставляется
   Android с этими фильтрами; фактический тип каждого URI отдельно проверяется.
2. Из SEND берутся только текст и URI потока/ClipData. URI должен быть content,
   чужого UID/provider и с явным URI read grant. `file:`, удалённые URL как файлы,
   чужой профиль `user@authority` и свои provider не принимаются. Имена очищаются
   и служат только отображению, на диске используются фиксированные номера.
3. Worker копирует источники в private storage буфером 32 KiB. Один набор:
   до 32 файлов, до 512 МиБ суммарно, до 32 КиБ текста UTF-8. Предел проверяется
   по реально прочитанным байтам. При ошибке не выдаётся частичный набор.
   Фиксация JSON после файлов позволяет восстановить готовый набор после
   перезапуска; незаконченный приём очищается. Дополнительных runtime-прав нет.
4. Второй набор не заменяет первый. После входа появляется выбор круга:
   только active, без frozen_at/space_full. Недоступный сервер не теряет набор.
   Новая запись открывается в обычном редакторе Wynd. Открытый редактор при
   новом SEND остаётся на месте, переход ждёт выхода из него.
5. Главный документ выбранного origin читает одноразово подтверждаемый набор
   через отдельный WebMessageListener. Отправитель не задаёт сервер, URL
   навигации или круг. В native URL чтения — UUID набора и номер файла;
   разрешён только GET subresource, без query/fragment. Неверный UUID/путь или
   главный документ получает 404. `no-store`/`nosniff`, без cookies и HTTP-прокси;
   JavaScript получает Blob/File через WebView InputStream, по одному.
6. После чтения всех File и проверки совмещённого текста редактор подтверждает
   приём: native-копии удаляются, параметр incomingShare убирается из URL.
   Текст добавляется к прежнему черновику через пустую строку. HTML/URL остаются
   обычным текстом. Публикация и загрузка требуют штатного действия владельца.
   При системной «Назад» на `/share` выбранного origin native сначала удаляет
   текущий набор, затем делает прежний шаг истории. Это работает и между
   документами, где страница не получает popstate. Повторные нажатия во время
   удаления не делают лишних шагов. Для браузерной истории страница также
   удаляет набор, не отменяя popstate/откат истории (C89); следующий peek ждёт
   удаления. Стрелка/текстовая отмена удаляют набор до перехода.

После передачи в редактор файлы живут по прежним правилам веб-клиента.
Это **не нативная очередь этапа 5**: закрытие/гибель редактора во время подготовки
ещё не обещает сохранения его вложений. Лимиты/сжатие сервера продолжают действовать.
GPS сохраняется в том виде, в котором его передал источник; удалённый отправителем
EXIF не восстанавливается. Постоянные права на исходные внешние URI не удерживаются.

Официальная основа:
[приём данных Android](https://developer.android.com/develop/ui/compose/sharing/receive),
[URI-права](https://developer.android.com/training/secure-file-sharing/share-file),
[границы ContentResolver](https://developer.android.com/privacy-and-security/risks/content-resolver).
Используется Java Activity/WebView, Compose в приложение не добавлен.

## Проверки на телефоне

Только `mixeme.wynd.debug`, USB reverse и собственный loopback 7696. Отдельный
отправитель `mixeme.wynd.sharefixture` имеет закрытый provider с выдачей read
grant и отдаёт лишь два синтетических asset. Он включается отдельным Gradle
флагом, не включён в основной APK/обычный CI, release-варианта нет.

| Образец | Размер и SHA-256 |
| --- | --- |
| Репозиторный JPEG `exif-gps.jpg` | 812; `144acdd01b122c1690de594e3c152add162d7c96c39b6618d09031ef0296b5da` |
| WebM VP8 96×96, цветные прямоугольники | 2463; `b08232dc6086a93406a9e8fca66824188d2324a380b347a9383b34bc4a465443` |

WebM создан canvas.captureStream/MediaRecorder без камеры/микрофона; это тестовое
видео, не изображение-макет интерфейса. Личная галерея и текущая геопозиция не читались.

Проверены обычный текст с URL и буквальными `<b>`, JPEG, смешанный SEND_MULTIPLE
JPEG+WebM и полное совпадение исходных SHA. Готовый JPEG-набор после force-stop
и холодного запуска имел тот же UUID/байты. Следующий текстовый SEND не заменил
этот набор. Отказ без read grant и текст 32770 байт не оставили набора/копий.
Неверная capability возвращала 404. В первой попытке теста file URI Android
остановил отправителя ещё до Wynd (FileUriExposedException); такой сломанный
вариант удалён из повторяемого отправителя. Отказ для file URI отдельно покрыт
нативным policy-тестом, не объявляется физическим прогоном ветки получателя.

`scripts/test-android-share-ui.mjs` проверяет **настоящий собранный Svelte** в
том же WebView. Явно синтетическая сессия допустима только в dev-профиле без
сохранённых входов. API замкнут на ответы fixture; любые записи API запрещены,
исходящие `/uploads`/`posts` дополнительно проверяются. После теста прежние
метаданные IDB/localStorage/sessionStorage восстанавливаются, mock удаляется.
Это не вход в настоящий аккаунт и не проверка публикации на сервере.

Проверены настоящий выбор круга, отсутствие read-only/full кругов, фото/видео
в существующем редакторе, сохранённый текст черновика, отсутствие перехода из
него при новом SEND, добавление plain text и отсутствие самовольной загрузки/
публикации. Сжатие синтетического видео ожидается до готовой плитки. Системная
«Назад» в выборе проверяется отдельно от шапки; отменённый набор не открывается снова.
