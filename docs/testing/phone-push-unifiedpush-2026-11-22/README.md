# UnifiedPush на OPPO — прогон с внешним доставщиком ntfy

22 ноября 2026. OPPO CPH1931, Android 10, отладочный APK `mixeme.wynd.debug`, собранный из HEAD этого дня (этап 4 плана 50 — коннектор `connector:3.3.5`). Два локальных стенда из той же сборки: «Стенд OPPO A» `http://127.0.0.1:7676` («Семья»: Аня-владелец, Боб-участник) и «Стенд OPPO Б» `http://127.0.0.1:7677` («Работа»: Аня-владелец, Вера-участник). Посты триггерили пуши через API. Доставщик — [ntfy 1.25.2](https://f-droid.org/packages/io.heckel.ntfy/) (F-Droid-сборка, versionCode 63, SHA-256 APK `b4baa6f6…819616f2a`), установлен через adb; конечная точка доставки — публичный ntfy.sh. Экран держался будильным фоновым циклом `keyevent 224` раз в 60 с: `settings put`/`appops`/`pm grant`/`svc stayon` на этой прошивке отрезаны (грабли в протоколе 17.11).

## Подготовка

- Установленный на телефоне debug-APK от 20.11 08:12 **не содержал моста пуша**: переключатель «Уведомления на этом телефоне» в «Настройки → Приложение» отсутствовал. Пересобран из HEAD (`scripts/build-android.ps1 -Tasks ':app:assembleDebug'`, 2 м 46 с) и установлен поверх — переключатель появился [под «Сменить сервер интерфейса»](push-switch.png), [включение](push-switch-on.png) прошло без системных диалогов (уведомления на Android 10 включены по умолчанию, доставщик один — выбран сам).
- Адрес локального стенда в обёртке **требует схемы**: `127.0.0.1:7676` давал «Сервер не отвечает», `http://127.0.0.1:7676` — [карточку «Стенд OPPO A · Сервер доступен»](source-address-scheme.png). Без схемы обёртка не спускается до HTTP.
- Первый тогл в 18:44 не дошёл до доставщика: ntfy был погашен `am force-stop` двадцатью минутами раньше, а остановленное приложение broadcast `REGISTER` не принимает. После запуска ntfy повторный тогл создал регистрацию — [тема `uplzP2j6aRABtM` появилась в «Темы подписок»](ntfy-first-topic.png) с подписью «mixeme.wynd.debug (UnifiedPush)».

## Регистрация и доставка (сервер А)

Коннектор нашёл доставщика, создал WebPush-ключи и зарегистрировал тему; веб-клиент передал серверу endpoint и ключи. Боб (API) опубликовал запись в «Семье» — через ntfy.sh пришёл сигнал, нативная служба расшифровала его и показала [уведомление «Семья · Новая запись в круге»](notification-circle-a.png) при свёрнутом приложении. Тап по уведомлению открыл [правильный круг «Семья» с записью Боба](opened-circle-a.png).

## Замена endpoint

Выключение и включение переключателя сняло прежнюю регистрацию и создало новую: [в ntfy осталась одна тема `upoynSiQcNLua7`](ntfy-endpoint-replaced.png) вместо `uplzP2j6aRABtM`. Новый endpoint был опубликован серверу — [уведомление пришло уже по нему](notification-new-endpoint.png).

## Снятие регистрации при выходе

«Серверы → Выйти на этом устройстве» вышло без диалога подтверждения; [список тем ntfy опустел](ntfy-empty-after-logout.png) — регистрация снята на телефоне, серверу отправлено удаление адреса.

Наблюдение: переключатель «Уведомления на этом телефоне» — настройка уровня приложения и **переживает выход**. После повторного входа тем же адресом подписка **не восстановилась сама** (ntfy оставался пустым, переключатель был ещё включён — погашен тапом на [кадре](switch-off-after-reregister.png)); регистрация появилась только после ручного выключить/включить — [новая тема `up8o5N3xhfgX3D`](ntfy-reregistered.png). Кандидат в дефекты или в решение владельца: включённый переключатель при новом входе не подписывает новую сессию.

## Смена источника интерфейса

«Сменить сервер интерфейса» → добавлен `http://127.0.0.1:7677` (проверка адреса показала карточку «Стенд OPPO Б · Сервер доступен») → источник переключён: приложение открыло [первый экран стенда Б](source-switched-to-b.png), прежняя регистрация [снялась — список тем ntfy пуст](ntfy-empty-after-source-switch.png). После входа на Б (anya@example.com, код из журнала) тогл создал [тему `upnMZ004Ls8B2w`](ntfy-topic-b.png). Вера (API) опубликовала запись в «Работе» — [уведомление «Работа · Новая запись в круге»](notification-circle-b.png) пришло от второго сервера с его VAPID-ключами; тап открыл [правильный круг «Работа» с записью Веры](opened-circle-b.png). Риск «одна подписка — один ключ» (бывшая A8) не воспроизвёлся: каждая регистрация получает свою пару ключей, второй сервер доставляет свою учётке.

## Остановленный процесс

При `am force-stop` Wynd пуш от Боба не показался: [в шторке остался только сервис ntfy](stopped-no-notification.png) («Ожидаются входящие уведомления»). Сообщение лежит в теме ntfy, но после запуска приложения **не догоняется** — доставка через broadcast до остановленного получателя не доходит и повторной пересылки нет. Записи при этом не теряются: лента догружает их обычной синхронизацией. Практическое следствие: «уведомление при закрытом приложении» работает, пока жив процесс службы (свёрнутый интерфейс), и не работает при убитом процессе — это свойство UnifiedPush-доставки, а не дефект Wynd.

## Что осталось

- **Две учётные записи на разных серверах одновременно в одном клиенте** — заблокировано C69: «Войти на сервер» на «Серверах» показывается только с настольным мостом, на Android кнопки нет, добавить второй сервер в один профиль нельзя. Проверено последовательной сменой источника вместо параллельных подписок; вернуться к ветке при решении C69.
- Системный показ при Android 13+ (разрешение уведомлений), запасной FCM-путь — отдельные прогоны по плану 50.
- Слежение за нативным API уведомлений Wails — план 66 (Настольный, не телефон).
