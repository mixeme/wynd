## Поведение и хранение

- Вход — существующий блок **Настройки → Приложение → Интерфейс** из
  действующего Настольного (`9225360e`, план 62). Веб-клиент показывает его
  также при наличии Android-моста; разметка, тексты и компоненты прежние.
  В браузере без моста раздел не появляется.
- `/settings/app/interface` использует существующие FormLayout, ServerRow,
  Input, Label, Hint, Button и ConfirmDialog. ServerRow расширен необязательным
  `onremove`: кнопки выбора и удаления соседние, без вложенных кнопок.
  Обычные строки сохранили разметку, что подтверждают прежние слепки.
- Проверка запрашивает только `GET /api/v1/instance`: HTTPS, либо debug
  loopback HTTP; без передачи сессий WebView, redirects и ослабления TLS.
  Проверяются статус, JSON, предел 64 KiB и поля name/version/registration_mode.
  Предпросмотр не пишет список. Добавление повторно проверяет адрес и только
  добавляет/обновляет источник. Вход и переключение не выполняются.
- Список и выбранный origin — private `interface-servers.json`, AtomicFile.
  Начальный debug-адрес используется только при отсутствии файла. Сохранённый
  выбор переживает перезапуск; ошибка записи не меняет состояние в памяти.
  Текущий источник удалить нельзя; неизвестный нельзя выбрать.
- Выбор проверяет доступность известного источника, сохраняет его и
  пересоздаёт Activity/WebView. Старая история другого origin не восстанавливается.
  Все мосты привязываются к новому origin. Cookies, IndexedDB, localStorage,
  очередь и медиа-кэш не очищаются и не копируются на новый адрес.
- `__wyndInterfaces` — отдельный AndroidX WebMessageListener только главного
  фрейма текущего origin. Обновления APK используют прежний независимый порт.
  Уничтоженный мост не пишет поздние результаты; смена блокируется при
  входящем Share, выборе файлов/разрешений и незавершённом экспорте.

## OPPO и завершение прогона

OPPO CPH1931, Android 10; текущий отчёт WebView — Chrome 157.0.8103.50,
viewport 360 × 728, DPR 2. Подтверждены восемь групп проверок:

1. Предпросмотр не добавляет и не выбирает источник.
2. Вложенный фрейм не меняет нативный список.
3. Отклонены чужой cleartext, удаление выбранного и выбор неизвестного.
4. Выбран новый настоящий origin, localStorage прежнего туда не скопирован.
5. Через реальную форму проверен адрес и добавлен источник без переключения.
6. Системная «Назад» закрыла подтверждение без удаления; «Убрать» удалило источник.
7. После полного force-stop выбранный origin и его маркер сохранились.
8. После возврата доступен прежний собственный маркер origin.

Два временных HTTP-источника обслуживали свежую production-сборку клиента,
синтетическую карточку сервера и отказ на прочие API. Учётных записей, писем
и публикаций прогон не создавал. В finally восстановлен исходный источник
`http://127.0.0.1:7696`, удалены только два собственных источника и собственные
маркеры, reverse для 7698/7699 снят. Нативный файл после прогона содержит
исходный источник; профиль телефона и БД не очищались.

На основном origin повторно прошли шесть прежних проверок WebView:
вход, переход внутри origin, системная «Назад», блокировка чужого документа,
localStorage после force-stop и отсутствие необработанных ошибок JS.
Дополнительно открыт раздел через настоящую строку настроек основного сервера.
