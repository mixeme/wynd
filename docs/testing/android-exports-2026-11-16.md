# Android: сохранение и «Открыть в…» — 2026-11-16

Следующий отдельный шаг этапа 1 плана 50 после `cb858912`. Работа над обновлениями
отложена владельцем. Интерфейс продолжает приходить с выбранного сервера.

## Реализация и границы доверия

`FileExports` предоставляет отдельный WebMessageListener `__wyndFiles` только
главному документу выбранного origin. На фоне/без живой Activity начало
сохранения не принимается. Системный ACTION_CREATE_DOCUMENT выбирает конкретный
документ; принимается content URI другого UID/provider. Нативные пути и широкие
разрешения на хранилище не выдаются. Следующее сохранение не присваивает себе
ответ прежнего незавершённого диалога.

Blob сохраняется частями по 32 KiB, с последовательностью, случайным токеном
операции, подтверждением каждой записи и проверкой итогового числа байтов.
`files.ts` читает только очередной slice; весь файл в JS ArrayBuffer не попадает.
Медиа и публичный VAPID-файл используют этот путь, обычный браузер и прежний APK
сохраняют прежний сценарий. Экранов/компонентов Wynd не добавлено.

Ссылка архива передаётся native worker после получения штатным apiJson. Worker
делает один GET только **после** выбора документа, пишет поток буфером 32 KiB,
проверяет статус и Content-Length. Это не повторный GET из DownloadListener:
одноразовая ссылка не тратится предварительно в WebView. Cookies, bearer-токены,
заголовки сессии и ответ архива через JS не копируются. URL — HTTPS либо выбранный
USB HTTP origin в debug; user-info/fragment, file/content URL, другой HTTP origin
отклоняются. До пяти redirect, каждый проверяется, HTTPS→HTTP запрещён.
Ожидание соединения/следующих данных ограничено 30 секундами.

Документ открывается в режиме `wt`, чтобы выбранный существующий файл не сохранил
старый хвост. По окончании flush/close читается настоящее DISPLAY_NAME: DocumentsUI
может дополнить расширение. При отказе/обрыве stream закрывается, но URI **не
удаляется**: provider вправе вернуть существующий документ. Может остаться
неполный файл. При гибели процесса незавершённая операция не восстанавливается.
Это не нативная очередь/докачка этапа 5.

`SavedFiles` публикует тихое уведомление с действием «Открыть в…». На API 33+
POST_NOTIFICATIONS запрашивается после первого сохранения, на старте — нет.
При отказе/выключенном канале остаётся сохранённый файл и сообщение о сохранении.
Read grants последних 16 документов сохраняются по возможности provider;
старые grants и уведомления освобождаются. Подписки на серверные push не добавлены.
`OpenExportActivity` не экспортируется: immutable PendingIntent собственного
уведомления запускает системный ACTION_VIEW chooser с grant только чтения.

Прототип автоматически показывал chooser после записи. На OPPO при одном
обработчике он сразу запускал «МойОфис» для тестового файла; этот вариант снят.
Финальный сценарий открывает обработчик после явного нажатия уведомления.

Источники: [SAF и постоянные grants](https://developer.android.com/training/data-storage/shared/documents-files),
[ACTION_CREATE_DOCUMENT](https://developer.android.com/reference/android/content/Intent#ACTION_CREATE_DOCUMENT),
[WebMessageListener](https://developer.android.com/reference/androidx/webkit/WebViewCompat.WebMessageListener),
[уведомления Android 13+](https://developer.android.com/develop/ui/compose/notifications/notification-permission).

## Повторение

`node scripts/test-android-exports.mjs aa8d50d0 blob`, затем `save` и `result`.
`url` вместо `blob` проверяет публичный manifest своего loopback сервера;
`cancel` и системная «Назад» до Wynd, затем `result` — отмену.
Тест компилирует точный исходник `files.ts` через esbuild и вызывает его через CDP
в незалогиненном Wynd. Диагностический Blob — синтетический, 1 МиБ + 7 байт;
в интерфейс он не вставляется и не публикуется. Выбирается только собственная папка.
Каждый сценарий начинает с force-stop своего debug-пакета и нового WebView,
чтобы CDP не выбрал оставшуюся страницу из прежней Activity.
После проверки SHA-256 тест открывает только своё уведомление, возвращает Wynd
и удаляет только свой файл с точным ожидаемым именем и совпавшей суммой.

- Точный `files.ts` в тесте: SHA-256

- Blob 1 048 583 байта: SHA-256
  `9e037498ddbb955fba0752812031c14ba299a4875cb400e8b8c1d77b3962c90e`,
  совпал на телефоне. Отмена и последующий выбор сработали.
- Native HTTP: публичный manifest своего тестового сервера, 342 байта,
  `c0e852ce0d793a920ce1a86daaf4cfb714727a16f87defbb73ae1c122c28b3fc`, совпал.
- Для обоих финальных сохранений после нажатия собственного уведомления
  подтверждён foreground `android/com.android.internal.app.ChooserActivity`.
  Файлы удалены тестом только после совпадения имени/суммы. Пробные запуски
  единственного обработчика «МойОфис» доходили до его требования обновить себя;
  просмотр содержимого в этом приложении не заявляется, оно не обновлялось.
- 24 JVM-теста, строгие lintDebug/lintRelease и assembleDebug прошли.
- 23 целевых веб-теста (files/openDownload/архивы), Svelte check 0 ошибок/0
  предупреждений, check:ui, ESLint/Prettier изменённых файлов и production build
  прошли. Существующие предупреждения qrcode/theme_color/chunk size остаются.
- Финальный scaffold-прогон: вход, same-origin переход и системная «Назад»,
  блокировка чужого документа, localStorage после холодного старта и отсутствие
  необработанных JS-ошибок — прошли. На кадре входа при той же теме и размере
  осмотрены прежние логотип, карточка, поле, действия и интервалы; отличий нет.
- Кадр сохранения SHA-256:
  `5e8c2faadcec7a73cf42b460550808deb977ee23bbae20e67ff975c91048de57`.
- Кадр входа `dev/screens/shots/android-exports-regression/android-scaffold-login.png`:
  `e151e5575504466dc0fbf718e6b6e69687dc4e94eb57a08234ddd159f8db8bd2`.

При отладке harness ожидание запуска обработчика заменено на проверку реального
foreground вместо фиксированных 500 ms. В одном прогоне DocumentsUI дополнил
тестовое имя `.bin` расширением `.zip`; содержимое совпало, образец проверен и
убран, затем финальный URL-прогон повторён с корректным предложением `.zip`.
Диагностические dumps окна/уведомлений удалены, исходные данные телефона не менялись.

Ограничения: Android 13+ permission prompt и realme физически не проверены;
настоящие авторизованные архивы/многогигабайтные файлы и cloud providers не
проверялись. Повторное открытие уведомления после смерти процесса не подтверждено:
OPPO не разрешил shell `am kill`; debug `run-as kill` также не завершил процесс.
Системные ограничения не отключались. Force-stop очищает уведомления и не служит
заменой этой проверки. Этап 1 целиком остаётся открытым.
