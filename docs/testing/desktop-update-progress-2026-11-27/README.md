# Ход скачивания в полосе обновления Настольного — 27.11.2026

Владелец 27.11, после зависшего обновления 0.5.2 → 0.5.5: «Не плохо бы
показывать прогресс скачивания.» Сейчас кнопка полосы на всё время установки
говорит «Обновляем…» — файл 18 МБ, и понять, идёт скачивание или встало, нельзя.

Новых компонентов нет: `Meter` — существующая полоса библиотеки; строка с
числами — тот же слот под заголовком полосы, где показывается отказ подписи.

## Изменение

- Оболочка отдаёт ход скачивания: `internal/selfupdate` сообщает байты и размер
  из `Content-Length` (`progressReader`, тесты `TestFetchReportsProgress`,
  `TestFetchWithoutProgress`), `cmd/wynd-desktop` хранит их и отдаёт
  `main.App.SelfUpdateProgress` (`desktop.UpdateProgress`) — без токенов и путей.
- Окно, пока идёт установка, спрашивает ход раз в 300 мс и показывает под
  заголовком строку «Скачиваем 8,2 из 18 МБ» и полосу `Meter`; кнопка остаётся
  «Обновляем…». Пока байтов нет — строки нет, как раньше.
- Полоса обновления выросла с 58 до 75 px на время скачивания; в покое и после
  отказа — прежняя.
- Мастерская пока без строки хода: общий `selfupdate.Apply` принимает обратный
  вызов, но её полоса передаёт `nil`.

## Рендер

Мок-стенд окна `cmd/wynd-desktop/frontend/mock/mock.html?update=progress`
(vite 5179, `base /__shell/`), настоящий Svelte-рендер оболочки, не эскиз;
headless Edge по CDP, окно 760 × 780, DPR 1, светлая тема. Стенд отвечает теми
же числами, что приходят с оболочки (8 200 000 из 17 952 256), и не заканчивает
установку — кадр снят в середине. Версия на кадре — `0.2.0` подставного Go;
на числа и вёрстку это не влияет.
