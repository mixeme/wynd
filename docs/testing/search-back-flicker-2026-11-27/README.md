## Причина

При шаге назад экран поиска монтируется заново, и его состояние живёт только
в компоненте:

- `hits`, `authorNames`, `thumbUrls` начинаются пустыми — до ответа сервера
  видны «Ищем…» и пустое место;
- `SearchField` на монтировании делает `input.focus()` (задумано для входа в
  поиск: «экран открывают, чтобы печатать»). В PWA Firefox программный фокус
  поднимает клавиатуру; в Android WebView — нет, поэтому в APK мигания не
  видно.

## Правка

- `web/src/lib/journal/search-memory.ts` — память экрана поиска: ключ
  «сервер + круг + канонический адрес запроса», до шести последних экранов,
  хранит строки, авторов, адреса превью и состояние «Ищем…». Что видно на
  экране, то и запоминается.
- Экран поиска восстанавливает этот кадр **до первой отрисовки**; первый
  прогон после возврата идёт молча — «Ищем…» не показывается, сеть уточняет
  строки следом, ошибка такого прогона показанное не стирает. Превью, которых
  в памяти нет, берутся из кэша устройства. Пустой запрос теперь отменяет и
  ответ, который ещё в пути (иначе он вернул бы строки под очищенным поиском).
- `search-scope.ts` + корневой макет: тип перехода запоминается в
  `beforeNavigate`; при возврате по истории (`popstate`) поле поиска не
  фокусируется — клавиатура заново не выезжает. Обычный вход в поиск
  (переход, ссылка) фокусирует как раньше.
- Выход из входа очищает память поиска (как память улочки, C97).
