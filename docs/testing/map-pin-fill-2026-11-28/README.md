# Метка карты: фотография заполняет кружок (C161)

Замечание владельца 28.11 по снимку «Мигание → Карта»: «Почему на карте
фотографии — это круги? И почему справа в круге пустое место?». Вёрстка
экрана не менялась; исправлено заполнение фотографией внутри уже принятой
метки.

- Основа: вкладка «Карта» круга — кадр
  [5.6](../../visual/screens.html#e5-6), реализация —
  `web/src/routes/circles/[id]/map/+page.svelte` и

## Круги — это стиль метки, а не ошибка отрисовки

Метка задана в `map.css`: круг 44 px, `border-radius: 50%`, кольцо 2 px цветом
бумаги и тень; картинка внутри — `object-fit: cover`. Скопления
`leaflet.markercluster` рисует своими кружками со счётчиком. Так метка
выглядит с первой версии интерфейса.

В утверждённом кадре 5.6 одиночная метка нарисована иначе — каплевидный
«пин» с маленькой круглой фотографией в головке; подпись кадра: «Скопления
схлопываются в счётчик, одиночные показывают миниатюру». В приложении
одиночная метка — просто круг с фотографией. Решения владельца заменить кадр
на круг не найдено; это расхождение с кадром, вопрос вынесен владельцу
отдельно. Кадр 5.6 этой правкой не менялся.

## Причина пустого места справа

Leaflet сбрасывает размеры картинок в маркерном слое:

```css
.leaflet-container .leaflet-marker-pane img { width: auto; }
```

У правила в `map.css` была та же специфичность:

```css
.ph .map-pin-thumb img { width: 100%; height: 100%; object-fit: cover; }
```

В собранном клиенте CSS идёт в порядке зависимостей маршрута: сначала
`assets/map.*.css`, затем CSS Leaflet (`assets/41.*.css`). При равной
специфичности побеждает последнее правило — Leaflet. В dev-режиме порядок
обратный, поэтому дефект был виден только в сборке, в том числе в APK.

С `width: auto` картинка сохраняет пропорции по высоте: на стенде без общего
сброса — 33 × 44 в рамке 48 px, в приложении — 30 × 40 в метке 44 px
(`box-sizing: border-box` из `+layout.svelte`); справа остаётся полоса
подложки ≈ 10–11 px. У квадратного фото ширина равна высоте, у
горизонтального — больше (обрезается). Поэтому на одних записях полосы не
было, а на портретных она появлялась.

## Правка

`web/src/lib/styles/map.css`: селектор усилен до
`.ph .map-wrap .leaflet-container .map-pin-thumb img` — он сильнее сброса
Leaflet при любом порядке файлов. Размер и вид метки не менялись: в
приложении метка 44 px (общий `box-sizing: border-box`), стенд без этого
сброса показывает 48 px; фотография внутри — 40 px в приложении, 44 px на
стенде.

## Проверка

Настоящий рендер Edge (headless, DPR 3, 300 × 260 CSS px) с собранными CSS
в порядке бандла: `map.CrYOTLws.css`, затем `41.9Hbp8J6b.css`; DOM маркера —
как у Leaflet (`leaflet-container` → `leaflet-marker-pane` →
`leaflet-marker-icon` 44 × 44 → `.map-pin-thumb` → `img`). Картинки в метках —
тестовые (портретная 300 × 400, квадратная 300 × 300, горизонтальная
400 × 300), чтобы видеть пропорции.

| Метка | До: размер картинки | После: размер картинки |
|---|---|---|
| Портретная | 33 × 44, справа полоса 11 px | 44 × 44, заполнено |
| Квадратная | 44 × 44 | 44 × 44 |
| Горизонтальная | 58,7 × 44 (обрезана справа) | 44 × 44, обрезка по кругу |
| Портретная (повтор) | 33 × 44 | 44 × 44 |

Числа — стенд, где нет общего `box-sizing: border-box`: рамка снаружи 48 px,
фото 44 px. В приложении те же пропорции при метке 44 px и фото 40 px; это
видно на настоящем экране в [протоколе формы метки](../map-pin-shape-2026-11-28/README.md).

Кадры: [до](pin-before.png) · [после](pin-after.png).

**Границы проверки.** Это рендер метки на стенде, а не полного экрана
