# Почему сторож Wynd UI пропустил копию шапки и что добавлено

26 ноября 2026. Вопрос владельца после приёмки C136: «почему наш сторож Wynd UI
не поймал эту самодеятельность? И есть ли она ещё где-то?»

## Почему пропустил

`check:ui` (`web/scripts/ui-guard.mjs`) — сторож **экранов**. Он смотрит
`src/routes/**`: экран обязан собираться из `$ui` и `$lib/layouts`; в экранах
запрещены сырые `btn`, `lab`, `fld`, `ta`, `row2`, `compose-text`, `role="button"`
и `{@html}`; файлы библиотеки обязаны быть названы в справочнике; кнопки в `$ui`
— из списка классов. `$ui` он считает готовой библиотекой и проверяет только
по гигиене.

Копия шапки жила **внутри библиотеки** — в `$ui/overlays/AvatarCrop.svelte`.
Ни одно правило её не касалось: правил «у структурного класса шапки один
хозяин» не было, а `compose-top` и `cbar` встречались в двух файлах — и это
никого не смущало. Сторож был слеп по построению: он не даёт экрану нарисовать
библиотеку вручную, но не мешает компоненту библиотеки нарисовать другой
компонент.

## Что добавлено

`web/scripts/chrome-guard.mjs` — отдельный сторож шапок (`checkChromeOwners`),
зовётся из `check:ui` сразу после общего сторожа. Структурный класс шапки
разрешён только своему компоненту или слою сборки:

| Класс | Где можно |
| --- | --- |
| `cbar` | `components/chrome/` и `layouts/` — цветную шапку собирают слой и chrome |
| `compose-top` | только `chrome/ComposeHeader.svelte` |
| `appbar` | только `chrome/AppBar.svelte` |
| `idn`, `idn-t`, `bar-act` | только `chrome/CircleBar.svelte` |
| `top-back` | только `layouts/FormLayout.svelte` |

Смотрит библиотеку, `layouts` и боевые экраны (кроме `/dev`). Классы читаются
по разметке, включая `class={…}` и `class:x` — как в общем сторожа. Тесты —
`web/src/test/chrome-guard.test.ts` (2: ловит копию в чужом компоненте и на
экране; на нынешнем дереве чисто). `check:ui` печатает `chrome-guard: OK`.

## Обход 26.11: есть ли ещё

Проверены все структурные классы шапки и соседние узоры по всему `web/src`:

- `cbar` — только `CircleBar`, `ComposeHeader` и `FormLayout`; `compose-top` —
  только `ComposeHeader`; `appbar` — только `AppBar`; `idn`/`idn-t`/`bar-act` —
  только `CircleBar`; `top-back` — только `FormLayout`. Других копий шапки нет.
- `class="top"` в `Lightbox` — ряд управления просмотра фото, не шапка: у него
  нет ни `cbar`, ни заголовка, ни вкладок.
- Диалоги на экранах `settings/servers/accept` и `.../move` собраны из
  `Dialog`, `Scrim` и `Button`; руками набрана только строка вопроса (`dlgq`) —
  это содержимое, а не копия компонента.
- Строки, карточки и баннеры — из компонентов `$ui`; общий класс `pay-banner`
  у трёх одобренных вариантов баннера, это один вид, а не копия.
- Все шапки в боевых экранах идут через `FormLayout`/`CircleLayout`/`ShellLayout`;
  собственных `BackBar`/`CircleBar`/`AppBar` на экранах нет, `barMinHeight=60`
  остаётся только у общего поиска (решение C98).

## Осталось

Запись C140 и отметка приёмки C136 в плане 46 — отдельным коммитом после
правок параллельной сессии в том же файле (она сейчас меняет C142).
