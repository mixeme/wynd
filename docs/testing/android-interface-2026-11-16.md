# Android: смена источника интерфейса

16 ноября 2026. Продолжение этапа 1 плана 50. Интерфейс приходит с сервера;
локальные страницы и основное веб-приложение в APK не включались.

## Реализация

`InterfaceBridge` доступен только главному фрейму выбранного origin через
AndroidX WebMessageListener. Проверка нормализует корневой адрес и запрашивает
только `GET /api/v1/instance`: без передачи cookies и Authorization из WebView,
без redirects, с проверкой статуса, типа JSON, схемы и предела 64 KiB.
HTTPS обязателен; HTTP разрешён только debug loopback. Проверку TLS не ослабляли.
Использованы штатные [HttpURLConnection и управление redirects](https://developer.android.com/reference/java/net/HttpURLConnection).

Ответ выдаёт временный одноразовый ticket. Новая проверка, отмена или смена
документа отменяет старый; устаревший ticket и произвольный непроверенный адрес
не меняют источник. Перед сменой проверяется отсутствие входящего Share,
выбора/сохранения файлов. После синхронного сохранения private preference
создаётся новый WebView с мостами нового origin и без старой истории.
Приглашение передаётся только как временная цель загрузки выбранного сервера;
его токен не попадает в запрос карточки или preferences.

Файлы сессий, IndexedDB, очередь и localStorage между origin не копируются
и не удаляются. Это граница хранения Chromium; реальный вход или публикацию
на двух серверах в этом прогоне не выполняли.

Системная «Назад» сначала посылает отменяемое событие странице. Существующий
стек модальных окон закрывает верхнее окно; если окна нет, сохраняется прежний
путь native Back / отмены Share. Это исправляет и вход в настройки отдельным
документом: WebView не уходит в старый документ поверх открытого подтверждения.
Старый серверный клиент без обработчика продолжает обычный шаг истории.

## Настоящий телефон

OPPO CPH1931, Android 10/API 29, WebView 157.0.8103.38,
`mixeme.wynd.debug`. Экран 720×1600, CSS viewport 360×728, DPR 2, светлая тема.
Debug APK SHA-256:
`8fea43da06a9b716558f33c0df6377bcb7116c478e3a4dadae2bac47ba05e127`.
Установка поверх существующего пакета, без очистки данных.

Два собственных loopback Go-сервера: 127.0.0.1:7696 и 127.0.0.1:7698,
ADB reverse; отдельные каталоги данных. Текст Share и QR-картинка синтетические.
Реальные приглашения, фото с геоданными, входы и записи людей не использовались.
Содержимое живой камеры не сохраняется в доказательства.

Повторяемый сценарий:

```powershell
node scripts/test-android-interface.mjs aa8d50d0
```

Проверено:

- «Назад» закрывает подтверждение, оставляя настройки и исходный сервер.
- Недоступный адрес показывает текст 7.44 и не заменяет источник.
- Ticket предыдущей проверки не позволяет сменить сервер.
- Входящий тестовый Share блокирует смену, его token и текст сохраняются;
  после проверки удаляется только этот собственный набор.
- QR-камера открывается; после выхода её tracks имеют `ended`.
  Синтетическая PNG с QR проходит настоящий `FilePicker`/декодер и проверку сервера.
- «Дальше» открывает второй origin. Маркер localStorage старого origin там отсутствует.
- Полный force-stop и запуск из launcher восстанавливает выбранный origin
  и его собственный маркер localStorage.
- При возвращении по синтетическому приглашению открывается именно `/invite/…`
  нужного сервера; старый маркер остаётся на месте.
- Исходный сервер восстановлен; оба собственных маркера удалены.

Для cold-start проверки после `localStorage.setItem` выдержано 6,5 с:
Chromium записывает localStorage на диск асинхронно. Отдельно воспроизведено,
что немедленный force-stop может потерять только что записанный тестовый маркер;
после штатной фоновой записи он сохраняется. Этот прогон не подтверждает
долговечность произвольных незавершённых записей при мгновенном убийстве процесса.
Нативная очередь/возобновление после гибели процесса остаётся этапом 5.
