# C71 — живые проверки на слабом сервере, 7–8 ноября 2026

Живые проверки хода сборки C71 ([план 45](../plans/workshop-servers.plan.md#c71--ход-сборки-на-сервере), пункт «Проверки») на слабом сервере владельца. Прогоны 1–2 завершены; обрыв/повтор, экран ошибки и журнал ожидают восстановления SSH-доступа (инцидент ниже).

## Сервер

`wynd2.mixfed.ru` = **45.144.64.241**, `firstbyte1.mixdep.ru`: **1 ядро** (QEMU v2.5+), **732 МБ** RAM, диск 6,7 ГБ (свободно 4,4 ГБ), Debian 13.2, Docker 29.9.2 + Compose 5.6.1, git 2.47.3, swap отсутствует. Профиль повторяет прежние замеры плана 45 («1 ядро, 709 МБ»). Имя `wynd2` до смены A-записи; машина отдана владельцем под эту проверку.

## Способ

Мастерская — **опубликованный exe 0.4.1** (CI, SHA-256 `6989…0E0D48`), временные профили, окно **680×501** — минимальный размер: приложение не позволяет менять размер программно (`SetWindowPos` принимается, окно возвращается к сохранённой геометрии; наблюдение для будущих прогонов). Управление окном — `PostMessage` в `Chrome_RenderWidgetHostHWND` (курсор и передний план в среде агента недоступны), снимки — `PrintWindow`, чтение текста и координат — локальный OCR WinRT (`dev/c71-weak/ocr-boxes.ps1`); телеметрия сервера — отдельные SSH-сессии paramiko. Инструменты — `dev/c71-weak/` (в git не входит).

## Прогон 1 — установка со сборкой (7 ноября, 21:09–21:22)

Чистый сервер (чужая пробная установка systemd-Wynd от 28.10 убрана вручную; осмотр до неё правильно показывал «Этот Wynd ставила не Мастерская» с предложением только переноса). Установка: план «сервер соберёт из исходного кода», «около 10 минут», домен wynd2.mixfed.ru.

- **Поток виден всю сборку**: последняя строка BuildKit менялась в каждом кадре — `#14 [web 5/7] RUN cd web && ci…` → npm-warn'ы eslint → `56.94 transforming` → `189.1 built in 3m 2s` → `[build 7/7] RUN CGO_ENABLED=… go build ./cmd/wynd` → `DONE 28.1s`; давность честно росла: «Последнее сообщение — сейчас» → «меньше минуты назад» → «1 минуту назад» (снимки `shots/build-000…079.png` каждые 15 с).
- **Время**: от «Установить» (21:09:45) до «Wynd работает. Проверка прошла: сайт открывается, сертификат действует» со ссылкой первого запуска — **≈ 12–13 минут**; оценка «около 10 минут» на этом сервере честная.
- **Очистка после успеха**: временный swap выключен и удалён, `/var/tmp/wynd-src` удалён, build-кэш вычищен (`builder prune` при «своём» кэше), диск вернулся к 4,1 ГБ свободно.
- **Скрипт сборки** (виден в телеметрии): `flock /var/tmp/wynd-build.lock`; идемпотентность — при готовом образе сразу выход; проверка места 2,3 ГБ + swap; временный swap 1,3 ГБ на слабом ядре (без него go build на 715 МБ RAM не прожил бы); клон `github.com/mixeme/wynd` по тегу v0.49.0; `docker build --progress=plain`.
- Контейнеры подняты с собственным Caddy, сертификат Let's Encrypt получен, `https://wynd2.mixfed.ru/` — 200.

- Поток снова живой до последнего шага (`#22 [build 7/7] RUN … go build -trimpath`).

## Инцидент: убит демон sshd (моя ошибка)

При подготовке сценария обрыва я поднимался по цепочке предков build-скрипта к сессии SSH и по имени `sshd` ошибочно выбрал **главный слушатель** (ppid=1), а не процесс сессии `sshd-session`. `kill` уронил порт 22; новые подключения не принимаются, systemd слушателя не поднял. Живы: сайт, контейнеры, SSH-сессии, существовавшие до убийства (благодаря этому прогон 2 завершился успешно уже после инцидента). Восстановление — перезагрузка из панели хостинга. Урок для сценариев обрыва: целевой процесс — `sshd-session` из цепочки сессии, проверять ppid ≠ 1 перед kill.

## Прогон 3 — обрыв во время сборки, повтор и журнал (8 ноября, 10:40–11:40)

После перезагрузки сервер восстановился сам (sshd поднят, контейнеры стартовали, сайт 200). Третья сборка подготовлена тем же приёмом (compose отодвинут, образ перетегирован). Наблюдения по ходу:

- **Сессия приложения пережила перезагрузку молча**: окно показывало прошлое состояние «Подключён / Wynd обновлён» до первого обращения; клик «К серверу» прозрачно переподключил и показал свежий осмотр (модель кадра 7е) — устаревшее состояние не выдаётся за текущее, но и пометки «нет связи» в простое нет.
- **Обрыв во время сборки**: убийство `sshd-session` (родителя build-скрипта, ppid ≠ 1) разорвало соединение в середине npm-шага. Приложение показало **«Связь с сервером оборвалась»**, список этапов и последняя строка вывода сохранены, внизу — «Нажмите „Повторить“ — подключимся снова и продолжим с этого шага» и «Полный вывод сборки». Сборка на сервере умерла вместе с сессией (SIGHUP процессной группе).
- **Повтор после обрыва**: «Повторить» переподключил и продолжил со шага сборки; вторая параллельная не запускается — повтор идёт через тот же замок `flock` и идемпотентную проверку образа. Повтор сразу упёрся в честную проверку места: **«Для сборки из исходного кода нужно 3,5 ГБ свободного места, а есть 2,6 ГБ»** (`WYND_NO_ROOM`, код 3) — кэш прерванной сборки съел место; после `docker builder prune` повтор пошёл дальше. Отдельная находка: место под сборку надо не только перед стартом, но и при повторе после прерывания.
- **Журнал и безопасность вывода**: в состоянии обрыва раскрытие «Полный вывод сборки» показывает журнал текущей операции — текст команды сборки и живые строки BuildKit; собрано 20 страниц, поиск пароля и служебных секретов — **ничего не найдено**.
- **Давность при тишине** — вживую: «1 минуту назад», «13 минут», «32 минуты» по мере остановки вывода; индикатор честно отличает долгий шаг от потерянной связи.
- **Автоповтор при сбое команды** (не было видно в ревью): убийство процесса `docker build` не даёт экрана ошибки — операция перезапускает сборку автоматически.
- **Компактное окно**: на минимальном 680×501 раскрытый журнал не отображает содержимое (переключатель работает, область пуста); на развёрнутом окне (1600×768, системная максимизация) журнал виден и прокручивается. Программный `SetWindowPos` приложение игнорирует — размер меняется только пользователем или максимизацией.

## Инцидент 2: трэшинг на автоповторе

Автоповтор после убийства docker запустил сборку заново; веб-сборка (vite, «transforming») на 1 ядре/732 МБ ушла в глубокий swap-трэшинг: строка вывода молчала 45+ минут, SSH перестал отвечать даже баннером (sshd не может породить сессию под нагрузкой). Лечится перезагрузкой из панели хостинга. Отдельно отметить: C71-давность («Последняя строка вывода — 32 минуты назад») честно показывала застрятие всё это время.

## Что осталось

- Экран ошибки «Сборка завершилась с кодом N»: автоповтор маскирует одиночные сбои — нужно исчерпать лимит повторов или найти неретраимый сбой.
- Большой журнал >256 КБ с пометкой «начало вывода не сохранено»; медленный потребитель — частично (окно продолжало отрисовку под нагрузкой).
- После перезагрузки — вернуть сервер в рабочее состояние: убрать образы-дубли `wynd:0.49.0-keep*`, проверить, что контейнер и сайт живы, докатить обновление до конца при возможности.
