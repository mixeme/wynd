# Проверки Wynd 0.53.3 на OPPO, 20 ноября 2026

OPPO CPH1931, Android 10, Firefox 132, USB. Снимки окна получены через
`adb exec-out screencap -p` (720 × 1600 px, светлая тема, DPR 2). Для прогона
на wynd2 использован тестовый круг «A26-проверка». Firefox предлагал
обновление с 0.53.2. После действия «Перейти на новую версию» в настройках
показана [0.53.3](version.png). [Протокол выпуска](../release-0.53.3-2026-11-20.md).

## C92. Дата в полях периода

**Пройдено на выпущенном клиенте 0.53.3.** В поиске круга раскрыли «Период».
В [пустых полях](c92-empty.png) видны «с» и «по», значки календаря и стрелки.

в том числе в поле «по» в фокусе. Обе подписи уступили место датам.
Геометрию полей и иконок сверили с [принятыми кадрами](../c92-date-range-2026-11-20/README.md).
Касание текстовой области пустого поля и смена области поиска остаются
отдельным прогоном с `13cb89e4` по [§9 реестра](../pending-device-checks.md#9-проверки-после-android-сессии-20-ноября).

## C99. Холодный запуск

### Сеть есть, ответы API задержаны

На изолированном сервере из `v0.53.3` в тестовой сессии заранее открыт список
с кругом «OPPO Cold Start». После `am force-stop org.mozilla.firefox` открыт
стартовый адрес `/` на стенде через USB. Прокси передавал запросы `/circles`
и `/instance` через 8 секунд после их получения. Съёмка и журнал прокси
использовали часы одного компьютера.

- На 2,9–3,7 с Firefox ещё загружал страницу. На 4,9–5,4 с виден фон Wynd.
- [Кадр 11,5–12,1 с](c99-delay-before-response.png) уже показывает «OPPO Cold Start».
  Первый задержанный запрос списка ушёл с прокси на сервер на 15,5 с.
  Список появился как минимум за 3,3 с до передачи запроса серверу.

### Сеть полностью отключена

На выданном клиенте wynd2 после прогрева «A26-проверки» отключили Wi-Fi и
мобильные данные. Android подтвердил `Active default network: none`.
После завершения Firefox и открытия `/circles` около 7 с оставалась полоса
загрузки браузера. Примерно через 12 с Wynd показал
[«Ни одного круга»](c99-offline-empty.png), а после восстановления сети
в той же вкладке список ещё оставался пустым. При повторном открытии `/circles`
онлайн [круг вернулся](c99-public-online-return.png). Это прямой запуск URL в
Firefox.

### Повтор прямого запуска с прогретым `/circles`

онлайн и [увидели «A26-проверку»](c99-direct-warm.png). Дважды отключили
Wi-Fi и мобильные данные, дождались `Active default network: none`,

системный `VIEW` для Firefox. Между попытками восстанавливали сеть и

## Офлайн-очередь файла и видео

В круге «A26-проверка» через временный ярлык Firefox открыли редактор
записи `oppoqueue`. Добавили синтетический BIN на 12 МиБ через «Файл»
и ролик WebM (VP8, 0:08, 5,6 МиБ) через «Фото и видео» → «Файлы».
Перед публикацией отключили Wi-Fi и мобильные данные. Android подтвердил
отсутствие сети по умолчанию.

- [Запись в очереди](queue-pending.png) показывает имя и размер файла
  отдельной строкой. У видео видны кнопка воспроизведения и `0:08` на заглушке.
- Сразу после снимка вернули оба канала связи. Отправка началась сама
  и показала [«отправляется · 51%»](queue-sending.png). К последнему кадру
  через 24 с после включения обоих каналов в ленте была
  [опубликованная запись с кадром видео и файлом](queue-published.png).
  Поиск по метке дал [одну запись](queue-search.png).
- В её обсуждении добавили тот же WebM через «Файл» как вложение к
  `oppocomment`. Снова отключили оба канала и подтвердили отсутствие сети
  перед нажатием отправки. Комментарий показался [в очереди](comment-pending.png).
  После возврата сети в обсуждении видны [71%](comment-sending.png), затем
  [один отправленный комментарий с вложением](comment-published.png).

**C107.** В ленте у WebM кадр появился только после публикации. Подтверждены
отображение файла в очереди, проценты в ленте и обсуждении, автоматическая
отправка после восстановления сети. Режим без подписи, долгое голосовое и
день без фотографий остаются в реестре.

Причина: Firefox на Android не отдаёт кадр ролика из файла в canvas — ни из
видимого элемента, ни во время проигрывания; сам ролик при этом браузер
рисует. Поэтому у ролика без кадра плитка показывает сам ролик на паузе
(лента очереди и редактор, `videoSrc` у `MediaTile`). Повтор 20.11 на
CPH1931/Firefox 132, стенд 0.53.3 + правка, круг «Дача», WebM VP8 10 с из
«Файлов»: редактор и [запись в очереди с кадром](c107-queue-frame.png) —
кадр, значок и `0:10`; после возврата сети запись ушла сама. На сервере без
ffmpeg (локальный стенд) у опубликованной записи кадра нет — это ограничение
стенда; на wynd2 кадр делает сервер.

В конце запись и её обсуждение удалили, [поиск по метке пуст](queue-clean-search.png).
Два временных файла и ярлык удалены. Wi-Fi и мобильные данные возвращены
в исходное состояние.
