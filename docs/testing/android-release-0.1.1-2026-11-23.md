## Не выполнено здесь и почему

- **Полная проверка `gh attestation verify`** (`-VerifyOnly` из `scripts/sign-android-release.ps1`) прошла контроль суммы, но упала на загрузке бандла удостоверения: локальный DNS (роутер 172.20.9.1) не резолвит `tmaproduction.blob.core.windows.net` (публичные 1.1.1.1/8.8.8.8 резолвят; `ipconfig /flushdns` и трёхкратный повтор не помогли). Проверка — при восстановлении DNS или из другой сети; запись удостоверения на GitHub есть.
- **Подпись постоянным ключом и публикация** — шаг владельца («Wynd Подпись», план 65; пароль ключа локальный). `releaseReady=true`, поэтому и запасной `-Publish` не заблокирован.
- **Запасной скрипт подписи не запускается штатно:** `powershell -File scripts/sign-android-release.ps1` на PowerShell 5.1 падает разбором — файл UTF-8 без BOM с кириллицей читается как ANSI (проверено копией с BOM в `dev/`, в git не входит; проверка остальных шагов сделана вручную). Относится к C118 плана 46: скрипту нужен BOM или запуск через PowerShell 7.

## 23.11 — пояснение к файлам выпуска

Владелец спросил, зачем в выпуске неподписанный APK. Решено оставить его: это исходный артефакт CI, на который выдано удостоверение сборки, а подпись встраивается в файл — подписанный APK уже другой файл, и без исходного проверять удостоверение и подписывать заново нечем. Чтобы страница выпуска не выглядела выбором из двух APK, в описание добавлена строка, какой файл ставить. У 0.1.1 описание исправлено в тот же день; «Подпись» (`internal/signing/android.go`) и запасной `scripts/sign-android-release.ps1` пишут строку со следующего выпуска.
