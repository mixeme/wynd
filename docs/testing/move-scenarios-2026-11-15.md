# Живые сценарии переноса круга — 15 ноября 2026

Раздел 2 [реестра](pending-device-checks.md), пункт «Перенос большого круга»: ветки с обрывом сети, перезапуском принимающего на ходу, нехваткой места и истёкшей ссылкой. Гладкий перенос 141 МБ был подтверждён 8 ноября. Обе стороны — Wynd 0.52.2 на выделенной машине wynd2; рабочий сервер wynd.mixfed.ru участвовал только чтением (карточка реального переноса «Текст»).

## Стенд

Источник и приёмник — два контейнера 0.52.2 на wynd2 (`--network host`, порты 8801/8802, каталоги `/srv/move-src`, `/srv/move-dst`). Стенд `/opt/wynd` не останавливался. Приёмнику задана `WYND_MOVE_ALLOWED_CIDRS=127.0.0.0/8` — легальная настройка переноса по локальной сети; без неё SSRF-охрана отбила loopback-ссылку с `502 source_unreachable` (проверено как побочный эффект). Круг «Перенос-тест»: 11 записей, 10 фото по 15 МБ (случайные байты, 150 МБ), заведён через API (админ-приглашение → код входа из журнала контейнера). Перед опытами — снимки БД `pre-move-tests-20261115.db` на обеих машинах (оставлены).

## Что подтверждено

| Сценарий | Как | Итог |
| --- | --- | --- |
| Недостаток места | квота приёмника 50 МБ < круга 150 МБ | ✓ карточка входящего: `fits:false`, `room_bytes` 50 МБ, `limit:"quota"`; «Поднять круг» — **507** (места не хватает). Квота 200 МБ → `fits:true` |
| Истёкшая ссылка (свой перенос) | срок ссылки переведён в прошлое в БД источника (свой тестовый круг) | ✓ карточка источника: `status:"expired"`; приёмник по ссылке: карточка остаётся видимой с `link_alive:false` (состояние «перенос истёк»), «Поднять круг» — **410 `move_expired`** |
| Истёкшая ссылка (реальный перенос) | «Текст» на wynd.mixfed.ru: заморожен 8.11, срок истёк 11.11 | ✓ карточка отвечает `status:"expired"`; «Отменить перенос» остаётся за владельцем (хозяйство) |
| Обрыв сети на ходу | `iptables DROP` на порт источника после первого куска 32 МБ | ✓ прогресс встал: 20 с без движения, статус `pulling` |
| Перезапуск принимающего на ходу | `docker restart` приёмника в паузе обрыва, затем снятие DROP | ✓ докачка **продолжилась с 32 МБ, не с нуля**; worker возобновил перенос сам при старте (`ResumeIncomingMoves`, без вызовов API) |
| Продолжение и сверка | куски по 32 МБ, темп loopback ограничен 8 Мбит/с для окна наблюдения | ✓ итог `accepted`: 11 записей == 11 принятых, 157 395 303 байта ровно; на приёмнике круг «Перенос-тест» с 11 записями, 152 МБ на диске |

Записи возобновления: при обрыве сохранённый префикс файла и `pulled_bytes` пережили перезапуск контейнера — как в модульном тесте A21 (`move_stream_test.go`).

## Убрано за собой

Контейнеры `move-src`/`move-dst`, каталоги `/srv/move-src`, `/srv/move-dst`, временные скрипты и журнал — удалены. Правило `iptables` и темп `tc netem` на `lo` сняты (проверено: `qdisc noqueue`, политика OUTPUT без правил). Стенд `/opt/wynd` поднят, `https://wynd2.mixfed.ru/api/v1/instance` отвечает. На рабочем сервере изменений не было (только чтение БД и карточки).
