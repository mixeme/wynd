# Настольный: сессии в системном хранилище — 22 ноября 2026

Функция 3 плана [66](../plans/66-desktop-functions.plan.md): токены уходят из IndexedDB профиля WebView2 в учётные записи Windows (Credential Manager).

## Реализация

- **Хранилище** (`internal/desktop/secrets_windows.go`): `WincredStore` — по учётной записи на origin (`Wynd.Desktop/<origin>`, `admin` — панель), блоб — JSON сессии целиком. Лимит блоба снят пробником заранее: **1024 байта принимается, 4096 — отказ RPC** («The stub received bad data») — потолок `secretBlobLimit` и отказ на превышение, а не молчаливая потеря. Кэш процесса (`SecretsCache`): Credential Manager читается на первом касании, дальше память; окно — единственный писатель.
- **Ручки** (`secrets.go`) на локальном порту окна, под тем же CORS-контуром, что API: `GET /__secrets` (мешок), `PUT /__secrets/session` и `/admin`, `DELETE /__secrets/session/<origin>` и `/admin`. Ключ `admin` зарезервирован за панелью — origin, равный ему, отвергается.
- **Клиент** (`web/src/lib/idb/db.ts`): при мосте с apiBase сессии идут в ручки окна, при отказе или 404 (старая оболочка без ручек — прокси отдаст ответ сервера) — откат в IndexedDB, как раньше. После записи в системное хранилище профиль очищается от токена. `migrateSessionsToSystemStorage()` при старте клиента (`initSession`) выгружает прежние записи; прерванная миграция продолжается при следующем запуске, до очистки IndexedDB не трогается. В браузере (моста нет) всё как было.

## Тесты

- Go: ручки на фейковом store (мешок, перезапись без дублей, резерв `admin`, лимит блоба, чужие методы и пути); **живой roundtrip Credential Manager** (`TestWincredStoreRoundtrip`: запись→чтение→перечень→удаление) и отказ на oversized-блоб.
- Vitest: роутинг браузер/окно (7 тестов), запись в окно очищает IndexedDB от токена, чтение из мешка, откат при сбое хранилища и при 404 старой оболочки, миграция (выгрузка, остановка при отказе с целой IndexedDB, повтор, в браузере не начинается).

Запущенный `dist\wynd-desktop.exe` (порт найден по PID): preflight `OPTIONS /__secrets/session` → **204 с `Access-Control-Allow-Origin: http://wails.localhost`**; `PUT` сессии → 204; **`cmdkey /list` показывает учётную запись `Wynd.Desktop/…`**; `GET /__secrets` отдаёт сессию с тем же токеном; `DELETE` → 204, мешок пуст; чужому `Origin` заголовок разрешения не выдаётся.

## Границы

Панель админа своего сервера хранит токен так же (ключ `admin`). Токен в памяти окна держится кэшем до выхода — без него клиент запрашивал бы Credential Manager на каждый API-вызов. Полной очистки Credential Manager при удалении Wynd нет — записи уходят при выходе из учётки; массовая чистка — по решению владельца, если потребуется.
