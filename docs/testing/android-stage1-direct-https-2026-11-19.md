# Android · прямой холодный запуск по HTTPS на OPPO

19 ноября 2026. OPPO CPH1931, Android 10, WebView 157.0.8103.50.
Сервер Wynd 0.53.0 и веб-клиент заново собраны из `22e7420b`.
Тестовый APK `mixeme.wynd.debug.directhttps` использовал тот же
`MainActivity.java`, что исходник этого коммита. SHA-256 APK
`667cb469a10a2ec95f239491dd55b196fa35f1654bd0028957aac1e83e868cd1`.

SHA-256 веб-ресурсов

- `sw.js` — `b901ea745cccb6dd90ec27caa8cbc680b1c8aa61b5550d595730ed3ae0935adc`;
- `index.html` — `e8c96c18edaf49e3281c8362a718dc2101479fe7b5ab0a183122607b2ce332af`.

WebView подключался напрямую к `https://wynd-direct.localhost:17795`
через ADB reverse, без CONNECT и без `ProxyController`. Сертификат
`wynd-direct.localhost` доверен в этом тестовом APK только для этого
имени. Системное хранилище сертификатов не менялось. Через штатную
форму выполнен вход в отдельную тестовую учётную запись. Для прогона
на локальном сервере создан круг с одной текстовой записью.

Service Worker зарегистрировался автоматически. Он управлял загруженной
лентой, `workerStart > 0`. Workbox сохранил 372 записи, включая
`index.html`. Снимки списка кругов и ленты проверены в IndexedDB.

## Круги и очередь после полного перезапуска

В чистом профиле обрыв до TLS открыл локальный ПК3. С прогретым кэшем
пять запусков после `am force-stop` открыли сохранённый список кругов.
В двух случаях стенд закрыл соединение до TLS, в одном снято ADB reverse,
в двух сервер ответил HTTP 503 на запросы API. В этих двух попытках
главный документ до сервера не дошёл. Для каждого запуска зафиксированы
новый PID, `controller.scriptURL` и `workerStart > 0`.

После холодного запуска при обрыве до TLS открылся сохранённый круг с
текстом записи. Контрольный API-запрос с `cache: 'no-store'` завершился
сетевой ошибкой. В штатном редакторе поставлена в очередь новая запись.
Она пережила ещё один полный перезапуск с тем же `client_id`. После
возврата связи очередь опустела, настоящий API вернул в ленте ровно одну
запись с проверочным текстом. Регистрация воркера и 372 записи Workbox
сохранились. Состояние сети для очереди переключалось в тестовом WebView
через CDP, а прямые запросы HTTPS дополнительно блокировались стендом.

Снимки `cold-circles.png` и `cold-feed.png` сделаны через `adb screencap`
и осмотрены. Область WebView 360 × 728 CSS px, DPR 2, светлая тема.
Снимки и журнал `observed.json` находятся в
`dev/screens/shots/android-stage1-direct-https-2026-11-19/`.
Изолированный пакет удалён, ADB reverse снят. Путь рабочего APK и байты
его каталога источников совпали до и после теста.

## HTTP 503 на главный документ

В сборке `22e7420b` ответ HTTP 503 на `/` открывал ПК3 даже при активном
Service Worker и сохранённом интерфейсе. Этот запуск записан в
`baseline-503.json`.

Правка даёт первому GET в том же WebView один повтор через 250 мс при
503 на главном документе. Её проверили на том же OPPO с прямым HTTPS.

- Чистый профиль. Стенд получил два GET на `/` и оба раза вернул 503.
  После второго ответа открылся ПК3.
- Профиль с автоматически активированным Service Worker. Стенд вернул
  503 на первый GET `/`. Повтор открыл сохранённые круги из WebView.
  Стенд получил один запрос на `/`. Контроллер остался активным,
  `workerStart > 0`, все 372 записи Workbox сохранились.

В том же прогоне круги открылись после обрыва до TLS и после снятия
ADB reverse. Все 43 JVM-теста Android прошли. SHA-256 тестового APK
`f14963afa11c75f48cb4b9f88b1e51945ed0306a6dd99cc7ab880e115993df34`.

Осмотрены снимки `candidate-clean-503.png` и `candidate-cached-503.png`
с того же телефона. Журнал `candidate-observed.json` содержит счётчики
HTTPS, состояние кэша и результат очистки стенда. Тестовый пакет удалён,
ADB reverse снят. Путь рабочего APK и файл списка источников совпали
до и после прогона.
