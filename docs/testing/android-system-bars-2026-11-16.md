- Меняются только системные полосы Android: фон темы и контраст значков.
  Верхняя полоса также получает существующий `statusColorOverride` шапки круга.
  Компоненты, CSS, типографика, действия и компоновка веб-экрана не менялись.

`AppearanceBridge` — отдельный необязательный origin-bound WebMessageListener:
только главный документ выбранного сервера, живая Activity, пара непрозрачных
RGB. У старого APK и обычного браузера вызов ничего не делает. Мост обновлений
и его команды не менялись. Последний цвет темы сохраняется для запуска окна;
временный цвет шапки круга вместо темы не сохраняется.

`SystemBarsFrame` сохраняет безопасные границы WebView. На API 30+ отступы
учитывают полосы, вырез и клавиатуру. На Android 15+ фон рисуется native View
под прозрачными полосами. На API 21–22 для верхней и API 21–25 для нижней
полосы светлый фон заменяется тёмным: там ещё нет системных тёмных значков.
Основание — [Window](https://developer.android.com/reference/android/view/Window)
и [WindowInsetsController](https://developer.android.com/reference/android/view/WindowInsetsController).

## Реальная проверка

OPPO CPH1931, Android 10/API 29, текущий WebView 157.0.8103.38.
720×1600 px; CSS viewport 360×728, DPR 2, масштаб 100% в обоих состояниях.
Тема выбиралась штатными кнопками `/settings/app`, затем открывался `/`.
Снимки через `adb exec-out screencap -p`, без перерисовки/обработки.

Команды: `node scripts/test-android-appearance.mjs aa8d50d0 before` на APK
шага `c26fccea`; после сборки/установки — та же команда с `after`.
Скрипт ждёт сохранения темы в IndexedDB и возвращает прежнее «Как в системе».
Снимки делаются **до** диагностического сообщения мосту, поэтому они проверяют
автоматическую реакцию приложения. Ответ моста дополнительно проверяет цвета окна.

Осмотрены реальные пары из `dev/screens/shots/` (локальные артефакты игнорируются
Git). Логотип, заголовок, карточка, поле, отступы, переносы и кнопки совпадают.

обе #F4F0E9 в светлой и #211E1C в тёмной. Пиксели исходных PNG проверены
