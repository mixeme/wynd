# «Назад» с улочки: мигание загрузки (C154)

27 ноября 2026. Замечание владельца: «Круги → Круг → Назад → Круги → Назад →
Экран мигает.» Вёрстка не менялась; проверялось поведение навигации.

## Причина

Улица — дом вошедшего приложения, но в истории браузера за ней остаётся запись
экрана входа:

1. Запуск открывает `/` (вход). Корневой макет кладёт запись-копию
   (`armEntryGuard`), чтобы «Назад» не закрыло приложение.
2. Корневой экран видит сохранённый вход и переводит на `/circles`
   (`goto('/circles')`, новый шаг истории).
3. «Назад» с улицы честно идёт на прошлую запись — `/`. Экран входа снова
   видит вход и переводит на `/circles`.

Получается петля `/circles → / → /circles`: человек видит кадр «Загрузка…».
История на стенде (карта `wynd:history` в `sessionStorage`):

```
[[…280,"/"],[…281,"/"],[…282,"/circles"],[…283,"/circles/<id>"]]
```

Пара 280/281 — документ входа и его запись-копия; 282 — улица после входа.

## Правка

`web/src/lib/navigation/up.ts`:

- `blockedHomeBack(from, to)` — шаг с `/circles` на `/` не делаем: выше улицы
  экранов нет, за ней только вход, который сразу уводит обратно. Запись-копия
  улицы (тот же адрес и тот же поиск) — тоже пропускаем. Настоящий прошлый
  экран не трогаем: настройки, поиск, другой круг и «Доступ закрыт»
  (`/circles?closed=…` — та же улица с другим поиском).
- `navigateBack()` — не идёт по истории на `/` с улицы и не уходит на родителя
  `/` (в том числе когда позади только запись-копия).
- `interceptHistoryBack(delta, from, to)` — шаг системной «Назад» к входу
  отменяется; SvelteKit сам возвращает запись истории (`history.go(-delta)`),
  экран и прокрутка остаются на месте.

`web/src/routes/+layout.svelte` передаёт в перехват `nav.from.url` и `nav.to.url`
(на момент `popstate` адрес в строке уже целевой, поэтому «откуда» берём у
навигации).

## Что не проверено

- Само устройство: стенд и браузер на компьютере. На Android системная
  «Назад» идёт через `wynd:android-back` → `webView.goBack()` → тот же
  `popstate`; путь кода общий, но живой кадр — за телефоном.
- В браузере «Назад» с улицы теперь не уводит на прошлый сайт: отменённый шаг
  возвращает запись. Это следствие правила «выше улицы экранов нет»; если
  владелец захочет на улице выходить из приложения/сайта — отдельное решение.

## C157: белый экран на телефоне — отмену заменили копией

27 ноября 2026, запись владельца 14:26 («Назад со списка кругов ведёт на белый
экран»). В записи — Firefox на Android (значок Firefox на ярлыке Wynd): запуск
→ улочка, системная «Назад» → белая страница с индикатором загрузки, улочка не
возвращается.

### Причина

C154 отменял шаг на `/` **после** того, как история его уже сделала:
`interceptHistoryBack` возвращал `true`, SvelteKit вызывал `history.go(-delta)`
и возвращал запись. В Chromium это работает (трассы выше). В оболочке Firefox на
Android к моменту отмены шаг уже начинал документную перезагрузку `/` — человек
видит белый экран, пока клиент снова не загрузится. Отмена шага — не тот
механизм: шаг не должен уходить на другой адрес вовсе.

### Что в записи на самом деле

Покадровый разбор (`docs/visual/flash-report.py` + замер среднего цвета):
последний кадр улицы — **10,25 с**, дальше до конца записи (15,0 с) ровный
светлый фон `#F5F4F9` (пикселей чистого белого ≥ 250 — меньше 0,2 %), на
14,4 с появляется индикатор загрузки. То есть страница подменялась не на кадр
«Загрузки», а на **4,4 секунды**: это документная перезагрузка, а не мигание
SvelteKit внутри страницы. Цвет фона — не бумага приложения (`#F4F0E9`, тёплая)
и не `#FFFFFF`: это пустая поверхность оболочки между документами.

Граница инструмента: `flash-report.py` это событие не поймал — `white` считает
только пиксели ≥ 250, а `blank` — std серого по всему кадру, включая строку
состояния и панель навигации; ровный `#F5F4F9` с ними проходит мимо обоих
порогов. Для «белых экранов» дополнительно смотреть средний цвет кадра (замер
по 0,25 с) — прохладный почти-белый фон без бумажного оттенка и есть подмена
документа.

### Правка

`web/src/lib/navigation/up.ts`:

- `armStreetGuard(url)` — перед записью улочки стоит её **копия** того же
  адреса (`pushState('', {})`). Системная «Назад» приходит на копию внутри
  того же документа: SvelteKit не делает перехода, ничего не грузится;
  обработчик `popstate` сразу ставит следующую копию. Копия — только когда
  позади улицы нет настоящего экрана (вход `/`, копия улочки или пусто);
  назад в настройки, поиск, круг или шлюз «Доступ закрыт» идёт как раньше.
- `armBackGuard(url)` — одна точка входа для записи-копии (`+layout.svelte`,
  `afterNavigate`): сначала копия улочки, иначе прежний страж входа.
- Запись-копия на экране входа больше не ставится: вошедшего вход сразу уводит
  на улочку **с заменой записи** (`goto('/circles', { replaceState: true })`,
  `web/src/routes/+page.svelte`), иначе замена легла бы на копию, а сам вход
  остался бы позади улицы.
