# Android: вшитый интерфейс — подготовка по схеме Настольного (24.11.2026)

Решение владельца 23.11: «По вшиванию интерфейса делаем по той же схеме, как с
Настольным» — [план 50, раздел «Вшитый интерфейс»](../plans/50-android-wrapper.plan.md#вшитый-интерфейс--по-схеме-настольного-решение-2311).
Схема Настольного — план 66, функция 9: клиент вшит в сборку, по умолчанию
интерфейс по-прежнему приходит с сервера, вшитый включается отдельным режимом;
переключение на вшитый как основной — после стабилизации интерфейса, отдельным
решением, с кадрами и приёмкой. Origin не меняется, поэтому данные клиента
переносить не нужно.

## Что сделано

- **Сборка.** `web/dist` собирается задачей `prepareEmbeddedWeb` (полный
  `vite build`, не только стартовые экраны) и кладётся в `assets/www` задачей
  `prepareEmbeddedAssets`. Включается только `-PwyndEmbeddedUi=true`
  (`BuildConfig.EMBEDDED_UI`); обычные APK остаются прежними и не растут.
  `scripts/build-android.ps1` получил ключ `-EmbeddedUi`.
- **Обход aapt.** aapt выкидывает каталоги, начинающиеся с `_` (шаблон
  `<dir>_*`). Каталог `_app` в APK лежит как `app/`; `EmbeddedAssets.storagePath`
  возвращает запросу `/_app/…` прежний URL. Без этого страница получала 404 на
  все модули клиента.
- **Отдача.** `EmbeddedAssets` отвечает только на GET/HEAD выбранного origin:
  файл из APK; если файла нет — `index.html` для главного фрейма и маршрута без
  расширения (SPA-фолбэк). `/api/`, `/health`, `/ready` никогда не подменяются.
  MIME, `Cache-Control` и защитные заголовки повторяют `web/serve.go`.
  Остальное (API, SSE, медиа, докачка, скачивания) идёт обычной сетью.
- **Origin и данные.** Страница отдаётся с адреса сервера, поэтому сессии,
  снимки и очередь в IndexedDB остаются на месте; переноса нет.
- **Старый Service Worker.** При смене сборки APK (по `lastUpdateTime`) один раз
  снимаются регистрации воркера и CacheStorage, затем страница перезагружается;
  IndexedDB не трогается. Это аналог чистки Service Worker в Настольном: без
  него старый воркер отдавал index и чанки прежней сборки, которых в APK уже
  нет (пустой экран).
- **CI.** В `android.yaml` добавлена сборка-сторож
  `assembleStandardDebug -PwyndEmbeddedUi=true` (в артефакты не попадает).
  `scripts/build-android.ps1` и `android/README.md` обновлены.

## Ворота

- Без флага: `testStandardDebugUnitTest`, `lintStandardDebug`,
  `assembleStandardDebug` — успешно; в APK нет `assets/www/`.
- С флагом: тот же набор — успешно; в APK 387 файлов клиента (369 в `app/`).
- `EmbeddedAssetsTest`: маршруты, запрет `/api`/`/health`/`/ready`, отказ от
  `..`/двойных слэшей, SPA-фолбэк только для главного фрейма, `_app` → `app`,
  MIME и правила кеша.

## Живая проверка на OPPO

OPPO CPH1931, Android 10, `mixeme.wynd.debug` 0.1.1-debug из текущего дерева;
локальный стенд 7676 (данные `dev/c92/data`), второй стенд 7677 не поднят.

- **Вшитый режим.** В logcat: `embedded ui: interface from APK`. Страница
  открылась на `/circles`, в DOM видны «Работа», «Семья», «Дача»; запросы
  пошли прямо на `127.0.0.1:7676` и `127.0.0.1:7677`, не через локальный
  прокси. Первый запуск после установки один раз перезагрузился после снятия
  старого воркера и кэшей.
- **Офлайн.** Стенд остановлен, приложение остановлено и запущено заново:
  страница снова открылась на `/circles` из APK, сохранённые круги на месте,
  у серверов подпись «не отвечает». Экрана оболочки «Сервер не отвечает» нет —
  это и есть ожидаемое поведение вшитого клиента. Сессии и снимки не потеряны.
- **Режим по умолчанию.** Установлен APK без флага: в logcat нет
  `embedded ui`, страница открылась с сервера, данные те же.
- **Граница.** На loopback-стенде `app.html` сам снимает Service Worker
  (`127.0.0.1`), поэтому работа вшитого воркера на HTTPS здесь не проверена;
  офлайн-кадр доказан вшитыми файлами и IndexedDB, без воркера. Во время
  съёмки экрана OPPO перехватывал Firefox (чужая сессия), поэтому кадры не
  использовались; доказательства — logcat и DOM через CDP отладочного APK.

## Осталось

1. Стабилизация интерфейса (решение владельца).
2. Переключение вшитого по умолчанию: роль в «Настройки → Приложение →
   Интерфейс», откат на серверный, судьба данных при смене режима, кадры и
   приёмка.
3. После переключения — подача F-Droid (план 67).
4. Повтор на HTTPS-сервере (вшитый Service Worker), realme 8 и Android 13+.
5. CI-сторож в GitHub на этом дереве не прогонялся.

## Повтор

```powershell
.\scripts\build-android.ps1 -ServerUrl 'http://127.0.0.1:7676' -EmbeddedUi
# APK: android\app\build\outputs\apk\standard\debug\app-standard-debug.apk
# без флага — обычная сборка, клиент в APK не попадает
```

подключения — из [протокола C123](../testing/phone-c123-2026-11-23/README.md).
