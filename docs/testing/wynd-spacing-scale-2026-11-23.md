# Wynd UI · лесенка вертикальных зазоров

23 ноября 2026. Задача [C120](../plans/46-open-questions-and-debt.plan.md#c120)
(решение владельца 23.11: зазоры по всем продуктам, формат — лесенка, как у
[высот шапок](wynd-header-scale-2026-11-19.md)). Ниже — замеры, лесенка,
ведомость «экран → зазор между блоками» и порядок внедрения.

## Лесенка

| Шаг, CSS px | Роль |
| ---: | --- |
| 4 | Части одного блока: заголовок → подзаголовок; подпись → своё поле; заголовок плашки → её текст. |
| 8 | Соседние блоки раздела, действие или пояснение к блоку: рамка → «подробнее»; плашка → плашка; поле → следующая подпись; ряд строк → галочка. |
| 16 | Новая роль, содержимое раздела или крупный раздел: подзаголовок → содержимое; содержимое → ряд действий; поля окна сверху и снизу. |

**Одно место.** Шаги заданы в `web/src/lib/styles/tokens.css` переменными
`--sp-1 … --sp-3`. Продукты импортируют этот файл (клиент, Мастерская,
«Подпись», Настольный), поэтому лесенка одна на всех. Разовые значения
`margin-top`/`margin-bottom` в размеченных файлах заменяются на
`var(--sp-N)`.

**Сторож.** `web/scripts/check-spacing.mjs` входит в `npm run check:ui` и
падает, если в размеченных файлах появляется вертикальный зазор вне
лесенки 4/8/16. Допустимы `0`, `auto`, оптический сдвиг до 2 px, `−1 px` нахлёста
рамки и явно перечисленные исключения (центровка приветствия, абзац сырого
вывода в `em`). Пока список файлов — Мастерская и общие стили окна;
следующие шаги добавляют клиент и Настольный.

**Приёмка группами по типу (владелец 23.11: «Можно я не буду дальше
принимать однотипные пары? Показывай только те, где реально другая
компоновка экрана»).** Однотипные варианты одного экрана (пульт работающий
и остановленный, формы плана обновления/бэкапа) отдельно не показываются:
они покрыты правилом и принятым представителем. На приёмку выносятся только
экраны с действительно другой компоновкой — по одному представителю типа.
