# C71 — продолжение после отклонения двух макетов

Дата: 2026-11-05. Цель — получить настоящий снимок изменения на утверждённой основе, без ручной перерисовки.

## Изменение исходника

Основа: `docs/visual/workshop-servers.fragment.html`, кадр `7в`, утверждённая компоновка от 3 ноября, SHA закреплён в `workshop-review-baselines.json`.

`node docs/visual/update-workshop-build-frame.mjs` получает первый C71 прямым преобразованием 7в. Оболочка, заголовок «Обновляем», разметка пяти строк, интервалы и нижняя панель не перевёрстаны. Меняются содержимое/состояния шагов; в текущую строку добавляются последняя строка сборки и время сообщения существующими классами `mono` и `dim`. Неизвестный процент не показывается. Действие раскрытия журнала остаётся в нижней панели. Для самого журнала использована существующая область вывода кадра 2е; новых визуальных стилей нет.

Смысл принят ранее. Новый первый кадр остаётся `draft`; другие два кадра ещё не пересобраны по этой основе и не предлагаются на утверждение.

Проверки исходника прошли: пять тестов сторожа, общий просмотр 80 кадров, раскрытие/сворачивание журнала без перехода, неизменность остальных 79 кадров, сохранение заголовка, стилей строк и примечания нижней панели. Проверка форматирования прошла. Эти результаты не являются визуальной приёмкой.

## Рендер: не принят

Инструмент Browser Use ранее отклонил локальный `file://` по политике URL и запретил обход. Повтор через другой браузерный маршрут не выполнялся.

Проверена безопасная альтернатива без браузерного действия: офлайн HTML/CSS-движок [WeasyPrint](https://doc.courtbouillon.org/weasyprint/latest/first_steps.html#windows), официальный Windows onedir [v70.0](https://github.com/Kozea/WeasyPrint/releases/tag/v70.0). Архив проверен по опубликованному API SHA-256 `ab1151f210b4e6bb7aa7a79e91a67e8ddb760094c107bfda55241b6aaefe7d53`; программа находится только в игнорируемом `dev/weasyprint-70`, в продукт и CI не добавлена.

Самодостаточные HTML эталона и C71 подготовлены из настоящих исходников при одинаковой ширине 1024 px и существующей светлой палитре; ресурсных сетевых запросов нет. Команда `weasyprint --media-type screen` создала PDF; страницы преобразованы в PNG через PDFium без ручного рисования элементов. Результаты и журналы оставлены в `dev/workshop-render`.

Вариант с `--pdf-forms` аварийно завершился в движке. Без него рендер получен, но при осмотре **самого неизменённого эталона** обнаружены искажения: кнопки и строки списка серверов наложились, элементы управления изменили геометрию, нижняя панель не отобразилась. Движок также сообщил о неподдерживаемых `accent-color` и media-условиях. Этот рендер не является достоверной проверкой UI и не отправляется владельцу как готовый кадр.

## Что требуется дальше

Для визуальной приёмки нужен разрешённый рендер в полноценном браузере/WebView с исходным и новым кадрами при одинаковом размере, масштабе и теме. Пока такой снимок не получен, нельзя считать визуальную часть завершённой, переиспользовать отвергнутые картинки или подменять рендер ручной иллюстрацией. Независимые проверки исходника не заменяют эту приёмку.
