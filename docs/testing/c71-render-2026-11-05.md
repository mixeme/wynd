# C71 — продолжение после отклонения двух макетов

Дата: 2026-11-05. Цель — получить настоящий снимок изменения на утверждённой основе, без ручной перерисовки.

## Изменение исходника

Основа: `docs/visual/workshop-servers.fragment.html`, кадр `7в`, утверждённая компоновка от 3 ноября, SHA закреплён в `workshop-review-baselines.json`.

`node docs/visual/update-workshop-build-frame.mjs` получает первый C71 прямым преобразованием 7в. Оболочка, заголовок «Обновляем», разметка пяти строк, интервалы и нижняя панель не перевёрстаны. Меняются содержимое/состояния шагов; в текущую строку добавляются последняя строка сборки и время сообщения существующими классами `mono` и `dim`. Неизвестный процент не показывается. Действие раскрытия журнала остаётся в нижней панели. Для самого журнала использована существующая область вывода кадра 2е; новых визуальных стилей нет.

Смысл принят ранее. Новый первый кадр остаётся `draft`; другие два кадра ещё не пересобраны по этой основе и не предлагаются на утверждение.

Проверки исходника прошли: пять тестов сторожа, общий просмотр 80 кадров, раскрытие/сворачивание журнала без перехода, неизменность остальных 79 кадров, сохранение заголовка, стилей строк и примечания нижней панели. Проверка форматирования прошла. Эти результаты не являются визуальной приёмкой.

## Рендер: не принят

Инструмент Browser Use ранее отклонил локальный `file://` по политике URL и запретил обход. Повтор через другой браузерный маршрут не выполнялся.

Проверена безопасная альтернатива без браузерного действия: офлайн HTML/CSS-движок [WeasyPrint](https://doc.courtbouillon.org/weasyprint/latest/first_steps.html#windows), официальный Windows onedir [v70.0](https://github.com/Kozea/WeasyPrint/releases/tag/v70.0). Архив проверен по опубликованному API SHA-256 `ab1151f210b4e6bb7aa7a79e91a67e8ddb760094c107bfda55241b6aaefe7d53`; программа находится только в игнорируемом `dev/weasyprint-70`, в продукт и CI не добавлена.

Самодостаточные HTML эталона и C71 подготовлены из настоящих исходников при одинаковой ширине 1024 px и существующей светлой палитре; ресурсных сетевых запросов нет. Команда `weasyprint --media-type screen` создала PDF; страницы преобразованы в PNG через PDFium без ручного рисования элементов. Результаты и журналы оставлены в `dev/workshop-render`.

Вариант с `--pdf-forms` аварийно завершился в движке. Без него рендер получен, но при осмотре **самого неизменённого эталона** обнаружены искажения: кнопки и строки списка серверов наложились, элементы управления изменили геометрию, нижняя панель не отобразилась. Движок также сообщил о неподдерживаемых `accent-color` и media-условиях. Этот рендер не является достоверной проверкой UI и не отправляется владельцу как готовый кадр.

## Что требуется дальше

Для визуальной приёмки нужен разрешённый рендер в полноценном браузере/WebView с исходным и новым кадрами при одинаковом размере, масштабе и теме. Пока такой снимок не получен, нельзя считать визуальную часть завершённой, переиспользовать отвергнутые картинки или подменять рендер ручной иллюстрацией. Независимые проверки исходника не заменяют эту приёмку.

## Вторая сессия: офлайн-рендер Prince 17

Прямой вызов Browser Use с `file:///D:/Local/Git/wynd/docs/visual/installer.html#c71` снова отклонён: разрешены только HTTP/HTTPS, инструмент явно запретил обходные маршруты. HTTP-просмотр в этой сессии не проверялся. Это не доказательство неисправности HTTP или недоступности браузера вообще. В истории согласования 3 ноября найден работающий HTTP-предпросмотр на `127.0.0.1:5196`, который ассистент запускал самостоятельно.

Независимая альтернатива без браузерного действия — офлайн HTML/CSS-движок [Prince 17](https://www.princexml.com/download/17/). Официальный переносимый ZIP сохранён только в игнорируемом `dev/prince-17`; SHA-256 загруженного архива `db01cd5c4906ac3fc7ab873639bc63b7963c2946835b2321652fa509ccdc8851`. В зависимости продукта и CI не добавлен. Рендер запущен с `--no-network`, JavaScript выключен; исходник не отправлялся в сеть. Метка бесплатной версии сохранена в верхнем поле, за пределами макета.

Воспроизведение из корня репозитория:

```powershell
node docs/visual/render-workshop-offline.mjs dev/prince-17/unpacked/prince-17-win64/bin/prince.exe dev/workshop-prince-review
```

Скрипт извлекает кадры `7в` и `c71-build` и общие стили непосредственно из `docs/visual/workshop-servers.fragment.html`. HTML кадров не меняет; для фиксированной светлой темы выбирает первую ветку существующих `light-dark()`. Размер страницы 1024×700 px, сверху служебное поле 50 px; сам макет имеет ширину 1024 px и высоту 650 px. Масштаб 96 dpi, 1 CSS px = 1 пикселю PNG. Размер необходимо передать и через CLI: одного `@page` недостаточно для правильной оценки media queries в Prince.

Основа: кадр `7в`, утверждённый коммит `b827aff8`; кандидат `c71-build` из `c5a98dff`; состояние исходника при рендере — `0e89c96e`. Контрольные суммы, команды и версия движка — [source.json](../visual/reviews/c71-offline-2026-11-05/source.json). Изображения: [исходный 7в](../visual/reviews/c71-offline-2026-11-05/baseline-7v-1.png) и [C71.1](../visual/reviews/c71-offline-2026-11-05/c71-build-1.png).

Оба PNG осмотрены при одинаковых размерах. Список серверов слева, шапка, навигация, блок соединения и нижняя панель отображаются без наложения. В кандидате сохранены заголовок «Обновляем» и пять строк; текущая строка содержит вывод и время сообщения, неизвестный процент отсутствует. Основное отличие от 7в — содержимое и состояние шагов, а также подпись раскрытия журнала. Эти изображения получены растеризацией HTML движком, без ручного рисования.

Границы: это **офлайн-рендер**, а не снимок браузера или WebView приложения. Пиксельное совпадение с WebView, нативный вид checkbox, интерактивное раскрытие и другие кадры C71 этим прогоном не подтверждены. Статус `draft` сохранён; нового решения владельца о вёрстке пока нет. Изображение можно использовать для обсуждения текущего исходника, но нельзя выдавать за завершённую браузерную проверку.

Диагностическая поправка UA-стилей WeasyPrint убрала наложение кнопок, но не восстановила нижнюю панель. Результат не используется для приёмки; UA-файл восстановлен из копии.

Ответ владельца после показа C71.1: «Плохо.» Показанный вариант отклонён; точная причина пока не сообщена. В реестре для `c71-build` установлен `rejected`. Офлайн-рендер сохранён как история отклонённой попытки, использовать его как утверждённую основу нельзя. Согласие со смыслом C71 не отменено.

Уточнение владельца: «Например, галочка». Подтверждён дефект движка: в поставляемом `style/html.css` Prince для `input[type="checkbox"][checked]` задан `content: "\2713"`; браузерный контрол заменяется текстовым знаком в рамке. В Wynd сохранены исходные `width/height:16px`, `margin:2px 0 0`, `accent-color:var(--c)`. Таким образом, неизменность HTML не обеспечила соответствия оформления. **Эти Prince-изображения непригодны для утверждения вёрстки.** Изменять утверждённый checkbox или дорисовывать его в PNG ради исправления рендера нельзя. Галочка названа как пример, остальные элементы не считаются принятыми.

## Возврат к браузеру: HTTP-предпросмотр восстановлен

Владелец поручил: «Вернись к варианту с браузером». Для штатного HTTP-предпросмотра подготовлен `docs/visual/serve-workshop-review.mjs`: сервер слушает только `127.0.0.1`, отдаёт два заранее извлечённых кадра из памяти (`/` — C71.1, `/baseline` — 7в), без просмотра файловой системы. Общие стили и HTML кадров взяты из текущего fragment без изменения; оболочка просмотра фиксирует светлую тему и ширину 1024 px. CSP запрещает внешние ресурсы и сетевые подключения из страницы. Внешний доступ к серверу не открыт.

Команда: `node docs/visual/serve-workshop-review.mjs 5197`. Порт 5196 был занят; другой процесс не останавливался. На 5197 HTTP 200 подтверждён. Первое открытие через `cua.createBrowserTab` завершилось таймаутом attach; после чтения штатной диагностики вкладка успешно открыта через документированные `browser.tabs.new()` и `tab.goto()` в том же выбранном IAB. Отказа URL-политики для этого HTTP-предпросмотра не было. Прежние утверждения о недоступности браузерного рендера вообще были чрезмерными.

Получены настоящие JPEG браузера: [7в](../visual/reviews/c71-browser-2026-11-05/baseline-7v.jpg), [C71.1](../visual/reviews/c71-browser-2026-11-05/c71-build.jpg). Исходное состояние репозитория — `7dc8ec5f`; HTML/CSS кадров по-прежнему из `c5a98dff`, утверждённая основа 7в — `b827aff8`. SHA исходника и каждого кадра прочитан из DOM страницы и сохранён вместе с геометрией в [geometry.json](../visual/reviews/c71-browser-2026-11-05/geometry.json).

Параметры обоих снимков: viewport 1024×760, devicePixelRatio 1, макет 1024×650, светлая тема, масштаб 100%. После снимков временный override viewport сброшен. Оба изображения осмотрены. Шапка, навигация, список слева, типографика, блок соединения, отступы и нижняя панель совпадают с исходной основой; переноса/наложения основных действий нет. Галочка нативная (`appearance:auto`, 16×16), акцент `rgb(175,88,57)`, её координаты совпадают с 7в. Геометрия всех семи сопоставленных областей также совпадает; это дополнительная проверка, а не замена осмотру снимков.

На C71.1 браузерным кликом проверено раскрытие и сворачивание полного вывода: ID кадра сохраняется, `aria-expanded` и видимость журнала меняются. Вывод подставной, Docker и SSH не запускались. Эта проверка касается макета, не реализации приложения.

Теперь первый C71 можно обсуждать по настоящему браузерному снимку. Предыдущее отклонение офлайн-варианта остаётся в истории; нового утверждения владельца пока нет. Остальные C71 не считаются принятыми.

## Выделение выполняемого этапа

После браузерного показа владелец попросил: «Выделить выполняемый этап. Сейчас выглядит, как пояснение». Основа оформления остаётся 7в из `b827aff8`; минимальная правка сделана в браузерном кандидате `c71-build`, показанном в `ed30fe54`.

Меняется только название текущего шага: «Собираем образ Wynd» обёрнуто в `strong.w` с существующими стилями (вес 500, цвет `--warn`, тот же, что у значка шага). Строка помечена `aria-current="step"`. Вывод команды и время сообщения остаются прежними. Общие стили, размеры и компоновка не изменены. Правка внесена в воспроизводимый генератор, fragment и галерею.

Рендер: тот же встроенный браузер, `http://127.0.0.1:5198/`, сервер `node docs/visual/serve-workshop-review.mjs 5198`; 1024×760, devicePixelRatio 1, светлая тема, масштаб 100%. [Новый снимок](../visual/reviews/c71-browser-2026-11-05/c71-active-stage.jpg) осмотрен и сопоставлен с [предыдущим C71.1](../visual/reviews/c71-browser-2026-11-05/c71-build.jpg) при тех же параметрах. Название текущего шага стало плотнее и выделено цветом; команда и время остались приглушёнными. Положение шапки, навигации, списка, блока подключения, нижней панели и пяти строк совпадает. SHA исходника и кадра, параметры и сравнение геометрии — [active-stage-geometry.json](../visual/reviews/c71-browser-2026-11-05/active-stage-geometry.json).

Во время проверки прежняя сессия управления возвращала `browser.user is unavailable`; документированный сброс сессии и повторное подключение к той же вкладке восстановили работу. Это не было отказом URL-политики. Проверка геометрии дополняет осмотр изображений. Статус нового варианта — `draft`, решение владельца по этой правке ещё ожидается; смысл C71 принят ранее.
