# Кадры «Войти по QR-коду» на стартовых экранах обёрток (план 72, этап 4) — 26 ноября 2026

Владелец принял кадры 26.11 словом «Принимаем» — после правок «поставить первой
ссылкой… может быть кнопкой», «Это неправильный кадр… ссылка про QR-код имеет
смысл на самом первом экране, где ничего не ввели» и «нужна ремарка, что в поле
можно вставить эту ссылку… поставить ремарку под кнопку про код».

## Принято

- **Место QR-входа — стартовые экраны обёрток**, где адрес не введён; из
  web-логина строка убрана (`76aefbe9`): в PWA сервер всегда известен.
- **Окно, «Войти в Wynd»:** «Дальше» → «Фото с QR-кодом» → ремарка «Ссылку из
  QR-кода можно вставить прямо в поле». Камера в окне не гарантирована — вход
  по фото кода; чужой сервер из кода окно принимает (переключается).
- **Android, стартовый экран:** «Дальше» → «Сканировать QR-код» → «Фото с
  QR-кодом» → та же ремарка. Кнопки существовали — изменено поведение:
  скан/вставка строки `https://сервер/?email=почта` даёт адрес и почту,
  проверку и вход с подставленной почтой одним действием; адрес не вводится.
- **Вставка ссылки в поле — то же, что скан** (`d73286d5`): общий разбор
  `loginLinkTarget` в `$lib/auth/links` (14 тестов).

## Коммиты

- `68ad7543` — Android: `StartupTarget` принимает `/?email=` (один параметр,
  почта по шаблону), мост `open` передаёт почту, страница разбирает QR и
  вставляет ссылку; Java-тесты 8/8 (3 новых класса), web-тесты моста 6/6.
- `9d1172b8` — окно: «Фото с QR-кодом» на «Войти в Wynd» (окно проверяет
  сервер, Go `CheckServer` сам сохраняет и переключает прокси).
- `d73286d5`, `ac64b000` — вставка ссылки в поле (обе обёртки) и ремарка под
  кнопкой QR-кода.
