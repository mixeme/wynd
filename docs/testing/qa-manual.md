# Wynd — инструкция для тестировщика

Версия продукта указана в имени архива (`wynd-qa-X.Y.Z.zip`). Инструкция написана для **0.9.0**; что изменилось с прошлого прогона (0.3.1) — раздел [«Что нового с 0.3.1»](#что-нового-с-031).

## Содержимое архива

Структура совпадает с репозиторием разработки:

```
распакованная папка/
  scripts/run.bat          ← единственный файл, который вы запускаете
  scripts/binary-stale.ps1 ← служебный; не запускать
  dist/wynd.exe            ← сервер и веб-клиент
  dev/data/                ← каталог данных (пустой до первого запуска)
  qa-manual.md             ← эта инструкция
```

| Файл | Нужно ли вам |
|------|----------------|
| `scripts\run.bat` | **Да** — запуск и остановка сервера |
| `scripts\binary-stale.ps1` | **Нет** — вспомогательный скрипт для `run.bat`; проверяет, не устарел ли `dist\wynd.exe`. Запускать отдельно не нужно |
| `dist\wynd.exe` | **Нет** — стартует через `run.bat` |
| `dev\data\` | **Нет** — создаётся и наполняется сервером автоматически |
| `qa-manual.md` | Справочник |

После первого запуска в `dev\data\` появятся база и файлы — каталог **не удаляйте** между прогонами, если нужно сохранить состояние сервера.

## Запуск и остановка

1. Распакуйте архив в любую папку (путь без кириллицы предпочтительнее).
2. Запустите **`scripts\run.bat`** (из корня распакованной папки или двойным щелчком). Другие файлы в `scripts\` трогать не нужно.
3. Откроется окно консоли и браузер. Пока администратор не создан — сразу
   экран первого запуска (`/admin/bootstrap`). После настройки — главная.
4. **С телефона:** сервер доступен и из локальной сети — адреса вида `http://192.168.…:7676/` напечатаны в окне консоли. Телефон должен быть в той же Wi-Fi-сети; если Windows спросит про брандмауэр, разрешите доступ для `wynd.exe`. Только для этого компьютера — `scripts\run.bat local`.
5. **Остановка:** закройте окно консоли или нажмите Ctrl+C.

Проверка, что сервер жив (необязательно):

```bat
curl http://127.0.0.1:7676/health
```

Ожидается ответ `{"status":"ok"}`.

## Где хранятся данные

Все данные инстанса лежат в каталоге **`dev\data\`** (как при локальной разработке):

| Путь | Содержимое |
|------|------------|
| `dev\data\wynd.db` | База SQLite |
| `dev\data\blobs\` | Медиафайлы |
| `dev\data\keys\` | Ключи (в т.ч. токен bootstrap) |
| `dev\data\config.json` | Адрес и порт (создаётся автоматически) |
| `dev\data\dev-auth-codes.log` | Коды входа участников (см. ниже) |

**Чистый старт:** удалите каталог `dev\data\` целиком и снова запустите `scripts\run.bat`.

## Первый запуск (bootstrap)

При первом запуске сервер ещё не настроен. Нужно один раз создать администратора.

1. Запустите `scripts\run.bat`.
2. В консоли появится блок **«Первый запуск»** и ссылка вида  
   `http://127.0.0.1:7676/admin/bootstrap?token=...`  
   Браузер откроет её сам.
3. На экране bootstrap задайте:
   - **пароль администратора** (минимум 8 символов) — обязателен, только для панели, это не почта участника;
   - **имя сервера** — можно пустым, задать позже в «Общие»;
   - **адрес** (`public_url`, на loopback можно оставить пустым);
   - **SMTP** как на экране почты (хост, порт, логин, пароль, From) — на loopback поля можно пустыми, в том числе частично; иначе обязательны. Кнопка «Проверить подключение» проверяет релей до сохранения; при сохранении проверочное письмо уйдёт на адрес «От кого», в том числе на loopback, если релей задан.
4. После сохранения откроется раздел «Проверка» панели администратора.

Если bootstrap не завершён, следующий `run.bat` снова откроет тот же мастер. Токен также лежит в файле `dev\data\keys\bootstrap`.

## Панель администратора

| Что | Адрес |
|-----|-------|
| Вход в панель | `http://127.0.0.1:7676/admin/login` |
| Главная панели (хранилище) | `http://127.0.0.1:7676/admin` |
| Доступ и приглашения | `/admin/access` |
| Общие | `/admin/general` |
| Люди | `/admin/people` |
| Проверка сервера | `/admin/check` |
| Исправить (подсказки к проверке) | `/admin/fix` |
| Сжатие медиа | `/admin/compress` |
| Оплата | `/admin/pay` |

Пароль — тот, что задан при bootstrap. Панель **не показывает** журналы кругов; это отдельная сессия от участника.

Участники заходят через **`http://127.0.0.1:7676/`** (экран «Войти»), не через `/admin`.

## Регистрация и вход пользователей

По умолчанию режим регистрации — **«По приглашению»**. Сменить можно в панели: **Доступ** (`/admin/access`).

| Режим | Как завести участника |
|-------|------------------------|
| **По приглашению** (умолч.) | В «Доступ» создать ссылку приглашения → открыть `/join/{token}` → указать почту → код → имя в круге (если ссылка на круг) |
| **Открытый** | На главной `/` или `/join` — почта и код без серверного инвайта |
| **Закрытый** | Новые участники только через приглашение **в круг** (ссылка из настроек круга) |

Типовой сценарий для тестов:

1. В `/admin/access` переключите режим на **«Открытый»** (если нужна простая регистрация без инвайта).
2. Либо создайте **ссылку приглашения на сервер** и откройте её в другом браузере / профиле (имитация второго человека).
3. Укажите почту → на экране `/auth/code` введите код (см. ниже).
4. Создайте круг, пригласите второго участника ссылкой из настроек круга — проверьте ленту у обоих.

Для двух «людей» удобно: обычное окно браузера + **InPrivate / гостевой профиль**, либо другой браузер.

## Где брать коды входа

На локальном запуске (`127.0.0.1`) **SMTP не нужен**. Коды не приходят на почту. Экран `/auth/code` заголовок «Код с сервера», текст: письмо не уходит, код в окне сервера.

Источники кода (шесть цифр):

1. **Файл** `dev\data\dev-auth-codes.log` — каждая строка: время и `auth code for email@example.com: 123456`.
2. **Окно консоли** `scripts\run.bat` — те же строки `auth code for ...` в логе сервера.

Код действует **15 минут**, не более **3** неверных попыток.

## С телефона

С 0.9.0 сервер из архива доступен в локальной сети: телефон — удобный второй участник и настоящая камера.

1. Телефон и компьютер — в одной Wi-Fi-сети.
2. Откройте на телефоне адрес из окна консоли (`http://192.168.…:7676/`). Если не открывается — проверьте, что Windows разрешила `wynd.exe` в брандмауэре (запрос появляется при первом запуске), и попробуйте другой адрес из списка.
3. Код входа для учётки на телефоне — там же, в окне консоли или в `dev\data\dev-auth-codes.log`.

На телефоне обязательно проверить: запись с фото **с камеры** и из галереи, видео, копирование ссылки-приглашения, создание группы кругов, ленту и обсуждение вдвоём с компьютером. До 0.9.0 по такому адресу фото не загружались и ссылки не копировались — это исправлено, любой отказ здесь — дефект.

Приглашение, созданное на телефоне, ведёт на адрес `http://192.168.…` — его можно открыть на компьютере так же.

## Что не входит в этот прогон

**Не проверяем** как дефект:

- отправку писем через SMTP (если не настроен);
- Web Push, установку приложения на экран (PWA) и открытие приложения без сети **после перезагрузки страницы**: на локальном запуске service worker не включается (на `127.0.0.1` — намеренно, на `http://192.168.…` браузер не даёт его без HTTPS). Очередь черновиков без сети в открытой вкладке (сценарий «Офлайн») работает и на компьютере, и на телефоне;
- HTTPS, прокси, systemd, Docker.

Эти темы — отдельные сценарии деплоя.

## Что нового с 0.3.1

Прошлый прогон был на 0.3.1. С тех пор интерфейс перерисован по макетам почти целиком, появились новые экраны, сервер прошёл аудит безопасности. Поэтому нужен **полный прогон** по всем сценариям ниже, а не только по списку изменений.

**Данные прошлого прогона.** Распакуйте архив в **новую папку** и начните с чистого `dev\data\`. Старые данные не переносите: с 0.3.1 база поменялась много раз.

### Появилось с 0.3.1

- **Телефон в локальной сети** — раздел «С телефона» выше.
- **Первый запуск** — три карточки: пароль панели, имя и адрес, почта; почту и имя можно отложить.
- **Панель по разделам:** Проверка, Исправить, Общие, Доступ, Люди, Хранилище, Сжатие, Оплата. Пароль, имя, адрес и почта — в «Общие».
- **Приглашения:** на сервер (с карточкой сервера и «позвал {имя}»), в круг, личные; «Позвать из других кругов»; живые ссылки круга — список, скопировать, отозвать; какие виды ссылок разрешены — в настройках круга.
- **Улочка `/circles`:** группы кругов (меню плюса), дневник — круг на одного, выбор сервера при нескольких учётках.
- **Запись:** правка вложений и «Отнести к дате», пока живо окно правок; упоминания `@`; видео сжимается на телефоне или компьютере перед отправкой.
- **Обсуждение и просмотр:** реакции, альбом записи, полноэкранный просмотр со скачиванием.
- **Поиск:** в круге — поле в цветной шапке, фильтры «период», «с фото», «с местом», автор; общий поиск `/search` — по всем кругам.
- **Квота и архив круга:** график по месяцам, линия отсечки перетаскивается, «Попросить место», «Архив и очистка», скачивание архива.
- **Уход из круга** «Совсем» или «Читать, не писать»; передача владения; удаление круга диалогом с цифрами.
- **Уведомления круга:** что присылать и «Приглушить» до завтра или на неделю.
- **Оплата** (если включить в панели): подписка или донат, заявка со скриншотом, продление, выдача срока админом.

### Исправлено недавно — проверить особо

#### Запись и очередь

- [ ] Текст новой записи не пропадает: набрать текст, открыть камеру (на телефоне) или перезагрузить вкладку — текст вернулся; после публикации окно пустое.
- [ ] Больше 5 вложений к записи не прикрепить. Слишком большой файл отсекается до отправки — с именем файла и пределом.
- [ ] Быстрый двойной тап по «Отправить» и по реакции не создаёт две записи или две реакции.
- [ ] Удаление черновика из очереди спрашивает подтверждение.
- [ ] Черновики, отправленные при остановленном сервере, после его запуска уходят без дублей.

#### Лента, обсуждение, поиск

- [ ] Полноэкранный просмотр: скачиваются и фото, и видео из альбома; снимок не обрезается.
- [ ] Лист реакций закрывается системной «назад» (Android) и не уводит с экрана.
- [ ] `@имя` дважды в тексте и два участника с одним именем не роняют ленту.
- [ ] Поиск по нескольким словам: «море дача» находит «море и лето на даче». Поиск не показывает комментарии и записи, которых участник не видит.

#### Круг и участники

- [ ] Покинул круг с «Читать, не писать»: видит прошлое только для чтения — нет «Напишите первым», «Пригласить», «сменить» у обложки дня, нет плюса реакций; прямые ссылки на выбор обложки и имя в круге возвращают назад.
- [ ] Владелец может исключить того, кто ушёл с «Читать, не писать».
- [ ] Исключённый участник не может править и удалять своё; его ссылки-приглашения перестают работать.
- [ ] Приглушённый круг («Уведомления круга» → «Приглушить»: до завтра / на неделю) молчит до срока; упоминание пробивается.
- [ ] Группа кругов на `/circles` (меню плюса): создать, переименовать, свернуть, удалить — в том числе с телефона.
- [ ] Числа склоняются: «ещё 3 ваших круга» на выборе сервера нового круга, «останется ~21 запись» на экране квоты.

#### Архив и квота

- [ ] «Архив и очистка» (`/circles/{id}/archive`) открывается и у круга без фото.
- [ ] Архив круга скачивается; в оглавлении кириллица без «�», названия дней на месте; прерванное скачивание можно продолжить.
- [ ] Срок архивации нельзя поставить раньше завтрашнего дня.
- [ ] Ползунок отсечки двигается стрелками, PageUp/PageDown, Home/End.

#### Клавиатура и окна

- [ ] Диалоги и листы (в том числе кадр аватара и меню плюса): фокус внутри, Tab не уходит под затемнение, Escape закрывает только верхнее окно, фокус возвращается на кнопку, которая открыла.

#### Панель

- [ ] «Выйти» из панели действительно выходит: после выхода старая вкладка панели требует пароль.
- [ ] `/admin/fix` показывает заголовки прокси и адрес клиента (не прочерки).
- [ ] `/admin/check` на локальном запуске: строки HTTPS, домен и сертификат — «не применимо», без красного.
- [ ] Оплата: двойное «продлить» не продлевает дважды; отклонённый скриншот нельзя приложить снова.

## Пользовательские сценарии

Отмечайте ✓ / ✗ и краткий комментарий при сбое.

### Вход и профиль

- [ ] Bootstrap → вход в панель по паролю.
- [ ] Регистрация участника (открытый режим или серверный инвайт).
- [ ] Повторный вход по той же почте (код из лога).
- [ ] Смена имени и аватара в профиле круга (кадр аватара, «Готово»).

### Круги

- [ ] Создание круга, список кругов `/circles`; при нескольких учётках — выбор сервера на `/circles/new/server`.
- [ ] Приглашение в круг — второй участник по ссылке, выбор имени.
- [ ] «Позвать из других кругов»: кнопка на экране пригласить, если есть люди в других кругах; позванный видит 1.3 и не появляется в участниках, пока не выберет имя.
- [ ] Настройки круга: название, цвет, окно правок, участники; чипы «какие ссылки можно создать» — при «Одноразовые» на экране пригласить нет вида и лимита 5/10/25.
- [ ] Удаление круга: диалог поверх настроек, цифры с сервера, набор сохранённого имени.
- [ ] «Покинуть круг»: «Совсем» или «Читать, не писать»; владельцу сначала предлагается передать владение.
- [ ] Квота круга (`/circles/{id}/quota`): «Попросить место», запрос виден админу на карточке круга.

### Лента и записи

- [ ] Новая запись с текстом и фото (`/circles/{id}/compose`).
- [ ] Лента у автора и у второго участника (sync).
- [ ] Обсуждение записи: комментарии, реакции (сердце / смех / удивление / злость).
- [ ] Редактирование своей записи в окне правок.
- [ ] Удаление своей записи / комментария.

### Дни, сетка, поиск

- [ ] Вкладка «Дни», карточка дня, обложка дня.
- [ ] Сетка фото, карта (если есть гео), поиск по кругу (поле в цветной шапке).
- [ ] Архив: подписи `/media` и `index.html` со счётчиками.

### Офлайн

- [ ] При остановленном сервере **или** живой сети без ответа сервера — черновик в очереди; после запуска — отправка и появление в ленте.

### Настройки приложения

- [ ] `/settings`, `/settings/app` — тема, три умолчания уведомлений (новые записи, комментарии к моим, реакции), не полный набор круга.
- [ ] `/settings/servers` — «N кругов · вошли {дата}» после входа на этом устройстве.

## Админские сценарии

Панель: `/admin` после входа по паролю.

### Хранилище (`/admin`)

- [ ] Чипы умолчания квоты: Нет / 5 ГБ / 10 ГБ / Своё.
- [ ] Карточка круга (`?circle={id}`): своя квота, pending-запросы — «Дать» / «Отказать».

### Доступ (`/admin/access`)

- [ ] Смена режима регистрации (открытый / по приглашению / закрытый).
- [ ] Создание серверного инвайта, QR, копирование ссылки.
- [ ] TTL ссылки: 1 ч / 72 ч / неделя.

### Люди (`/admin/people`, `/admin/people/{id}`)

- [ ] Поиск по почте на клиенте.
- [ ] Карточка учётки: круги, блокировка входа; строка подписки (если шлюз включён) ведёт на выдачу срока.
- [ ] Удаление учётки без кругов; для владельца круга — отказ (409).

### Оплата (`/admin/pay`)

- [ ] Подписка: очередь заявок и таблица «На сервере»; выдать срок или «Бессрочно» без заявки.
- [ ] У участника без срока шлюз говорит «подписки ещё не было», не «закончилась сегодня».

### Проверка и общие (`/admin/check`, `/admin/general`)

- [ ] Страница проверки: заголовок считает только fail; на loopback HTTPS/прокси — «не применимо», не FAIL. Почта — одна строка (ушло / ошибка), без настройки релея.
- [ ] Общие: пароль панели, имя, адрес, SMTP и проверочное письмо.
- [ ] Потолок инстанса: ГБ или % диска, не оба; на карточке круга «Просят больше» скрыт.

### Сжатие (`/admin/compress`)

- [ ] Пороги фото (px, WebP q), видео (`p`, Мбит/с) и потолок вложения (МБ) сохраняются.
- [ ] Новая запись: выбранное видео сжимается на клиенте (hint прогресса); без WebCodecs уходит как есть.

## Сообщение об ошибке

При дефекте укажите:

1. Версию из имени архива.
2. Устройство и браузер; открыто на компьютере (`127.0.0.1`) или с телефона (`http://192.168.…`).
3. Шаги воспроизведения.
4. Ожидание и факт.
5. Скрин или текст из консоли / `dev-auth-codes.log` (без реальных паролей).
