Инструменты остались в репозитории: бенчмарк `BenchmarkQuotaCheck`/`BenchmarkQuotaParts` и `TestQuotaQueryPlans` в `internal/blob/quota_bench_test.go`; код проверки не менялся.

## Что проверяется

`CheckMediaQuota`, `CheckWriteQuota` и `ReserveWrite` выполняются перед каждой записью и каждым вложением. Внутри — до четырёх агрегатных выражений (`usedBytes`, `reservedBytes`, `circleUsedBytes`, `circleReservedBytes`) плюс точечные чтения настроек.

## Условия

Windows, Intel Core i3-6100U 2,3 ГГц (слабый ноутбучный CPU — числа консервативны), Go 1.27.3, `modernc.org/sqlite`, база в памяти ≈ тёплый кэш страниц реального файла (холодная — медленнее). Засев: 6 тыс. и 60 тыс. блобов (две трети с дедупликацией через `blob_contents`), по 3 фото на запись, 2 комментария на запись, треть комментариев с вложением, аватары, открытые сессии, живые и просроченные резервации. ANALYZE в проекте не выполняется — планы планировщика от объёма не зависят. Команды — в конце.

## Планы (EXPLAIN QUERY PLAN)

`TestQuotaQueryPlans`, полный вывод — `go test ./internal/blob -run TestQuotaQueryPlans -v`:

- **circleUsedBytes, подзапрос медиа записей** — образцовый: `SEARCH posts` по `idx_posts_circle_entry_date (circle_id=?)` → `post_media` по посту → `blobs` по ключу. Пропорционален кругу.
- **circleUsedBytes, подзапрос медиа комментариев — главный источник стоимости**: `SCAN blobs` — планировщик развернул соединение и перебирает **все блобы сервера**, для каждого ищет `comment_media` по `idx_comment_media_blob` и `comments` по ключу. Индекса `comments(circle_id)` нет, и на каждую проверку квоты одного круга приходится O(всех блобов сервера).
- **usedBytes**: полные сканы `blob_contents`, `circles`, `move_snapshots`, `move_snapshot_literals`; ветка дедупликации обходит `blobs` с временной B-деревиной для GROUP BY; `circle_archives` — по индексу.
- **reservedBytes**: `SCAN upload_sessions`, `SCAN blobs` (фильтр `pending` без индекса), резервации — по индексу.
- **circleReservedBytes**: индекс `quota_reservations_circle`, микросекунды — не трогать.

## Выводы

1. **Объединение агрегатных запросов выигрыша не даёт.** Накладной расход modernc/sqlite на запрос — микросекунды; вся стоимость — внутри планов, в полных сканах. Исходное предложение ревью закрыто отрицательно по замерам.
2. **Узкое место одно: circleUsedBytes (73–85 %)**, внутри него — инвертированный план подзапроса медиа комментариев: полный скан `blobs` ради одного круга.
3. **Цена растёт линейно по объёму всего сервера**, а не по кругу: 6 тыс. файлов — ~40–50 мс на каждую запись и вложение, 60 тыс. — ~0,4 с на слабом CPU. На тёплом кэше; холодный — медленнее.
4. Кэширование `usedBytes` не вводится (правило раздела 8 сохраняется).

## Что это значит

Реальная цель — не объединение, а индексы и форма подзапроса: `comments(circle_id)` (или переписать подзапрос медиа комментариев от `comments`), частичный индекс `blobs` по `pending`, возможно покрывающие для `blob_contents` и ветки GROUP BY. Это миграция схемы на рабочем пути — отдельное решение с владельцем; кандидаты перечислены выше, выигрыш проверяется повторным прогоном этих же бенчмарков.

Планы после миграции: `SEARCH cm USING INDEX idx_comments_circle (circle_id=?)` вместо `SCAN blobs`; `SCAN blobs USING COVERING INDEX idx_blobs_pending_size`; `SCAN blob_contents USING COVERING INDEX idx_blob_contents_size` — полный вывод прежней командой `TestQuotaQueryPlans -v`.

Цена записи: комментарий добавляет одну запись индекса; pending-индекс существует только на незавершённых загрузках; реестр содержимого — одна запись на дедупликацию. Отдельный замер записи не проводился: вклад индексов мал на фоне файлового ввода-вывода загрузки. Тест миграции — `TestQuotaIndexesMigration`; общие Go-ворота (`go test ./...`) зелёные.

## Воспроизведение

```
go test ./internal/blob -run '^$' -bench BenchmarkQuotaCheck -benchmem
go test ./internal/blob -run '^$' -bench BenchmarkQuotaParts -benchmem
go test ./internal/blob -run TestQuotaQueryPlans -v
```

Засев большого масштаба ~15 с: сотни тысяч строк уходят пакетными multi-row INSERT (пересечение границы modernc/sqlite на каждый Exec стоит слишком дорого). Тест планов использует малый засев (~2 с), чтобы не замедлять общие ворота; инвариант «копия запроса в тесте равна функции» проверяется по значению.
