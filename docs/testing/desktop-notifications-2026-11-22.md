# Настольный: механизм системных уведомлений — 22 ноября 2026

Функция 2 плана [66](../plans/66-desktop-functions.plan.md), шаг 1 — механизм. Кто и когда зовёт мост (шаг 2) — решение владельца, сюда не входит.

## Реализация

- Wails v3.1.0 системных уведомлений Windows не имеет (только iOS) — «иной механизм» по записи плана 46: toast через [go-toast](https://github.com/go-toast/toast) (MIT, в exe только окна; `go list -deps ./cmd/wynd` — сервер не затронут, лицензии сервера не меняются). Скрипт уведомления запускается скрытым PowerShell (`HideWindow: true`).
- **Идентичность** (`internal/desktop/notify_windows.go`): `EnsureToastIdentity` пишет `HKCU\Software\Classes\AppUserModelId\com.wynd.desktop` — DisplayName «Wynd Настольный» и IconUri; значок — крупнейший PNG-слой `build/windows/icon.ico`, извлекается как есть (`extractIconPNG`, все шесть слоёв значка — PNG) и пишется в `%AppData%\Wynd\desktop\toast-icon.png` только при изменении. По прецеденту автозапуска — права только HKCU; AUMID тот же, что у SingleInstance.
- **Правило показа** (`notify.go`): `ShouldNotify(visible, minimised)` — уведомлять, когда окно спрятано в трей или свёрнуто; на виду мост молчит. Мост `App.Notify(title, body)` в `cmd/wynd-desktop/main.go` применяет правило, `ShowToast` — механизм без правила (им пользуется живая проверка).
- **Охраняющие тесты** (`notify_test.go`): таблица ShouldNotify; `sanitizeToastText` — «]]>» не должна закрыть CDATA шаблона раньше времени; `extractIconPNG` на синтетическом ICO (крупный слой, не-PNG слой, мусор); охрана настоящего `icon.ico` — без PNG-слоя тест падает, значок уведомлений молча не потерять.

## Дальше (шаг 2 — решение владельца)

**Решение владельца 22.11 — вариант 3, оба потребителя** (вопрос «уведомления и Wails 3.2 — связанные?» разъяснён: v3.2.0 ещё не вышла — только nightly; механизм go-toast не ждёт её, при появлении нативного API ShowToast заменяется одной функцией):

- **«Вышла версия окна» — сделано 22.11.** Периодическая проверка в спрятанном окне (`runUpdateToasts`, каждые 6 ч — фронтенд спрашивает один раз при запуске) + toast при скрытии окна (`maybeNotifyUpdate` из «крестика» и хука WindowClosing): уведомление о найденной версии, которую человек мог пропустить у открытого окна. Текст — [NotifyUpdateText](../internal/desktop/selfupdate.go) «Вышла версия X / Откройте Wynd Настольный, чтобы обновиться.» (в строке полосы — «Вышла версия X»); дедуп по версии, охраняющий тест `TestNotifyUpdateText`.
- **Новые записи в кругах — сделано 22.11.** Правила новые не понадобились: сервер уже решает «кому можно» (`NotifyPrefAllows`, тишина, упоминания) в точках рассылки пуша (`internal/api/notify.go`) — тот же сигнал теперь уходит живой рамкой `event: notify` в открытый поток `/sync` адресата (`liveSignal`, реестр потоков в `Server`). Клиент (`web/src/lib/desktop/notify.ts`) показывает toast через `postMessage('wynd:notify')` → оболочка → `App.Notify`; тексты — те же, что у push (`push-sw.js`), паритет держит тест; пачка одного круга и типа — один toast за 10 с. В браузере моста нет — кадр игнорируется. Тесты: `TestSSENotifyFrameForNewPost` (участнику рамка с именем круга, автору — нет), `TestSSENotifyRespectsMute` (тишина глушит живой сигнал, sync остаётся), vitest клиента (тексты, дроссель, паритет, рамка → оболочка). Серверная рамка и клиентские тексты едут следующим серверным выпуском; потребность в новых правилах показа у владельца не возникла — правила уже есть в `NotifyPrefs`.
