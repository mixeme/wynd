# Toast «Новая запись в круге» — живая проверка (23.11.2026)

Проверка функции 2 плана 66 на настоящем окне и сервере 0.53.6:
[реестр §7](../pending-device-checks.md#7-рядом--не-телефон).

## Что проверялось

- Черновик **Настольного 0.4.4** — `dev/release-0.4.4/wynd-desktop.exe`,
  17 691 136 байт, SHA-256
  `7d43821d2019a340302add112b53cf3a1cc0254b1f8ee0fe33577fce3770c573`
  (совпадает с CI-черновиком `desktop-v0.4.4`).
- Сервер **0.53.6** — локальная сборка `go build ./cmd/wynd` из текущего дерева
  (`VERSION` 0.53.6), стенд `127.0.0.1:7684`, данные — копия `dev/data`
  (учётки `anya@example.com` и `bob@example.com`, общий круг «Семья»).
- Профиль окна изолирован: `APPDATA=dev/checks-desktop-20261123/appdata-toast`,
  сессия Ани положена в хранилище окна через `/__secrets/session`.
- Запись в «Семью» публиковал **второй участник (Боб) через API**, а не с
  телефона: серверный путь и веб-клиент те же, что у телефона; отдельный
  телефонный повтор не делался.

## Скрытое окно — toast есть

- Окно запущено скрытым (`--from-startup`).
- После `POST /api/v1/circles/<Семья>/posts` от Боба появилось системное
  уведомление Windows от «Wynd Настольный».
- **Computer Use видит toast через дерево доступности**: окно
  `Новое уведомление` (ShellExperienceHost), тексты `Семья` и
  `Новая запись в круге`, заголовок `Новое уведомление от Wynd Настольный`.
- Собственный снимок Computer Use для окна toast недоступен
  (`Screenshot unavailable … hidden or unrendered`), но **PrintWindow по HWND,
  который отдал Computer Use, снимает toast полностью** — см.
  `toast-new-post.png` (396×205, настоящий баннер Windows с значком Wynd).
- Та же запись видна в истории уведомлений Windows: `History.GetHistory(
  "com.wynd.desktop")` вернула `<text>Семья</text>` и
  `<text>Новая запись в круге</text>` — `toast-history.xml`.

## Окно на виду — уведомления нет

- Второй запуск того же exe с тем же профилем показал скрытое окно
  (SingleInstance): `MainWindowTitle = Wynd [0.4.4]`.
- Новая запись Боба при видимом окне: число уведомлений Wynd в истории
  **не изменилось** (9 → 9), нового toast нет.
- Это совпадает с правилом `ShouldNotify`: уведомление только когда окно
  спрятано/свёрнуто.

`getScreenshot` для этого окна отказывает; рабочий путь к пикселям —
PrintWindow по HWND из Computer Use. Это же работает для ручной проверки
будущих уведомлений.

## Уборка

Тестовая сессия удалена из Credential Manager (`/__secrets` → пусто,
`cmdkey` записи `Wynd.Desktop` не видит); окно и стенд остановлены; временная
запись схемы `wynd:` удалена (приложение создаёт её при следующем запуске);
`IconUri` уведомлений возвращён на реальный профиль
`%APPDATA%\Wynd\desktop\toast-icon.png`. Данные `dev/data` не менялись —
использовались копии.
