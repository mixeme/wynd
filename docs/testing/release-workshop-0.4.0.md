## Почему удалённого выпуска пока нет

`git fetch origin main --tags` через штатный HTTPS-remote Gitea вернул `remote: Failed to authenticate user`. Проверка без сохранённой учётной записи запросила вход. Проверка уже настроенного SSH с `BatchMode=yes`, `StrictHostKeyChecking=yes` и таймаутом завершилась `Connection timed out during banner exchange`; ключи доверия не менялись. В известных файлах настроек проекта нет Git-настройки Gitea; ключ подписи не открывался.

Из-за этого remote refs не обновлены и удалённая актуальность `origin/main` не подтверждена. Локальный тег не отправлен. GitHub на момент проверки отвечает `release not found` для `workshop-v0.4.0`; его workflow не запускался. Обход штатного зеркала прямой отправкой в GitHub не выполнялся.

## Продолжение

1. Восстановить вход в Gitea для Git Credential Manager; заново выполнить fetch и проверить ancestry удалённой main. Не применять force push и не переписывать тег.
2. Проверить настоящее окно реализации по утверждённой основе при одинаковом размере, масштабе и теме. Принятие исходных кадров сохраняется, повторно согласовывать их не нужно.
3. Отправить main и `workshop-v0.4.0` в Gitea; проверить совпадение тега на зеркале GitHub.
4. Дождаться Workshop CI, проверить exe, сумму и удостоверение сборки по тегу; заполнить черновик текстом раздела 0.4.0 из `whatsnew.md`.
5. Владелец подписывает и публикует через «Wynd Подпись». Выполнить живую проверку подписанного обновления из 0.3.1; не закрывать её по тестам или встроенному ключу.
