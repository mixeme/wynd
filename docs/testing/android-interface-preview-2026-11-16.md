## Изменения для телефона

Предпросмотр: `web/src/routes/dev/smoke/android-interface/+page.svelte`.
Показываются список, добавление с предпросмотром и подтверждение удаления.
`FormLayout shell app` заменяет рамку окна и убирает Windows TitleBar.
Слово «Окно» в пояснении заменено на «Приложение».

Сохранены `ServerRow`, галочка текущего, крестик неактивного источника,
проверенная плашка из трёх строк, тексты добавления и удаления, стандартный
`ConfirmDialog` с «Оставить» / «Убрать». Позиция крестика взята из действующего
`app.css`. Новых компонентов, шрифтов, размеров и правил Wynd UI нет.
Внешний контейнер стенда снимает только поля галереи `/dev`.

Все серверы на стенде демонстрационные. Проверка `files.example.org`, выбор,
добавление и удаление работают только с памятью страницы. Это не проверка
сети, нативного моста или хранения. Кнопка назад из списка — заглушка;
назад из добавления возвращает к списку. Предпросмотр доступен только в dev,
по действующему запрету `/dev/*` вне Vite dev.

## Настоящий рендер и повторение

Запустить `npm run dev -- --port 5173 --strictPort` в `web` и
`npm run dev -- --port 5179 --strictPort` в `cmd/wynd-desktop/frontend`, затем
из корня выполнить `node scripts/render-android-interface.mjs`.

- Инструмент: отдельный headless Edge по CDP, масштаб 100%, DPR 1,
  светлая тема, одинаковые viewport 390 × 780 и 360 × 640.
- Основа рендерится непосредственно из действующего Desktop App.svelte.
  Подставной Wails-мост даёт те же имена и адреса, iframe — `about:blank`.
  Приложение пользователя и его профиль не используются.
- Android-предпросмотр рендерится SvelteKit из `/dev/smoke/android-interface`.
  Адрес введён настоящим CDP `Input.insertText`, проверка — после Tab.
  «Оставить» закрывает настоящий диалог перед переходом к добавлению.
- Снимки: `dev/screens/shots/android-interface-preview-2026-11-16/`.
  Пары `desktop-{390,360}-{choice,add,confirm}.png` и
  `android-{390,360}-{choice,add,confirm}.png`.
  `source-sha256.json` связывает изображения с суммами исходников,
  записывает геометрию и ошибки JS. Исходное дерево — `046c6906` плюс
  файлы предпросмотра этого законченного шага; точная версия — по суммам.

Первый запуск Edge в ограниченной среде не ответил на `Page.enable`.
Штатное повышение доступа для отдельного локального headless-процесса
позволило получить настоящий рендер. Ручной перерисовки не было.

## Проверка и границы

Осмотрены все три состояния в обоих размерах и их исходные кадры.
Шапка, типографика, строки серверов, поля, переносы и действия читаются,
наложений и обрезанных кнопок нет. Диалог остаётся стандартным и помещается
в 360 × 640. Убрана полоса Windows (34 px); пояснение переносится естественно
после замены слова «Окно» на «Приложение». Положение стандартного диалога не менялось.

`npm run check:ui`, `npm run check` (0 ошибок и предупреждений), адресные
Prettier и ESLint прошли. Рендер дал 12 PNG, без исключений JS и
горизонтального переполнения. Это браузерная проверка, не снимки Android
WebView; системные полосы, клавиатура, USB и реальный телефон здесь
не проверялись. APK, настройки, сессии и данные телефона не менялись.

**Следом:** реализовать принятые три кадра без изменения их оформления.
Вход из серверных настроек, первый запуск без источника, приглашение/QR
и недоступность выбранного сервера этим набором не приняты. Для локальной
стартовой части объём уже разрешён (`120263db`), её актуальные кадры ещё
требуется подготовить и предварительно утвердить. Обновления, Play Защита
и вшивание основного интерфейса остаются отложенными.

перенесена и в Настольное (`41ea3955`). Поэтому различием платформ она больше
не является. Старые снимки Desktop выше сохраняют состояние до этой правки;
их не заменяли и не объявляли новыми эталонами.
