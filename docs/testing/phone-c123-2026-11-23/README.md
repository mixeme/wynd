# OPPO 23.11.2026 — C123 (второй сервер), C120, хвост C99/C108

Телефон OPPO CPH1931, Android 10, Firefox 132. Приложение — отладочный пакет
`mixeme.wynd.debug` 0.1.0-debug, собранный из `main` вечером 23.11; выпуск
`mixeme.wynd` 0.1.0 остаётся установленным, 0.1.1 не ставился.

Стенды — два локальных сервера, собранные из `main` (по коду это ровно
`v0.53.6`: после выпуска менялись только версии окон и документация).
`/api/v1/instance` обоих отвечает `"version":"0.53.6"`:

- **A** `http://127.0.0.1:7676`, данные `dev/c92/data` — «Дача» (Аня, Боб),
  «Семья» с Бобом;
- **Б** `http://127.0.0.1:7677`, данные `dev/c92/data2` — «Работа» (Аня, Вера),
  у Ани бессрочная подписка, у Веры до прогона висела заявка на оплату.

`adb reverse tcp:7676`/`tcp:7677`. Коды входа — `dev/c92/data*/dev-auth-codes.log`.

**CORS настоящих серверов проверен отдельно:** `wynd.mixfed.ru` и
`wynd2.mixfed.ru` на `Origin` отвечают `Access-Control-Allow-Origin` эхом и
списком `Access-Control-Expose-Headers`, preflight `OPTIONS /api/v1/instance`
даёт 204 с разрешёнными методами и заголовками; у админского маршрута CORS нет.

## Граница прогона: http-стенд и защита оболочки

В `MainActivity.shouldInterceptRequest` оболочка отдаёт 403 на любой чужой
`http`-запрос (`MainActivity.java:220-225`) — это защита от чужого cleartext.
Для настоящих серверов она не срабатывает: и интерфейс, и второй сервер идут
по https, а `ServerOrigin.parse` в выпускной сборке вообще не принимает http вне
отладочной петли. На локальном http-стенде второй сервер из-за этого
недоступен, поэтому **только на время прогона** в отладочную сборку добавлено
послабление: чужой http разрешён, если сам интерфейс тоже http (смешанного
содержимого нет). После прогона правка откачена, чистый debug-APK собран заново
и установлен на телефон.

## C123 — второй сервер в приложении

1. **Кнопка.** На «Серверы» у единственного сервера видна кнопка «Войти на
   другой сервер» ([servers-one.png](servers-one.png)). В Firefox её нет —
   она приходит по `androidPort()`, как и решено в C69.
2. **Добавление Б.** Адрес нужно вводить с явной схемой
   `http://127.0.0.1:7677`: голый адрес клиент дополняет до `https://`, и
   проверка падает на TLS (`net::ERR_SSL_PROTOCOL_ERROR` в WebView). После
   явного http карточка «Стенд OPPO Б · Открыт для новых» построилась живым
   ответом через CORS ([server-b-card.png](server-b-card.png)); код входа
   пришёл и принят.
3. **Оба списка.** На улочке в интерфейсе A одновременно видны «Работа» (Б) и
   «Семья»/«Дача» (A) ([street-both-servers.png](street-both-servers.png)).
   «Серверы» показывает две карточки с отдельными входами:
   A — `anya@example.com`, 7 кругов; Б — `anya@example.com`, 1 круг
   ([servers-two.png](servers-two.png)).
4. **Две подписки UnifiedPush.** Включение «Уведомления на этом телефоне» при
   двух входах создало по подписке на каждом сервере одновременно:

   | Сервер | endpoint ntfy | created_at |
   | --- | --- | --- |
   | A | `https://ntfy.sh/uptNlCuLIm9VKV?up=1` | 2026-11-23T20:00:46.839683300Z |
   | Б | `https://ntfy.sh/upOO4rtMbks9eL?up=1` | 2026-11-23T20:00:46.954707000Z |

   Запись Бобом в «Семью» (A) и Верой в «Работу» (Б) дала два уведомления
   одновременно: «Семья — Новая запись в круге» и «Работа — Новая запись в
   круге» ([notifications-both.png](notifications-both.png)). Риск A8 не
   воспроизвёлся: у каждого сервера свой endpoint и свои ключи VAPID. Нажатие
   на уведомление Б открыло именно «Работу» с записью Веры.
5. **Выход по серверам.** «Выйти на этом устройстве» на A убрало только
   карточку A; Б остался и его лента работала
   ([logout-a-keeps-b.png](logout-a-keeps-b.png)). **Но** тумблер
   «Уведомления на этом телефоне» выключился целиком
   ([toggle-off-after-logout.png](toggle-off-after-logout.png)), и после этого
   не приходили пуши ни с A, ни с Б: записи 23:09–23:12 не дали новых
   уведомлений, хотя строки подписок на серверах остались. Повторное включение
   тумблера создало Б новую подписку
   (`upnuxLZ7JzK64b`, 2026-11-23T20:13:07.755678900Z,
   [toggle-on-again.png](toggle-on-again.png)) и доставка восстановилась.
   Это **дефект C126**: выход с одного сервера не должен гасить уведомления
   оставшихся.
6. **Смена сервера интерфейса.** Переключение интерфейса на Б показало только
   вход Б и только «Работу» ([interface-b-only.png](interface-b-only.png));
   после возврата на A оба сервера снова видны. Входы не теряются, но
   «многосерверный» вид существует только у того источника, с которого
   добавляли второй сервер: входы хранятся в хранилище origin. Вопрос C127
   владельцу: оставить как есть (интерфейс — отдельный профиль) или показывать
   все входы при любом источнике.

## Хвост C99/C108

Ветка «прогрев из ленты → офлайн-запуск» на http-стенде не воспроизводится:

- **Приложение.** После прогрева «Дачи» стенд A остановлен, приложение
  запущено заново. Вместо кэшированной улочки оболочка показала свою локальную
  плашку «Стенд OPPO A · Сервер не отвечает», «Проверить сеть…», «Повторить»,
  «Другой сервер» ([app-offline-cold-start.png](app-offline-cold-start.png)).
  Сохранённые круги в этом состоянии не показываются.
- **Firefox.** Вход на A, прогрев «Дачи», остановка стенда, `force-stop`
  Firefox и холодное открытие `/circles`: пустой экран, затем сетевая страница
  Firefox «Соединение было сброшено»
  ([firefox-offline-http-stand.png](firefox-offline-http-stand.png)). Оболочка
  service worker на этом http-стенде навигацию не обслужила, снимки не
  показаны.

Это не тот путь, который проверялся в C108 (HTTPS/PWA на wynd2, где есть
кэш оболочки). Хвост остаётся открытым и требует HTTPS-стенда или PWA.
