# Настольный: вшитый интерфейс по умолчанию (27.11.2026)

План [66](../plans/66-desktop-functions.plan.md), функция 9. Решение владельца
27.11: «Переходим в Настольном приложении на вшитый интерфейс». Подготовка без
переключения и устройство режима — [desktop-embedded-ui-2026-11-23](desktop-embedded-ui-2026-11-23.md).

## Модель

- Источник интерфейса — отдельная настройка `source` в `servers.json`:
  `embedded` (по умолчанию, в том числе для старых файлов без поля) или
  `server`. Выбранный сервер (`selected`) остаётся источником **данных** в
  обоих режимах: адрес API, событий и медиа в мост страницы подставляет
  оболочка, origin окна прежний.
- Вшитый — основной. Серверный — явный откат: «Настройки → Приложение →
  Интерфейс» → «Сменить источник интерфейса» → сервер, либо запуск с
  `--server-ui` (только на этот запуск, настройка не перезаписывается).
  Прежний ключ `--embedded-ui` принимается для совместимости.
- В списке источников «Встроенный» стоит первым; сервер, с которого идут
  данные в текущем режиме, подписан «Данные с этого сервера» и не имеет
  крестика удаления. Выбор сервера временно открывает его интерфейс, выбор
  «Встроенный» возвращает вшитый клиент с тем же сервером данных.
- Смена источника не меняет входы и круги: IndexedDB, Credential Manager и
  очередь остаются на месте, перенос данных не нужен (origin окна прежний).

## Что сделано

- `internal/desktop/store.go` — `source`, `Source()`, `SetSource()`; пустое
  поле читается как `embedded`; `ClearSelection`/`Remove` без выбранного
  сервера возвращают вшитый источник.
- `internal/desktop/proxy.go` — раскладка по источнику: `/` в рамке без метки
  отдаёт текущий источник, `?wynd=server` и `?wynd=embedded` — явный выбор;
  служебные пути (`/api/`, `/archive/`, `/admin/bootstrap`, `/__srv/…`) всегда
  через прокси; метка снимается с адреса страницы.
- `internal/desktop/embedded.go` — мост `window.__wyndDesktop` получает
  признак `"embedded":true`, по нему клиент показывает «Встроенный».
- `cmd/wynd-desktop/main.go` — exe всегда несёт клиент; источник берётся из
  `servers.json`, `--server-ui` перекрывает его на запуск;
  `App.InterfaceSource`/`SelectEmbedded`, `SelectServer` сохраняет серверный
  источник.
- Оболочка (`cmd/wynd-desktop/frontend`) — строка «Встроенный», переключение
  в обе стороны, рамка на `/ ?wynd=embedded` или `/ ?wynd=server`.
- Веб-клиент — `$lib/desktop/bridge.ts` знает `embedded`; «Настройки →
  Приложение → Интерфейс» показывает «Встроенный / Интерфейс приложения», а
  строка смены называется «Сменить источник интерфейса»; на пустых «Серверах»
  подсказка говорит «Интерфейс открывается из приложения».

## Найденный дефект моста

В `web/src/app.html` с C143 есть проверка `if (window.__wyndDesktop)` для
класса `desktop-window`. Вставка моста искала в HTML голое имя
`__wyndDesktop` и считала, что мост уже стоит, — поэтому с появлением этой
проверки **и вшитый, и серверный интерфейс могли открыться без моста**: без
настоящего адреса сервера, локального порта API и настольных строк. Живой
прогон 27.11 это и показал (`bridge: null`, экран входа как в браузере).

Исправлено: и `internal/desktop/embedded.go`, и `internal/desktop/proxy.go`
ищут точный маркер `window.__wyndDesktop={`. Охраняющие тесты содержат HTML с
упоминанием имени без моста — старый поиск на них падает. Дефект есть в
черновике Настольного 0.5.6 (клиент 0.58.0): подписывать и публиковать его без
этой правки нельзя, нужен следующий выпуск.

## Живая проверка

Стенд: локальный сервер Wynd 0.58.0 на `127.0.0.1:7690`, отдельный `APPDATA`,
собранный `dist\wynd-desktop.exe` (без ключа подписи). Вход участника —
синтетическая учётная запись на локальном сервере; сессия положена в
`/__secrets` локального порта окна, как это делает клиент. Профиль и
учётные данные после проверки убраны.

Проверено вживую:

- окно открывает **вшитый** клиент (`source` пуст → embedded), в HTML есть
  мост с настоящим адресом сервера и локальным портом API, `"embedded":true`;
- «Настройки → Приложение → Интерфейс» показывает «Встроенный»;
- «Сменить источник интерфейса» → сервер «Дом проверки»: страницы пошли с
  сервера, `servers.json` получил `"source":"server"`, мост без `embedded`;
- возврат на «Встроенный»: страницы снова из exe, `"source":"embedded"`;
- запуск с `--server-ui`: интерфейс серверный, `servers.json` не изменился;
- перезапуск: источник и выбранный сервер читаются из `servers.json`.

Настоящие кадры окна (PrintWindow, 1060×780, светлая тема, масштаб 100 %):

- [settings-app.png](desktop-embedded-default-2026-11-27/settings-app.png) —
  «Настройки → Приложение → Интерфейс» во вшитом режиме;
- [source-list-embedded.png](desktop-embedded-default-2026-11-27/source-list-embedded.png) —
  список источников, выбран «Встроенный», сервер подписан «Данные с этого
  сервера»;
- [source-list-server.png](desktop-embedded-default-2026-11-27/source-list-server.png) —
  тот же список после выбора сервера: отмечен сервер, «Встроенный» не выбран.

**Приёмка вёрстки не выполнена:** кадры показаны владельцу 27.11 и ждут его
слова. До приёмки вариант считается предложенным, а не утверждённым.

Не проверено вживую: подсказка на «Серверах» при нуле входов (ветка видна
только без сессий); первый запуск с `--server-ui` без сохранённого сервера
(выбор источника при вводе адреса); поведение на других масштабах Windows и в
выпускной сборке — реестр проверок.
