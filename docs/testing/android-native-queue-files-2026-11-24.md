# Android: нативная очередь 5.2 — вложения (24.11.2026)

Этап 5 плана [50](../plans/50-android-wrapper.plan.md): после 5.1 (записи без
вложений) native получил файлы, постеры и обложки. Сжатие по-прежнему в
foreground; фоновое сжатие — 5.3.

## Что сделано

- **Передача файлов в native.** `begin` (метаданные записи, файлов и aux) →
  `chunk*` по 128 КиБ base64 → `commit`; `abort` отменяет. Мост только для
  главного фрейма выбранного origin; файлы и токен лежат в private
  `files/native-queue/<id>/`, наружу не отдаются. Незавершённые каталоги
  удаляются при следующем запуске; страница помечает запись `native_pending`.
- **Хранилище.** `NativeQueue.Record` получил `files`, `aux` (постер/обложка с
  `media_index` и полем), состояние сессии/блоба каждого файла. Лимиты: 32
  части, 512 МиБ, payload 64 КиБ.
- **Отправка.** `NativeQueueSender` повторяет протокол очереди страницы:
  `POST /uploads`, `HEAD` с `Upload-Offset`, `PUT` порциями по 1 МиБ,
  `POST /complete` с SHA-256, затем запись/комментарий с media. При обрыве
  SHA считается заново по уже принятой части; 404 сессии начинает заново,
  401 — `unauthorized`, 507/сеть — повтор, остальные 4xx — `failed`.
- **Постеры и обложки.** Байты `video_poster`/`audio_cover` отделяются от JSON
  и идут отдельными частями; после загрузки подставляются
  `video_poster_blob_id`/`audio_cover_blob_id` в media.
- **Страница.** `native_pending` исключает запись из очереди страницы; передача
  файлов идёт в фоне после `enqueue`. Если окно закрылось до записи
  `native_id`, `reconcileNativeQueue` подхватывает native-запись по
  `client_id`; если передача не удалась — возвращает запись странице. Правка,
  удаление и повтор отменяют native-копию.
- **WorkManager** тот же, что в 5.1; отдельного foreground-уведомления пока
  нет.

## Живой прогон на OPPO

OPPO CPH1931, Android 10, debug APK из текущего дерева; стенд 7676 из
текущего клиента. PNG 1×1, 68 байт, передан через `__wyndQueue` (CDP):
begin → chunk (base64, 68 байт) → commit. Стенд был остановлен; запись с файлом
лежала в native (`attempts=1`), приложение свёрнуто кнопкой «Домой». Стенд
поднят — запись ушла **при невидимой активности**: в очереди `state: sent`,
каталог файла удалён; в ленте появилось вложение `test.png`, 68 байт,
`image/png`, blob `01a20bf3…`. SHA-256 скачанного блоба совпал с исходным PNG
(`8f493dcb…`). Это проверяет передачу файла, фоновую отправку и SHA.

**Границы:** живой прогон шёл через мост, а не через кнопку публикации в UI
(путь `enqueue → native` покрыт веб-тестами); видео/постер/обложка и resume
большого файла проверены unit-тестами, но не живьём; автоматический
перезапуск WorkManager после гибели процесса без открытия приложения
остаётся открытым (как в 5.1). Для длинных роликов foreground-режим не
включён — WorkManager может прервать загрузку, она продолжится следующим
прогоном.
