## Что было в порядке

- **Архив круга.** Каждая пользовательская строка в HTML проходит `html.EscapeString`, инлайн-скриптов нет, `href`/`src` — только серверные UUID. Имена в ZIP — `media/<uuid>.<ext>` и `posts/<uuid>.html`, расширение из таблицы по MIME; пользовательские имена, `../`, зарезервированные имена Windows и дубли невозможны. Состав архива фильтруется отрезками читателя, `gone` — 403. BLB-3 подтверждён исправленным.
- **Права хроники.** `requireWriter`/`requireAuthor` во всех мутаторах содержимого (SEC-3 выполнен); IDOR по составным путям невозможен — запись/комментарий сверяются с кругом, реакция ищется по своей identity, обложка дня — только блоб записи этого круга; владельческие операции — в одной транзакции с проверкой. Кросс-круговой доступ к блобу по id невозможен; сирота привязывается только владельцем во всех четырёх путях (запись, аватар, обложка, оплата). E-mail в участнических ответах не отдаётся.
- **Аутентификация.** Сессии — `sha256(token)`, разделение admin/participant по `kind` строгое; bootstrap — SEC-1/1a/1b закрыты, `smtp-test` на установленном инстансе мёртв при любом токене; коды — атомарные попытки, константное сравнение, лимиты до поиска учётки (AUTH-1/2); soft-delete чистит сессии, pending joins и личные инвайты (AUTH-3/4); `clientIP` — крайний правый недоверенный адрес.
- **Оплата.** Чужой блоб приложить нельзя; `pay/status` не отдаёт чужого; баннер сбрасывается только себе; реквизиты и текст баннера рендерятся текстом; `GET /admin/pay/blob` — только блобы заявок.
- **Файлы.** Пути на диске — из UUID в БД, не из URL; `.part` только после проверки владельца сессии; SHA-256 обязателен; исполняемые MIME → `octet-stream` + `attachment`; SPA — traversal невозможен (`embed.FS`), SW не кэширует `/api/` и блобы, `/dev/*` закрыт константой сборки.
- **Исходящие и секреты.** SEC-4 (push) и SEC-5 (STARTTLS, CR/LF) подтверждены; `InsecureSkipVerify` нигде; пароль SMTP и приватный ключ VAPID не отдаются ни одним ответом и не логируются; токены сессий и коды входа в логах отсутствуют (коды — только loopback-фолбэк, файл 0600); push-payload — `{circle_id, type, count}` без текста; письма без содержимого записей; `install.sh` ничего не скачивает по HTTP; compose не публикует порт `wynd` наружу.
- **Клиент.** `{@html}` — только манифест PWA и SVG QR-кода; цвета через таблицу `CIRCLE_COLORS`; `src` — только `blob:` URL; автолинковки нет; токены только в IDB; `Authorization` уходит строго на выбранный origin; открытого редиректа после входа нет.

## В очередь плана 42 (не высокой серьёзности)

Перечислено в `docs/plans/42-code-review.plan.md`, волны 3–7, с пометкой «аудит 2026-09-22»:

- **DNS-rebinding push-endpoint** (низкая): фильтр приватных адресов — только при подписке; при доставке имя может резолвиться в 127.0.0.1. Свой `DialContext` с проверкой IP — волна 3.
- **`POST /auth/verify` без лимита по IP** (низкая): знающий e-mail жертвы сжигает 3 её попытки. Лимит по IP или единый `400` на not_found/expired/too_many — волна 3.
- **Глобальный ключ `*` лимитера входа** (низкая): 50 неудач с 10 адресов запирают `/admin/login` и `/bootstrap` для всех на 15 мин. Замедление вместо запрета — волна 3.
- **`chargeRate` не атомарен** (низкая): параллельные `POST /auth/code` на один адрес обходят 5/час.
- **`pending_circle_joins` бессрочна** (низкая): приглашение нельзя отозвать, переживает исключение пригласившего и смену `invite_who`.
- **SMTP-проба возвращает баннер сервиса** (низкая, только админ): классифицировать причину без сырого текста.
- **`EstimateArchivePersonal` на каждом `GET /circles`** при активном цикле — N+1 по всем записям до отсечки (средняя нагрузка, не безопасность) — волна 5.
- **Архив в памяти** — стрим во временный файл, Range — волна 7.
- Заметки: инвайты заблокированного создателя живут; peek инвайта не проверяет остаток и `closed`; `max_uses`/`ttl_sec` без потолка; endpoint push в логе при ошибке; `account_id` участников виден каждому читателю; упоминание обходит mute; `writeFileConfig` — мёртвый код; строка `blobs.pending` при сбое между `Rename` и коммитом; отрицательный `edit_window_sec` в `POST /circles`; число медиа на запись не ограничено; исключённый возвращается по живой ссылке (по справочнику — осознанно); нет `ReadTimeout` на чанк загрузки.

## Не подтвердилось

- «Аватар, поставленный после ухода, доступен бывшему участнику через `effective_at`» — аватар хранится `UPDATE`-ом на текущей строке имени и собственной метки времени не имеет; предложенная правка SQL пробником не подтвердилась. Поведение принято ниже как риск.

## Принятые риски

- **Текущее состояние видимых записей.** Отрезок видимости применяется к моменту создания записи, комментария, события. Правка тела, замена вложений, новый заголовок или обложка дня, новый аватар лица после ухода участника видны ему в снимках (`feed`, `days`, аватар по id), тогда как `sync` этих правок не отдаёт. Замораживать содержимое по журналу для `left_with_access` — дорого и противоречит модели «снимок = текущее состояние». Записано в `server-reference.md`.
- **Плитки OpenStreetMap.** При открытии карты браузер участника ходит к `tile.openstreetmap.org`: третья сторона видит IP и район просматриваемых фото; `Referer` урезан до origin. Записано в `client-reference.md`; настраиваемый URL плиток — вне плана.
- **`http://` для удалённого сервера** принимается клиентом без предупреждения (нужен для loopback-разработки).
- **CSP без `script-src`**: клиент ходит на другие origin'ы; хэши SvelteKit — возможное усиление, не дефект.
- **Секреты в БД открытым текстом** (DEC-1) — остаётся; условие 0600 теперь выполняется кодом.
- **404 на неизвестный адрес в режимах invite/closed** — прежнее решение (2026-09-03) в силе.

## Что стоит помнить при развёртывании

- Права `wynd.db` выравниваются до 0600 при старте; каталог бэкапа создаётся 0700, но существующий общедоступный каталог (`/var/backups`) сервер не переназначает — проверьте `stat` после первого `wynd backup`.
- Загрузка файлов теперь доступна участнику с истёкшей подпиской (для скриншота оплаты); квота и владение проверяются как прежде.
- Миграция 0014: если у одной учётки было несколько ожидающих заявок на оплату, младшие помечены отклонёнными (файлы скриншотов сохранены).
- `X-Forwarded-For`: прокси, добавляющий заголовок отдельной строкой (HAProxy `option forwardfor`), теперь обрабатывается корректно; `WYND_TRUSTED_PROXIES` по-прежнему обязан перечислять только свои прокси.

## Повторный проход

Обязателен перед публичным релизом (по изменённому с этой даты) и при любом из триггеров, записанных в [CONTRIBUTING.md](../CONTRIBUTING.md): новый маршрут без сессии; новый исходящий запрос сервера на адрес, заданный пользователем; новый секрет на диске или в БД; новый путь отдачи пользовательских файлов; изменение проверки прав в `chronicle` (`requireReader`/`requireWriter`/`requireAuthor`/`RequireOwner`/`requireSettingsTx`).
