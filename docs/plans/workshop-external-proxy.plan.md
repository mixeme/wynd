# Мастерская: Wynd за прокси на другой машине — C70

**Статус:** владелец выбрал поддержку этого способа установки 2026-11-05 (вариант 1). Кадры и подробности ниже подготовлены для согласования; код режима ещё не реализован.

Мастерская устанавливает Wynd на выбранную машину по SSH. Существующий Apache, nginx или Caddy на другой машине принимает HTTPS и передаёт запросы Wynd. Сценарий владельца: домашний Apache и Raspberry Pi в одной сети.

[Кадры C70](../visual/installer.html#c70) · [Интерактивный просмотр](../visual/workshop-servers.fragment.html) — группа «Внешний прокси — C70». Основа списка и пульта уже утверждена в [общем плане](workshop-servers.plan.md); новые состояния C70 в утверждение от 3 ноября не входят.

## Предлагаемый путь

1. После осмотра выбрать «Веб-сервер на другой машине». Прежний способ установки на одной машине остаётся доступным.
2. Указать публичный адрес сайта, адрес Wynd в локальной сети, точный адрес машины с прокси и тип веб-сервера. SSH-адрес Wynd, адрес его сетевого интерфейса и адрес сайта — разные значения. Пример: SSH и Wynd `192.168.1.20`, прокси `192.168.1.10`, сайт `https://wynd.example.org`.
3. Показать план: установить Wynd без Caddy, слушать только выбранный адрес на порту 7676, разрешить доступ только прокси; настройка HTTPS и DNS находится на другой машине. До подтверждения удалённых изменений нет.
4. После установки показать «Wynd установлен. Настройте веб-сервер» и подходящий пример для Apache/nginx/Caddy. Адрес upstream — `http://192.168.1.20:7676`. Примеры не перезаписывают чужой сайт и не заменяют его сертификат. Из Мастерской на машину прокси не подключаемся.
5. Пользователь применяет настройку прокси, нажимает «Проверить сайт». Проверка не запускает установку повторно. Пока она не прошла, состояние профиля — «Wynd установлен · сайт не проверен»; разрешено уйти к другому серверу и вернуться.
6. При ошибке назвать причину и предложить повтор проверки либо возврат к адресам. Сохранять установленный Wynd и введённые значения. Не предлагать переустановку как способ исправить DNS или прокси.
7. После успеха показать ссылку сайта и явный результат «Сайт открылся с этого компьютера». Это не доказательство доступа из интернета: проверка из домашней сети может идти другим маршрутом. Отдельная приёмка с внешней сети обязательна.

## Состояния кадров

| ID | Состояние |
|---|---|
| c70-mode | Выбор размещения веб-сервера |
| c70-address | Сайт, адрес Wynd и адрес прокси |
| c70-plan | План перед изменением сервера |
| c70-route | Wynd установлен, ожидает настройки прокси |
| c70-check | Проверка сайта, установка уже завершена |
| c70-error | Сайт недоступен, повтор без переустановки |
| c70-ready | Сайт проверен с этого компьютера |
| c70-remove | Удаление Wynd; внешняя настройка остаётся |

Данные в кадрах подставные. Кнопки меняют кадр, подключений к серверам нет. Проверку, успешный исход и ошибку выбирают в списке кадров; макет не выполняет сетевую проверку.

Проверено 2026-11-05: `node docs/visual/check-workshop-servers.mjs` — 77 кадров, 8 групп, ошибок нет. Отдельно сверены неизменность прежних 69 кадров, совпадение галереи с интерактивным просмотром, вход по `#c70-mode` и повтор проверки без установки. Визуальная приёмка не выполнена: встроенный браузер отклонил локальный `file://` по политике URL; геометрию нужно проверить при просмотре HTML.

## Границы и безопасность реализации

- До установки проверить, что адрес Wynd принадлежит выбранной машине, порт свободен, адрес прокси допустим и отличается от Wynd. Не подставлять `0.0.0.0`, `::` или всю локальную сеть как безопасное значение по умолчанию.
- Одного bind на локальный интерфейс недостаточно. До открытия порта обеспечить и проверить ограничение источника на пути опубликованного Docker-порта. Не полагаться на наличие обычного правила хостового firewall без проверки фактического доступа. Если механизм ограничений нельзя надёжно определить, остановиться с объяснением до изменения установки.
- Правила доступа принадлежат конкретной установке; чужие правила не переписывать. При отмене и ошибке убирать только созданные правила, при обновлении сохранять ограничения.
- Доверять заголовкам IP клиента только от своего прокси. Шаблоны должны заменять недоверенные входные заголовки, сохранять Host, сообщать HTTPS и поддерживать потоки SSE, большие загрузки и probe. Фактический адрес peer после Docker/NAT проверить тестом; широкие доверенные подсети не использовать как обход ошибки.
- HTTP между двумя машинами допускается для выбранной доверенной локальной сети. Через публичную сеть этот вариант не поддерживать; зашифрованный канал — отдельная задача.
- Сертификат и DNS обслуживает внешний прокси. На машине Wynd не устанавливать Caddy, certbot, сертификат и правила перенаправления портов 80/443. Мастерская не меняет другую машину.
- Проверка HTTPS проверяет сертификат и принадлежность ответа установленному Wynd, а не только статус 200 или номер версии. До реализации выбрать способ одноразового подтверждения экземпляра и проверить отсутствие утечки секретов. Ограничить время, размер ответа и перенаправления; не отправлять SSH-реквизиты или токены другому адресу.
- Ссылку первого входа с секретом выдавать только после проверки HTTPS нужного экземпляра; не помещать её в журнал, кадры и сообщения ошибки.
- В профиле и на сервере сохранять режим, bind, адрес прокси и публичный URL. После перезапуска Мастерской не угадывать режим по отсутствию Caddy. Прежние установки распознавать прежним способом.

## Обслуживание

Обновление и откат сохраняют режим и сетевые ограничения, затем проверяют сайт. Ошибка сайта не превращает успешно запущенный Wynd в «не установлен». Удаление убирает только Wynd и принадлежащие ему локальные правила; заранее сообщить, что настройку на внешнем прокси пользователь убирает сам. При переезде проверить адрес назначения заново и выдать новую настройку upstream, сохраняя прежний путь до подтверждения нового сайта. Не обещать автоматическую правку внешнего прокси.

- [ ] Реализовать ограниченное сетевое размещение без Caddy и примеры трёх прокси. Тесты: неверные адреса и занятый порт, правила доступа до открытия порта, отмена/ошибка, доверие заголовкам и сохранение настроек.
- [ ] Реализовать проверку экземпляра по HTTPS и отдельное состояние «сайт не проверен». Тесты: DNS/тайм-аут, неверный сертификат, чужой Wynd, неожиданный redirect, повтор без переустановки.
- [ ] Проверить обновление, откат, удаление, повторный запуск Мастерской и смену выбранного профиля; не терять ожидающий настройки сайт.
- [ ] Пройти безопасность изменённых SSH-команд и сетевых границ по [SECURITY](../SECURITY.md), затем общие Desktop checks.
- [ ] Живой проход на двух машинах: Apache + Pi, отдельно nginx/Caddy; доступ только от прокси, подмена заголовков, SSE, загрузка файла, обрыв и повтор. Доступ к сайту проверить также из внешней сети. ARM-компиляция не закрывает живую проверку Pi (C64).
- [ ] Обновить инструкцию, выпустить Мастерскую отдельно и проверить подписанное обновление из 0.3.1. Только после приёмки удалить этот план, перенести правила в справочник, а незакрытые проверки — в список проверок.
