## Почему сейчас

Сработали триггеры из CONTRIBUTING:

- **Проверка прав в `chronicle` и шлюзы.** `requireReader`/`requireWriter`/`requireAuthor`/`requireSettingsTx`/`RequireOwner` перенесены в `internal/chronicle/gate.go` вместе с правкой (`42deade`, REF-1). Шлюз оплаты стал одним запросом вместо четырёх (`5e52448`, PAY-1). `pay.go` разложен на `pay_settings`/`pay_requests`/`pay_gate` (`b749692`, PAY-9).
- **Новый путь отдачи файлов.** Архив круга отдаётся из временного файла с `Range` и докачкой, а отсечка фиксируется по полной отдаче (волна 7, ARC-8).
- **Секреты в новых местах.** Команда `wynd admin-password`. Бэкап копирует `wynd.db` и `keys/` в другом порядке и с проверкой цели (0.8.1).
- **Исходящие запросы на адрес пользователя или админа** переписаны: доставка push со своим `DialContext` (`internal/push/endpoint.go`), проверки сертификата, домена и редиректа на нестандартном порту (`internal/check/*`), классификация отказа SMTP (`internal/mail/errors.go`).

Число маршрутов не изменилось (119), но режимы `/sync` урезаны до SSE (0.8.2) — это тоже проверить по таблице.

## Охват

### B1. Шлюз прав

- [ ] `gate.go` против `bbf5d5f`: каждая проверка эквивалентна прежней. Особенно `left_with_access`, отрезки видимости, `can_write`, `blocked`/`deleted_at`.
- [ ] Шлюз оплаты одним запросом: `required && expired && has_requisites` даёт то же, что четыре запроса. Загрузка скриншота истёкшему участнику по-прежнему проходит.
- [ ] Пробные тесты 2026-09-22 (`TestClearDaySaidRequiresWriteAccess`, `TestClientIDReplayIsScopedToAuthor`, `TestSearchHidesCommentWrittenAfterLeaving`) на месте и проверяют то же самое.
- [ ] `CanAccessBlob` (`internal/blob/serve.go`): аватары пачкой (ARC-10) не открывают чужие блобы.

### B2. Отдача файлов

- [ ] Архив: `Range` на границах, пустой и перевёрнутый диапазон, докачка чужим участником, временный файл в каталоге данных (права, уборка при обрыве), `Content-Disposition` с кириллицей.
- [ ] Отсечка архива: её двигает только полная отдача своего же архива. Нельзя сдвинуть чужой отсечкой или частичным запросом.
- [ ] Отдача блобов: `attachment` + `nosniff`, опасные MIME, без изменений с 0.7.1.

### B3. Секреты

- [ ] `wynd admin-password`: пароль не попадает в историю shell, лог и аргументы процесса. Права на `wynd.db` сохраняются.
- [ ] Бэкап: копии `wynd.db` и `keys/*` 0600, каталог 0700, цель внутри копируемого отклоняется (0.8.1), инкрементальный режим не расширяет права.
- [ ] Лог: токен bootstrap, коды входа в режиме `code_delivery=log`, endpoint push при ошибке (заметка 2026-09-22), текст отказа SMTP.

### B4. Исходящие запросы

- [ ] Push: `DialContext` проверяет IP при каждом соединении, а не только при подписке (DNS-rebinding из очереди 2026-09-22). IPv6, `0.0.0.0`, редиректы.
- [ ] Проверки инстанса: запрос идёт только на `public_url` админа, таймауты (общие 15 с), без следования на внутренние адреса.
- [ ] SMTP-проба: наружу уходит классифицированная причина, а не сырой баннер (заметка 2026-09-22).

### B5. Публичные маршруты и лимиты

- [ ] Таблица маршрутов со шлюзами — заново, сверить с отчётом 2026-09-22. Публичных маршрутов не прибавилось.
- [ ] `limiter.go`: глобальный ключ `*` у `/admin/login`, лимит `POST /auth/verify` по IP, атомарность `chargeRate` — что из очереди 2026-09-22 сделано.
- [ ] `/sync` только SSE: 406 без `Accept`, соединение не удерживается без сессии.

### B6. Очередь 2026-09-22

По каждому пункту раздела «В очередь плана 42»: сделан (где и чем), принят как риск (записать) или остаётся открытым (перенести в отчёт). В том числе мелкие: инвайты заблокированного создателя, peek инвайта без проверки остатка и `closed`, `max_uses`/`ttl_sec` без потолка, `pending_circle_joins` без срока, `account_id` участников виден читателям, упоминание обходит mute, отрицательный `edit_window_sec`, число медиа на запись, `ReadTimeout` на чанк загрузки.

### B7. Клиент и локальный запуск

- [ ] Режим `lan` (`scripts\run.bat` — по умолчанию, `run.bat local` — выключить; `make run LAN=1`, `npm run dev:lan`, `662ca17`): сервер на `0.0.0.0`, а `public_url` loopback. Что loopback-режим разрешает соседу по сети: bootstrap без SMTP, коды в логе, проба `/probe`, доверие `X-Forwarded-For` только от loopback. Решить, нужно ли предупреждение при старте.
- [ ] Запасные пути без secure context (`$lib/sha256`, `$lib/uuid`, `$lib/clipboard`) не используются там, где нужна криптостойкость: `getRandomValues` — да, `Math.random` — нигде.
- [ ] `{@html}`, `Authorization` только на выбранный origin, открытые редиректы — без изменений с 0.7.1.

### B8. Зависимости

- [ ] `govulncheck ./...`, `npm audit --omit=dev`; dev-зависимости — отдельной строкой, как в 2026-09-22.

## Метод

Как в 2026-09-22: рецензенты по узким областям (B1–B7), только чтение кода. Каждый пишет находки в файл, а не в ответ. Находки о правах и данных перепроверяются пробными тестами через `go test -overlay`, не трогая дерево. Подтверждённые пробники переносятся в репозиторий как тесты. Внешнего аудитора и пентест-инструментов не привлекать (до 1.0).
