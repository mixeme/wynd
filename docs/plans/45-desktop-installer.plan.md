# 45 — Настольное приложение для установки Wynd на удалённый сервер

**Тип:** новая возможность (развёртывание)
**Статус:** задумка — не начат
**Дата:** 2026-09-27
**Срез:** `main` @ `276be18`, версия 0.10.0.

Человек без опыта администрирования ставит Wynd на свой VPS из настольного приложения: вводит адрес сервера и доступ, приложение само подключается по SSH, ставит Wynd и отдаёт ссылку первого запуска.

---

## Почему

Сейчас установка — это `deploy/install.sh` или Docker (`deploy/docker/`) плюс прокси и сертификат (`deploy/proxy/`, `deploy/caddy/`). Всё это делается руками в терминале на сервере. Развёртывание на wynd.mixfed.ru (0.9.x) показало, сколько там шагов: SSH-ключ и known_hosts, Docker, compose, vhost прокси, certbot, синхронизация часов, доверенные прокси, проверка `/admin/check`. Владельцу круга это не по силам — а свой сервер и есть главная идея Wynd.

## Что должно уметь (набросок, уточнить)

- [ ] Подключение по SSH: пароль или ключ; ключ можно создать в приложении. Отпечаток хоста показать и сохранить.
- [ ] Осмотр сервера до изменений: ОС, Docker, занятые порты, уже работающий прокси (Apache, nginx, Caddy), свободное место, часы. Чужие сервисы не трогать — только показать, что найдено.
- [ ] Выбор пути: свой Caddy с сертификатом (чистый сервер) или готовый шаблон под найденный прокси (`deploy/proxy/*`, `compose.own-proxy.yaml`).
- [ ] Установка: образ, compose, прокси, сертификат, синхронизация часов. Каждый шаг виден человеку и повторяем, если оборвался.
- [ ] Итог: прогон `/admin/check` и ссылка первого запуска.
- [ ] Обновление до новой версии и откат. IndexedDB клиента откатить нельзя (справочник клиента, «Хранилище IndexedDB — версии»), и это надо предупреждать.
- [ ] Бэкап и выгрузка данных с сервера на компьютер.

## Решения

- **Стек — Go + Wails**, в этом репозитории (`cmd/wynd-installer`, фронтенд рядом с `web/`). Бэкенд переиспользует `internal/check` и шаблоны прокси из `internal/api/admin_check.go`, окно — Svelte и `$ui`, как у клиента. Wails, а не Tauri: Tauri добавил бы Rust ради того, что Go уже умеет. Fyne отпадает: свой набор виджетов не даёт взять `$ui`. Версию Wails выбрать при старте: v2 стабильна, v3 — только если к тому времени вышел релиз.
- **Секреты — в системной связке ключей** (Credential Manager, Keychain, Secret Service), не в файлах приложения.
- **SSH — системные ключи и доверие**: `~/.ssh` (ключи, `known_hosts`, `config`) и системный ssh-agent (на Windows — канал агента OpenSSH). Протокол — `golang.org/x/crypto/ssh` и `knownhosts` в процессе, без запуска `ssh.exe`: сборки ssh на Windows (Git, OpenSSH) по-разному читают пути с кириллицей в профиле — это видно на машине разработки.
- **Автообновление приложения — позже**, не в первом выпуске. Подпись сборок — вопрос первого публичного выпуска.
- **Аудит безопасности обязателен** до выпуска: секреты в новом месте, исходящие SSH-подключения, команды на чужом сервере (CONTRIBUTING, «Аудит безопасности»).

## Открытые вопросы

- Какие ОС сервера поддержать с первого выпуска: минимум — Debian/Ubuntu.
- Какие ОС для приложения: Windows, macOS, Linux. На Windows Wails нужен WebView2 (в Windows 11 есть, в 10 — ставится вместе с приложением).
- Команды на сервере: свой сценарий по шагам или `deploy/install.sh` плюс `docker compose`.
