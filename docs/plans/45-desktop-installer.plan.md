# 45 — Wynd Мастерская

**Тип:** настольная установка и обслуживание сервера.
**Статус:** Мастерская 0.3.0 выпущена 2026-10-29 без подписи и самообновления по решению владельца. Основные сценарии реализованы; ниже — оставшиеся задачи и проверки.
**Обновлено:** 2026-10-29.

## Назначение и правила

Новичок ставит Wynd на свой VPS по SSH, получает ссылку первого запуска и затем обслуживает установку. Администратору остаются install.sh и Docker — приложение их не заменяет.

- Чужие сервисы не трогать; перед изменениями показывать план «поставим / изменим с копией / не тронем».
- Шаги: проверить, выполнить, убедиться. Повтор после обрыва безопасен; ошибка названа понятными словами с дальнейшим действием.
- ОС сервера — Debian и Ubuntu. Приложение — Windows и Linux; Linux собирается отдельно, требует cgo и WebKitGTK.
- Вход по ключу предпочтителен; пароль по умолчанию только в памяти. «Запомнить пароль» сохраняет его в системной связке после успешного входа.
- Секреты не в планах и не в Git. Учётки и адреса проверки — в закрытом myenv рядом с проектом; чужие установки и процессы не использовать без разрешения.
- До выпуска изменённых SSH-команд, переноса или обновления нужен проход безопасности по SECURITY.md.
- Перед откатом предупреждать: хранилище IndexedDB клиента не откатывается вместе с сервером.

[Единый макет](../visual/installer.html), стенд — cmd/wynd-installer/frontend/gallery.html. Компоненты workshop находятся в общей Wynd UI; правила — [справочник](../reference/ui-components.md). Сборка, подпись и выпуск — [DEVELOPMENT](../DEVELOPMENT.md#настольный-установщик).

## Уже реализовано

- Подключение, отпечаток хоста, осмотр, план и установка из образа или со сборкой на сервере.
- Свой Caddy либо размещение за найденными nginx, Apache, Caddy; пульт, обновление с копией, откат, бэкап на компьютер, удаление и переезд.
- Обнаружение чужой установки Wynd и перенос; это не обещание обновления произвольной установки на месте.
- Вкладка архивов: объединение без повторов по id с выбором поздней правки, деление по годам/периоду, преобразование полного .wynd в читаемый архив. Исходные файлы не меняются; пароль вводится локально.
- Метаданные личных архивов без копирования текстов, метки записей в HTML, сообщение у неподходящего файла «Мастерская не может прочитать этот файл как архив Wynd».
- Подписанные обновления, проверка удостоверения сборки и помощник «Wynd Подпись» подготовлены. Без зашитого открытого ключа самообновление отключено.

Версии 0.1.0–0.3.0 опубликованы; у 0.3.0 проверены сумма exe и удостоверение по тегу и коммиту. История выпусков и проб — в Git, а не в списке следующих действий. Установка собранным exe, пульт, бэкап, переезд и обновления за чужим прокси уже проходились; устаревшие пометки «пульт ещё не сделан» удалены.

## Осталось сделать

На следующем выпуске проверить полный путь удостоверение → подпись → проверка → самообновление. Решение выпустить 0.3.0 без подписи остаётся в силе.
- [ ] **Linux-приложение.** Собрать и пройти основные сценарии на Linux; Windows-сборка этого не доказывает.
- [ ] **Другой сервер прокси — C70.** Wynd и веб-сервер на разных машинах: отдельный план и кадры после обсуждения. Текущая Мастерская ставит их на одной машине.
- [ ] **Ход сборки — C71.** Показать осмысленный прогресс, пока docker build выполняется на сервере; сейчас окно долго молчит.
- [ ] **Воспроизводимость.** Собрать exe дважды и сравнить результат; Nix и независимые пересборщики — после замера, не обещать доказанную воспроизводимость заранее.
- [ ] **Распространение «Wynd Подпись».** Решить, нужен ли готовый бинарник в публичном выпуске. Предложение не распространять его остаётся предложением, утверждения нет.

## Оставшиеся живые проверки

Ни один пункт не требует останавливать рабочий сервер без отдельной задачи. Состояния старых пробных VPS, DNS и версий из журналов 2026-10-08–28 перед новой пробой нужно узнавать заново.

- [ ] Копия на работающем сайте и обновление без остановки на время копии: проверить именно эту ветку, а не обычное обновление.
- [ ] Сверить покрытие обоих путей переезда: только данные за чужим прокси и свой Caddy с DNS/сертификатом, включая обрыв, повтор и незавершённый переезд. Старые записи «ждём A-запись» не считать текущим состоянием: позднее записан завершённый переезд.
- [ ] Удаление/повторная установка с сохранёнными данными, откат с удалением данных, отказ сертификата при закрытых портах, исправление несинхронных часов.
- [ ] nginx с conf.d, чужой certbot и чужие сертификаты — есть тесты, живой проход не зафиксирован. Отдельно сервер с AAAA: текущий шаблон nginx слушает IPv4.
- [ ] Apache вне пакетной раскладки sites-enabled/a2enmod и Caddy без ожидаемых Caddyfile/systemd: проверить понятность отказа.
- [ ] Занятый порт 7676 выявляется на запуске, не при осмотре; оценить, нужен ли более ранний отказ.
- [ ] После удаления с сохранением данных сертификат certbot остаётся, но без сайта не продлевается. Проверить пояснение и состояние Stale, когда прокси не перечитал настройку.
- [ ] Сверить оценку времени установки за чужим прокси с замером. Проверить сборку на слабом сервере; старая оценка «не хватит ресурсов» без замера не является результатом.

ARM-сервер проверяется отдельно по C64 плана 46 на Raspberry Pi владельца. Инструкция для Pi за домашним Apache и поддержка такого размещения в Мастерской — разные задачи.
