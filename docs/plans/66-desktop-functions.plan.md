# 66 — Функции C66 «Wynd для компьютера»

**Тип:** остаток C66 (план 46) — девять отложенных функций окна.
**Статус:** план. Владелец 22.11.2026: «Берём все функции. Порядок выбирай сам.», затем «Кроме Мастерской внутри клиента». «Мастерская внутри клиента» из объёма исключена. Подробных ТЗ функций нет — объём каждой записан здесь по краткому названию плана 46 и устройству окна; при реализации владелец поправляет.
**Обновлено:** 2026-11-22 (создание плана).

## Правила этого плана

- Каждый законченный шаг — отдельный коммит; ворота (`scripts\test-desktop.bat`, при правках сервера полный `test.bat`) перед коммитом.
- Новые экраны и настройки — сначала настоящий рендер и приёмка владельца, потом включение (AGENTS.md 8). Механизмы без экранов — сразу.
- Окно берёт данные из собранного `dist\*.exe`; после правок Go — `scripts\build-desktop.bat` перед живой проверкой.
- Функции, меняющие web-клиент сервера, попадают в следующий серверный выпуск и в Windows-окно одновременно (совместимость — desktop-reference).

## Порядок работ

Выбран по зависимости и риску: сначала маленькие самостоятельные функции оболочки без новых экранов, затем мосты клиент↔оболочка, затем функции с новыми экранами, последним — самое крупное перестроение.

1. **Общая горячая клавиша.** Показать и сфокусировать окно из любого места Windows. Wails v3.1.0 умеет (`app.GlobalShortcut.Register`, Win32 `RegisterHotKey`) — без новых зависимостей. Комбинация по умолчанию — `Ctrl+Alt+W` (владелец может сменить при приёмке). Настройки в интерфейсе нет — значение не показывается на экране; смена комбинации — отдельное решение, если понадобится. **Сделано 22.11** (`cmd/wynd-desktop/main.go`, попутно `ErrorHandler` — ошибки Wails в журнал): ворота зелёные, регистрация без ошибок и диспетчеризация до показа спрятанного окна доказаны живьём ([протокол](../testing/desktop-hotkey-2026-11-22.md)); физическое нажатие — ручной пункт реестра §7 (инъекция ввода в среде проверки недоказуема).
2. **Системные уведомления.** Wails v3.1.0 API не имеет (только iOS) — «иной механизм» по записи плана 46: всплывающее уведомление Windows (toast) через AUMID-запись в реестре (`HKCU\Software\Classes\AppUserModelId\…`: имя и значок Wynd; сбрасывается удалением Wynd). Шаг 1 — механизм: мост `main.App.Notify` и показ toast, окно спрятано в трей или свёрнуто. **Шаг 1 сделан 22.11** (go-toast + `EnsureToastIdentity`, охраняющие тесты, ворота зелёные, платформа уведомлений приняла приложение — [протокол](../testing/desktop-notifications-2026-11-22.md)); показ баннера на экране — ручной пункт реестра §7 (снимок экрана в среде проверки недоступен). Шаг 2 — когда клиент зовёт мост (события кругов при скрытом окне; кандидаты — новая версия окна, новые записи): решения — с владельцем. Без своего экрана настроек в этом плане (у клиента уже есть «уведомления по умолчанию»).
3. **Системное хранилище токенов.** Сессии переезжают из IndexedDB профиля WebView2 в системное хранилище Windows (Credential Manager, `wincred`) через мост оболочки. Прозрачно для интерфейса: миграция старых входов при первом запуске, хранилище профиля очищается от токенов. Без новых экранов. Список серверов и токены не смешиваются: в `servers.json` токенов нет и не будет (desktop-reference).
4. **Приглашения из браузера.** Ссылка приглашения, открытая в браузере, предлагает продолжить в окне: схема `wynd:` (обработчик записывается в реестр при запуске/первой проверке), веб-клиент сервера показывает ссылку «Открыть в приложении» рядом с приглашением. Окно получает `wynd:invite/…` и открывает свой экран приглашения. Отдельная приёмка владельцем не нужна (нет нового экрана), но сценарий и текст ссылки в веб-клиенте — да.
5. **Докачка архивов.** Обрыв при скачивании не теряет прогресс: сервер отвечает `Range` на эндпоинтах скачивания (архив, полный архив), клиент хранит недокачанный файл и продолжает с `Range`. Без экранов: строка хода уже есть. Охраняющий тест на продолжение с середины.
6. **Хранилище кругов на диске.** ~~Отдельный шаг.~~ **22.11 слито с функцией 9, владелец подтвердил («держать её в резерве, когда она реально будет нужна, и не делать её до тех пор»)** — вопрос владельца «это не то же самое, что кэш, который мы недавно добавляли?» по существу верен: снимки C97/C100 и медиа-кэш уже живут в IndexedDB постоянного профиля WebView2 и переживают перезапуски; потеря профиля не теряет данные круга (они на сервере), только прогрев кэша. Один перенос данных на диск делается внутри функции 9, если при встраивании перенос вообще понадобится; если не понадобится — закрыть как «сделано кэшем» без отдельного кода.
7. **Копии по расписанию.** Окно по расписанию сохраняет архив круга (или кругов) в выбранную папку — локальная копия без ручного «Скачать». Новый экран настроек: что копировать, куда, как часто — сначала кадры и приёмка, потом код.
8. **Папка новых фото.** Выбранная папка наблюдается; новые фото появляются в подготовке записи (зона приёма уже есть, ПК6). Экран настройки папки — кадры и приёмка. Наблюдатель — Win32 `ReadDirectoryChangesW`, без новых зависимостей.
9. **Вшитый интерфейс с переносом данных при смене origin.** Клиент встраивается в exe (`go:embed`), источник интерфейса перестаёт зависеть от версии сервера (desktop-reference называет роль источника «временной»); данные чтения переживают смену источника. **Включает прежнюю функцию 6** — при встраивании снимки и медиа-кэш переезжают из IndexedDB профиля в файлы под `%AppData%\Wynd\desktop` (мост), если перенос данных вообще понадобится. Самое крупное перестроение — последним, чтобы все мосты выше легли в него один раз. Порядок переноса данных — с владельцем при записи объёма шага.

Выполнение не обязано идти строго по номерам, но номер выше — раньше; каждый шаг закрывается фактом и коммитом, отклонённые варианты помечаются.
