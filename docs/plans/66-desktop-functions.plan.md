# 66 — Функции C66 «Wynd для компьютера»

**Тип:** остаток настольного клиента — девять отложенных функций окна.
**Статус:** план. Владелец 22.11.2026: «Берём все функции. Порядок выбирай сам.», затем «Кроме Мастерской внутри клиента». «Мастерская внутри клиента» из объёма исключена. Подробных ТЗ функций нет — объём каждой записан здесь по краткому названию плана 46 и устройству окна; при реализации владелец поправляет.
**Обновлено:** 2026-11-27. **Выпуск:** Настольный 0.5.7 — черновик 27.11, ждёт подписи (0.5.6 опубликован владельцем раньше и исправления моста не содержит); 27.11 переключение на вшитый интерфейс сделано, кадры ждут приёмки владельца.

## Правила этого плана

- Каждый законченный шаг — отдельный коммит; ворота (`scripts\test-desktop.bat`, при правках сервера полный `test.bat`) перед коммитом.
- Новые экраны и настройки — сначала настоящий рендер и приёмка владельца, потом включение (AGENTS.md 8). Механизмы без экранов — сразу.
- Окно берёт данные из собранного `dist\*.exe`; после правок Go — `scripts\build-desktop.bat` перед живой проверкой.
- Функции, меняющие web-клиент сервера, попадают в следующий серверный выпуск и в Windows-окно одновременно (совместимость — desktop-reference).

## Порядок работ

Выбран по зависимости и риску: сначала маленькие самостоятельные функции оболочки без новых экранов, затем мосты клиент↔оболочка, затем функции с новыми экранами, последним — самое крупное перестроение.

1. **Общая горячая клавиша.** Показать и сфокусировать окно из любого места Windows. Wails v3.1.0 умеет (`app.GlobalShortcut.Register`, Win32 `RegisterHotKey`) — без новых зависимостей. Комбинация по умолчанию — `Ctrl+Alt+W` (владелец может сменить при приёмке). Настройки в интерфейсе нет — значение не показывается на экране; смена комбинации — отдельное решение, если понадобится. **Сделано 22.11** (`cmd/wynd-desktop/main.go`, попутно `ErrorHandler` — ошибки Wails в журнал): ворота зелёные, регистрация без ошибок и диспетчеризация до показа спрятанного окна доказаны живьём ([протокол](../testing/desktop-hotkey-2026-11-22.md)); физическое нажатие — ручной пункт реестра §7 (инъекция ввода в среде проверки недоказуема).
2. **Системные уведомления.** Wails v3.1.0 API не имеет (только iOS) — «иной механизм» по записи плана 46: всплывающее уведомление Windows (toast) через AUMID-запись в реестре (`HKCU\Software\Classes\AppUserModelId\…`: имя и значок Wynd; сбрасывается удалением Wynd). Шаг 1 — механизм: мост `main.App.Notify` и показ toast, окно спрятано в трей или свёрнуто. **Шаг 1 сделан 22.11** (go-toast + `EnsureToastIdentity`, охраняющие тесты, ворота зелёные, платформа уведомлений приняла приложение — [протокол](../testing/desktop-notifications-2026-11-22.md)); показ баннера на экране — ручной пункт реестра §7 (снимок экрана в среде проверки недоступен). **Шаг 2, решение владельца 22.11 — оба потребителя.** «Вышла версия окна» — сделано 22.11: периодическая проверка в спрятанном окне (6 ч) + toast при скрытии, дедуп по версии ([протокол](../testing/desktop-notifications-2026-11-22.md)). **Новые записи в кругах** — **сделано 22.11**: новые правила не понадобились — сервер уже решает «кому можно» (`NotifyPrefAllows`, тишина, упоминания) в точках пуша, и тот же сигнал уходит живой рамкой `event: notify` в поток `/sync` адресата; клиент окна показывает toast через оболочку (`wynd:notify` → `App.Notify`), тексты как у push (тест паритета), пачка — один toast за 10 с ([протокол](../testing/desktop-notifications-2026-11-22.md)). Серверная рамка едет следующим серверным выпуском; живой прогон toast на настоящих записях — реестр §7. Без своего экрана настроек в этом плане (у клиента уже есть «уведомления по умолчанию» и настройки круга). **Слежение за Wails (владелец 22.11):** следить за нативным API уведомлений в Wails (v3.2 не вышла, nightly 11.2026) — при его появлении заменить `ShowToast` одной функцией, мост и правило «на виду — молча» не меняются. Баннеры уведомлений владелец подтвердил 22.11 («Баннеры в панели уведомлений Windows вижу») — ручной пункт §7 закрыт.
3. **Системное хранилище токенов.** Сессии переезжают из IndexedDB профиля WebView2 в системное хранилище Windows (Credential Manager, `wincred`) через мост оболочки. Прозрачно для интерфейса: миграция старых входов при первом запуске, хранилище профиля очищается от токенов. Без новых экранов. Список серверов и токены не смешиваются: в `servers.json` токенов нет и не будет (desktop-reference). **Сделано 22.11**: по учётной записи на origin (`Wynd.Desktop/<origin>`), ручки `/__secrets` на локальном порту под тем же CORS, откат в IndexedDB при отказе/старой оболочке, миграция при старте клиента с очисткой профиля; лимит блоба снят пробником (1024 — да, 4096 — отказ), живой roundtrip Credential Manager и ручек в запущенном окне ([протокол](../testing/desktop-secrets-2026-11-22.md)). Клиентская часть едет следующим web-выпуском.
4. **Приглашения из браузера.** Ссылка приглашения, открытая в браузере, предлагает продолжить в окне: схема `wynd:` (обработчик записывается в реестр при запуске/первой проверке), веб-клиент сервера показывает ссылку «Открыть в приложении» рядом с приглашением. Окно получает `wynd:invite/…` и открывает свой экран приглашения. Отдельная приёмка владельцем не нужна (нет нового экрана), но сценарий и текст ссылки в веб-клиенте — да. **Механизм сделан 22.11** (`wynd:open?url=<https-адрес>`; реестр HKCU, доставка первым/вторым запуском, свой сервер — сразу на экран приглашения, чужой — переключение интерфейса проверкой адреса, отказ — экран адреса со словами об отказе; оба случая доказаны живьём — [протокол](../testing/desktop-invite-scheme-2026-11-22.md)). **Осталось:** было — ссылка «Открыть в приложении» в веб-клиенте: строка-ссылка отклонена владельцем 23.11 («Плохо»), **кнопка `ghost` «Открыть в приложении» принята 23.11 («Принимаем»)** — кадр [invite-link-button.png](../testing/desktop-invite-scheme-2026-11-22/invite-link-button.png), снят с настоящего стенда (страница приглашения `/invite/<токен>`); показывается только в браузере Windows, в окне и на телефоне её нет (протокол). **Функция 4 закрыта целиком.**
5. **Докачка архивов.** Обрыв при скачивании не теряет прогресс: сервер отвечает `Range` на эндпоинтах скачивания (архив, полный архив), клиент хранит недокачанный файл и продолжает с `Range`. Без экранов: строка хода уже есть. Охраняющий тест на продолжение с середины. **Сделано 23.11 для архива участника:** `Range bytes=N-` (повторная детерминированная сборка + пропуск), ETag-версия (`круг|отсечка|max_seq|размер`) и `If-Range`, 416; одноразовая ссылка снимается по результату («целиком ушёл»), оборванная продлевается; отсечка фиксируется и на доклеенном хвосте; склейка частей побайтово равна полному файлу (тест и живой прогон curl — [протокол](../testing/archive-resume-2026-11-23.md)). **Полный архив — вне этого шага:** одноразовая ссылка и недетерминированное шифрование age; докачка потребовала бы кэша файла на сервере — отдельное решение. **24.11 оставлено как есть:** потоковый режим не докачивается, кандидат [C129](46-open-questions-and-debt.plan.md) — ждём красивое решение.
6. **Хранилище кругов на диске.** ~~Отдельный шаг.~~ **22.11 слито с функцией 9, владелец подтвердил («держать её в резерве, когда она реально будет нужна, и не делать её до тех пор»)** — вопрос владельца «это не то же самое, что кэш, который мы недавно добавляли?» по существу верен: снимки C97/C100 и медиа-кэш уже живут в IndexedDB постоянного профиля WebView2 и переживают перезапуски; потеря профиля не теряет данные круга (они на сервере), только прогрев кэша. Один перенос данных на диск делается внутри функции 9, если при встраивании перенос вообще понадобится; если не понадобится — закрыть как «сделано кэшем» без отдельного кода.
7. **Копии по расписанию.** Окно по расписанию сохраняет архив круга (или кругов) в выбранную папку — локальная копия без ручного «Скачать». Новый экран настроек: что копировать, куда, как часто — сначала кадры и приёмка, потом код. **Сделано 23.11:** экран «Копии по расписанию» (переключатель сверху, папка с «Открыть/Выбрать…», частота день/неделя/календарный месяц/свой интервал, хранение числом или сроком, «Последняя копия», «Сохранить») и строка входа в своей секции «Копии» в «Настройки → Приложение» — приняты владельцем; механизм в Go: `backups.json`, проверка срока раз в полчаса, сборка архива участника токеном из Credential Manager в папку `«<круг> ГГГГ-ММ-ДД.zip»`, ротация только своих файлов; окно можно закрыть ([протокол](../testing/desktop-backups-2026-11-23.md)). Живой прогон включения на настоящем сервере — реестр §7.
8. **Папка новых фото.** Выбранная папка наблюдается; новые фото появляются в подготовке записи (зона приёма уже есть, ПК6). Экран настройки папки — кадры и приёмка. Наблюдатель — Win32 `ReadDirectoryChangesW`, без новых зависимостей. **Отложена владельцем 23.11** («какая-то фигня получилась… подумаю, как её переосмыслить»): и экран, и кадр пользы не приняты, код из дерева убран, в коммиты не входил. Вернуться по слову владельца с его переосмыслением.
9. **Вшитый интерфейс с переносом данных при смене origin.** Клиент встраивается в exe (`go:embed`), источник интерфейса перестаёт зависеть от версии сервера (desktop-reference называет роль источника «временной»); данные чтения переживают смену источника. **Включает прежнюю функцию 6** — при встраивании снимки и медиа-кэш переезжают из IndexedDB профиля в файлы под `%AppData%\Wynd\desktop` (мост), если перенос данных вообще понадобится. Самое крупное перестроение — последним, чтобы все мосты выше легли в него один раз. Порядок переноса данных — с владельцем при записи объёма шага. **Подготовка сделана 23.11, переключение отложено владельцем** («нужно ещё получше стабилизировать интерфейс перед вшиванием»): клиент вшит в exe (exe 17,7 МБ), режим `--embedded-ui` отдаёт страницы из exe, серверные пути — через прокси, мост и SPA-фолбэк; по умолчанию — прежний интерфейс с сервера; перенос данных не нужен (origin окна прежний); тесты и живая проверка — [протокол](../testing/desktop-embedded-ui-2026-11-23.md). **Прежнее «осталось»** (стабилизация интерфейса, решение о роли «встроенный» как источнике по умолчанию, кадры и приёмка) закрыто 27.11 по слову владельца. Прежняя функция 6 остаётся резервом при этой работе. **27.11 переключение сделано по слову владельца** («Переходим в Настольном приложении на вшитый интерфейс»): вшитый — по умолчанию, отдельная настройка `source` в `servers.json`, «Встроенный» в списке источников, серверный режим — откат в «Настройки → Приложение → Интерфейс» или ключом `--server-ui`. Попутно найден и исправлен дефект вставки моста после C143: и вшитый, и серверный интерфейс могли открыться без `window.__wyndDesktop`; кадры и живая проверка — [протокол](../testing/desktop-embedded-default-2026-11-27.md). **Осталось по функции 9:** приёмка трёх кадров владельцем и живая проверка выпускной сборки 0.5.7 (черновик 27.11). Опубликованный 0.5.6 исправления моста не содержит, но сервер 0.58.1 его не ломает: имя моста в странице собрано из частей, а 0.5.7 несёт исправление вставки.

Выполнение не обязано идти строго по номерам, но номер выше — раньше; каждый шаг закрывается фактом и коммитом, отклонённые варианты помечаются.
