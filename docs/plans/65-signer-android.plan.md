# 65 — Подпись Android-выпуска в окне «Wynd Подпись»

**Тип:** инструмент разработчика («Wynd Подпись»), расширение плана 63.
**Статус:** основа и объём собраны 2026-11-19; кадры готовятся, реализация — после утверждения.
**Обновлено:** 2026-11-19.

## Зачем

APK выпусков Android собирает CI ([android.yaml](../../.github/workflows/android.yaml)): тег `android-v*` создаёт черновик с `wynd-android-unsigned.apk`, SHA-256 и attestation. Подпись и публикация сейчас — локальный сценарий `scripts/sign-android-release.ps1`; владелец 2026-11-19: «давай сначала добавим в Подпись поддержку подписи Android приложения». Окно «Wynd Подпись» должно подписывать Android-выпуск так же, как Мастерскую и Настольный: список выпусков → проверка → пароль → подпись и публикация.

## Принятые решения

- **Android — третья строка в таблице продуктов** `internal/signing` (план 63: «новая программа экосистемы — строка в products; окно своих списков программ не держит»). Имя в окне — «Wynd Android» (решение владельца 19.11: «приложение я бы называл в общем стиле Wynd Android», как Wynd Мастерская и Wynd Настольный; прежде было «Wynd для Android»), тег `android-vX.Y.Z`, файл выпуска `wynd-android.apk`, признак подписи — наличие `wynd-android.apk` в выпуске (у exe — `.sig`, у Android — подписанный APK сам по себе).
- **Проверка перед паролем** повторяет скрипт: сумма, attestation с проверкой workflow `android.yaml` и тега, пакет/версия из `aapt dump badging` (пакет `mixeme.wynd`, `versionName`/`versionCode` из тега, без `application-debuggable`), выравнивание `zipalign -c 4`, раздел версии из `android/whatsnew.md` тега (существующий `WhatsNew`), `releaseReady` из `android/version.properties` тега. Каждый отказ — `Problem`, подпись недоступна, как у exe.
- **Окно создаёт ключ Android само** (решение владельца 19.11: «Подпись должна уметь его создавать»): экран «Ключ Android» по образцу 12а — пароль с повтором (не короче 12 знаков), место хранения (по умолчанию `D:\Local\Git\myenv\wynd\wynd-android.p12`), `CreateKeystore` зовёт `keytool -genkeypair` из среды Android с теми же параметрами, что скрипт (PKCS12, RSA 3072, SHA256withRSA, срок 10000 дней, CN=Wynd Android, alias `wynd-android`); пароль keytool получает через stdin, не в аргументах. Создание доступно с экрана «Ключи» и с экрана Android-выпуска без ключа; скрипт `new-android-signing-key.ps1` остаётся запасным путём.
- **Подпись — apksigner** из среды Android (`D:\android-env`: JDK `jdk-17*`, build-tools `35.0.0`), keystore — постоянный ключ владельца (`D:\Local\Git\myenv\wynd\wynd-android.p12`, alias `wynd-android`); среда и keystore — настройки окна, значения по умолчанию как в скрипте. Пароль передаётся apksigner через переменную окружения процесса, не в аргументах и не через окно apksigner: в GUI консольного запроса нет. Неверный пароль — «Пароль не подошёл», как у exe (12в). Подпись с сертификатом `CN=Android Debug` запрещена.
- **Публикация** — как у exe: загружаем подписанный APK и `.sha256`; черновик публикуется с заголовком «Wynd Android X» и «Что нового» из тега. Блокировка первого выпуска сохраняется: без `releaseReady=true` в теге публикация невозможна — выпуск подписывается и остаётся черновиком, окно объясняет это словами из Go.
- **Ключи — отдельный экран окна** (решение владельца 2026-11-19, вместо строки ключа на экране выпусков): экран «Ключи подписи» показывает оба ключа — ключ подписи Wynd (экосистема Ed25519) и ключ Android (.p12, alias `wynd-android`) — с выбором другого файла у каждого. На экране выпусков вместо строки ключа — строка «Ключи подписи — настроить». Первый запуск (12а, создание ключа) не меняется; предупреждение о ненайденном файле ключа остаётся на экране выпусков.
- **Поле ключа Android — только там, где применяется** (решение владельца 13.11): путь к keystore не добавляется в общие формы. Основное место управления — экран «Ключи»; если при подписи Android-выпуска ключа нет, экран выпуска предлагает выбрать его на месте, не уводя со экрана.
- Этапы проверки приходят из Go (StepList), окно новых списков этапов не держит; тексты итога подписи для Android приходят из Go тем же путём.
- **Эталонный сертификат Android — в репозитории** (решение владельца 19.11, «Да»): открытая часть ключа Android экспортируется из keystore владельца один раз (`keytool -exportcert`, пароль вводит владелец) и коммитится в `android/` как эталон. Этап подписи сверяет сертификат подписанного APK с эталоном (сертификат читается из APK без пароля) и отказывает при несовпадении; запрет `CN=Android Debug` остаётся вторым барьером. Этапы проверки выпуска до пароля этим не меняются; текст итога подписи называет сверку с эталоном.
- **Имена строк ключей** (решение владельца 19.11): «Ключ программ на Windows» и «Ключ программ на Android» — однотипно с формулировкой «один ключ для программ на Windows, другой для программ на Android». Заголовок принятого 12а («Ключ подписи Wynd») к переименованию не отнесён — вопрос владельцу открыт.

## Отличия от exe-потока (для кадр-основы)

Экран выпуска (12в) остаётся тем же: этапы проверки, поле пароля, «Что нового — из выпуска», «Подписать». Отличается содержимое, всё оно приходит из Go:

- набор этапов: нет «Проверяем открытый ключ»; вместо него «Проверяем пакет и версию», «Проверяем выравнивание» и «Проверяем готовность к публикации» (последняя с пояснением «первый выпуск: публикация заблокирована» при `releaseReady=false`);
- черновик без `releaseReady=true`: кнопка «Подписать» (не «Подписать и опубликовать») и пояснение, что выпуск останется черновиком;
- итог (12г): «Файл wynd-android.apk выложен в выпуск/черновик», без слов о `.sig`;
- строка выпусков (12б) без изменений: Android-черновик приходит данными.
