# 56 — Ревизия плашек сервера

**Тип:** ревизия интерфейса и данных.
**Статус:** ревизия и макеты трёхстрочных плашек утверждены владельцем 2026-10-29 («Да»). В существующий `ServerRow` добавлен необязательный `detail` для их сборки; применение к продуктовым страницам и обновление прежних эталонов предстоит.
**Основание:** просьба владельца «Нужно провести ревизию всех плашек про сервер. Понять, что где нужно».

## Вывод

Одна визуальная основа `ServerRow` подходит разным местам, но состав сведений должен зависеть от решения человека. Имя и адрес опознают сервер; тип регистрации нужен при входе и регистрации; число кругов — при выборе места нового круга; место и квота — при переносе и оживлении. Постоянно показывать всё сразу не нужно.

Главная найденная путаница — смешение трёх независимых признаков: сервер ответил, сервер принимает новых, сервер выбран. Сейчас `ok` рисует одну галочку и для ответа, и для выбора; `warn` обслуживает ограничение регистрации. Текст должен объяснять смысл, а значок не должен обещать лишнее.

## Данные и границы ответственности

`ServerRow` сейчас получает свободную строку `subtitle`, вариант значка и `gdpr`; сам режимов регистрации не знает. Именно страницы собирают смысл по-разному. Одной заменой CSS расхождения не исправить.

- `/instance` даёт имя, версию, три режима регистрации и `allow_name_erasure`. Эти данные подходят для проверки сервера до входа.
- Ответ приглашения даёт имя, host и `allow_name_erasure`, но не версию и режим. Для карточки приглашения их не требуется выдумывать или делать дополнительный запрос только ради общей подписи.
- Сессия даёт адрес сервера, сохранённое имя и учётку; свежие свойства, состояние связи и число кругов — отдельные источники. Отсутствие ответа не равно false или нулю.
- `roomCaption` получает результат расчёта места для круга. Его нельзя заменять количеством свободных байтов, полученным Мастерской по SSH.
- Подпись, статус и действие следует собирать из данных одного и того же origin. При одинаковых именах адрес различает серверы. При отсутствии имени допустим адрес как заголовок без его повторения в подписи.
- GDPR в текущей модели — отображение `allow_name_erasure`, то есть возможности ухода со стиранием имени/фото. Ревизия не подтверждает этим значком какие-либо иные свойства сервера.

## Предлагаемое общее правило

1. **Основа любой карточки — имя и адрес на отдельных строках.** Дополнительные сведения — третьей строкой. Адрес не исчезает при добавлении режима, квоты или статуса. Если имени нет, не дублировать один адрес двумя строками.
2. **Тип регистрации показывать на входе, регистрации и добавлении сервера.** Формулировки: «открыт для новых», «только по приглашению», «регистрация закрыта». Для действующей учётки вход сохраняется при любом режиме. На входе ссылки — по уже утверждённому правилу 2/1/0.
3. **После входа показывать сведения для текущего действия.** Круги — при выборе места нового круга; квота/доступный объём — при приёме; почта и дата входа — под сервером в настройках. Тип регистрации туда автоматически не переносить.
4. **GDPR — у имени по действующему общему правилу.** Не трактовать неизвестный флаг как запрет. Отдельной новой плашки под каждый экран не создавать.
5. **Версию убрать из обычной регистрационной подписи**, сохранив в технических сведениях, панели и Мастерской. Это предложение меняет часть эталонов, поэтому пока не применено.
6. **Шеврон означает реальный выбор/переход, галочка в списке — выбор.** Доступность сервера и ограничения регистрации выражать недвусмысленным текстом; неизвестность и сбой не подменять бизнес-режимом.

Примеры содержания в предложенных макетах:

| Контекст | Имя | Адрес | Третья строка |
|---|---|---|---|
| Вход, open | Дом Ани | home.example.org | Открыт для новых |
| Вход, invite | Дом Ани | home.example.org | Только по приглашению |
| Вход, closed | Дом Ани | home.example.org | Регистрация закрыта |
| Приглашение в круг | Дом Ани | home.example.org | Нет |
| Место нового круга | Дом Ани | home.example.org | Ещё 5 ваших кругов |
| Приём, ограничение квотой | Дом Ани | home.example.org | Квота по умолчанию 3 ГБ |
| Прежний сервер | Дом Ани | home.example.org | Нет |

У известного, но недоступного сервера третья строка временно заменяется на «Сервер не отвечает»; при явной проверке — «Проверяем связь…». Плашка не краснеет и сама по себе не блокируется: возможность действия зависит от действия, а не от оформления карточки. Сохранённые имя и адрес не считаются свежим ответом. До первого успешного определения сервера — ошибка под полем, как в ПК4.

Значок GDPR добавляется к имени при подтверждённом свойстве, а не включается в текст подписи. Состав и внешний вид утверждены владельцем 2026-10-29 после исправления интервалов между строками.
