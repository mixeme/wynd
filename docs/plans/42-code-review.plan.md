## Итог

Проект архитектурно здоров: слои разделены правильно, хроника + проекция в одной транзакции, решения записаны, guard держит библиотеку UI. Масштабу (домашний инстанс) сложность в целом соответствует. Но рецензия нашла **пять дефектов уровня «стоп-кран»**, все подтверждены тестом или прямым чтением:

1. **HEAD не собирается.** `web/src/routes/circles/[id]/posts/[postId]/+page.svelte:66-67` — `commentAvatarUrls` объявлена дважды (коммит `c80e61f`, план 41 / 4.5). Это ошибка разбора: `svelte-check` даёт 6 ошибок, `vite build` невозможен. Релизы 0.6.6 и 0.6.7 заявлены как принятые, но собранного клиента у них нет (`dist/wynd.exe` датирован 19.09, до коммита).
2. **Аноним перенастраивает работающий инстанс.** `POST /admin/bootstrap` пишет `config.json`, SMTP-релей и шлёт письмо **до** проверки токена и флага `bootstrapped` (`internal/api/admin.go:57-84`). Подмена релея = перехват кодов входа = захват любой учётки. Подтверждено тестом.
3. **Исключённый участник продолжает писать.** `EditPost`, `DeletePost`, `EditComment`, `DeleteComment`, `DeleteReaction`, `SetPostCover` не проверяют статус членства. Исключённый стирает свою ветку вместе с чужими комментариями. Подтверждено тестом.
4. **Ежедневная рутина уничтожает данные и сама ломается.** Сборщик «сирот» не знает про аватары и скриншоты оплаты: аватар исчезает с сервера через 24 ч после загрузки; скриншот оплаты теряет файл, затем `DELETE` падает по FK, рутина выходит с ошибкой и **перестаёт выполнять все остальные шаги навсегда**. Подтверждено тестом.
5. **Процесс приёмки не работает.** Пункты 1 и сломанный `docker build` (`.dockerignore` исключает `web/src/`) прожили через несколько «принятых» релизов. CI нет, `scripts/test.bat` не собирает клиент.

Дальше по убыванию: SSRF через push-endpoint, необязательный STARTTLS, утечка в поиске мимо отрезков видимости, неотзываемый доступ «вышедшего с доступом», дубли записей из офлайн-очереди, не работающая инвалидация снимков, несортируемый формат времени. Полный перечень — раздел A, план — раздел C.

## Метод и степень уверенности

Каждая находка помечена:

- **[тест]** — воспроизведена пробным тестом через `go test -overlay` (репозиторий не менялся);
- **[код]** — прослежена рецензентом по коду лично, трактовка однозначна;
- **[чтение]** — найдена вспомогательным рецензентом по коду, выборочно не перепроверена; перед правкой исполнитель пишет падающий тест.

Прогоны: `go vet ./...` — чисто; `go test ./...` — зелёный; `svelte-check` — 6 ошибок (лог рецензента). `npm run build`, `check:ui`, `vitest` не запускались (машина на пределе памяти; сборка заведомо падает на п. 1).

**Две гипотезы проверкой опровергнуты и в план не вошли:** сбой FK-каскада при `DeleteCircle` и «FTS-триггеры не срабатывают на каскадном удалении» — тест показал `content_fts` = 0 строк после удаления круга.

**Не отрецензировано (рецензенты оборвались):** внутренности `internal/auth/pay.go` (874 строки), `internal/check`, `internal/archive` (экранирование HTML, имена в ZIP), `internal/backup` (восстановление), планировщик в `cmd/wynd/main.go`, `web/src/lib/media/`, service worker / PWA, доступность оверлеев `$ui`, правила `ui-guard.mjs`, экраны кроме ленты. Дорецензирование — волна 7.

## A. Рецензия по вопросам

### 1. Архитектура и структура

Хорошо: `cmd → api → {auth, chronicle, blob, mail, push} → store`, stdlib HTTP, один бинарник, клиентское ядро отделено от экранов, `$ui` под сторожем. Замечания:

- **ARC-1 [код]** Авторизация размазана по трём местам: middleware (`RequirePaidParticipant`), обработчик (`RequireSettings` зовётся из `api`), домен (`requireWriter` / `requireReader` / инлайн `mem.Status != StatusActive` / ничего). В `internal/chronicle` 40 вызовов `c.membership(...)`, и каждый сам решает, проверять ли статус. Прямое следствие — SEC-3.
- **ARC-2 [чтение]** Оплата живёт в пакете `auth` (`internal/auth/pay.go`, 874 строки — самый большой файл Go). К аутентификации относится только шлюз `RequirePaidParticipant`.
- **ARC-3 [код]** `push` импортирует `auth` ради одной константы `AdminSentinelEmail` (`internal/push/push.go:15,251`) — зависимость направлена не туда.
- **ARC-4 [чтение]** Обработчики заявок на квоту лежат в `internal/api/notify.go`; `TestNotifyPrefsMentionsAlwaysOn` — в `admin_test.go`. Файлы названы по волнам работ, а не по предмету (`admin_wave_f_test.go`).
- **ARC-5 [код]** Три разных реализации предиката «на блоб кто-то ссылается»: `internal/jobs/routine.go:85-93`, `internal/blob/serve.go:179-201`, `internal/auth/pay.go:~730`. Все три разные, ни одна не полная (см. BLB-1).
- **ARC-6 [код]** Путь модуля `gitea.mixdep.ru/mix/wynd`, а README, UI и systemd-юнит называют исходники `github.com/mixeme/wynd`. Это намеренно: рабочий remote — Gitea, GitHub — публичное зеркало, которое появится к релизу (см. LIC-1). Нигде не записано — записать в CONTRIBUTING.

### 2. Соответствие сложности масштабу

В целом соразмерно: нет брокеров, ORM, DI-контейнеров; SSE опросом; SQLite. Несоразмерно:

- **CPX-1 [код]** OpenAPI-контур: два yaml, генератор, 3 631 строка `schema-*.d.ts` — и **ни одного импорта** этих типов в `web/src`. В спеках нет ни одной схемы в `components`, у ~25 операций нет обязательного `responses`. Контур стоит трёх ручных правок на каждое изменение API и не даёт ничего.
- **CPX-2 [чтение]** `ui.css`: ~16 пар `.X` / `button.X` с продублированной вёрсткой и ~130 строк guard-кода (`BUTTON_LAYOUT_SPECS`, `checkButtonCssSync`), который существует только чтобы сторожить этот дубль. Один сброс `:where(button)` убирает и дубль, и сторожа.
- **CPX-3 [код]** `ui-guard.mjs` (589 строк) + хук Cursor — собственный линтер. Оправдан как замена ESLint, но правило «экран = только `$ui`, без своих компонентов и без `<style>`» выдавило вёрстку в **578 инлайн-`style=`** (206 разных значений) и 60–75 % экранного файла в `<script>`. Буква сторожа соблюдена, дух — нет.
- **CPX-4 [чтение]** CHANGELOG: 250 КБ, 125 версий на 116 коммитов, включая «0.6.7: сверка CHANGELOG — без расхождений». Это рабочий дневник, а не журнал изменений.

### 3. Качество кода

Сильные стороны: ошибки оборачиваются с контекстом, `defer tx.Rollback()` везде, атомарные `UPDATE … WHERE … + RowsAffected` для инвайтов и попыток кода, `crypto/rand`, `subtle.ConstantTimeCompare`, раздельные виды сессий, снимок ленты — 5 запросов на любое N. Слабые:

- **QLT-1 [код]** Проверки предусловий на `c.db` **до** `BeginTx`, запись — в `tx` (TOCTOU): `TransferOwnership` (`circle.go:188,198`), `forbidOwnerLeave → leave` (`member.go:201`), `Exclude` (`member.go:213`), `SetCircleName` (`members.go:196`), `DeleteCircle` (`members.go:268`), `auth.Bootstrap` (`admin.go:74-101`).
- **QLT-2 [чтение]** Все транзакции deferred (`BeginTx(ctx, nil)`): при повышении read→write SQLite отдаёт `SQLITE_BUSY` сразу, `busy_timeout` не помогает.
- **QLT-3 [код]** Многошаговые обработчики без общей транзакции: `DELETE post` — 4 шага (`journal.go:173-194`), `PATCH /circles/{id}` — до 5 транзакций с частичным применением (`circle_settings.go:60-90`), bootstrap — запись конфигурации до создания админа.
- **QLT-4 [код]** Гонка данных: `Server.PublicURL/Loopback`, `mail.Service.loopback` пишутся из обработчика без синхронизации.
- **QLT-5 [код]** Самодельный `itoa` с буфером `[4]byte` при импортированном `strconv` (`internal/api/respond.go:117-129`) — паника на числе длиннее 4 цифр.

### 6. Логические ошибки

Критические и высокие:

- **REL-1 [код]** HEAD не собирается — см. «Итог», п. 1.
- **SEC-1 [тест]** Bootstrap до проверки токена — см. «Итог», п. 2. Сопутствующие: **SEC-1a [код]** bootstrap не атомарен (сбой `SendTest` оставляет сохранённый битый релей при не созданном админе); **SEC-1b [код]** `UPDATE … SET bootstrapped = 1` без `WHERE bootstrapped = 0`, проверка вне транзакции.
- **SEC-3 [тест]** Исключённый/вышедший правит и удаляет своё — `internal/chronicle/content.go:142,213,568,616,655`, `media.go:290`.
- **BLB-1 [тест]** Сборщик сирот удаляет аватары (`identity_names.avatar_blob_id`) — `internal/jobs/routine.go:85-93`. Клиентский кэш IDB маскирует потерю.
- **BLB-2 [тест]** Скриншот оплаты: `os.Remove` (`routine.go:121`) стоит **до** `DELETE` (123), `DELETE` падает по FK `pay_requests.blob_id` → файл потерян, а `RunDailyRoutine` выходит на первой ошибке (`routine.go:49-81`) и больше не чистит сессии, коды, инвайты, загрузки.
- **CHR-1 [тест]** `Exclude` против `left_with_access` возвращает `invalid` (`member.go:243-245`): владелец не может отозвать чтение у вышедшего, кроме как удалив круг.
- **SRCH-1 [тест]** Поиск проверяет видимость по `created_at` строки FTS, а не записи-носителя (`internal/search/search.go:143-150`): новичок находит комментарий к записи, которой не видит, вместе с `thumb_blob_id` скрытой записи. То же для названия дня.
- **BLB-3 [тест]** Архивный purge не освобождает место: `purgePostBranch` (`internal/chronicle/archive.go:682-694`) удаляет `post_media`, но не `blob_refs`; `ReleaseBlobs` видит ссылку и выходит. Удалённое медиа остаётся на диске и отдаётся по прямому id.
- **BLB-4 [чтение]** `DeleteCircle` (`members.go:267-284`) — один `DELETE FROM circles`; `blob_refs` каскадом не снимаются, `ReleaseBlobs` не зовётся: файлы удалённого круга остаются навсегда.
- **SEC-4 [код]** SSRF: endpoint push-подписки не валидируется (`internal/push/push.go:101-107`), сервер шлёт на него POST через `http.DefaultClient` (без таймаута, с редиректами, `:58`). 404/410 удаляет подписку — однобитный оракул сканирования внутренней сети для любого участника.
- **SEC-5 [код]** STARTTLS необязателен (`internal/mail/mail.go:289-296`): посредник вырезает `250-STARTTLS`, и письмо с кодом входа уходит открытым текстом без предупреждения.
- **CLI-1 [код]** `invalidateSnapshots(origin, {circleId})` без `kind` ничего не удаляет (`web/src/lib/idb/db.ts:455-477`): префикс `origin:`, остаток `feed:<uuid>` сравнивается с `circleId`. ~25 вызовов. После исключения из круга, правки, удаления записи кэш круга остаётся и читается офлайн.
- **CLI-2 [чтение]** Офлайн-очередь без ключа идемпотентности (`web/src/lib/queue/queue.ts:156-179`, `internal/api/journal.go:13-18`): ответ на принятый POST не дошёл → повтор → дубль записи. Флаг `draining` — на вкладку: две вкладки сливают одну очередь дважды.
- **GUI-1 [код]** Дубли ключей `{#each … (part.kind + part.value)}` в пяти местах (лента :552, день :237, обсуждение :366, :455, :476): текст «@Аня и @Аня» даёт одинаковые ключи — `each_key_duplicate`.
- **API-1 [код]** Остановка сервера: `Shutdown` не отменяет открытые SSE → 10 с ожидания → `log.Fatalf` → `st.Close()` и `WaitNotify` не выполняются, systemd видит код 1 (`cmd/wynd/main.go:135-168`, `internal/api/sync.go:63-83`).

Средние:

- **TIME-1 [тест]** `xtime.Format` = `time.RFC3339Nano` обрезает хвостовые нули → строки разной ширины, которые SQLite сравнивает лексикографически: вступление `10:00:00.25Z`, запись `10:00:00.2501Z` — как строка запись «раньше». 30 сравнений и 30 `ORDER BY` по меткам, включая отрезки видимости. Срабатывает только внутри одной секунды.
- **API-2 [код]** SSE проверяет сессию один раз: заблокированная учётка и истёкшая подписка получают события до разрыва соединения.
- **API-3 [чтение]** SSE без heartbeat: прокси с таймаутом 300 с рвёт тихий поток; клиент (`sync.ts:55-79`) читает без таймаута и при тихой смерти TCP считает себя подключённым — «приложение перестаёт обновляться до перезагрузки». Ретрай фиксированный 5 с без backoff; парсер берёт первую строку `data:` и ломается на CRLF.
- **API-4 [код]** Фоновые задачи шлют письма со старым `public_url` до рестарта (`main.go:102,113`); остановка не ждёт идущую рутину (`:104-116`).
- **API-5 [код]** `config.json` пишется `os.WriteFile` без temp+rename; `WYND_PUBLIC_URL` молча перекрывает сохранённое панелью; `NormalizePublicURL` принимает любую строку с `://`.
- **API-6 [код]** Бандлы `_app/immutable/*` отдаются с `no-cache` и без валидатора (`web/serve.go:58-61`); `/_app/`, `/fonts/` отдают листинг каталога; неизвестные `/api/*` отвечают `text/plain`, клиентский `res.json()` падает.
- **API-7 [код]** Отдача блоба: нет `Cache-Control` (блоб неизменяем по id), `Content-Disposition` собран конкатенацией — кавычка или кириллица в имени дают невалидный заголовок (`internal/api/blobs.go:143-148`); нет Range.
- **AUTH-1 [чтение]** Расход кода входа — `DELETE` без проверки `RowsAffected` (`codes.go:269-271`): два параллельных `Verify` получают две сессии.
- **AUTH-2 [чтение]** Перебор адресов не бьёт по лимиту: `checkRate` стоит после `accountByEmail` (`codes.go:73-92`).
- **AUTH-3** Смена пароля админа не отзывает админские сессии **[чтение]**; клиент не зовёт `POST /admin/logout` **[код]** (`session.svelte.ts:138-140`) — «выход» оставляет серверный токен живым.

- **UPL-2 [чтение]** Квота: check-then-act, открытые сессии не учитываются — N параллельных загрузок превышают потолок в N раз. Квота круга считает только `post_media` (без аватаров и обложек).
- **SRCH-2 [тест]** Запрос из нескольких слов — одна фраза: «море дача» не находит «море и лето на даче». NUL в запросе → 500.
- **SRCH-3 [чтение]** Триггеры дня адресуют FTS по `(circle_id, entry_date)`: удаление/правка старой версии названия затирает актуальную; purge `day_titles` уносит живой день из поиска.
- **CHR-2 [чтение]** `DaysSnapshot` — 3N+1 запросов без `LIMIT` (`snapshot.go:287-339`). **CHR-3 [чтение]** Запись №2001 теряется молча: ни флага, ни лога.
- **MIG-1 [чтение]** `migrate.go:36-58` применяет пропущенную в середине миграцию поверх более новой схемы. Миграция 0009 молча превращает осознанные 100 ГБ в 80 % диска.
- **GUI-2 [чтение]** `font:inherit` после `font-size`/`font-weight` в семи блоках `button.X` (`ui.css:293` и др.) стирает жирность и кегль: главная кнопка 400 вместо 600.
- **GUI-3 [код]** `onMount(async …)` в `routes/search/+page.svelte:83` возвращает промис — очистка `popstate` не выполняется никогда.
- **QUE-1 [чтение]** Очередь: недоступный сервер A блокирует отправку на сервер B (общий FIFO с `break`); зависший `uploading` после падения вкладки нельзя ни удалить, ни править; нет счётчика попыток и backoff; 401 переводит элемент в вечный `failed`; 404 на сессию загрузки не пересоздаёт её.

### 13. Неучтённые граничные случаи

Два события в одной секунде (TIME-1); две вкладки и одна очередь (CLI-2); два сервера на одном хосте с разными портами — коллизия префиксов ключей снимков (`https://a` и `https://a:8443`, `db.ts:461`); обрыв между файлом и строкой БД при завершении загрузки (UPL-1); параллельные чанки одной сессии; круг на 2001 запись; одиночный круг — владелец не может выйти, единственный путь ведёт через `DeleteCircle` (BLB-4); soft-deleted учётка остаётся строкой `memberships`; IDB недоступна (приватный режим) — ядро падает до перезагрузки; IDB v3 при открытой старой вкладке; повторные упоминания в тексте (GUI-1); `cursor=abc` в sync → полный реплей вместо 400; `kind=foo` у инвайта молча становится `single`; `public_url` вида `ftp://x`; имя файла с кавычкой; запрос поиска с управляющими символами.

## B. Закрытые развилки

Не переоткрывать. Прежние закрытые решения (SQLite, stdlib HTTP, SSE опросом, без пагинации ленты, без E2E/Playwright, без SPDX в каждом файле, без перенумерации миграций, Bits UI только в `$ui`, макеты не синхронизировать с `VERSION`) остаются в силе.

| Тема | Решение |
|---|---|
| **CI** | Прежнее «CI — не в этой очереди» **снято**: без него два релиза вышли несобираемыми, а Docker сломан десятки версий. Один файл `.gitea/workflows/ci.yaml` (remote — Gitea): `go vet`, `go test ./...`, `npm ci`, `check`, `check:ui`, `test`, `build`, `go build`, `docker build`. Не GitHub Actions. |
| **Ворота релиза** | `scripts/test.bat` дополняется `npm run build` и `go build ./cmd/wynd`. Коммит, меняющий `VERSION`, допустим только после зелёного `test.bat` на том же дереве. Запись «проверено» в CHANGELOG без прогона запрещена. |
| **Bootstrap** | Порядок: токен и `bootstrapped` (`ConfirmBootstrapToken`) → длина пароля → `mail.Probe` несохранённого релея (сбой = 502, ничего не записано) → одна транзакция `Auth.Bootstrap` + `SaveConfig` → `WritePublicURL` → `SendTest`. Сбой проверочного письма bootstrap **не** откатывает: пишется в `smtp_last_error`, ответ 200 с `mail_sent:false`. `UPDATE … WHERE bootstrapped = 0` + `RowsAffected`. |
| **Право писать** | Править и удалять своё (запись, комментарий, реакцию, обложку) может только тот, кто сейчас может писать. Вышедший с доступом и исключённый — `forbidden`.
