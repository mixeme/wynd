## A8. Push со второго сервера — закрыта как устаревшая (2026-11-16)

Риск из чтения кода остаётся описанным здесь для истории: одна PushSubscription создаётся с VAPID-ключом первого сервера и передаётся остальным (и так же `getSubscription()` переиспользуется между сессиями в `web/src/lib/push/push.ts`); каждый сервер подписывает своим ключом, и подписка может принимать уведомления только от первого.

**Закрыто 2026-11-16 по решению владельца («в pwa мы же отказались от добавления нескольких серверов»):** в браузере и установленном веб-приложении второй сервер отключён с 0.43.7 (`ADD_SERVER_IN_BROWSER` — только окно с мостом), а хранилище сессий у каждого адреса своё — сценарий «две сессии одного клиента, одна подписка» у PWA не возникает, телефонная проверка не нужна. Остаточный риск живёт только там, где несколько серверов возможно: **окно для компьютера** (мост разрешает добавление; поддерживает ли WebView2 Web Push — не проверено, нативные уведомления окна отложены в C66) и **приложение Android** — [план 50, уведомления](../plans/50-android-wrapper.plan.md): «подписки по серверам» и ключ каждой подписки там и проверять. C69 решён окончательно 23.11.2026 («Оставляем многосерверность только настольному и мобильному приложению. В PWA её не будет»): в браузере A8 не вернётся; остаточный риск остаётся в окне и в Android, где многосерверность ещё не сделана — задача C123 плана 46. stack.html многосерверность в браузере не описывает — так и остаётся.

Связано с C69 и [настольным клиентом — C66](46-open-questions-and-debt.plan.md), а нативные уведомления Android — с [планом 50](50-android-wrapper.plan.md). При нескольких серверах браузерная проверка сначала должна иметь рабочий путь запросов; тест с отключённой CORS-защитой не доказывает готовность продукта.
