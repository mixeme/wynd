## A3. Установка одной командой — отложено

Решение владельца 2026-10-11: главный путь установки — Мастерская; путь одной командой прорабатывать позже. install.sh пока запускается из клона и сам бинарник не скачивает. Готовый образ и сборка Мастерской не закрывают задачу выпуска серверного бинарника.

- [ ] install.sh без клона: скачать бинарник своей архитектуры из выпуска, сверить сумму, выполнить установку. Сохранить пути --from-source и --bin.
- [ ] Сборка серверных бинарников и SHA256SUMS в CI по тегу, публикация на GitHub.
- [ ] После реализации обновить README и описания установки в stack.html/wynd.html. До этого не обещать готовую установку одной командой.

## A8. Push со второго сервера — не проверено

В чтении кода найден риск: одна PushSubscription создаётся с VAPID-ключом первого сервера и передаётся остальным; каждый сервер подписывает своим ключом. Подписка может принимать уведомления только от первого. Это предположение по устройству кода, не результат живой проверки.

- [ ] Телефон, два сервера с разными VAPID-ключами, сессии на обоих: проверить доставку со второго и ответ push-сервиса. Запасной путь — реальный endpoint и другой ключ.
- [ ] Если проблема подтвердится, выбрать решение: отдельные регистрации service worker и подписки либо нативные уведомления оболочки. Уточнить обработку 403; не считать всякий 403 истечением подписки без проверки причины.
- [ ] Обновить stack.html по проверенному поведению нескольких серверов и ограничениям Android без Google-сервисов.

Связано с C69 и [настольным клиентом](55-desktop-client.plan.md), а нативные уведомления Android — с [планом 50](50-android-wrapper.plan.md). При нескольких серверах браузерная проверка сначала должна иметь рабочий путь запросов; тест с отключённой CORS-защитой не доказывает готовность продукта.
