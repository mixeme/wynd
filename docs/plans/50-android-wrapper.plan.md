# 50 — Обёртка для Android

**Тип:** новая возможность (клиент)
**Статус:** задумка, решения приняты в разговоре 2026-10-08; код не начат, инструменты сборки не поставлены
**Дата:** 2026-10-08
**Срез:** `main`, версия 0.28.2.

Приложение для Android, которое открывает тот же интерфейс Wynd и добавляет то, чего браузер странице не даёт.

---

## Почему

Wynd на телефоне — веб-приложение, установленное из браузера. Часть его бед чинится со страницы, часть — нет: это ограничения браузера, и они копятся. Обёртка снимает их по одному.

Это меняет прежнее решение. В [stack.html](../stack.html) стояло «Нативных клиентов не будет», в [плане 46](46-open-questions-and-debt.plan.md) оболочка была пунктом B2 «не в 0.x», UnifiedPush — B1 «если Web Push не хватит». TWA по-прежнему не берём: это тот же Chrome и ограничений не снимает (план 43, A5).

## Что решено (2026-10-08)

- **Цель — снять ограничения браузера.** В перспективе все, этапами по сложности; сразу всё не делаем.
- **Интерфейс не вшит — открывается с сервера по адресу.** Многосерверность в настоящей работе понадобится нескоро, сначала нужна аудитория; зато новая версия сервера сразу и есть новая версия интерфейса — удобно для разработки. Обёртка пересобирается, только когда меняется нативная часть.
- **Уведомления — UnifiedPush; путь через Google тоже предусмотреть.**
- Веб-приложение из браузера остаётся и работает как сейчас: обёртка — второй способ, не замена.

## Что из этого следует

- **Первый запуск спрашивает сервер:** адрес, ссылка-приглашение или QR. Открыть приглашение из браузера сразу в приложении для произвольного своего сервера нельзя — такие привязки Android берёт из сборки, под заранее известные домены.
- **Мост — только выбранному серверу.** Нативные возможности страница получает через мост; он отвечает адресу, который выбрал человек, а не любой открытой странице. Чужие ссылки уходят в браузер.
- **Интерфейс и обёртка бывают разных версий.** Интерфейс спрашивает у моста, что тот умеет, и без ответа работает как в браузере. Ни одна возможность моста не обязательна для страницы.
- **Без сети — как сейчас:** сохранённая оболочка и очередь держатся на сервис-воркере и IndexedDB, в WebView они есть.
- **Переход на вшитый интерфейс позже** сменит адрес, с которого живёт страница: вход и локальные данные на телефоне не перенесутся. Цена принята.

## Этапы

По возрастанию сложности. Каждый проверяется на телефоне (realme 8) и выходит отдельно.

- [ ] **1. Оболочка.** Окно с интерфейсом выбранного сервера. Выбор сервера при первом запуске; системная «Назад»; выбор файлов, камера и микрофон (разрешения); загрузки и «открыть в…»; цвет строки состояния и системных кнопок по теме Wynd, а не системы; значок из сборки. Снимает само: вылет после простоя и пустой значок в Firefox (план 46, «Запуск после фона»), цвет полос (C23), сжатие видео из галереи — в WebView есть WebCodecs. Клавиатуру и панель автозаполнения проверить заново: поведение своё.
- [ ] **2. Место со снимков** (C22). Свой выбор фото с разрешением `ACCESS_MEDIA_LOCATION`: координаты доходят до страницы. Сейчас Android их обнуляет для браузера.
- [ ] **3. «Поделиться» в Wynd.** Фото, видео и текст из галереи и других приложений — в новую запись.
- [ ] **4. Уведомления.** UnifiedPush; запасной путь через Google. В WebView нет Push API — подписка и показ нативные. Затрагивает сервер. Заодно — уведомления от нескольких серверов (план 43: одна подписка браузера привязана к ключу одного сервера).
- [ ] **5. Дозагрузка в фоне** (B2). Нативная очередь: видео сжимается и уходит, когда окно закрыто. Затрагивает очередь клиента и, возможно, сессии загрузки на сервере. Тогда же — убрать съём кадра на сервере (план 49: `internal/poster`, ffmpeg в образе).

Этап 1 без уведомлений не заменяет установленное из браузера приложение — он для проверки рядом с ним. Заменой обёртка становится после этапа 4.

## Уведомления: что известно и что проверить

По памяти, **не сверено со спецификацией** (unifiedpush.org 2026-10-08 не открылся):

- сообщение UnifiedPush шифруется как веб-уведомление (RFC 8291), сервер шлёт его на адрес, который дал телефон, — значит, `internal/push` в основном годится как есть;
- у UnifiedPush есть запасной режим: нет приложения-доставщика — приложение получает сигнал через Google (FCM) само. Для сервера Wynd это тот же адрес.

Что тянет путь через Google:

- проект Firebase владельца приложения;
- **общий шлюз**: Google принимает сообщения только с ключом владельца приложения, раздавать ключ серверам нельзя — запасные уведомления всех серверов идут через один шлюз, который держит владелец приложения. Единственная общая точка в схеме; текста записей через неё нет — только сигнал, как сейчас;
- **две сборки**: библиотека Google закрытая, F-Droid такую не примет — «с Google» и «без».

У кого стоит доставщик UnifiedPush (например, ntfy), тот от шлюза и Google не зависит.

## Не решено

- **Распространение.** Предложено: APK-файлом с сайта, сборку без Google держать готовой к F-Droid. RuStore и Google Play — отдельно. Ответа нет.
- **Имя пакета** (потом не сменить) и **ключ подписи**: хранит владелец, не в репозитории; потерян — обновления не поставить.
- **На чём писать оболочку.** Предложено: Kotlin без Capacitor — нативного кода немного, а мост свой. Не обсуждалось.
- **Наименьшая версия Android.**
- **Где лежит код:** в этом репозитории (`android/`) или отдельно.
- **Макеты** новых экранов (выбор сервера, разрешения) — в `docs/visual/screens.html` до кода.

## Что нужно для работы

- На компьютере разработки: JDK 17 или новее (стоит 11), Android SDK — инструменты командной строки, платформа, сборочные средства; несколько гигабайт, ставить на диск D. Сборке нужна сеть до Google и Maven.
- Телефон по USB с отладкой: ставить сборку и читать системный журнал (`adb logcat`). Тот же журнал покажет, кто закрывает окно Firefox при вылете, — и без обёртки. Эмулятор — запасной путь, особенностей realme не покажет.
