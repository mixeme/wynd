# 50 — Обёртка для Android

**Тип:** новая возможность, клиент.
**Статус:** решения и начальные кадры утверждены; среда установлена, отладочный Java/WebView-каркас собран и запущен на OPPO CPH1931. Этап 1 начат, не завершён.
**Обновлено:** 2026-11-16.

## Принятые решения

- Цель — поэтапно снять ограничения браузера. Веб-приложение остаётся самостоятельным способом пользоваться Wynd.
- Сначала интерфейс с выбранного сервера. **Уточнение владельца 2026-11-16:** причиной отсрочки вшитого интерфейса была доставка частых обновлений. Следующий шаг — канал APK через GitHub Releases; после проверки канала переходить к вшитому интерфейсу, не ждать окончания частых правок. Смена origin и отсутствие автоматического переноса локальных данных приняты ранее; перенос при переходе отдельно проверить.
- Java без Capacitor и других каркасов; небольшой файл Kotlin допустим, если этого потребует библиотека. Код — android/ в этом репозитории.
- Пакет mixeme.wynd. Ключ подписи хранит владелец вне репозитория; потеря ключа мешает обновлению того же приложения.
- Минимальная версия Android — самая низкая, которую допускают необходимые библиотеки. Точное значение определить при первой сборке; повышение — когда поддержка старых версий начнёт мешать.
- Сначала APK, магазины позже; сборку без Google держать пригодной для F-Droid.
- Уведомления — UnifiedPush с предусмотренным путём через Google. WebView не даёт Push API, подписка и показ будут нативными.
- Нативный мост доступен только выбранному источнику интерфейса; чужие ссылки открываются в браузере. Страница спрашивает возможности моста и без него работает как в браузере.
- Источник интерфейса видит входы на все серверы и может менять код страницы. Этот довод за вшитый интерфейс не отменил начальное решение загружать с сервера.
- Поиски TWA завершены: это не способ снять ограничения. Повторный выбор Wails — после перехода к вшитому интерфейсу.

## Утверждённые кадры

[Единый эталон](../visual/screens.html): 7.41–7.47, утверждены 2026-10-12 (при прежней нумерации 7.17–7.22 и 7.28).

- Первый запуск: адрес, приглашение, QR камерой и из фото. Привязки произвольных серверных ссылок к приложению заранее нет.
- Сервер ответил — видны имя и адрес. Ошибка проверки одна для опечатки, сети, выключенного сервера и чужого сайта.
- Известный сервер недоступен и сохранённого интерфейса нет — отдельное состояние. При сохранённом приложении без сети открывается оно и очередь.
- Разрешения спрашивает система в момент действия; собственного экрана разрешений на старте нет.
- В настройках «Что нового» и «Сменить сервер» — строки. Подтверждение объясняет смену источника приложения, а не перенос кругов; старые входы и неотправленное остаются при прежнем origin.
- Плашки при реализации привести к утверждённым правилам [плашки сервера](../reference/ui-components.md#плашка-сервера).

## Этапы

### Приоритет 2026-11-16 — канал обновления APK

**Отложено владельцем 2026-11-16:** «Вопрос обновления откладываем. Делай остальное».
Работа над выпуском, установкой обновлений и обращением в Play Защиту остановлена.
Продолжается этап 1 оболочки с интерфейсом сервера: файлы, камера/микрофон и
системные разрешения. Вшивание до подтверждения автообновления по-прежнему отложено.

- GitHub Releases, отдельные теги `android-vX.Y.Z`; черновики и prerelease не предлагать.
- **72 часа сохраняются для всех программ.** Владелец отдельно потребовал переключатель «Скачивать сразу» для разработки: он обходит только выдержку времени, а не подпись, имя пакета или проверку версии. Доступен в debug и при включённых системных настройках разработчика телефона, по умолчанию выключен; так разработчик может получать обычные подписанные APK того же канала. Без режима разработчика обход не применяется, даже если значение сохранилось в настройках.
- Подпись APK — постоянный Android-ключ владельца вне GitHub/репозитория; debug-ключ только для прогона двух отладочных версий. Системное подтверждение установки сохраняется.
- Проверить цепочку: выпуск → загрузка → проверка APK → системная установка → новый номер и сохранённые локальные данные. Локальный тестовый выпуск не объявлять проверкой публичного GitHub-канала.
- После рабочего канала APK — вшитый интерфейс; это новый порядок работы, а не уже выполненный перенос. **Уточнение владельца 2026-11-16:** пока автообновление не подтверждено, интерфейс не вшивать. Начатые незакоммиченные заготовки вшивания удалены; текущая оболочка продолжает открывать интерфейс сервера.

Реализация канала подготовлена: нативные проверки APK, протокол возможностей,
существующие строки/плашка Wynd UI, CI unsigned и локальная подпись владельца.
Постоянный ключ создан и хранится в `myenv/wynd`; реальный CI, attestation,
подпись и обратная загрузка подписанного APK из черновика GitHub проверены.
Локальный прогон на OPPO прошёл девять проверок до установщика. Владелец разрешил
отправить тестовый APK в Play Защиту; Google вернул POTENTIALLY_UNWANTED /
generic_malware и заблокировал установку, конкретная причина ещё не установлена.
Предупреждение не обходилось. Публичный канал,
сохранение данных после обновления и окончательная вёрстка ещё не приняты.
[Проверки и оставшаяся работа](../testing/android-updates-2026-11-16.md).

### Оболочка и возможности

Каждый этап отдельно проверяется на realme 8. Этап 1 без нативных уведомлений — проба рядом с PWA, замена становится возможна после этапа 4.

Подготовка 2026-11-16: `android/`, официальный Gradle wrapper, отдельный debug-пакет,
прямой origin, системная «Назад», тесты границ origin, строгий lint и сборка APK.
На подключённом OPPO проверены существующий экран входа, переход к приглашению
и назад, отмена чужого главного документа и сохранение маркера localStorage
после полного перезапуска. Учтены решения настольных планов 55, 61, 62;
веб-интерфейс в первом каркасе не менялся. Начальный debug-адрес задаётся при сборке;
смена после открытия описана ниже.
[Протокол, реальный снимок и оставшиеся проверки](../testing/android-scaffold-2026-11-16.md).

Выбор после открытия интерфейса реализован по кадрам 7.41, 7.42, 7.44,
7.46 и 7.47: адрес, приглашение, существующий QR-сканер и QR из картинки.
Проверка публичной карточки идёт нативно, без cookies/входов WebView и redirects;
HTTPS обязателен вне debug loopback. Выбор сохраняется только после проверки
и «Дальше». Новый WebView привязан к новому origin, история не переносится;
старые входы и очередь остаются при прежнем адресе. Незавершённый Share или
сохранение файла блокирует смену. Системная «Назад» закрывает диалог до перехода
между документами. На OPPO проверены два тестовых сервера, холодный запуск,
разделение localStorage, возврат к старому origin и маршрут приглашения.
[Протокол и границы проверки](../testing/android-interface-2026-11-16.md).

Первый запуск без выбранного сервера и состояние недоступности выбранного
источника ещё не выполнены. Локальных экранов в APK нет: требуется ответ на
ранее заданное уточнение о минимальных стартовых экранах при запрете вшивания.
Весь интерфейс этого шага, включая настройки и выбор, приходит с сервера.
Утверждение прежних кадров сохраняется; новая самостоятельная вёрстка не объявлена принятой.

Продолжение этапа 1 после отсрочки обновлений: WebChromeClient для системного
выбора файлов и runtime-доступа камеры/микрофона. На OPPO проверены отказ,
выдача разрешений, живой поток, декодируемые записи и чтение своего файла.
Внешняя фотосъёмка через HTML capture не включена: в прогоне на OPPO не подтверждён
возврат callback после пересоздания процесса; нужен отдельный устойчивый сценарий.
[Протокол](../testing/android-media-2026-11-16.md).

Цвет системных полос связан с действующей темой Wynd и существующим цветом
шапки круга. На OPPO Android 10 проверены светлая/тёмная темы, снимки до/после
при одинаковом viewport и полный перезапуск. Содержимое экрана не сдвинулось.
На Android 15+ фон рисуется под прозрачными системными insets; эта ветка
и старые API 21–25 физически пока не проверены.
[Протокол](../testing/android-system-bars-2026-11-16.md).

Добавлено сохранение через ACTION_CREATE_DOCUMENT: Blob частями по 32 KiB,
ссылки архивов — native HTTP-потоком в выбранный документ. Уведомление готового
файла предлагает «Открыть в…» по отдельному нажатию. Доступ к общему хранилищу
не запрашивается; Android 13+ спрашивает уведомления после действия сохранения.
На OPPO проверены собственный бинарный образец, отмена и общедоступный файл
тестового сервера. Возобновления после гибели процесса пока нет; это этап 5.
[Протокол](../testing/android-exports-2026-11-16.md).

Этап 2 реализован в коде: существующий выбор фото записи и кнопка «Файл»
запрашивают исходный снимок через MediaStore и ACCESS_MEDIA_LOCATION. На Android
10–11 для этого также требуется READ_EXTERNAL_STORAGE; запрос появляется только
после выбора локальной фотографии. При отказе файл и дата доступны, координаты
не подставляются. Текущее положение телефона не запрашивается. На OPPO Android 10
проверены неизменность JPEG, дата/GPS, отказ и повторный выбор; исходная проблема
с вырезанными координатами на realme здесь не воспроизвелась. Поэтому этап
остаётся открытым до проверки на realme и других версиях Android.
[Протокол и ограничения](../testing/android-photo-location-2026-11-16.md).

Этап 3 реализован: Android SEND/SEND_MULTIPLE принимает текст, фотографии и
видео в закрытый входящий набор. После входа человек выбирает доступный для
записи круг и попадает в существующий редактор; публикация остаётся отдельным
действием. Открытая запись не заменяется новым Share. До передачи в редактор
набор переживает перезапуск; отмена удаляет временные копии. Это не нативная
очередь этапа 5. На OPPO проверены обмен с отдельным тестовым приложением и
настоящий Svelte-редактор на синтетической сессии. Новый вариант выбора круга
собран из FormLayout/Hint/CircleRow/TextButton; вёрстка владельцем ещё не принята.
[Протокол и реальные снимки](../testing/android-share-2026-11-16.md).

Поправка владельца: подпись «Отменить получение» и её левое выравнивание
отклонены. Вместо них — «Отмена» по центру штатным `Hint centered`.
Остальной экран сохраняется; принятие всей новой вёрстки этим не подразумевается.
[Проверка исправления](../testing/android-share-cancel-2026-11-16.md).

Рекомендация Chrome/Vivaldi на улочке скрывается при наличии настоящего
Android-моста Wynd; настройки веб-версии не меняются. На OPPO осмотрен настоящий
кадр без этой плашки; остальные компоненты улочки сохранены.

## Кандидаты в этапы (решение владельца 2026-11-12)

- **Чтение архива круга.** Владелец: «Когда будет нативное приложение под Android, можно подумать в нём над функцией чтения архива.» Речь о C73: распакованный читаемый архив из файлового менеджера на Android не показывает вложенные файлы (`content://` не даёт странице подгружать соседние файлы), и чинить компоновку архива не стали. В приложении это решается иначе: оно само открывает файл архива и достаёт медиа из него. Не этап, пока не начата работа по плану; встаёт после этапа 1.

## Что проверить при реализации

- [ ] До первой сборки сверить действующие требования Android/Google к имени пакета и установке не из магазина; определиться с ключом подписи владельца.
- [x] При первой сборке назвать минимальную версию по библиотекам: API 21; канал обновлений использует AndroidX WebKit 1.14.0 с тем же минимумом. Новые библиотеки могут потребовать пересмотра минимума; проверка самого API 21 ещё не выполнена.
- [ ] При реализации соответствующих этапов учесть уведомления до каналов Android 8, доступ к месту со снимков с Android 10 и разрешение уведомлений с Android 13.
- [ ] У UnifiedPush-коннектора проверить создание p256dh/auth и расшифровку: в прежней сверке библиотечная реализация не подтверждена.
- [ ] При первой сборке этапа 4 проверить, нужен ли собственный проект Firebase. В исходном примере не было Google-плагина и ключей, но это не доказательство отсутствия требования.
- [ ] Нарисовать состояние устаревшей нативной оболочки; обновление интерфейса с сервера не обновляет мост.
- [ ] Магазины и схема публикации — после работоспособного APK.

Сведения для этапа 4, сверенные 2026-10-10 по UnifiedPush AND_3.0.0: RFC 8291, тело 1–4096 байт, открытое сообщение до 3993, endpoint RFC 8030 до 1000 байт. Приложение получает исходные bytesMessage и расшифровывает их; серверный internal/push уже использует Web Push. Для каждого сервера свои VAPID, token и подписка.

По сверке embedded_fcm_distributor 2026-10-15 Wynd с VAPID не требует отдельного шлюза. Библиотека заявляла отсутствие закрытых Google-компонентов. Эти сведения не заменяют проверку при сборке; открытый вопрос Firebase сохранён выше. С доставщиком UnifiedPush, например ntfy, путь через Google не обязателен.

## Среда разработки

Android CI расширен на push в main и pull request при изменениях Android,
значков или workflow. Actions хранит unsigned APK с суммой и отчёты; сборка
не получает прав записи в репозиторий. Черновик и attestation остаются
отдельной задачей только для Android-тега. Публичный выпуск не выполняется.
[Проверка CI](../testing/android-ci-2026-11-16.md).

Условия владельца от 2026-10-14: ставить, когда начнётся разработка оболочки, всё в D:\android-env.

2026-11-16: по поручению владельца установлены официальные Platform Tools 37.0.1;
USB-отладка подтверждена, ADB выполняет команды на OPPO CPH1931 (Android 10, API 29).
[Протокол и повторное подключение](../testing/android-usb-setup-2026-11-16.md).

По следующему поручению владельца установлены переносные Liberica JDK 17.0.21.0.3+5,
SDK 36, Build Tools 35.0.0, Command-line Tools 19.0 и Gradle 8.13.
[Версии, источники и проверка архивов](../testing/android-environment-2026-11-16.md).

- Liberica JDK 17 и Android SDK — распакованные архивы, без установщиков. Старый JDK не менять.
- Gradle и Android-кэши тоже в этой папке; JAVA_HOME, PATH, GRADLE_USER_HOME и ANDROID_USER_HOME задавать только процессу сборки.
- Вне папки допустимы временные файлы и отладка USB на телефоне. Драйвер — только если Windows не узнает устройство, с отдельным согласованием.
- Нужна сеть до Google и Maven. Перед началом заново проверить установленную среду: запись о JDK 11 от 2026-10-14 не является текущим осмотром.
- Проверять сборку на телефоне по USB и читать adb logcat. Эмулятор не заменяет особенности realme.
