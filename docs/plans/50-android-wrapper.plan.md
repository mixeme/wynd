# 50 — Обёртка для Android

**Тип:** новая возможность, клиент.
**Статус:** решения и начальные кадры утверждены; код не начат. Инструменты устанавливаются при переходе к разработке по условиям владельца от 2026-10-14.
**Обновлено:** 2026-10-29.

## Принятые решения

- Цель — поэтапно снять ограничения браузера. Веб-приложение остаётся самостоятельным способом пользоваться Wynd.
- Сначала интерфейс с выбранного сервера. Позже интерфейс вшивается, когда частые правки закончатся (решение 2026-10-28); смена origin и отсутствие автоматического переноса локальных данных приняты.
- Java без Capacitor и других каркасов; небольшой файл Kotlin допустим, если этого потребует библиотека. Код — android/ в этом репозитории.
- Пакет mixeme.wynd. Ключ подписи хранит владелец вне репозитория; потеря ключа мешает обновлению того же приложения.
- Минимальная версия Android — самая низкая, которую допускают необходимые библиотеки. Точное значение определить при первой сборке; повышение — когда поддержка старых версий начнёт мешать.
- Сначала APK, магазины позже; сборку без Google держать пригодной для F-Droid.
- Уведомления — UnifiedPush с предусмотренным путём через Google. WebView не даёт Push API, подписка и показ будут нативными.
- Нативный мост доступен только выбранному источнику интерфейса; чужие ссылки открываются в браузере. Страница спрашивает возможности моста и без него работает как в браузере.
- Источник интерфейса видит входы на все серверы и может менять код страницы. Этот довод за вшитый интерфейс не отменил начальное решение загружать с сервера.
- Поиски TWA завершены: это не способ снять ограничения. Повторный выбор Wails — после перехода к вшитому интерфейсу.

## Утверждённые кадры

[Единый эталон](../visual/screens.html): 7.41–7.47, утверждены 2026-10-12 (при прежней нумерации 7.17–7.22 и 7.28).

- Первый запуск: адрес, приглашение, QR камерой и из фото. Привязки произвольных серверных ссылок к приложению заранее нет.
- Сервер ответил — видны имя и адрес. Ошибка проверки одна для опечатки, сети, выключенного сервера и чужого сайта.
- Известный сервер недоступен и сохранённого интерфейса нет — отдельное состояние. При сохранённом приложении без сети открывается оно и очередь.
- Разрешения спрашивает система в момент действия; собственного экрана разрешений на старте нет.
- В настройках «Что нового» и «Сменить сервер» — строки. Подтверждение объясняет смену источника приложения, а не перенос кругов; старые входы и неотправленное остаются при прежнем origin.
- Плашки при реализации привести к утверждённым правилам [плана 56](56-server-cards.plan.md).

## Этапы

Каждый этап отдельно проверяется на realme 8. Этап 1 без нативных уведомлений — проба рядом с PWA, замена становится возможна после этапа 4.

- [ ] **1. Оболочка.** Выбор сервера, системная «Назад», файлы, камера/микрофон и разрешения, скачивания и «открыть в…», цвет системных полос по теме Wynd, значок из сборки. Проверить клавиатуру, автозаполнение, запуск после простоя, сохранённый интерфейс и сжатие видео в выбранном WebView.
- [ ] **2. Место со снимков (C22).** Свой выбор фото с ACCESS_MEDIA_LOCATION. На realme Android отдавал браузеру GPS с 0/0 даже через «Файл»; NaN уже отсеян с 0.19.3, вернуть исходные координаты со страницы нельзя. На iPhone поведение другое, эта оболочка его не меняет. Ручная точка/подсказка не выбраны, «отметить, где я сейчас» отвергнуто владельцем.
- [ ] **3. «Поделиться» в Wynd.** Фото, видео и текст из галереи/других приложений в новую запись.
- [ ] **4. Уведомления.** UnifiedPush и запасной Google-путь, подписки по серверам и нативный показ. Проверить собственные ключи каждой подписки; связанный браузерный риск — A8 плана 43.
- [ ] **5. Нативная очередь.** Сжатие и дозагрузка после закрытия окна, возобновление сессий. После этого убрать временную съёмку кадра видео на сервере (C48).
  - Файл .wynd помнить с постоянным правом доступа: после ответа о месте и после обрыва продолжать без повторного выбора файла (решение 2026-10-17).

## Что проверить при реализации

- [ ] До первой сборки сверить действующие требования Android/Google к имени пакета и установке не из магазина; определиться с ключом подписи владельца.
- [ ] При первой сборке назвать минимальную версию по библиотекам. Учесть уведомления до каналов Android 8, доступ к месту со снимков с Android 10 и разрешение уведомлений с Android 13.
- [ ] У UnifiedPush-коннектора проверить создание p256dh/auth и расшифровку: в прежней сверке библиотечная реализация не подтверждена.
- [ ] При первой сборке этапа 4 проверить, нужен ли собственный проект Firebase. В исходном примере не было Google-плагина и ключей, но это не доказательство отсутствия требования.
- [ ] Нарисовать состояние устаревшей нативной оболочки; обновление интерфейса с сервера не обновляет мост.
- [ ] Магазины и схема публикации — после работоспособного APK.

Сведения для этапа 4, сверенные 2026-10-10 по UnifiedPush AND_3.0.0: RFC 8291, тело 1–4096 байт, открытое сообщение до 3993, endpoint RFC 8030 до 1000 байт. Приложение получает исходные bytesMessage и расшифровывает их; серверный internal/push уже использует Web Push. Для каждого сервера свои VAPID, token и подписка.

По сверке embedded_fcm_distributor 2026-10-15 Wynd с VAPID не требует отдельного шлюза. Библиотека заявляла отсутствие закрытых Google-компонентов. Эти сведения не заменяют проверку при сборке; открытый вопрос Firebase сохранён выше. С доставщиком UnifiedPush, например ntfy, путь через Google не обязателен.

## Среда разработки

Условия владельца от 2026-10-14: ставить, когда начнётся разработка оболочки, всё в D:\android-env.

- Liberica JDK 17 и Android SDK — распакованные архивы, без установщиков. Старый JDK не менять.
- Gradle и Android-кэши тоже в этой папке; JAVA_HOME, PATH, GRADLE_USER_HOME и ANDROID_USER_HOME задавать только процессу сборки.
- Вне папки допустимы временные файлы и отладка USB на телефоне. Драйвер — только если Windows не узнает устройство, с отдельным согласованием.
- Нужна сеть до Google и Maven. Перед началом заново проверить установленную среду: запись о JDK 11 от 2026-10-14 не является текущим осмотром.
- Проверять сборку на телефоне по USB и читать adb logcat. Эмулятор не заменяет особенности realme.
