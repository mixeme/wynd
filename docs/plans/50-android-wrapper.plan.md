# 50 — Обёртка для Android

**Тип:** новая возможность, клиент.
**Статус:** решения и начальные кадры утверждены; среда установлена, отладочный Java/WebView-каркас собран и запущен на OPPO CPH1931. Этап 1 начат, не завершён.
**Обновлено:** 2026-11-19.

## Принятые решения

- Цель — поэтапно снять ограничения браузера. Веб-приложение остаётся самостоятельным способом пользоваться Wynd.
- Сначала интерфейс с выбранного сервера. **Уточнение владельца 2026-11-16:** причиной отсрочки вшитого интерфейса была доставка частых обновлений. Следующий шаг — канал APK через GitHub Releases; после проверки канала переходить к вшитому интерфейсу, не ждать окончания частых правок. Смена origin и отсутствие автоматического переноса локальных данных приняты ранее; перенос при переходе отдельно проверить.
- **Разрешённое исключение 2026-11-16:** на вопрос о локальной стартовой части владелец ответил «Да, только стартовые экраны». В APK разрешены адрес сервера, приглашение/QR и недоступность сервера; лента, редактор, настройки и остальной интерфейс остаются серверными. Это разрешение на объём вшивания, а не утверждение новых экранов: сначала адаптация существующего сценария Настольного, настоящий рендер и предварительное утверждение владельцем, затем включение в APK. Отклонённый вариант `22fc7366` этим ответом не восстановлен.
- Java без Capacitor и других каркасов; небольшой файл Kotlin допустим, если этого потребует библиотека. Код — android/ в этом репозитории.
- Пакет mixeme.wynd. Ключ подписи хранит владелец вне репозитория; потеря ключа мешает обновлению того же приложения.
- Минимальная версия Android — самая низкая, которую допускают необходимые библиотеки. Точное значение определить при первой сборке; повышение — когда поддержка старых версий начнёт мешать.
- Сначала APK, магазины позже; сборку без Google держать пригодной для F-Droid.
- Уведомления — UnifiedPush с предусмотренным путём через Google. WebView не даёт Push API, подписка и показ будут нативными.
- Нативный мост доступен только выбранному источнику интерфейса; чужие ссылки открываются в браузере. Страница спрашивает возможности моста и без него работает как в браузере.
- Источник интерфейса видит входы на все серверы и может менять код страницы. Этот довод за вшитый интерфейс не отменил начальное решение загружать с сервера.
- Поиски TWA завершены: это не способ снять ограничения. Повторный выбор Wails — после перехода к вшитому интерфейсу.

## Утверждённые кадры

[Исторические кадры](../visual/screens.html): 7.41–7.47, утверждены 2026-10-12 (при прежней нумерации 7.17–7.22 и 7.28). Они не разрешают включать новый экран без предварительного утверждения актуального рендера. Для сценария источника сначала учитывать более позднее решение Настольного — [план 62](62-desktop-servers-settings.plan.md), вариант Б, принят 2026-11-10.

- Первый запуск: адрес, приглашение, QR камерой и из фото. Привязки произвольных серверных ссылок к приложению заранее нет.
- Сервер ответил — видны имя и адрес. Ошибка проверки одна для опечатки, сети, выключенного сервера и чужого сайта.
- Известный сервер недоступен и сохранённого интерфейса нет — отдельное состояние. При сохранённом приложении без сети открывается оно и очередь.
- Разрешения спрашивает система в момент действия; собственного экрана разрешений на старте нет.
- В настройках «Что нового» и «Сменить сервер» — строки. Подтверждение объясняет смену источника приложения, а не перенос кругов; старые входы и неотправленное остаются при прежнем origin.
- Плашки при реализации привести к утверждённым правилам [плашки сервера](../reference/ui-components.md#плашка-сервера).

**Отложено владельцем 2026-11-16:** «Вопрос обновления откладываем. Делай остальное».

по-прежнему отложено; для минимальной стартовой части отдельно разрешено исключение
выше, с обязательным предварительным утверждением экранов.

- GitHub Releases, отдельные теги `android-vX.Y.Z`; черновики и prerelease не предлагать.
- **72 часа сохраняются для всех программ.** Владелец отдельно потребовал переключатель «Скачивать сразу» для разработки: он обходит только выдержку времени, а не подпись, имя пакета или проверку версии. Доступен в debug и при включённых системных настройках разработчика телефона, по умолчанию выключен; так разработчик может получать обычные подписанные APK того же канала. Без режима разработчика обход не применяется, даже если значение сохранилось в настройках.
- Подпись APK — постоянный Android-ключ владельца вне GitHub/репозитория; debug-ключ только для прогона двух отладочных версий. Системное подтверждение установки сохраняется.
- Проверить цепочку: выпуск → загрузка → проверка APK → системная установка → новый номер и сохранённые локальные данные. Локальный тестовый выпуск не объявлять проверкой публичного GitHub-канала.
- После рабочего канала APK — вшитый интерфейс; это новый порядок работы, а не уже выполненный перенос. **Уточнение владельца 2026-11-16:** пока автообновление не подтверждено, интерфейс не вшивать. Начатые незакоммиченные заготовки вшивания удалены; текущая оболочка продолжает открывать интерфейс сервера.

Реализация канала подготовлена: нативные проверки APK, протокол возможностей,
существующие строки/плашка Wynd UI, CI unsigned и локальная подпись владельца.
Постоянный ключ создан и хранится в `myenv/wynd`; реальный CI, attestation,
подпись и обратная загрузка подписанного APK из черновика GitHub проверены.

Предупреждение не обходилось. Публичный канал,

## Кандидаты в этапы (решение владельца 2026-11-12)

- **Чтение архива круга.** Владелец: «Когда будет нативное приложение под Android, можно подумать в нём над функцией чтения архива.» Речь о C73: распакованный читаемый архив из файлового менеджера на Android не показывает вложенные файлы (`content://` не даёт странице подгружать соседние файлы), и чинить компоновку архива не стали. В приложении это решается иначе: оно само открывает файл архива и достаёт медиа из него. Не этап, пока не начата работа по плану; встаёт после этапа 1.

Сведения для этапа 4, сверенные 2026-10-10 по UnifiedPush AND_3.0.0: RFC 8291, тело 1–4096 байт, открытое сообщение до 3993, endpoint RFC 8030 до 1000 байт. ## Среда разработки

Android CI расширен на push в main и pull request при изменениях Android,
значков или workflow. Actions хранит unsigned APK с суммой и отчёты; сборка
не получает прав записи в репозиторий. Черновик и attestation остаются
отдельной задачей только для Android-тега. Публичный выпуск не выполняется.
