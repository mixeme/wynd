# 55 — Wynd для компьютера

**Тип:** новая возможность (клиент), C66 плана 46.
**Статус:** техническая проверка и проект плана; кадры не утверждены, продуктовый код не начат.
**Дата:** 2026-10-29.

## Принятые решения

- Windows — первая система, затем Linux. macOS — при появлении спроса.
- Wails v2.16.0, как у Мастерской. Трей, системные уведомления и работа при закрытом окне — после выхода Wails v3 из беты.
- Сначала интерфейс с выбранного сервера, позже — вшитый, когда правки станут реже.
- Несколько серверов, своё окно и рамка, запуск вместе с системой, перетаскивание файлов. Перечень второго эшелона сохраняется в C66 плана 46.

Решения владельца от 2026-10-28, полный разговор и формулировки — в [плане 46, C66](46-open-questions-and-debt.plan.md).

| Проверка | Результат |
|---|---|
| Несколько серверов, 2026-10-28 | Прямой запрос из WebView2 к другому серверу блокируется CORS; через Go-прокси работает. Код — [первый образец](46-c66-prototype.go.txt). |

| Регистрация команды автозапуска | Временное значение `WyndC66Probe_20261029` в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` записано и прочитано обратно. Команда содержит полный путь в кавычках и аргумент `--from-startup`. |
| Команда запуска вне папки программы | Сохранённая команда запустила exe из папки с пробелами; рабочая папка — `C:\Windows\System32`, специальных переменных C66 нет, журнал подтвердил загрузку страницы и готовность окна. |
| Уборка проверки | Запущенный сценарием процесс остановлен, пробная запись Run удалена в `finally`; отсутствие записи проверено отдельно. |
| Настоящий вход в Windows | **Не проверен:** сессия владельца не завершалась. Проверка команды не выдаётся за проверку входа. |
| Настоящее перетаскивание | **Ждёт проверки:** окно подготовлено, два тестовых файла созданы. Инструмент Windows читает дерево доступности, но снимок окна падает по таймауту; ввод — `coordinate input geometry is unavailable`. |

Механизм Run сверён с [документацией Microsoft](https://learn.microsoft.com/en-us/windows/win32/setupapi/run-and-runonce-registry-keys): запись действует при входе пользователя, Windows может отложить её запуск. Наличие записи не доказывает немедленный старт при входе.

## Образец для оставшейся проверки

Исходники вне продуктовой сборки: [окно и журнал](46-c66-desktop-probe.go.txt), [сценарий автозапуска](46-c66-startup-probe.ps1.txt). Они собираются в отдельной временной папке из уже установленных зависимостей корневых `go.mod` и `go.sum`. `go build -tags desktop,production -ldflags '-H windowsgui'` прошёл.

Окно одновременно проверяет обычный `DataTransfer.files` и получение путей через Wails (`DragAndDrop.EnableFileDrop`, `runtime.OnFileDrop` на стороне Go и JavaScript). Для каждого файла записываются имя, размер и SHA-256. Файлы никуда не загружаются. Настоящий DOM drop должен иметь `isTrusted=true`; программно созданное событие не считается живой проверкой.

Тестовые файлы по 22 байта:

- `c66-one.txt`: `e965f84d10eb8950fb884293b9d002110c7ce3628f71ff24a21d76d935997826`.
- `c66-two.txt`: `3937ce7632f9d41eca73dcace88053b4c8dcdc96f9fa3dcadb9238001522e85a`.

После переноса одного, затем обоих файлов сверить журнал DOM и Go. Проверить, что страница не заменилась просмотром файла. Отдельно проверить файл из обычного диалога выбора. После проверки остановить только собственный процесс образца.

## Предлагаемый порядок реализации

1. Закончить проверку перетаскивания; согласовать кадры первого запуска, рамки, добавления сервера, автозапуска и приёма файлов. Интерфейс внутри окна — существующий клиент и его адаптивная раскладка, без отдельного редизайна.
2. Оболочка Windows: выбор первого сервера, собственная рамка, профиль WebView2 в постоянном каталоге приложения, сохранение адреса сервера. Первый запуск без сети и недоступный сервер — отдельные состояния кадров.
3. Несколько серверов: один адаптер адресов для API и потока событий, Go-прокси только к явно добавленным серверам. Проверить авторизацию, редиректы, отмену запросов, переподключение событий и сохранение сессий после перезапуска. Не переносить отключение CORS из диагностического браузера.
4. Приём файлов в открытый круг: использовать существующую подготовку медиа, очередь и правила вложений. Выбрать минимальный мост по результату проверки. Не давать странице произвольное чтение локальных путей или запуск команд; только явно выбранные или перенесённые пользователем файлы.
5. Автозапуск Windows: настройка с явным выбором человека и возможностью выключить, точный путь exe в кавычках; не полагаться на текущую папку. В v2 открывается окно. Запуск сразу в трей отложен вместе с треем. После обновления и переноса exe проверять актуальность записи.
6. Сборка и выпуск: своя версия оболочки, совместимость моста со старым интерфейсом, подпись и самообновление по согласованному примеру Мастерской. До распространения — проход безопасности по прокси, нативному мосту и обновлению.

Это предложение по разбиению работ. Новые кадры и дополнительные продуктовые решения утверждаются владельцем до реализации. Пробел Wynd UI, если обнаружится, оформляется отдельным планом.

## Отложено

- Трей, число новых на значке, уведомления, жизнь и дозагрузка при закрытом окне — Wails v3 после беты.
- Вшитый интерфейс и перенос локальных данных при смене origin — отдельный этап.
- Хранилище кругов на диске, системное хранилище токенов, приглашения из браузера, докачка архивов, копии по расписанию, папка новых фото, общая горячая клавиша и Мастерская внутри клиента — второй эшелон C66.
