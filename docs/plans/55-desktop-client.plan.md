# 55 — Wynd для компьютера

**Тип:** новая возможность (клиент), C66 плана 46.
**Статус:** предварительные проверки механизмов пройдены; план согласуется по кадрам: ПК1–ПК4 и правило ссылок утверждены; ПК5 на согласовании, продуктовый код не начат.
**Дата:** 2026-10-29.

## Принятые решения

- Windows — первая система, затем Linux. macOS — при появлении спроса.
- Wails v2.16.0, как у Мастерской. Трей, системные уведомления и работа при закрытом окне — после выхода Wails v3 из беты.
- Сначала интерфейс с выбранного сервера, позже — вшитый, когда правки станут реже.
- Несколько серверов, своё окно и рамка, запуск вместе с системой, перетаскивание файлов. Перечень второго эшелона сохраняется в C66 плана 46.

Решения владельца от 2026-10-28, полный разговор и формулировки — в [плане 46, C66](46-open-questions-and-debt.plan.md).

## Что проверено до кадров

| Проверка | Результат |
|---|---|
| Несколько серверов, 2026-10-28 | Прямой запрос из WebView2 к другому серверу блокируется CORS; через Go-прокси работает. Код — [первый образец](46-c66-prototype.go.txt). |
| Окно Wails v2, 2026-10-29 | Изолированный production-бинарник запускается, открывает `http://wails.localhost` в защищённом контексте. Профиль WebView2 отдельный, данные Wynd не используются. |
| Регистрация команды автозапуска | Временное значение `WyndC66Probe_20261029` в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` записано и прочитано обратно. Команда содержит полный путь в кавычках и аргумент `--from-startup`. |
| Команда запуска вне папки программы | Сохранённая команда запустила exe из папки с пробелами; рабочая папка — `C:\Windows\System32`, специальных переменных C66 нет, журнал подтвердил загрузку страницы и готовность окна. |
| Уборка проверки | Запущенный сценарием процесс остановлен, пробная запись Run удалена в `finally`; отсутствие записи проверено отдельно. |
| Настоящий вход в Windows | **Не проверен:** сессия владельца не завершалась. Проверка команды не выдаётся за проверку входа. |
| Получение файлов в WebView2 | **Пройдено автоматически через CDP:** одиночный и множественный drop, `isTrusted=true`, содержимое и SHA-256 совпадают в JavaScript и Go; проверены три нативных callback и обычное поле выбора файла. |
| Мышью из Проводника | **Не проверено:** инструмент Windows читает дерево доступности, но снимок окна падает по таймауту; ввод — `coordinate input geometry is unavailable`. CDP обходит Windows-ввод, а не проверяет его. |

Механизм Run сверён с [документацией Microsoft](https://learn.microsoft.com/en-us/windows/win32/setupapi/run-and-runonce-registry-keys): запись действует при входе пользователя, Windows может отложить её запуск. Наличие записи не доказывает немедленный старт при входе.

## Образец для оставшейся проверки

Исходники вне продуктовой сборки: [окно и журнал](46-c66-desktop-probe.go.txt), [сценарий автозапуска](46-c66-startup-probe.ps1.txt). Они собираются в отдельной временной папке из уже установленных зависимостей корневых `go.mod` и `go.sum`. `go build -tags desktop,production -ldflags '-H windowsgui'` прошёл.

Окно одновременно проверяет обычный `DataTransfer.files` и получение путей через Wails (`DragAndDrop.EnableFileDrop`, `runtime.OnFileDrop` на стороне Go и JavaScript). Для каждого файла записываются имя, размер и SHA-256. Файлы никуда не загружаются. Настоящий DOM drop должен иметь `isTrusted=true`; программно созданное событие не считается живой проверкой.

Тестовые файлы по 23 байта:

- `c66-one.txt`: `e965f84d10eb8950fb884293b9d002110c7ce3628f71ff24a21d76d935997826`.
- `c66-two.txt`: `3937ce7632f9d41eca73dcace88053b4c8dcdc96f9fa3dcadb9238001522e85a`.

**Автоматическая проверка 2026-10-29:** [сценарий CDP](46-c66-cdp-check.mjs.txt) отправил `Input.dispatchDragEvent` с настоящими путями тестовых файлов, сначала один, затем два. WebView2 создал доверенные drop-события; Go получил три пути через штатный Wails callback. Имя, размер и SHA-256 сверены автоматически между источником, JavaScript и Go. Поле выбора проверено через `DOM.setFileInputFiles` после сброса значения, как в клиентском FilePicker. Страница осталась на `http://wails.localhost/`.

Для диагностического порта понадобилась временная копия Wails: загрузчик go-webview2 очищает `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS`. В `setupChromium` копии добавлена только строка `if port := os.Getenv("C66_DEBUG_PORT"); port != "" { chromium.AdditionalBrowserArgs = append(chromium.AdditionalBrowserArgs, "--remote-debugging-port="+port) }`; временный модуль подключён через `replace`, файлы установленной зависимости не менялись. Политика CORS и обработчики drop не менялись. Номер порта лежит в `cdp.port`, журнал — `cdp-drop.jsonl`, файлы — в `fixtures/` рядом со сценарием. Команда: `node cdp-check.mjs`.

Снимок WebView2 и JSON с результатами сохранены локально в `dev/c66-evidence/`; сценарий — в репозитории. Собственный процесс остановлен, диагностический порт закрыт. Проверка мышью из Проводника остаётся ручным пунктом перед выпуском.

## Предлагаемый порядок реализации

1. Согласовать кадры первого запуска, рамки, добавления сервера, автозапуска и приёма файлов. Интерфейс внутри окна — существующий клиент и его адаптивная раскладка, без отдельного редизайна.
2. Оболочка Windows: выбор первого сервера, собственная рамка, профиль WebView2 в постоянном каталоге приложения, сохранение адреса сервера. Первый запуск без сети и недоступный сервер — отдельные состояния кадров.
3. Несколько серверов: один адаптер адресов для API и потока событий, Go-прокси только к явно добавленным серверам. Проверить авторизацию, редиректы, отмену запросов, переподключение событий и сохранение сессий после перезапуска. Не переносить отключение CORS из диагностического браузера.
4. Приём файлов в открытый круг: использовать существующую подготовку медиа, очередь и правила вложений. Выбрать минимальный мост по результату проверки. Не давать странице произвольное чтение локальных путей или запуск команд; только явно выбранные или перенесённые пользователем файлы.
5. Автозапуск Windows: настройка с явным выбором человека и возможностью выключить, точный путь exe в кавычках; не полагаться на текущую папку. В v2 открывается окно. Запуск сразу в трей отложен вместе с треем. После обновления и переноса exe проверять актуальность записи.
6. Сборка и выпуск: своя версия оболочки, совместимость моста со старым интерфейсом, подпись и самообновление по согласованному примеру Мастерской. До распространения — проход безопасности по прокси, нативному мосту и обновлению.

Это предложение по разбиению работ. Новые кадры и дополнительные продуктовые решения утверждаются владельцем до реализации. Пробел Wynd UI, если обнаружится, оформляется отдельным планом.

## Отложено

- Трей, число новых на значке, уведомления, жизнь и дозагрузка при закрытом окне — Wails v3 после беты.
- Вшитый интерфейс и перенос локальных данных при смене origin — отдельный этап.
- Хранилище кругов на диске, системное хранилище токенов, приглашения из браузера, докачка архивов, копии по расписанию, папка новых фото, общая горячая клавиша и Мастерская внутри клиента — второй эшелон C66.

## Кадры

**ПК1 — первый запуск, утверждён владельцем 2026-10-29 («Да»).** [Макет](../visual/desktop.html), [снимок](../visual/desktop-first-launch.png), [исходник сборки из компонентов Wynd UI](55-desktop-first-frame.svelte.txt).

Первый запуск спрашивает адрес сервера или ссылку-приглашение одним полем. Пустое поле — «Дальше» недоступно; непустое — доступно. Проверка адреса и ответ сервера происходят на следующем шаге, а не объявляются успешными по одному вводу. Приглашение определяет свой сервер. Вход по почте и коду остаётся существующим входом выбранного сервера.

Рамка — существующий `$ui/workshop/TitleBar`; знак — `$ui/Mark`; поле, подпись и кнопка — `$ui/forms`, без новых компонентов библиотеки. Шрифты, цвета и стили взяты из действующего клиента. Предложенный размер окна в кадре — 1000 × 660; форма в колонке 390 px. Это предложение первого кадра, а не решение о всех размерах окна.

Собрано отдельным Vite/Svelte-стендом в `dev/desktop-mockup`, зависимости уже установленные (`web/node_modules`), новые пакеты не ставились. В браузере проверены загрузка шрифтов и доступность кнопки при вводе/очистке поля. `desktop.html` — самостоятельный снимок отрендеренных компонентов с их CSS; шрифты подключены из `web/static/fonts`. Библиотека и продуктовый клиент не менялись.

**ПК2 — вход на выбранный сервер, утверждён владельцем 2026-10-29 («Кадр да»).** [Макет](../visual/desktop-login.html), [снимок](../visual/desktop-login.png), [исходник](55-desktop-login-frame.svelte.txt).

После адреса из ПК1 — существующий вход выбранного сервера (кадр 1.6): логотип, имя и адрес сервера, почта, «Пришлём код для входа. Пароля нет.», «Получить код». Показан открытый сервер «Дом Ани» (`home.example.org`); только в этом случае есть «Регистрация без приглашения». «У меня есть приглашение» остаётся отдельным входом. При ссылке-приглашении в ПК1 — соответствующий экран приглашения, а не потеря ссылки на обычном входе.

Добавлена только стрелка возврата к адресу сервера в оболочке. Рамка и размер окна те же, элементы входа — существующие `Logo`, `ServerRow`, `Label`, `Input`, `Hint`, `Button`, `TextButton`, `IconButton`. Сервер и почта в кадре — примеры; запросы на сервер и отправка писем в макете не выполняются. Проверены загрузка шрифтов, карточка и тип поля email.

**Уточнение ПК2 по замечанию владельца, 2026-10-29 — учтено в утверждённом кадре.** Первое добавление отдельной строки «Регистрация открыта» было неверным: владелец указал, что существующая карточка выглядит иначе. Исправлено по эталону `screens.html`: для открытого сервера — кадр **1.7**, подпись `home.example.org · открыт для новых · Wynd 0.43.8` и галочка; для приглашений — кадр **1.9**, подпись «только по приглашению» и `!`. Использован тот же `ServerRow`, ручной перенос строки и собственные формулировки открытого/пригласительного режима убраны. Версия в кадре — пример данных сервера. Отдельного эталонного варианта карточки закрытого сервера в этих кадрах нет; его текст пока остаётся предложением.

**Правило зависимости ссылок утверждено владельцем 2026-10-29 («Правило да»):**

| Регистрация | «Регистрация без приглашения» | «У меня есть приглашение» | Вход существующего участника |
|---|---|---|---|
| Открыта | Есть | Есть | Есть |
| По приглашению | Нет | Есть | Есть |
| Закрыта | Нет | Нет | Есть |

Правило зафиксировано для реализации. В действующем клиенте скрывается только первая ссылка (если режим не open), ссылка приглашения показывается всегда. Сервер при closed отвергает приглашения (`auth.validateInvite`), поэтому скрытие этой ссылки на выбранном закрытом сервере — утверждённое устранение тупика, ещё не внесённое в продуктовый код. Приглашение на другой сервер можно ввести на ПК1. Режим задаёт администратор сервера; участник здесь его не меняет.

В стенде проверены все три режима: количество ссылок — 2/1/0, поле почты есть во всех. Вариант стенда выбирается параметром `?mode=open|invite|closed`; этот параметр не является элементом интерфейса продукта. Снимок и статический HTML обновлены для открытого режима.

**ПК3 — сервер выбран, интерфейс недоступен, утверждён владельцем 2026-10-29 («Да»).** [Макет](../visual/desktop-unavailable.html), [снимок](../visual/desktop-unavailable.png), [исходник](55-desktop-unavailable-frame.svelte.txt).

Основа — существующий кадр **7.43**, с теми же словами и действиями: «Сервер не отвечает», имя и адрес, «Проверьте сеть. Если сеть есть — сервер выключен или переехал.», «Повторить» и «Другой сервер». Рамка — как в ПК1/ПК2, содержимое — существующие `Logo`, `Hint`, `Button`, `TextButton`. Проверены загрузка шрифтов, обе кнопки и отсутствие выдуманного ответа сервера в статическом стенде.

Этот экран — только когда сервер уже выбран, а сохранённого интерфейса ещё нет или он стёрт. «Повторить» заново загружает выбранный сервер; «Другой сервер» возвращает на ПК1 и ничего не стирает, пока новый сервер не выбран. При наличии сохранённого приложения открывается оно, с действующей полосой состояния сети (7.36–7.40), а не этот экран. Сбой первичной проверки введённого адреса до выбора сервера — отдельный следующий кадр по образцу 7.44.

**ПК4 — ошибка первичной проверки адреса, утверждён владельцем 2026-10-29 («Да»).** [Макет](../visual/desktop-address-error.html), [снимок](../visual/desktop-address-error.png), [исходник](55-desktop-address-error-frame.svelte.txt).

Состояние утверждённого ПК1 после неудачной проверки: введённый адрес или приглашение остаётся в единственном поле, под ним текст из эталона **7.44**: «Сервер Wynd по этому адресу не отвечает. Проверьте адрес и сеть.». Один ответ для опечатки, отсутствия сети, выключенного сервера и чужого сайта: надёжно различить эти причины нельзя. Сервер пока не выбран, поэтому имя и карточка сервера не появляются.

Утверждённое поведение кнопки следует ПК1: «Дальше» доступна при непустом поле и повторяет проверку, в том числе без изменения адреса после восстановления сети; на время запроса недоступна. В эталоне Android 7.44 кнопка погашена, поскольку проверка там автоматическая при изменении адреса. Для ПК1 уже выбрана явная проверка по кнопке — её не блокируем прежним сбоем. При изменении поля старое сообщение убирается. Ссылка-приглашение сохраняется целиком до успешного перехода к своему серверу и кругу.

Использованы те же компоненты ПК1 и существующий Hint. В изолированном стенде проверены загрузка шрифтов, сохранённый адрес, недоступная кнопка при пустом поле, доступная при ссылке-приглашении и скрытие прежней ошибки при правке. Ответ сети в стенде показан образцом; реальных запросов нет.

**ПК5 — настройка автозапуска Windows (2026-10-29), не утверждён.** [Макет](../visual/desktop-startup.html), [снимок](../visual/desktop-startup.png), [исходник](55-desktop-startup-frame.svelte.txt).

Место — «Настройки → Приложение», действующий экран 7.6. Перед уведомлениями добавлен раздел «Запуск»: строка «Запускать при входе в Windows» с существующим Switch, по умолчанию выключенным; под ней Hint «При входе в Windows откроется окно Wynd.». Остальная форма взята из текущего клиента: уведомления по умолчанию, место на устройстве, аватары, тема. Их данные в кадре — примеры, настройки учёток не читаются. Уведомления по умолчанию относятся к кругам; системные уведомления Windows остаются отложенными до Wails v3.

При включении в реализации оболочка записывает команду автозапуска текущего пользователя, при выключении удаляет свою запись. Настройка действует только на этом компьютере, не синхронизируется с учёткой. Во время изменения переключатель недоступен; при ошибке возвращается к подтверждённому состоянию, под строкой появляется «Не удалось изменить автозапуск. Попробуйте ещё раз.». Успешное состояние показывается только после проверки записи. При закрытии окна Wynd завершает работу по принятому решению для v2; автозапуск относится к следующему входу в Windows.

Кадр собран из TitleBar, BackBar, SectionLabel, SettingsRow, Switch, Hint, Meter, Chip и ChipGroup; ширина содержимого ограничена действующим адаптивным токеном приложения, тело прокручивается под шапкой. Новых компонентов библиотеки нет. В браузере проверены загрузка шрифтов и переключение off → on → off. Это макет: Windows Run и сохранение настроек не вызываются.

## Следующий шаг

Согласовать ПК5 — настройка автозапуска Windows. ПК1–ПК4 и правило ссылок по режиму регистрации утверждены. Затем — приём файлов, без перехода к продуктовому коду до утверждения кадров. Перед выпуском отдельно проверить перенос мышью из Проводника. Проверку настоящего входа Windows оставить отдельным ручным пунктом, не перезагружать и не завершать сессию ради пробы.
