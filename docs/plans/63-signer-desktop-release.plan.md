# 63 — Подпись и самообновление «Wynd Настольного»

**Тип:** инструмент разработчика («Wynd Подпись») и окно «Wynd Настольный».
**Статус:** 2026-11-10 кадры «Подписи» приняты владельцем по смыслу и вёрстке («Кадры да»). Работа влита в `main` слиянием `efad127b`; «Wynd Подпись» собрана для работы владельца (`dist\wynd-signer.exe`, версия 0.2.0). Первый подписанный Настольный 0.2.0 собран CI и первоначально опубликован 2026-11-11; сумма, удостоверение, подпись и публичные загрузки проверены. При более поздней сверке тег и публичная страница выпуска отсутствовали — состояние и необходимое восстановление зафиксированы в [протоколе](../testing/release-0.52.0-desktop-0.2.0.md). Полоса обновления окна отклонена по вёрстке и отложена: «Полосу нет, её доделаем позже» — этот вариант не основа и вынесен в ветку `desktop-update-strip` (в main его нет); переделать и показать заново. Подпись и публикация выпусков Настольного — по той же схеме, что у Мастерской (решение владельца 2026-11-10).

## Зачем

«Wynd Подпись» подписывала только выпуски Мастерской (`workshop-v…`, `wynd-workshop.exe`). Окно для компьютера собиралось из тега `desktop-v…` (`wynd-desktop.exe`) без ключа и самообновления. Владелец 2026-11-10: «Не умеет подписывать Wynd для компьютера»; затем: «Wynd для компьютера переименовываем в Wynd Настольный. И добавляем в него ключ и самообновление. Формулировки пиши такие, которые дойдут до любого количества программ экосистемы Wynd».

## Что сделано (ветка signer-desktop)

- **Имя программы из описания, а не из окна.** В `internal/signing` у каждой программы есть строка: идентификатор, имя для окна, имя exe, префикс тега, путь к вшитому ключу и к `whatsnew.md`. Новая программа экосистемы — строка в таблице; окно берёт имена, файл, наличие самообновления и набор этапов проверки из Go, своих списков программ не держит. Отличия «Мастерская / Настольный» в коде окна убраны.
- **Один ключ экосистемы.** `signing-key.pub` переехал из `cmd/wynd-installer/` в корень репозитория; его вшивают в сборку обе программы (`build-installer.bat`, `build-desktop.bat`), у обеих в Подписи этап «Проверяем открытый ключ» и одинаковые правила публикации.
- **Wynd Настольный самообновляется** по модели Мастерской: `internal/desktop/selfupdate.go` (выпуски `desktop-v…`, задержка 72 часа, черновики и пробные не предлагаются), общая часть `internal/selfupdate` (проверка подписи и подмена своего exe — одна на все программы), общие `internal/relver` (сравнение версий). Не подписано ключом — не ставим; подпись не сошлась — «Подпись не сошлась: обновление не установлено».
- **Окно показывает новую версию** полосой над страницей: «Вышла версия X», строки «Что нового» и действия «Обновить и перезапустить», «Позже», «Что нового» (страница выпусков). Не молча и не сразу — как у Мастерской. **Вёрстка полосы не принята 2026-11-10** («Полосу нет, её доделаем позже»): это черновик, а не основа; сама полоса вынесена в ветку `desktop-update-strip` и в main не входит. Backend самообновления (`internal/desktop/selfupdate.go`, мост `CheckSelfUpdate`/`ApplySelfUpdate`) остаётся в main.
- **Выпуск Настольного** собирается черновиком (`desktop-client.yaml`), подпись и публикация — «Wynd Подпись»: «Что нового» из `cmd/wynd-desktop/whatsnew.md` в теге, раздел версии публикуется с выпуском; нет раздела — подписан, но черновик. Заголовок выпуска — «Wynd Настольный X».
