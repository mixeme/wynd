# План 49. Видео: кадр вместо ролика, честное сжатие

**Тип:** исправление
**Статус:** в работе. Квадрат и кадр видеосообщения подтверждены файлами с телефона (0.21.5); кадр на сервере (0.22.0) и запись по настройкам сжатия (0.21.6) ждут проверки
**Дата:** 2026-10-07
**Срез:** `main` @ `52300ed`, версия 0.20.3 (схема 27). Сервер wynd.mixfed.ru — 0.19.11, схема 26.

## Откуда

После 0.19.11 в Cursor вышли 0.20.0–0.20.3 — попытка закрыть семь сообщений с телефона (realme 8, Firefox, PWA). На телефоне не помогло, сервер вернули на 0.19.11.

1. Пустой круг: кнопка «Пригласить» не влезает по ширине.
2. Видеосообщения в Firefox пишутся квадратными.
3. Видео в Firefox не сжимается; отказ не пишется.
4. Для видео нужны обложки, как у звука.
5. Обложка дня из видео не предлагается.
6. Видео нет в «Сетке».
7. Лента с множеством видео тормозит телефон вплоть до перезагрузки.

## Разбор

**Корень неудачи.** В Firefox на Android нет WebCodecs. На нём стоят и сжатие, и кадр 0.20.2 (декодер mediabunny) — на тестовом телефоне они не могли сработать.

| № | Что сделано в 0.20.x | Что с этим |
|---|---|---|
| 1 | Поля 60px — на обёртке, кнопке `width: 100%` | Верно: кнопка `100% − 32px` с полями по 60px вылезала на 88px. Остаётся. |
| 2 | `aspectRatio` у камеры; размер для сжатия — по пикселям дорожки | `aspectRatio` Firefox не учитывает, осталась одна «высота 1920». Причина квадрата не установлена. Убрать, чинить по фактам. |
| 3 | Определение видео по сигнатуре, повтор через 400 мс, строка «Видео без сжатия» | Сжать в этом браузере нельзя. Сигнатура и повтор — убрать, строка остаётся; у видеосообщения причина терялась. |
| 4 | Сервер: миграция 0027, поле кадра, права, архив, объём, тесты. Клиент: кадр через WebCodecs | Сервер остаётся. Клиентский кадр и «детектор чёрного квадрата» — переписать. |
| 5 | Кадр в «Днях» | Выбор обложки (альбом дня) не тронут: там `<video>`, Firefox его не рисует. |
| 6 | Сервер отдаёт в «Сетку» и видео | Верно, но без кадра «Сетка» качает ролики целиком. |
| 7 | Лента не тронута | Лента качает каждый ролик-обложку целиком (до 100 МБ, по 8 сразу), держит до 256 МБ и ставит `<video>` с перемоткой на каждую запись. |

Ролики на сервере (метаданные, 2026-10-07): оба H.264 1920×1080 с поворотом на 90° — не квадратные.

## Решения (2026-10-07)

- Откат частичный: сервер 0.20.0 и кнопка остаются, клиентские догадки убираются.
- Ролик без кадра (отправлен до этой версии) — плитка-заглушка со значком, без скачивания; после первого открытия кадр хранится на устройстве.
- Сервер медиа не трогает ([ARCHITECTURE.md](../ARCHITECTURE.md)) — кадр делает отправитель.

## Проверка на телефоне, 0.21.1 (2026-10-07)

Не сработало, по файлам на сервере и словам с телефона:

- Видеосообщение — WebM **720×720**: 720p применилось, квадрат остался. `applyConstraints` с рамкой стоймя не помог.
- Кадр не снялся ни у видеосообщения, ни у видео из галереи; у старых роликов после открытия — тоже. `videoPosterJpeg` в Firefox на Android возвращает пусто.
- Строку «Видео ушло без сжатия» не видно: она стояла под лентой и стиралась перезагрузкой ленты. Исправлено в 0.21.2 — над полосой ввода.

Дальше — по фактам, не догадкам: `/api/diag-video` (временная). Перебирает просьбы к камере и способы снять кадр с ролика, показывает текст для отправки. В 0.21.2 страница жила на `/diag-video.html` и на телефоне открылась пустой: установленный service worker отдал вместо неё оболочку приложения; с 0.21.3 её отдаёт сервер под `/api`, куда service worker не ходит. После исправления убрать: `web/static/diag-video.html`, обработчик в `cmd/wynd/main.go`, строку в `navigateFallbackDenylist`.

## Диагностика с телефона (2026-10-07, Firefox 157, realme 8)

- **Камера.** Настройки дорожки повторяют просьбу («1280×720»), а сам кадр — 720×720: проверка 0.21.1 смотрела в настройки и не срабатывала ни разу. `applyConstraints` на живой дорожке кадр не меняет. `aspectRatio` и `getCapabilities`-пропорции не поддержаны; `resizeMode` — `none` и `crop-and-scale`.
- **Кадр из файла.** `drawImage`, `createImageBitmap` и `VideoFrame` с видеоэлемента, играющего файл (WebM с камеры и MP4 4K), дают прозрачную пустоту — до игры, во время и после паузы, в документе и вне его. С видеоэлемента, показывающего камеру, кадр снимается (яркость 165).

Что сделано в 0.21.4:

- Квадрат: размер кадра меряется по видео; квадрат — камера переоткрывается следующей просьбой из `cameraAsks` (обычная, стоймя, `resizeMode: none`).
- Кадр видеосообщения берётся с живой камеры во время записи (`liveFrameJpeg`).
- Кадр видео из галереи в Firefox на Android по-прежнему не снимается. Диагностика 2 пробует обычный холст, JPEG с него, WebGL и поток из играющего ролика.

## Диагностика 2 с телефона (2026-10-07)

Камера, телефон стоймя, настоящий размер кадра по видео:

| Просьба | Кадр |
|---|---|
| 1280×720 | 720×720 |
| 720×1280 | 1280×720 — лежачий |
| 1280×720, `resizeMode: none` | **720×1280** |
| 1920×1080 | 1080×1080 |
| 1920×1080, `resizeMode: none` | **1080×1920** |
| 720×1280, `resizeMode: none` | 1088×1088 |
| только `facingMode` | 480×640 |

Вывод: порядок 0.21.4 (обычная, стоймя, без подгонки) остановился бы на лежачем кадре. С 0.21.5 `cameraAsks` — сначала без подгонки, потом обычная.

Кадр из файла: программный холст, обычный холст, JPEG с холста, `createImageBitmap`, WebGL и поток `captureStream` из играющего ролика — всё пусто, и для WebM с камеры, и для MP4 из галереи. С живой камеры все пять способов дают картинку. **В Firefox на Android снять кадр с ролика из файла нечем** — на устройстве это не решается.

Проверка 0.21.4 на телефоне: кадр видеосообщения с камеры приложился (JPEG 1024×576) и виден в ленте; сам ролик — лежачий 1280×720, как и следовало из таблицы. Строка «Видео ушло без сжатия» над полосой ввода без подложки не читалась — в 0.21.5 предупреждение стоит на экране перед отправкой (4.26), у строки над полосой появилась подложка.

## Кадр на сервере (0.22.0, решение 2026-10-07)

Проверка 0.21.5 на телефоне: видеосообщение 720×1280 с кадром — квадрат исправлен. Кадр видео из галереи в Firefox на Android на устройстве не снять, поэтому решено: кадр ролику без кадра делает сервер через ffmpeg. Временно — пока нет нативной обёртки, которая снимет его на телефоне. Устройство: [server-reference.md](../reference/server-reference.md), «Кадр на сервере»; исключение записано в [ARCHITECTURE.md](../ARCHITECTURE.md).

Команда проверена на девяти роликах тестового сервера (H.264 1080p и 4K с поворотом, WebM VP8): кадр снят с каждого, поворот учтён. Образ вырос примерно на 120 МБ.

## Проверено до телефона (2026-10-07)

Локально, сборка с вшитым клиентом, Chromium: кнопка «Пригласить» на 375 и 320 px — поля по 60px, без прокрутки вбок; ролик из «Новой записи» уходит с кадром; лента, «Сетка», «Дни», выбор обложки дня рисуют картинку, `<video>` на этих экранах нет, блоб ролика не запрашивается; лайтбокс качает ролик и играет; ролик без кадра — заглушка без запросов, после открытия — кадр из кэша.

Не проверено: Firefox на Android (кадр через видеоэлемент, запись 720p, отсутствие тормозов на ленте с десятком роликов), iPhone.

## Осталось после 0.21.0

- **Длительность видео на плитке** (макет 4.27 показывал «1:12» в углу). Длительность ролика нигде не хранится; в 0.21.0 кадр 4.27 перерисован под значок, как в 5.5. Вернуть длительность — отдельное поле у вложения.
- **Сжатие видео из галереи в Firefox на Android** невозможно, пока в браузере нет WebCodecs. Сейчас — честная строка «Видео без сжатия». Серверное перекодирование отвергнуто архитектурой.
- **Снять кадр на сервере — временно.** Когда появится нативная обёртка клиента: убрать `internal/poster`, ffmpeg из образа и исключение из ARCHITECTURE.md.
- **Убрать диагностику** после подтверждения с телефона: `web/static/diag-video.html`, обработчик `/api/diag-video` в `cmd/wynd/main.go`, строку в `navigateFallbackDenylist`.
