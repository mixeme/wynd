# План 52. Оживление круга из архива (A1, этап 2)

Записано 2026-10-15. Макет утверждён владельцем (план 46, A1): 7.15 «Принять круг» в «Серверах», 7.16, 2.21/2.25 (пароль), 2.22 (что оживляем и где), 2.23/2.24/2.26 (не помещается, место попросили, отказали), 2.28/2.34 (итог), 6.35 («Ещё не вошли»). Файл — `.wynd` из [плана 51](51-full-circle-archive.plan.md). Решения ниже — мои, владельцу не показывались.

## Устройство читает файл

- **Расшифровка — на устройстве, кусками по номеру.** Формат age позволяет расшифровать любой кусок потока отдельно: ключ потока выводится из ключа файла и nonce, у куска i nonce — его номер. Устройство разбирает заголовок age (получатель X25519, HKDF, ChaCha20-Poly1305 — `@noble`), проверяет MAC заголовка и дальше читает файл как обычный, только каждый кусок — через расшифровку. Пароль не уходит никуда (A1), попытки не считаются (2.25).
- **ZIP — по оглавлению с конца.** И зашифрованный, и открытый файл читаются выборочно: конец центрального каталога (с zip64 — архив бывает больше 4 ГБ), затем нужные записи. Гигабайты подряд в память не грузятся.
- **Проверка до загрузки:** `manifest.json` (`format: wynd-circle`, версия разметки и схемы), размер — из описаний файлов; место на сервере — у сервера (2.23).

## Загрузка

- Файлы круга — существующими загрузками частями (переживают обрыв, 2.22), по одному; сумма sha256 из `blobs.json` сверяется сервером. Файл, который на сервере уже есть с той же суммой, второй раз не грузится.
- Потом один запрос «оживить»: строки таблиц из `data/*.json` и соответствие «блоб архива → блоб сервера».

## Сервер оживляет

- **Все идентификаторы новые.** Круг может ожить и рядом с живым исходным (резервная копия, 6.33) — на том же сервере. Сопоставление старых id новым — для всех таблиц и всех ссылок между ними (события по `seq`, записи, комментарии, реакции, дни, лица, членства, отрезки видимости, медиа).
- **Люди — по почте** («кто войдёт сюда той же почтой, попадёт в своё имя», 2.22). Почта есть на сервере — членство этой учётки. Нет — учётка заводится по почте без входа; войдёт этой почтой — она и есть. Такие и составляют «Ещё не вошли» (6.35): учётки без единого входа. Режим «только по приглашению» им вход не закрывает (план 46, A1: по почтам из перенесённого или оживлённого круга сервер пускает).
- **Владелец — тот, кто оживил** (2.22). Его почта есть в архиве — его лицо и становится лицом владельца. Нет — он получает лицо прежнего владельца круга: файл и пароль у него, круг продолжается от его имени (решение моё; иначе владельцу нужно было бы новое имя, а экрана для него нет).
- Журнал продолжается с того места, где замер; оживление — служебная строка («Круг оживлён из архива: Аня»).
- Сверка: число записей, имён и байт файлов после вставки — с `manifest.json` и `blobs.json` (2.28: «сверено с файлом архива, ничего не потерялось»).
- Рассылка (по умолчанию выключена, 2.22): письмо каждому из «Ещё не вошли» — «вас ждут в круге … на сервере …, войдите этой почтой». То же письмо — «Позвать всех письмом» и «позвать одного» на 6.35.

## Место

- Сколько есть для круга: квота круга по умолчанию, но не больше, чем свободно на сервере (2.22: «для круга есть 3 ГБ»).
- Не помещается — просьба «место для круга, которого пока нет» (2.23): та же очередь в панели, с именем круга из архива. Ответ — письмом (как у обычной просьбы, 0.30.3). Дали — оживлённый круг получает свою квоту такого размера. Просьба живёт на сервере при учётке, файл выбирают снова (2.24).

## Порядок (каждый шаг — коммит)

1. Клиент: чтение `.wynd` — age по кускам, ZIP по оглавлению, `manifest.json`; тесты на файле, собранном сервером.
2. Сервер: оживление из строк — новые id, люди по почте, владелец, событие, сверка; тесты: архив → оживление → те же записи.
3. Место: проверка и просьба для круга, которого нет (миграция).
4. Клиент: 7.15, 7.16, 2.21/2.25, 2.22/2.23/2.24/2.26, ход загрузки, 2.28/2.34.
5. «Ещё не вошли» (6.35) и письма-приглашения.
6. Выпуск.
