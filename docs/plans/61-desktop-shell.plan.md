# 61 — Оболочка Wynd для компьютера

**Тип:** реализация плана 55.
**Статус:** открыт, шаг 6.
**Обновлено:** 2026-11-09.

## Что делаем

Собираем Windows-оболочку Wynd: своя рамка, постоянный профиль WebView2, выбор и сохранение сервера, состояния ПК1–ПК5, приём файлов из Проводника и добавление второго сервера. Кадры утверждены в плане 55.

## Архитектура

- Wails v2.16.0, окно 1000 × 660 без системной рамки; полоса заголовка — `$ui/workshop/TitleBar`.
- Оболочка и интерфейс сервера живут в одном окне: оболочка — Svelte-приложение `cmd/wynd-desktop/frontend` (алиасы `$ui`, `$lib`, шрифты из `web/static`), интерфейс выбранного сервера — в `iframe` без рамки.
- `AssetServer`: `/` и `/__shell/*` — файлы оболочки; `/__server/*` — начальная страница сервера; остальные пути — обратный прокси к выбранному серверу (`httputil.ReverseProxy`), поэтому `/api/v1/*`, поток событий, медиа и переходы SvelteKit работают без CORS.
- Один origin (`wails.localhost`) на оболочку и сервер: сессия, IndexedDB и медиа-кэш общие. Вход выполняет оболочка и кладёт `SessionRecord` в ту же базу (`$lib/idb/db`); интерфейс сервера видит вход без второго экрана.
- Постоянный профиль: `%AppData%\Wynd\desktop\webview` (`WebviewUserDataPath`). Список серверов и выбранный адрес: `%AppData%\Wynd\desktop\servers.json`; токенов и паролей там нет.
- Проверка адреса, вход и запросы к серверу идут из Go; страница не получает произвольное чтение локальных путей и запуск команд.
- Файлы из Проводника принимает Wails (`EnableFileDrop` → `OnFileDrop`), передаёт их странице как `File`; дальше работает существующая подготовка медиа, очередь и ограничения вложений.
- Несколько серверов: выбранный — в корне прокси; остальные — `/__srv/<host>/...`. Мост `window.__wyndDesktop` переводит логические адреса в пути прокси; сессии хранятся по логическому origin.

## Шаги

1. **План** — этот документ, связь с планом 55. Коммит.
2. **Каркас** — `cmd/wynd-desktop`: Wails, рамка, профиль, встроенная оболочка, хранилище серверов, проверка адреса, ПК1 и ошибка ПК4; ворота `test-desktop.bat` и CI. Коммит.
3. **Прокси и интерфейс сервера** — обратный прокси, `/__server`, `iframe` после выбора сервера; проверка `/api/v1/instance` через прокси. Коммит.
4. **Вход** — ПК2: почта и код через Go, запись сессии, ПК3 при недоступном интерфейсе, повтор. Коммит.
5. **Автозапуск** — ПК5: запись `HKCU\...\Run`, состояние переключателя, откат при отказе, проверка команды после обновления. Коммит.
6. **Серверы** — ПК7: список, добавление, переключение, `/__srv`, логические origin, выход. Коммит.
7. **Файлы** — ПК6/ПК6а: приём из Проводника, зона приёма, передача в новую запись. Коммит.
8. **Сборка и проверки** — версия оболочки, подпись/самообновление по модели Мастерской, ручные проверки, документация. Коммит.

## Проверки

- Go: `go test -tags desktop ./cmd/wynd-desktop ./internal/desktop`, `go vet -tags desktop ...`.
- Frontend: `npm run check` и `npm run build` в `cmd/wynd-desktop/frontend`.
- Прокси: `httptest` на методы, заголовки, поток, отмену и чужой адрес; живой сервер Wynd — отдельно.
- Кадры: снимок реального окна при 1000 × 660, светлая тема; сверка с ПК1–ПК7.
- Ручные: перенос мышью из Проводника, вход Windows — с владельцем, не завершая его сессию.

## Сделано

- Шаг 2: каркас `cmd/wynd-desktop`, хранилище `servers.json`, проверка адреса, ПК1/ПК4, ворота. Коммит `a387a0c2`.
- Шаг 3: обратный прокси, iframe интерфейса, мост `window.__wyndDesktop` и логический origin; проверено на локальном сервере 127.0.0.1:7691. Коммит `81737391`.
- Шаг 4: ПК3 — сохранённый сервер не отвечает, «Повторить» и «Другой сервер»; проверено окном на недоступном адресе. Вход и код — интерфейс сервера в iframe (решение плана 55 «интерфейс с выбранного сервера»), отдельной копии ПК2 в оболочке нет. Коммит `597f707f`.
- Шаг 5: ПК5 — автозапуск в Run текущего пользователя, команда с путём exe в кавычках, отметка `--from-startup`, проверка устаревшей команды; строка «Запускать при входе в Windows» в «Настройки → Приложение». Коммит — этот.

## Границы

- macOS и вшитый интерфейс — позже; Linux после Windows.
