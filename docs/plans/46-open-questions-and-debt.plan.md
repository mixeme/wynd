- [ ] **A17. «Отделиться» на другой сервер (2026-10-24, задача, потом).** Владелец: «Отделиться на другой сервер запиши в задачи. Сделаем потом». Решение A9 (6): новый круг — на любом сервере, где у человека учётная запись; на другом сервере файлы копируются, позванным — письма. Сейчас (A9, сделано на том же сервере) карточка сервера на 6.42 показывает этот сервер без выбора, подсказки «Любой сервер, где у вас есть учётная запись» нет. Путь: снимок `splitTables` → `.wynd` (как полный архив) → тот сервер забирает его, как перенос (план 53, `move_in.go`, `reviveFromTables`), с `SplitFrom`; позванные — по почте, как «Ещё не вошли» при переносе; отрезки видимости позванных — те же пересечения. - [ ] **A24. Повторное сжатие одного оригинала и общее хранение (2026-11-03, подумать позже).** По просьбе владельца отложить обсуждение. Нынешнее клиентское сжатие не гарантирует одинаковые байты на разных устройствах: отличаются доступные форматы, кодировщики и пути обработки. A22 в 0.48.0 объединяет побайтно одинаковые результаты; повторные загрузки одного оригинала могут занимать отдельное место.
  - Обсудить, нужно ли гарантированно объединять такие загрузки и как учитывать разные настройки, качество и версии обработки. Рассмотреть дополнительный хеш оригинала, воспроизводимое сжатие и проверяемую связь оригинала с сохранённым результатом; решение не выбрано, реализация не поручена.
  - Хеш оригинала не заменяет хеш сохранённых байтов и не доказывает владение. Сейчас сервер получает сжатый результат и не может проверить заявленный клиентом хеш оригинала. Будущее решение должно сохранять независимые права и метаданные копий, не раскрывать чужие файлы и не позволять подменить содержимое по одному заявленному хешу.

- [ ] **A25. Показ обновления и гашение кнопок — единообразно с Настольным (2026-11-11, подумать).** Владелец: у Мастерской и Настольного обновление показывается и ведёт себя по-разному. В Настольном — полоса поверх интерфейса; после отказа подписи кнопка установки гаснет, «Позже» и «Что нового» остаются. В Мастерской — отдельный экран обновления; после отказа подписи остаётся активная «Попробовать ещё раз». Подумать, привести ли Мастерскую к виду Настольного (полоса и погашенная установка) или Настольный к виду Мастерской (отдельный экран и повтор). Решения нет; до него поведение не менять.

## C. Технический долг

- [ ] **C81. «Отделиться» отказала с общим кодом invalid, подсказка — про адрес (2026-11-08, realme 8, wynd.mixfed.ru 0.49.0, по ходу C44в). Исправлено в 0.50.0 (`dc8d8c28`), подтверждено на телефоне 2026-11-08 23:27 — «Отделение снова работает».** Причина: проверка оживления (`ValidateReviveTables`) принимала только целые и текст, а рамка кадрирования фото — REAL-столбцы `crop_x…crop_h` (в «Тестовом круге» одно кадрированное фото); любой такой круг получал 400 `invalid` и на «Отделиться», и на оживление архива. Найдено локальным повтором на копии боевой базы; после выпуска отделённый «Fork 2» перенесён на wynd2 со сверкой (22 записи, 5 имён, 141 МБ) — заодно живая проверка приёма архивов схемы 17 (`3ae6f770`) и дробных столбцов. Открытым оставался вопрос читаемой подсказки отказа. **Решение владельца 2026-11-11 («вариант, который правильный»):** сервер отвечает отдельным кодом вместо `invalid` там, где знает причину — сборка и оживление архива, «Отделиться» (один код на старте, словарь кодов не плодить); детали `ErrInvalid` пишутся в журнал тем же коммитом; клиент показывает адресную подсказку только на входе и проверке сервера, для нового кода — одна строка формулировки. **Формулировка согласована владельцем 12 ноября:** «Сервер не смог прочитать данные круга. Если повторится — напишите администратору сервера.» (одна на все три случая: сборка архива, оживление, «Отделиться»; действие называет сам экран). Вопросов по C81 не осталось — только реализация; правку взять в следующий выпуск вместе с C83–C86. **Реализовано в main 12 ноября (`bcdf97d0`):** отказ по данным архива идёт через новую ошибку `chronicle.ErrArchiveTables` (по-прежнему `ErrInvalid` для тех, кто различает только «неверный запрос») и уходит наружу кодом `archive_invalid`; подробности отказов `ErrInvalid` и данных архива пишутся в журнал (`writeDomainError`). Клиент: строка для `archive_invalid` по согласованной формулировке, «invalid» вне входа — «Не получилось — проверьте введённое», адресная подсказка осталась только на «Войти» и «Без приглашения / Войти на сервер» (`addressErrorHint`). Тесты: `TestWriteDomainErrorArchiveTables`, проверка кода в `revive_validate_test.go`, vitest по подсказкам. Ждёт выпуска и телефонной проверки на «Отделиться» и оживлении архива. Старым клиентам незнакомый код не ломается — они покажут нейтральное «не получилось». [Протокол](../testing/phone-checks-2026-11-08.md#c81-и-перенос-fork-2--подтверждено-вечером-8-ноября).

- [ ] **C69. Сервер не пускает клиент другого сервера: нет CORS (найдено 2026-10-28).** При проверке C67: клиент с `127.0.0.1:7690` → «Настройки → Серверы» → «Добавить сервер» → `http://127.0.0.1:7691` отвечает «Сервер не отвечает — проверьте адрес»; в консоли браузера — запрос к `7691/api/v1/instance` заблокирован политикой CORS: сервер Wynd не отдаёт `Access-Control-Allow-Origin` и не отвечает на `OPTIONS` (405). Значит, в браузере войти на второй сервер с клиента первого нельзя, хотя концепция это предусматривает (`docs/wynd.html`: «Выход здесь не один, а по серверам»), а кадры 7.40, 10.16, 10.17 и «Настройки → Серверы» рассчитаны на несколько серверов. Не проверено: было ли так всегда, или раньше это обходилось иначе; как ведёт себя установленное приложение (у PWA те же правила). Решать с владельцем: разрешать ли серверу запросы с других адресов (каких — любых, или только с серверов Wynd, и как это совместить со входом по токену), или многосерверность — только в обёртке для Android (план 50) и будущей программе для компьютера (C66). **Подтверждено на настоящих серверах 2026-10-28:** `wynd2.mixfed.ru` (0.43.3) на запрос с `Origin: https://wynd.mixfed.ru` не отдаёт `Access-Control-Allow-Origin`, `OPTIONS` — 405; телефон владельца (wynd.mixfed.ru → «Настройки → Серверы» → «Добавить сервер» → `wynd2.mixfed.ru`, 18:26) — «Сервер не отвечает — проверьте адрес». Заодно: эта строка стоит внизу экрана, под кнопками QR, далеко от поля адреса, к которому относится. Варианты для владельца: (а) сервер отвечает клиенту с любого адреса — только запросы участников, не панель (вход по токену, не по cookie); (б) только клиентам других серверов Wynd; (в) несколько серверов — только в приложениях. Я за «а». **Решение владельца 2026-10-28 (временное):** «Что-то выглядит сомнительно. Тогда пока гасим возможность подключить второй сервер в PWA. Вернёмся к вопросу позже.» Сделать: в браузере и установленном веб-приложении убрать добавление второго сервера («Настройки → Серверы» → «Добавить сервер» и другие входы), с правкой кадров; сам вопрос CORS остаётся открытым. **Сделано в 0.43.7:** `ADD_SERVER_IN_BROWSER = false` (`web/src/lib/session/addServer.ts`): на «Серверах» кнопки «Добавить сервер» нет (без серверов — «Войти»), `/join` у вошедшего уводит на «Серверы», «Перейти на новый сервер» у переехавшего круга (3.15) открывает страницу нового сервера; кадры 1.9, 7.9, 3.15 — с пометкой. В программе для компьютера CORS обходится без сервера — запросы идут через Go (C66, пробный образец 2026-10-28).
