Сводка

Один бинарник, один репозиторий, тонкий клиент

Стек вытекает из образа продукта: self-hosted приватная сеть кругов, где ценность появляется на пяти людях, а не на миллионе MAU. Значит — дешёвая установка, низкие требования к железу, отказ от E2E и федерации, сжатие медиа на клиенте. Всё остальное — следствие.

Go SQLite SvelteKit + TypeScript PWA Web Push (VAPID) AGPL-3.0 монорепо
КлиентPWA · Service Worker · IndexedDB · Golos Text
ФронтендSvelteKit + TypeScript · SPA, вшит в бинарник через embed
APIREST + JSON · SSE для синхронизации
СерверGo — один бинарник, отдаёт API и статику сборки
ДанныеSQLite (WAL) · файловое хранилище блобов
ИнфраCaddy (дефолт TLS) · Docker · systemd

Монорепо

Один репозиторий, один артефакт деплоя

Весь код — в одном репозитории. Бинарник собирает Go-сервер и вшитый фронтенд; снаружи остаются только данные (БД, блобы, конфиг).

Язык кода

Идентификаторы, комментарии, сообщения коммитов, имена веток — английский. Продуктовые тексты в UI и документация в docs/ — русский. API-поля и JSON-ключи — английский (circle_id, не krug_id).

Сервер

Go, один бинарник

Решение зафиксировано в образе продукта. Go даёт статическую сборку, низкое потребление RAM, встроенный HTTP-сервер и embed для фронтенда. Паттерн проверен: Memos, GoToSocial, значительная часть Immich.

База данных

SQLite (WAL) — единственный драйвер в коде. Файл рядом с бинарником, ноль внешних зависимостей, ~50–100 МБ RAM на инстанс. Event log с материализованным снимком и отрезки видимости укладываются в SQLite (один писатель). Immich выбрал PostgreSQL из-за дедупликации миллионов фото — у Wynd другая модель: сжатые блобы и журнал, не медиатека.

PostgreSQL, chi, TWA и Svelte stores рассматривались на раннем этапе — отвергнуты для 0.x; группы кругов — только IDB, без API. См. таблицу ниже.

API

REST + JSON. Синхронизация — GET /sync?cursor=… (SSE или long-poll). Event log естественно ложится на курсор: «дай события после N». OpenAPI-спека — для генерации типов в JS и документации.

GraphQL отвергнут: один клиент, предсказуемые эндпоинты, проще кэшировать. Специализированные sync-фреймворки (Replicache, ElectricSQL) — лишняя зависимость; модель Wynd (сигнальный пуш → догрузка) проще.

Клиент

PWA, один стек с админкой

Мобильное приложение и панель администратора — один фронтенд, разные layout’ы (/ и /admin). Нативных клиентов не будет: Android — PWA в браузере; iOS — PWA в Safari (best effort, без гарантий). TWA отвергнут для 0.x.

Почему SvelteKit

Мобильный клиент Wynd — по сути толстый клиент: офлайн-очередь, сжатие медиа, агрегация нескольких серверов, 43 экрана. Нужен фреймворк с компонентами, а не набор разрозненных скриптов.

Wynd UI

«Взять готовую библиотеку» — не одно решение, а три. Разделять их обязательно: ответы противоположные, а слипшись они дают либо велосипед на пустом месте, либо чужой облик поверх своей марки.

СлойЧто входитРешение
Поведение и доступностьFocus trap, возврат фокуса, Esc, inert, позиционирование, блокировка прокрутки, клавиатура, ARIAГотовое. Здесь настоящие грабли; своё — не экономия, а отладка на чужих устройствах
Визуальный слойПалитра, кегли, отступы, радиусы, тёмная темаСвой. Уже оплачен работой по марке — купить его значит выбросить её
Прикладные компонентыPostCard, CircleRow, MemberRow, InviteCard, лентаСвои. Их не продаёт никто и не продаст

Из ~40 компонентов Wynd UI поведенческих около десяти: Sheet, Dialog, Lightbox, PushBanner, Switch, табы в CircleBar, Fab. Остальные тридцать — разметка поверх собственных токенов. Поэтому задача формулируется как «взять первый слой, не покупая второй», а это умеет один конкретный формат.

Первый слой берём готовым в любом случае — спорить тут не о чем. Открытым остаётся вопрос, покупать ли вместе с ним ещё и Tailwind с пре-стилизованными компонентами. Отсюда две ветки.

Ветка А — shadcn-svelte. Не зависимость, а генератор: CLI кладёт исходники компонентов в репозиторий, под капотом Bits UI (поведение) и Tailwind. Следствия ровно те, что нужны:

  • Код наш. Перекрасить в бумагу и чернила — правка своих файлов, а не борьба с чужими стилями через !important.
  • Нет version lock. Проект self-hosted и AGPL, жить ему долго; миграция Svelte 4→5 положила немало библиотек-зависимостей, а сгенерированный код пережил бы её.
  • Темизация совпадает с моделью круга. Tailwind настраивается нативными CSS-переменными — восемь цветов кругов, --c / --ct и тёмная тема встают без правок внутри компонентов.

Ветка Б — Bits UI напрямую плюс свой CSS на токенах: те же гарантии по доступности, без Tailwind и без пре-стилизованных компонентов.

Почему Б — не запасной вариант

Дизайн из макетов лежит вне сетки Tailwind, и это измеримо. Кегли: 12.5px — 80 вхождений, 11.5px — 42, 13.5px — 12, 17px — 11; половинные значения стоят в 136 объявлениях font-size из ~162. Самый частый gap — 10px. Отступы вида 8px 13px, 6px 13px, 4px 18px 14px. Шкала Tailwind кратна 4px, кегли целые (text-xs 12, text-sm 14, text-base 16) — ни один из трёх основных кеглей и самый частый зазор туда не попадают.

Значит развилка внутри ветки А такая: либо полностью своя тема — и тогда Tailwind перестаёт быть системой ограничений, оставаясь многословным синонимом наших же токенов (px-[13px] py-2 вместо padding:8px 13px), либо округление до сетки — а это уже другой дизайн. Точность с половинами пикселей — не случайность, а то, ради чего макеты и рисовались.

Второе: Svelte скоупит <style> сам и выкидывает мёртвый CSS на компиляции. Три из четырёх задач, ради которых Tailwind придумали в мире JSX, здесь закрыты языком. Аргументы из сравнений, написанных про React, к SvelteKit переносятся не целиком.

Третье: обычный CSS не ломается на мажорных обновлениях, а Tailwind между v3 и v4 сменил движок и формат конфига. Для AGPL-проекта с горизонтом в годы и случайными патчами со стороны это имеет вес: 206 семантических классов правит любой, кто знает CSS.

Решение принимается спайком, а не спором: экран e3-1 (лента круга — самый плотный) собирается дважды, по ветке на каждый вариант, с таймбоксом в день, и обе версии живут рядом на /dev/spike/. Замеряются доля готовых компонентов, попадание в типографику, стоимость overlay-слоя и прирост бандла. Таблица сравнения и правило решения — в Wynd UI и этом документе, раздел «Wynd UI».

Итог спайка (август 2026): победила ветка Б — Bits UI напрямую плюс свой CSS на токенах. Ветка А (shadcn-svelte + Tailwind) не попала в типографику макетов без px-[12.5px] и дала больший бандл при том же поведении табов. Поведение берём из Bits UI; визуальный слой — классы из screens.html. Эталон e3-1 — /dev/spike/b; маршрут ветки А удалён.

Честно о масштабе выигрыша

Выбор библиотеки ощущается крупным решением, но это рычаг средней длины. В приложении с офлайн-очередью, журналом событий, агрегацией нескольких серверов и сжатием медиа на клиенте время уходит в синхронизацию и состояние, а не в компоненты. Готовое поведение снимает недели отладки доступности — и не снимает ничего из остального.

Медиа на клиенте

Сжатие — в foreground, пока приложение открыто. Canvas + WebCodecs для фото; WebCodecs для видео с fallback «загрузить как есть». Оригиналы не покидают телефон — сервер хранит только сжатое.

Видео в фоне — честно

Надёжного фонового перекодирования и загрузки видео в PWA нет. Android/TWA иногда дотягивает загрузку после сворачивания; iOS Safari убивает процесс. Модель:

  1. сжатие — с прогрессом, пока вкладка жива;
  2. загрузка чанками сразу после сжатия;
  3. обрыв — запись в очереди «дослать», resume при открытии;
  4. большое видео — предупреждение: держите приложение открытым.

Сервер видео не трогает (нет ffmpeg) — вся тяжесть на клиенте, фон не гарантируем.

Пуши: Web Push (VAPID)

MVP — только Web Push. UnifiedPush рассмотрим позже, если Web Push окажется недостаточным (de-Googled Android без Google Play Services).

Сигнальные: круг, тип события, число — без текста записи. Текст рисуется после sync на устройстве.

КаменьЧто делаем

UnifiedPush — не в MVP. Сначала Web Push на Android (TWA), Chrome и Safari PWA; UnifiedPush добавим отдельно, если появится реальный запрос.

Деплой

Одна команда, HTTPS обязателен

СпособДля кого
curl | sh → бинарник + systemdЧистый VPS, домашний сервер
Docker / composeUnraid, YunoHost, привычный контейнерный стек

TLS — на реверс-прокси. Дефолт — Caddy с автонастройкой; при существующем nginx/traefik — готовый конфиг в логе установки. Без HTTPS продукт не работает: service worker, PWA, пуши, камера.
