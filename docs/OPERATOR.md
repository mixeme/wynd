# Руководство оператора Wynd

Оператор — тот, кто поставил сервер Wynd и отвечает за него: домен, TLS, почту, обновления, резервные копии и панель. Это руководство ведёт от чистого VPS до обслуживания. Как устроена система — [ARCHITECTURE.md](ARCHITECTURE.md); разработка и сборка — [DEVELOPMENT.md](DEVELOPMENT.md); уязвимости и модель доверия — [SECURITY.md](SECURITY.md).

Один процесс на каталог данных. Второй сервер на той же `wynd.db` не поддерживается.

## 1. Что нужно

- **Сервер.** VPS с Debian 12 или Ubuntu 24.04 для Мастерской и Docker. Для ручного пути через `install.sh` — Linux с systemd.
- **Домен и DNS.** A-запись (при IPv6 — и AAAA) на адрес сервера. Порты 80 и 443 открыты: сертификат и HTTPS.
- **Почта.** SMTP-релей: хост, порт, логин, пароль и адрес отправителя. Участники входят по коду из письма. Без релея вход работает только на loopback: код пишется в журнал сервера и в `<каталог данных>/dev-auth-codes.log`.
- **SSH.** Доступ с sudo или root. Лучше по ключу; пароль — только если иначе нельзя.
- **Место.** Медиа растут; заводской предел хранения — 80% диска. Для сборки на сервере нужно не меньше 2 ГБ памяти или подкачки: Мастерская добавляет swap на время сборки.
- **Точное время.** NTP на сервере: от него зависят TLS, сроки и события.

Выберите путь:

1. **Wynd Мастерская** — рекомендуемый путь для владельца: настольное приложение подключается по SSH и ставит Wynd в Docker. Debian и Ubuntu.
2. **Docker вручную** — если нужен полный контроль над compose, прокси и обновлениями.
3. **`install.sh` и systemd** — если сервер без Docker или нужен один бинарник под systemd.

## 2. Быстрый старт: Wynd Мастерская

Мастерская — отдельная настольная программа. Сейчас она работает на Windows; Linux-сборка появится после отдельного выпуска. Скачать — на [странице выпусков](https://github.com/mixeme/wynd/releases).

1. **Добавьте сервер.** Адрес, SSH-порт, пользователь и ключ или пароль. Мастерская покажет отпечаток хоста — сверьте его, если подключаетесь впервые.
2. **Осмотрите сервер.** Мастерская покажет, что уже установлено: Docker, прокси, чужие сайты, сертификаты, свободное место. Чужие сервисы она не трогает.
3. **Посмотрите план.** До изменений будет видно: «поставим», «изменим с копией», «не тронем». Если план не подходит, установку можно не начинать.
4. **Установите.** По умолчанию каталог — `/opt/wynd`; другой каталог можно выбрать. Установка идёт через Docker; поддерживаются Debian и Ubuntu. Выберите прокси: свой Caddy или уже работающий nginx, Apache или Caddy. Для своего Caddy нужен домен, который уже указывает на сервер.
5. **Откройте ссылку первого запуска.** В конце Мастерская покажет адрес с токеном. Там задаются пароль панели, имя инстанса и SMTP; проверочное письмо уходит сразу.

Дальше сервер живёт в **пульте** Мастерской: обновление с копией, откат, бэкап на компьютер, переезд и удаление. Вкладка **«Архивы»** объединяет архивы, делит их по годам или периоду и открывает ленту из полного архива круга.

Если установка сорвалась, повтор безопасен: Мастерская сначала проверяет состояние, а не выполняет шаги вслепую. Ошибка называет причину и следующее действие.

## 3. Первый запуск и панель

Ссылка первого запуска ведёт на `/admin/bootstrap?token=…`. Токен лежит в `<каталог данных>/keys/bootstrap` и действует один раз.

1. **Пароль панели.** Не короче 8 знаков. Панель — отдельный вход администратора, не учётная запись участника.
2. **Имя инстанса.** Его видят участники на экране входа и в письмах.
3. **SMTP.** Хост, порт, логин, пароль и адрес отправителя. Проверочное письмо приходит на адрес «От кого». Без SMTP вход остаётся только loopback.
4. **Доступ.** Режим регистрации: `open` — «Открыт для новых», `invite` — «Только по приглашению» (заводской), `closed` — «Закрыт».
5. **Проверка.** После DNS и TLS откройте «Проверку» в панели: домен, HTTP → HTTPS, сертификат, таймаут прокси, PWA, пуш. Она же подскажет, что именно не так.

В панели также настраиваются люди и приглашения, круги, квоты и место, сжатие медиа, оплата и сбор, уведомления, архивы и очистка. Список людей показывает, кто вошёл, кто ждёт и кто ушёл. Администратор может включить стирание имён при уходе — тогда уходящий сам решает, стереть ли имя и фото во всех кругах.

## 4. Установка вручную: Docker

В репозитории — `deploy/docker/compose.yaml` (Wynd и Caddy) и `deploy/docker/compose.own-proxy.yaml` (только Wynd за уже работающим прокси).

### Свой Caddy

```bash
cd deploy/docker
mkdir -p data && chown 100:101 data && chmod 700 data
```

- В `compose.yaml` замените `WYND_PUBLIC_URL` на свой адрес и домен в `deploy/caddy/Caddyfile`.
- В `compose.yaml` `WYND_TRUSTED_PROXIES` — приватные сети, потому что порт Wynd не публикуется и до него доходит только Caddy. Не расширяйте его без нужды.
- Запуск:

```bash
docker compose up -d --build
```

- Токен первого запуска: `docker compose logs wynd | grep -i bootstrap` или `docker compose exec wynd cat /data/keys/bootstrap`.
- Адрес — `https://<домен>/admin/bootstrap?token=…`.

### Чужой прокси

Если на хосте уже есть nginx, Apache или Traefik:

```bash
cd deploy/docker
mkdir -p data && chown 100:101 data && chmod 700 data
docker compose -f compose.own-proxy.yaml up -d --build
```

- Wynd слушает `127.0.0.1:7676`; наружу его публикует ваш прокси.
- Шаблоны — `deploy/proxy/`: nginx, Apache, Traefik, Caddy.
- Таймаут чтения прокси — не меньше 300 с: через него идут SSE и длинные загрузки.
- `WYND_TRUSTED_PROXIES` — только адрес шлюза, через который приходит прокси. Широкий диапазон позволит любому контейнеру на хосте подменять адрес для лимитов.
- Порт 7676 не публикуйте в интернет. HTTPS обязателен: без него не работают service worker, пуш и камера.

### Обновление

Если compose собирает из исходников:

```bash
git pull
docker compose build
docker compose up -d
```

Если используется готовый образ `ghcr.io/mixeme/wynd:<версия>`, замените в compose `build:` на `image:` и выполните:

```bash
docker compose pull
docker compose up -d
```

Перед обновлением сделайте бэкап: миграции схемы необратимы.

## 5. Установка вручную: systemd и `install.sh`

Из корня репозитория:

```bash
sudo ./deploy/install.sh --from-source --public-url https://home.example.org
```

Скрипт:

- заводит пользователя `wynd` и каталог данных `/var/lib/wynd`;
- ставит бинарник в `/usr/local/bin/wynd`, юнит `wynd.service` и запускает службу;
- при публичном адресе ставит Caddy и настраивает его на домен;
- печатает ссылку первого запуска с токеном.

Опции:

- `--own-proxy` — не трогать Caddy, напечатать фрагмент конфигурации для вашего прокси;
- `--data-dir PATH` — другой каталог данных;
- `--bin PATH` — готовый бинарник вместо сборки.

Для `--from-source` на сервере нужны Go и Node: скрипт собирает клиент и бинарник. Если их нет, соберите бинарник на другой машине и передайте через `--bin`.

Если Caddy уже стоял до скрипта, его `Caddyfile` не перезаписывается: скрипт печатает фрагмент и просит настроить прокси. Это защита чужих сайтов.

Обновление — тем же скриптом поверх установленного:

```bash
git pull
sudo ./deploy/install.sh --from-source
```

Перед заменой бинарника скрипт снимает бэкап **старым** бинарником в `/var/lib/wynd/backups/pre-update-<время>/` и кладёт туда же прежний `wynd`. Если бэкап не удался, обновление не выполняется. `config.json` не перезаписывается.

## 6. Настройки

Три слоя, каждый следующий перекрывает предыдущий: умолчания → `config.json` в каталоге данных → переменные окружения. Большая часть настроек (имя, режим регистрации, SMTP, квоты, сжатие, оплата) живёт в базе и меняется в панели.

| Переменная | Поле `config.json` | Умолчание | Что задаёт |
|---|---|---|---|
| `WYND_DATA_DIR` | — | `dev/data` (от текущего каталога) | Каталог данных. `install.sh` — `/var/lib/wynd`, образ Docker — `/data` |
| `WYND_LISTEN` | `listen` | `127.0.0.1:7676` | Адрес, который слушает сервер. В Docker — `:7676` |
| `WYND_PUBLIC_URL` | `public_url` | `http://127.0.0.1:7676` | Адрес, по которому инстанс видят участники: ссылки в письмах, приглашения, проверки |
| `WYND_TRUSTED_PROXIES` | `trusted_proxies` | пусто = только loopback | Через запятую — адреса или CIDR, чьему `X-Forwarded-For` верить (лимиты по адресу) |
| `WYND_MOVE_ALLOWED_CIDRS` | — | пусто | Исключения для переноса по LAN: через запятую точные CIDR источников. По умолчанию перенос обращается только к публичным IP; DNS проверяется перед соединением, редиректы и системный proxy отключены. Разрешайте только доверенные адреса: любой оплаченный участник сможет запросить на них API переноса |
| `WYND_MOVE_MAX_BYTES` | — | `34359738368` (32 ГиБ) | Верхняя граница ZIP и распакованных медиа одного переноса. Дополнительно проверяется реальное свободное место с запасом 64 МиБ и резервами других переносов. JSON: manifest до 1 МиБ, таблица до 16 МиБ, суммарно до 32 МиБ и 250000 строк; каталог ZIP до 16 МиБ и 100000 файлов. Одновременно работают не более двух переносов, разбор/импорт архива — один; одна попытка — до 24 часов |

- `public_url` — только `http(s)://хост[:порт]`: без пути, запроса, якоря и учётных данных. С неверным адресом сервер не стартует и пишет почему.
- Адрес на `127.0.0.1`, `localhost` или `::1` — профиль loopback: вход без SMTP (код — в журнале сервера), проверки прокси и HTTPS «не применимо».
- `config.json` появляется, только когда его сохраняют: `install.sh`, первый запуск, смена адреса в панели. Если `WYND_PUBLIC_URL` перекрывает сохранённый адрес, сервер пишет это в журнал.
- `WYND_CREDENTIALS_DIR` и `WYND_CREDENTIALS_FILE` читают только интеграционные тесты почты.

## 7. Каталог данных

| Путь | Что | Права |
|---|---|---|
| `wynd.db` (+ `-wal`, `-shm`) | Вся база: учётки, круги, хроника, настройки. **Содержит пароль SMTP и приватный ключ VAPID открытым текстом** | `0600`, выравнивается при старте |
| `config.json` | Адрес, порт, доверенные прокси | `0640` |
| `blobs/<2 знака>/<uuid>` | Файлы вложений, аватаров, скриншотов оплаты — ровно те байты, что прислал клиент | |
| `blobs/.uploads/` | Незавершённые загрузки; в бэкап не входят | |
| `tmp/` | Архивы кругов на время скачивания; очищается при старте, в бэкап не входит | `0700` |
| `keys/bootstrap` | Токен первого запуска | `0600` |
| `backups/pre-update-*` | Копии, которые `install.sh` снимает перед заменой бинарника | |
| `dev-auth-codes.log` | Коды входа — только на loopback | |

Каталог данных и его подкаталоги нельзя делать общедоступными. В `wynd.db` лежат секреты; в бэкапе — те же секреты, что и в базе.

## 8. Бэкап

```bash
sudo -u wynd env WYND_DATA_DIR=/var/lib/wynd wynd backup /var/backups/wynd/2026-09-23
sudo -u wynd env WYND_DATA_DIR=/var/lib/wynd wynd backup -incremental /var/backups/wynd/current
```

- Сервер останавливать не нужно: база снимается `VACUUM INTO` — целостная копия без `-wal`/`-shm`.
- В каталог назначения ложатся `wynd.db`, `config.json` (если есть), `keys/` и `blobs/` с `blobs/manifest.json`.
- `-incremental` в тот же каталог копирует только файлы, которых нет в `manifest.json` или чья копия отсутствует либо короче оригинала; остальные не перечитываются. База, конфиг и ключи переписываются всегда. Файлы, удалённые с инстанса после прошлого прогона, в каталоге бэкапа остаются. Такой каталог — рабочая копия, а не единственная: держите рядом хотя бы одну датированную.
- Запускать от пользователя сервиса: команда отмечает время бэкапа в самой базе (его показывает панель) и должна читать файлы `0600`. Каталог бэкапа создаётся `0700`, копия базы — `0600`.
- Сам каталог данных и каталоги внутри `blobs/` и `keys/` команда как цель не примет; подкаталог рядом, например `/var/lib/wynd/backups/<дата>`, можно.
- В Docker:

```bash
docker compose exec wynd wynd backup /data/backups/<дата>
docker compose cp wynd:/data/backups/<дата> ./<дата>
```

Поставьте бэкап в cron или systemd timer от пользователя `wynd` и проверяйте, что он действительно появляется. Панель показывает время последнего бэкапа; если его нет дольше недели, сервер пришлёт письмо о неполадке (если настроен `admin_email`).

## 9. Восстановление

Из каталога, снятого `wynd backup`, в чистый каталог данных.

1. Остановить сервер: `sudo systemctl stop wynd`.
2. Отложить текущий каталог, не удалять: `sudo mv /var/lib/wynd /var/lib/wynd.broken`.
3. Разложить копию:

   ```bash
   sudo install -d -o wynd -g wynd -m 0750 /var/lib/wynd
   sudo cp -a /var/backups/wynd/2026-09-23/. /var/lib/wynd/
   sudo rm -f /var/lib/wynd/blobs/manifest.json
   sudo chown -R wynd:wynd /var/lib/wynd
   sudo chmod 0600 /var/lib/wynd/wynd.db
   ```

   Если в копии нет `config.json` — адрес задавался только окружением, так и оставить.

4. Запустить: `sudo systemctl start wynd`. В журнале — `schema version: N`; `curl http://127.0.0.1:7676/ready` отвечает `ready`.
5. Проверить в клиенте ленту круга и пару вложений.

В Docker те же шаги: `docker compose down`, заменить содержимое `data/` копией, вернуть владельца `100:101` (`chown -R 100:101 data`) и поднять `docker compose up -d`.

Что теряется: всё, что появилось после бэкапа. Сессии, выданные после него, недействительны — участник входит заново. Клиенты, помнящие номера событий из прежней жизни базы, при первом подключении узнают от сервера последний номер и сами сбрасывают курсор и снимки — счётчик событий трогать не нужно. Копию, снятую **более новой** версией, старый бинарник не откроет («устаревшая схема»): восстанавливать тем же или более новым бинарником. Каталог `wynd.broken` удалить, когда восстановленный инстанс проверен.

## 10. Обновление и откат

1. Прочитайте в [CHANGELOG.md](CHANGELOG.md) блоки «Оператору» всех версий между текущей и новой: миграции, новые поля конфигурации, требования к прокси.
2. Сделайте бэкап. Для Мастерской достаточно «Обновить»: она снимает копию перед изменениями.
3. Обновите:
   - **Мастерская:** «Обновить» в пульте сервера. Копия снимается до замены; «Откатить» возвращает предыдущую версию, но не откатывает IndexedDB клиента.
   - **systemd:** `git pull`, затем `sudo ./deploy/install.sh --from-source`. Скрипт снимает бэкап старым бинарником и сохраняет прежний `wynd` в `pre-update-*`.
   - **Docker:** `git pull`, `docker compose build`, `docker compose up -d`; или `docker compose pull` и `docker compose up -d` для готового образа. Бэкап — вручную.
4. Миграции схемы применяются сами при старте. В журнале — новая `schema version`.
5. С версии младше 0.33.6 — в два шага: сначала 0.33.6, затем нужная. С версии младше 0.25.10 — в три: 0.25.10, 0.33.6, нужная. В 0.34.0 миграции свёрнуты в один файл схемы и пронумерованы заново, и более старую базу новый бинарник не открывает.

Отката после миграции нет: схема только растёт. Вернуться на прежнюю версию — это восстановление из `pre-update-*` прежним бинарником, который лежит там же: вернуть его в `/usr/local/bin/wynd` и пройти «Восстановление». После восстановления (шаг 2) копия окажется в `/var/lib/wynd.broken/backups/`; файл `wynd` из неё в новый каталог данных не нужен. После отката клиентам может понадобиться перезагрузить страницу: их IndexedDB не откатывается вместе с сервером.

## 11. Диагностика

- **Живость.** `curl http://127.0.0.1:7676/health`; готовность — `curl http://127.0.0.1:7676/ready` (ответ `ready`). Версия и режим — `curl http://127.0.0.1:7676/api/v1/instance`.
- **Журнал.** systemd: `journalctl -u wynd -f`; Docker: `docker compose logs -f wynd`. При старте ищите `schema version: N`, адрес и предупреждения о `public_url`.
- **Порты.** Сервер слушает `127.0.0.1:7676`; наружу — только прокси на 80/443. Проверьте `ss -ltnp | grep 7676`.
- **Прокси.** Ошибки 502/504 — прокси не видит upstream или не хватает таймаута. Таймаут чтения — не меньше 300 с; `X-Forwarded-For` должен идти от доверенного адреса.
- **Почта.** «Проверить подключение» и проверочное письмо в панели. На loopback код входа — в журнале и `dev-auth-codes.log`. Если письма не приходят, проверьте SMTP-логин, порт, TLS и папку «Спам».
- **Сертификат.** Срок и цепочку показывает «Проверка». Мастерская в осмотре находит сломанное продление certbot и предлагает «Убрать сертификат» для своего.
- **Место.** `df -h`, `du -sh <каталог данных>/blobs`, раздел «Хранилище» в панели. Квота круга и предел инстанса — разные вещи.
- **Бэкап.** Панель показывает время последнего бэкапа; проверьте, что каталог назначения существует и доступен пользователю `wynd`.
- **Пуш.** Нужен HTTPS и разрешение в браузере; тестовый пуш — в панели. На Android доставка зависит от приложения-доставщика.

Частые ошибки:

| Симптом | Что проверить |
|---|---|
| «Сервер не отвечает» на телефоне | VPN, DNS, HTTPS, доступность `https://<домен>/health`; не истёк ли сертификат |
| Код входа не приходит | SMTP в панели, проверочное письмо, «Спам»; на loopback — журнал и `dev-auth-codes.log` |
| «Неверный пароль панели» | Сброс командой `wynd admin-password` (см. ниже), сессии панели закроются |
| «Устаревшая схема» после отката | База новее бинарника; восстановить копию или поставить более новый бинарник |
| 502/504 от прокси | Upstream `127.0.0.1:7676`, таймаут 300 с, запущен ли контейнер/служба |
| «Нет места» | `df -h`, предел инстанса и квота круга; старые архивы и очистка — в панели |
| Сертификат не продлевается | Certbot, webroot, DNS; в Мастерской — осмотр и «Убрать сертификат» |

### Забытый пароль панели

Старый пароль не нужен, сервер останавливать не надо. Новый пароль команда читает первой строкой стандартного ввода; открытые сессии панели закрываются.

```bash
read -rs P && printf '%s\n' "$P" | sudo -u wynd env WYND_DATA_DIR=/var/lib/wynd wynd admin-password; unset P
```

`read -rs` не показывает пароль на экране; если ввести его прямо в команду, он будет виден. Не короче 8 знаков. В Docker: `docker compose exec -T wynd wynd admin-password`, пароль — так же через трубу.

## 12. Безопасность

- **Секреты.** В `wynd.db` открытым текстом лежат пароль SMTP и приватный ключ VAPID. Бэкапы содержат те же секреты. Не кладите их в общедоступное место и не отправляйте в чат.
- **Права.** `wynd.db` — `0600`, `config.json` — `0640`; каталог данных закрыт для посторонних (`0750` в systemd, `0700` в Docker); бэкапы — `0700`, копия базы — `0600`. Не запускайте команды от root: от root создаются `-wal`/`-shm`, которые служба потом не откроет.
- **Наружу — только HTTPS.** Порт 7676 слушает loopback; его публикует прокси. Без HTTPS не работают service worker, пуш и камера.
- **Доверенные прокси.** `WYND_TRUSTED_PROXIES` — только те адреса, откуда действительно приходит прокси. Иначе лимиты по адресу обходятся подделкой `X-Forwarded-For`.
- **Панель.** Пароль не короче 8 знаков; после смены старые сессии закрываются. Не передавайте ссылку первого запуска — она одноразовая, но до использования действует.
- **Почта.** Для SMTP лучше отдельный пароль приложения, а не основной пароль ящика.
- **Обновления.** Читайте «Оператору» в CHANGELOG и ставьте выпуски с исправлениями безопасности. До 1.0 исправления выходят только в последней минорной ветке.
- **Сообщение об уязвимости.** Порядок — в [SECURITY.md](SECURITY.md). Не публикуйте детали до исправления.
