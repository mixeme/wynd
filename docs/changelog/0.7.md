# Изменения 0.7.x

Ветка 0.7 целиком, как она велась в корневом `CHANGELOG.md`.
Записи не переписывались. Ссылки на файлы указывают на их место в момент
записи и могли устареть.

## [0.7.3] — 2026-09-23

План 42, волны 4 и 5 — тесты на непокрытые обработчики и рефакторинг.
Сам рефакторинг поведения не меняет; версия поднята из-за находок аудита и мелких поломок экранов, перечисленных ниже.

### Исправлено

- **Заглушённый круг снова молчит.** Срок «не беспокоить» разбирался только при чтении: строка, которую разобрать не удалось, молча означала «не заглушено». Теперь она проверяется при сохранении.
- **Список реакций и кнопка «назад».** Лист реакций закрывается системной «назад», а не уводит с экрана.
- **Двойная отправка.** Кнопка отправки и реакция гасятся на время запроса — быстрый двойной тап больше не заводит две записи и не гоняет реакцию туда-сюда.
- **Удаление из очереди** спрашивает подтверждение.
- **Поиск.** Обработчик истории снимался не всегда: экран оставлял его за собой.
- **Пределы ввода.** Запрос мимо клиента мог приложить к записи сколько угодно вложений — теперь не больше пятидесяти. Отрицательное окно правки отвергается и при создании круга. Название дня приходит обрезанным по краям, из одних пробелов — не название.

### Изменено

- **Учётка соседа не видна.** `account_id` в списке участников круга приходит только владельцу и тем, у кого право на настройки. Учётка на сервере — не лицо в круге; связывать лица в разных кругах по ней обычному участнику незачем.
- **Быстрее на больших кругах.** Список дней собирается тремя запросами вместо запроса на каждый день; оценка личного архива — одним агрегирующим; срез архива — пакетно. Лента не ждёт адресов картинок.
- **Убраны редирект-маршруты** `/admin/smtp` и `/circles/[id]/settings/delete`, отладочный раздел `/dev/spike` и скрипт `extract-ui-assets.py`.
- Кнопки в библиотеке интерфейса опираются на один сброс `:where(button)` вместо 44 классов-зеркал; вёрстка экранов переезжает с `style="…"` на служебные классы — все экраны панели переписаны, инлайн-стилей стало 585 → 348. За тем, чтобы их число не росло, следит `npm run check:ui`.
- Логика экранов (жесты, реакции, состояние поиска, склонения, адреса-параметры) вынесена в `$lib` и покрыта тестами.
- `SendSignal` снимает список push-подписок целиком до первой доставки: курсор по таблице больше не держится открытым на время сетевых запросов. Поведение то же.
- Файл `admin_wave_f_test.go` назван по предмету — `admin_accounts_quota_test.go`; в README вместо таблицы областей — ссылка на инварианты.

### Добавлено

- Тесты на то, что до сих пор не исполнялось ни разу: права владельца круга и состояние после отказа, подтверждение удаления круга, передача владения, исключение, чтение круга посторонним со всех десяти поверхностей, авторство комментария, одна реакция на участника, три обработчика поиска с фильтрами, утверждение и отказ по оплате, шлюзы панели оплаты, пароль релея, заявки на квоту, отзыв серверной ссылки, совпадение JSON, SSE и NDJSON, HEAD загрузки после оборванного куска, курсор прочитанного, доставка push по всем видам ответа.
- У каждого теста инвариантов хроники и архива — строка с тем, что он держит; перечень инвариантов в справочнике пополнен.

## [0.7.2] — 2026-09-22

План 42, волна 3 — процесс, лицензия, деплой и остаток находок аудита.

### Исправлено

- **Ссылки-приглашения перестали быть вечными.** Ссылка, выданная участником, теперь снимается вместе с ним: при выходе, исключении, блокировке и удалении учётки. Незавершённое вступление («вас пригласили, осталось выбрать имя») живёт сутки, а не всегда, и снимается вместе с отозванной ссылкой; раньше по нему входили в круг и через месяц. Просмотр ссылки проверяет её так же, как и вход: исчерпанная ссылка больше не показывает постороннему название круга и список участников. У ссылки появились потолки — сто входов и тридцать суток.
- **Вход.** Знающий чужую почту мог раз за разом сжигать три попытки её кода и держать хозяина без входа — теперь попытки считаются и по адресу обратившегося. Полсотни неудачных попыток пароля с чужих адресов замедляют вход в панель, а не закрывают его хозяину. Потолок запросов кода не обходится одновременными запросами. На закрытую учётку открытый сервер отвечает как на любую другую — и не сообщает посторонним, кто здесь есть и кого закрыли.
- **Уведомления.** Сервер проверяет адрес push-службы при каждой отправке, а не только при подписке: имя, переведённое на внутренний адрес после подписки, больше не открывает дорогу внутрь сети. Адрес устройства не попадает в журнал целиком — он равносилен ключу от него.
- **Почта.** Ответ о неудачной отправке называет причину (не ответил, шифрование, логин, протокол), а не пересказывает ответ чужого сервера.
- **Установка.** Неверный публичный адрес отвергается сразу: раньше он записывался в настройки, и сервер после перезапуска не стартовал, а установка считалась выполненной.
- **Карта.** Атрибуция OpenStreetMap ведёт на условия использования, плитки берутся с актуального адреса.
- **`docker build` снова собирается** — сломан был с 0.1.x.

### Добавлено

- **Сборка проверяется автоматически.** `.gitea/workflows/ci.yaml` прогоняет те же ворота, что и `scripts/test.bat`, плюс сборку образа. На Unix — `Makefile` с целями `build`, `test`, `run`, `docker`, `licenses`.
- **Лицензии компонентов.** `THIRD_PARTY_LICENSES.txt` отдаётся клиентом по ссылке рядом с «исходный код» (настройки участника и футер панели); файл собирается скриптом из боевых зависимостей клиента и модулей сервера, его свежесть проверяют тесты.
- **Адрес исходников — один.** Сервер отдаёт его в `/api/v1/instance`, клиент берёт оттуда; форку достаточно поменять одну строку.
- Тесты: доставка push на внутренний адрес, лимиты входа, отзыв ссылок и срок вступления, причина отказа почты, адрес при установке, совпадение версии в спеках OpenAPI, свежесть файла лицензий.

### Изменено

- Образ: `HEALTHCHECK`, метки OCI, копия лицензии внутри; сборка без путей сборочной машины.
- Юнит systemd: песочница (`ProtectKernel*`, `RestrictAddressFamilies`, `SystemCallFilter`, `UMask=0077`, пустой `CapabilityBoundingSet`).
- [CONTRIBUTING.md](../../CONTRIBUTING.md) — разделы об адресе исходников и о файле лицензий; справочники сервера и клиента.

### Оператору

- Миграции 0015 и 0016 применяются при запуске. 0016 добавляет срок незавершённым вступлениям: если кто-то получил приглашение и не выбрал имя больше суток назад, ему понадобится новая ссылка.
- Ссылки-приглашения заблокированных и удалённых учёток, а также тех, кто вышел из круга, будут отозваны — в том числе уже выданные.
- `install.sh` изменился: Caddy, установленный **до** скрипта, больше не перенастраивается (это режим `--own-proxy`, в лог печатается фрагмент конфигурации); перед заменой бинаря снимается копия данных в `<data>/backups/pre-update-<дата>`, и при её сбое обновление не выполняется.
- Юнит systemd переписывается установщиком: после обновления проверьте `systemctl status wynd`.

## [0.7.1] — 2026-09-22

План 42, волна 2а — аудит безопасности (`docs/security-audit-2026-09-22.md`). Критических и высоких находок нет; всё среднее исправлено, часть низкого — тоже, остальное в очереди плана.

### Исправлено

- **Чужой ключ повтора.** Повтор записи или комментария по `client_id` возвращал сущность другого автора и дописывал к ней вложения отправителя; честный повтор с фото дублировал вложение. Ключ теперь только свой, повтор ничего не привязывает второй раз.
- **Заголовок и обложка дня.** Исключённый или вышедший участник мог стереть общий заголовок и обложку дня — теперь только тот, кто пишет в круг.
- **Поиск после ухода.** Вышедший с сохранением доступа находил поиском комментарии, написанные после его ухода; лента их скрывала — поиск теперь тоже.
- **Оплата не запирает всех.** Загрузка файла требовала оплаченной подписки, а заявка на оплату — загруженного скриншота; включение подписки оставляло участников без выхода до ручного продления. Загрузка открыта истёкшему участнику, привязать файл к кругу без оплаты по-прежнему нельзя. Одна ожидающая заявка на учётку; утверждение не удваивает срок при двойном нажатии и не переписывает отказ.
- **Квота и пустые загрузки.** Место резервировалось по заявленному размеру: участник без единого байта мог занять всю квоту на сутки. Считаются принятые байты.
- **Архив.** Одна сборка архива на участника одновременно (иначе параллельные запросы держали копии всего среза в памяти).
- **Права на файлы.** База данных и её копия в бэкапе — только владельцу (0600), каталог бэкапа — 0700; раньше копия получала права по умолчанию.
- **Клиент.** Повтор `@имя` в тексте или два одноимённых участника роняли экран у всех читателей. Выход из учётки стирает неотправленную очередь, кэш фото и снимает push-подписку — на общем устройстве неотправленная запись могла уйти под следующей учёткой. Ссылка-приглашение с чужого сервера не разбирается (её токен уходил на текущий сервер), своя строится от сервера круга.
- **Мелкое.** Блокировка и удаление учётки снимают push-подписки; сигналы о новой активности уходят только действующим участникам; один молчащий push-адрес больше не глушит уведомления остальным; имена файлов с кавычкой в `Content-Disposition`; скриншот оплаты админу — как вложение; `/probe/body` принимает объявленные 2 МиБ; каталоги `/_app/`, `/fonts/` не листаются; `/ready` не раскрывает текст ошибки базы; `X-Forwarded-For` читается из всех строк заголовка; потолки длины комментария заявки, реквизитов и текста баннера.

### Добавлено

- `CONTRIBUTING.md` с триггерами повторного аудита; ссылки на оба отчёта в README; принятые риски записаны в справочниках.
- Тесты: право писать при стирании дня, повтор по `client_id` только свой, поиск по отрезку, шлюз оплаты и загрузка истёкшего, миграция 0014 на заполненной базе, права бэкапа (Unix), листинг каталогов, лимит пробы тела, XFF из нескольких строк, снятие push при блокировке, настройки уведомлений только своего круга, разбор чужих ссылок и очистка состояния сервера на клиенте.

### Оператору

- Миграция 0014: если у одной учётки было несколько ожидающих заявок на оплату, младшие помечены отклонёнными; файлы скриншотов сохранены.
- Права `wynd.db` выравниваются до 0600 при старте. Каталог бэкапа создаётся 0700; существующий общедоступный каталог сервер не переназначает — проверьте после первого `wynd backup`.
- `docker build` по-прежнему сломан (`.dockerignore`, DEP-1) — волна 3.

## [0.7.0] — 2026-09-22

План 42, волна 2 — целостность данных: время, ссылки на файлы, очередь, загрузки, конфигурация.

### Исправлено

- **Порядок внутри секунды.** Метки времени писались переменной длиной, и база, сравнивая их как строки, могла поставить более позднее событие раньше. Затрагивало порядок ленты, курсоры и отрезки видимости. Теперь формат фиксированной ширины, существующие значения выровнены миграцией.
- **Удалённые фотографии освобождают место.** Архивная чистка и удаление круга снимали записи, но не ссылки на файлы: файлы оставались на диске навсегда и по-прежнему отдавались по прямой ссылке.
- **Удаление записи стало одним действием.** Запись, её ветка, вложения и ссылки на файлы уходят вместе или не уходят вовсе.
- **Настройки круга применяются целиком.** Раньше правка нескольких полей шла по одному: неверное значение в конце оставляло круг наполовину изменённым.
- **Очередь не создаёт дублей.** Если ответ на отправленную запись не дошёл, повтор больше не создаёт вторую такую же: у записи и комментария появился ключ, по которому сервер узнаёт повтор.
- **Очередь не запирается.** Недоступный сервер задерживает только свои отправки, а не все; паузы между попытками растут; «выход из учётки» больше не хоронит запись навсегда; зависшая отправка после закрытия вкладки возвращается в работу; две вкладки не сливают очередь дважды.
- **Кэш круга сбрасывается.** После исключения из круга, правки и удаления записи локальный кэш круга оставался и читался офлайн — теперь уходит.
- **Загрузки.** Оборванный кусок файла больше не портит загрузку безвозвратно; завершение не может оставить файл без записи или запись без файла; открытые загрузки учитываются в потолке места (раньше несколько параллельных превышали его кратно).
- **Поиск слов.** «море дача» находит «море и лето на даче» — запрос больше не одна фраза. Название дня не пропадает из поиска после правки или чистки старых версий.
- **Хранилище.** Пропуск миграции в середине цепочки — отказ запуска, а не применение поверх более новой схемы. Круг больше 2000 записей отмечается в журнале сервера, а не обрезается молча.
- **Конфигурация.** Чтение настроек больше ничего не создаёт на диске; запись `config.json` атомарна; неправильный публичный адрес (`ftp://…`, без хоста, с путём) отвергается при старте; `wynd backup` отказывается бэкапить пустой каталог данных.

### Добавлено

- Тест миграций поверх **заполненной** базы предыдущей версии; тесты порядка меток времени, идемпотентности очереди, освобождения файлов, атомарности настроек, инвалидации кэша, пауз очереди.

### Изменено

- [server-reference.md](../reference/server-reference.md) — формат времени, транзакции, удаление, очередь, загрузки, поиск, мигратор, конфигурация.

### Оператору

- **Миграции 0011, 0012, 0013** применяются при первом запуске: выравнивание меток времени, пересборка поиска по дням, ключ идемпотентности. Сделайте `wynd backup` перед обновлением — миграция 0011 переписывает значения во всех таблицах со временем.
- **Проверьте публичный адрес.** Если в `config.json` или `WYND_PUBLIC_URL` лежит адрес с путём, без хоста или с необычной схемой, сервер не запустится и скажет почему. Исправьте адрес на вид `https://home.example.org`.
- Откат на прежнюю версию после обновления не предусмотрен: схема базы поднялась до 13.
