# Wynd для компьютера

Оболочка Windows: своя рамка, постоянный профиль WebView2, выбранный сервер и его интерфейс в окне. Решения — [план 55](../plans/55-desktop-client.plan.md), шаги — [план 61](../plans/61-desktop-shell.plan.md).

## Сборка

```
scripts\build-desktop.bat
```

Скрипт собирает `cmd/wynd-desktop/frontend` и кладёт `dist\wynd-desktop.exe` (Windows GUI, без консольного окна). Для проверки без установки: `go build -tags "desktop,production" -ldflags "-H windowsgui" ./cmd/wynd-desktop`. Ворота — `scripts\test-desktop.bat`, CI — `.github/workflows/desktop.yaml`.

Подпись и самообновление пока не входят: выпуск оболочки — отдельная задача по модели Мастерской.

## Данные

- Список серверов и выбранный адрес: `%AppData%\Wynd\desktop\servers.json`. Токенов и паролей там нет.
- Профиль WebView2: `%AppData%\Wynd\desktop\webview`; данные Wynd из системного профиля не используются.
- Сессии, очередь и медиа-кэш — в IndexedDB профиля, как у веб-клиента.

## Устройство

- Окно Wails: `cmd/wynd-desktop`, полоса заголовка `$ui/workshop/TitleBar` без отдельной кнопки серверов.
- Оболочка — Svelte под `/__shell/`; интерфейс выбранного сервера — в iframe на `/`.
- `internal/desktop.Proxy` отдаёт оболочку и сервер с одного origin: `/api/v1`, поток событий, медиа и переходы идут в выбранный сервер. Другие добавленные серверы — через `/__srv/<scheme>/<host>`; список разрешённых берётся из `servers.json`, адрес из запроса сам доступа не даёт. `X-Frame-Options` снимается, `frame-ancestors 'none'` заменяется на `'self'`.
- В HTML сервера вставляется `window.__wyndDesktop={"origin":…,"apiBase":…}`; `$lib/desktop/bridge.ts` подставляет настоящий адрес в плашки, ссылки и запросы. `apiBase` — локальный порт окна (`127.0.0.1:<случайный>` с CORS): API и поток событий идут туда обычным TCP, потому что WebView2 через asset-сервер Wails буферизует ответы целиком и SSE не течёт (иначе сервер ложно «не отвечает»).
- У сервера две независимые роли: источник интерфейса (временная, пока клиент не вшит в приложение) и учётная запись с данными (постоянная, как на телефоне; экран «Настройки → Серверы»). Роли хранятся в `servers.json`; записи прежней версии при открытии получают обе роли.
- Структура реализована 2026-11-10: «Серверы» — только учётные записи и действие «Войти на сервер»; источник и его смена — «Настройки → Приложение → Интерфейс». Строка смены открывает экран оболочки через `wynd:open-interface`. Смена источника не меняет входы и круги; добавление источника после предварительной проверки не создаёт учётную запись и не переключает окно. У неактивного источника есть крестик с подтверждением удаления; текущий источник удалить нельзя. Удаление источника сохраняет вход и разрешение прокси. Подробности и кадры — [план 62](../plans/62-desktop-servers-settings.plan.md).
- Служебный воркер PWA в окне не нужен: оболочка удаляет `webview/EBWebView/Default/Service Worker` при запуске, а клиент не регистрирует SW при наличии моста; иначе окно показывает старый интерфейс из кэша. Окно открывается 760×780 (MinWidth 500) — по ширине интерфейса.
- ПК3 — сохранённый сервер не отвечает; ПК7 — список, добавление и переключение источника интерфейса из «Настройки → Приложение».
- ПК5 — автозапуск: запись `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, значение `Wynd`, путь exe в кавычках и `--from-startup`; строка в «Настройки → Приложение».
- ПК6/ПК6а — HTML5 drop внутри интерфейса сервера: на странице круга появляется зона приёма, файлы уходят в существующую подготовку новой записи. Нативный мост Wails не включён; он остаётся запасным путём.

## Совместимость

Оболочка открывает интерфейс любого сервера Wynd. Настольные возможности внутри интерфейса — мост адреса, «Войти на сервер», смена источника, зона приёма файлов и строка автозапуска — есть только у сервера, собранного с этим изменением клиента. С сервером 0.50.0 окно выберет и откроет его, но этих строк и зоны не будет: клиент сервера их ещё не знает.

## Границы

- Пока Windows; macOS и вшитый интерфейс — позже, Linux после Windows.
- Одновременные серверы: выбранный в корне окна, остальные через `/__srv`; сессии, выход и общий список кругов — в веб-интерфейсе. «Войти на сервер» в браузере по-прежнему скрыто (C69), в окне для компьютера работает.
- Не проверены вручную: перенос мышью из Проводника и вход Windows. Ввод в тестовой сессии недоступен; проверка входа — клавиатурой и мышью на обычном рабочем столе.
