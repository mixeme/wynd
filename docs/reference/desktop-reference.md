# Wynd для компьютера

Оболочка Windows и Linux ([план 69](../plans/69-linux-desktop.plan.md); Linux — `.deb` и AppImage с 0.5.7): своя рамка, выбранный сервер и его интерфейс в окне. Решения — [план 66](../plans/66-desktop-functions.plan.md) (оболочка выпущена), шаги — план 61.

## Сборка

```
scripts\build-desktop.bat
```

Скрипт собирает `cmd/wynd-desktop/frontend` и кладёт `dist\wynd-desktop.exe` (Windows GUI, без консольного окна). Для проверки без установки: `go build -tags "desktop,production" -ldflags "-H windowsgui" ./cmd/wynd-desktop`. Ворота — `scripts\test-desktop.bat`, CI — `.github/workflows/desktop.yaml`.

Выпуски подписываются общим ключом экосистемы через «Wynd Подпись»; в exe и Linux-бинарник вшит открытый ключ, backend самообновления реализован. С 0.3.0 окно предлагает новую версию полосой поверх интерфейса (план 63, принята 2026-11-11); пока идёт установка, под заголовком полосы — ход скачивания, на кнопке — «Скачиваем 46 %…» (принята 2026-11-27, [протокол](../testing/desktop-update-progress-2026-11-27/README.md)). Порядок выпуска — [DEVELOPMENT.md](../DEVELOPMENT.md#wynd-мастерская).

## Linux (план 69)

Целевые системы — Ubuntu 24.04 и Debian 12, x86_64. Сборка — `scripts/build-desktop-linux.sh` на GTK3/WebKit2GTK 4.1; ворота — `scripts/test-desktop-linux.sh` и job в `.github/workflows/desktop.yaml`; выпуск — `.deb` и AppImage. Трей на Linux — нативное меню, кастомное окно 92×56 остаётся только на Windows. До живого замера `wails://` запись голоса/видео, камера, геолокация и скачивание в Linux-версии не обещаются: secure context проверяется первым этапом.

**Самообновление Linux** (с версии после 0.5.7; 0.5.7 собрана без ключа): сборка вшивает открытый ключ из `signing-key.pub`; вид определяется по `APPIMAGE` или записи `/var/lib/dpkg/info/wynd-desktop.list`. AppImage подменяет сам файл (прежний остаётся `.old`), `.deb` после проверки подписи ставится `pkexec dpkg -i` — нужен PolicyKit и окно пароля. Локальная сборка без установки обновлений не предлагает. Новый процесс получает `WYND_UPDATE_FROM_PID` и ждёт выхода прежнего, а окружение чистится от путей смонтированного AppImage.

## Данные

- Список серверов, выбранный адрес данных и источник интерфейса: `%AppData%\Wynd\desktop\servers.json` (`source`: `embedded` по умолчанию или `server`). Токенов и паролей там нет.
- Профиль WebView2: `%AppData%\Wynd\desktop\webview`; данные Wynd из системного профиля не используются.
- Сессии (план 66, функция 3): токены учётных записей и панели живут в Credential Manager (`Wynd.Desktop/<origin>`), клиент работает с ними через ручки `/__secrets` локального порта окна; при отказе или старой оболочке — откат в IndexedDB профиля, как у веб-клиента. Очередь и медиа-кэш — в IndexedDB профиля. Форматы и сроки снятия — [реестр миграций](migrations.md).

## Устройство

- Окно Wails: `cmd/wynd-desktop`, полоса заголовка `$ui/workshop/TitleBar` без отдельной кнопки серверов.
- Оболочка — Svelte под `/__shell/`; интерфейс (вшитый клиент или страницы выбранного сервера) — в iframe на `/`.
- `internal/desktop.Proxy` отдаёт оболочку и сервер с одного origin: `/api/v1`, поток событий, медиа и переходы идут в выбранный сервер. Другие добавленные серверы — через `/__srv/<scheme>/<host>`; список разрешённых берётся из `servers.json`, адрес из запроса сам доступа не даёт. `X-Frame-Options` снимается, `frame-ancestors 'none'` заменяется на `'self'`.
- Окно в трее не засыпает: у WebView2 отключён троттлинг фоновых таймеров, очередь отправки планирует повтор сама (после неудачи и для прерванных отправок). Недоступный сервер прокси рвёт соединением, а не ответом 502 — иначе клиент считал бы это ответом API и не ставил запись в очередь. Локальный порт разрешает и открывает странице заголовок `Upload-Offset` для загрузки кусками. Подробности и живой прогон — [протокол](../testing/desktop-background-upload-2026-11-19.md).
- В HTML страницы вставляется `window.__wyndDesktop={"origin":…,"apiBase":…}`; у вшитого клиента есть ещё `"embedded":true`. `$lib/desktop/bridge.ts` подставляет настоящий адрес в плашки, ссылки и запросы. `apiBase` — локальный порт окна (`127.0.0.1:<случайный>` с CORS): API и поток событий идут туда обычным TCP, потому что WebView2 через asset-сервер Wails буферизует ответы целиком и SSE не течёт (иначе сервер ложно «не отвечает»). Вставка моста ищет точный маркер `window.__wyndDesktop={`, а не голое имя: в `app.html` с C143 есть проверка `if (window.__wyndDesktop)`, из-за которой прежний поиск молча оставлял страницу без моста (найдено 27.11).
- У сервера две независимые роли: источник данных (постоянная, как на телефоне; экран «Настройки → Серверы») и источник интерфейса (с 27.11 необязательная: по умолчанию интерфейс вшит). Роли хранятся в `servers.json`; записи прежней версии при открытии получают обе роли. Отдельное поле `source` (`embedded`/`server`; пусто = `embedded`) говорит, откуда окно берёт страницы; `selected` — сервер данных.
- Структура реализована 2026-11-10: «Серверы» — только учётные записи и действие «Войти на другой сервер»; источник интерфейса и его смена — «Настройки → Приложение → Интерфейс». На экране источников первой строкой «Встроенный» (выбран по умолчанию), ниже серверы; сервер, с которого идут данные, подписан «Данные с этого сервера» и не удаляется. Выбор сервера открывает его интерфейс (серверный режим), «Встроенный» возвращает вшитый с тем же сервером данных. Строка смены открывает экран оболочки через `wynd:open-interface`. Смена источника не меняет входы и круги; добавление источника после предварительной проверки не создаёт учётную запись и не переключает окно. У неактивного источника есть крестик с подтверждением удаления. Удаление источника сохраняет вход и разрешение прокси. Подробности и кадры — план 62 (кадры в истории git) и [протокол переключения](../testing/desktop-embedded-default-2026-11-27.md).
- Служебный воркер PWA в окне не нужен: оболочка удаляет `webview/EBWebView/Default/Service Worker` при запуске, а клиент не регистрирует SW при наличии моста; иначе окно показывает старый интерфейс из кэша. Окно открывается 1060×780 (MinWidth 500): сразу две колонки — список 340 и содержимое 720. Уже 1060 окно показывает одну колонку, как на телефоне.
- ПК3 — сохранённый сервер не отвечает; ПК7 — список, добавление и переключение источника интерфейса из «Настройки → Приложение».
- ПК5 — автозапуск: запись `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, значение `Wynd`, путь exe в кавычках и `--from-startup`; строка в «Настройки → Приложение».
- Схема `wynd:open?url=<https-адрес приглашения>` (план 66, функция 4): браузер передаёт приглашение окну; на Windows запись обработчика — HKCU при каждом запуске, на Linux — `~/.local/share/applications/wynd.desktop` с `Exec` на `SelfPath()` (у AppImage — сам файл образа). Свой сервер — интерфейс сразу на экран приглашения, чужой — переключение интерфейса проверкой адреса, отказ — экран «Добавить сервер интерфейса» с адресом и словами об отказе. Кнопка «Открыть в приложении» на странице приглашения показывается в браузере Windows и Linux (телефон и окно — нет).
- ПК6/ПК6а — HTML5 drop внутри интерфейса сервера: на странице круга появляется зона приёма, файлы уходят в существующую подготовку новой записи. Нативный мост Wails не включён; он остаётся запасным путём.
- Общая горячая клавиша `Ctrl+Alt+W` показывает и фокусирует окно из любого места Windows (план 66, функция 1). Ошибки Wails без экрана — в журнал через `ErrorHandler`.
- Вшитый интерфейс (план 66, функция 9; основной с 27.11): exe содержит собранный клиент (`web.Build`); страницы и статика — из exe, а `/api/`, `/archive/`, `/admin/bootstrap`, `/__srv/…` — через прокси на выбранный сервер; origin окна прежний, данные не переносятся. Источник — поле `source` в `servers.json`; серверный режим — явный откат в «Настройки → Приложение → Интерфейс» или ключом `--server-ui` (на один запуск, настройка не перезаписывается; прежний `--embedded-ui` принимается для совместимости). Живая проверка и кадры — [протокол](../testing/desktop-embedded-default-2026-11-27.md).
- Копии архивов по расписанию (план 66, функция 7): настройки — `%AppData%\Wynd\desktopackups.json`; раз в полчаса окно сверяет срок и собирает архивы участника выбранного сервера в папку (`«<круг> ГГГГ-ММ-ДД.zip»`) токеном из Credential Manager — пока приложение запущено, окно может быть закрыто. Ротация — по числу последних или сроку, только свои файлы. Экран — «Настройки → Приложение → Копии по расписанию».
- Системные уведомления Windows (план 66, функция 2): toast от AUMID `com.wynd.desktop` (HKCU-запись с именем и значком при запуске), мост `App.Notify` уведомляет только когда окно спрятано в трей или свёрнуто (`ShouldNotify`); Wails v3.1.0 API уведомлений не имеет — используется go-toast (следить за нативным API v3.2+; при появлении `ShowToast` заменяется одной функцией). Потребители: «Вышла версия X» — периодическая проверка (6 ч) и момент скрытия окна, дедуп по версии; новые записи — живая рамка `event: notify` потока `/sync` (сервер решает тем же правилом, что для пуша), клиент пересылает её оболочке как `wynd:notify`.
- Меню значка в трее — своё окно Wails 92×56 в стиле рамки (бумага/чернила, Golos, строки 24) вместо нативного меню Windows: «Открыть» и «Выход»; принято 24.11, [протокол](../testing/desktop-tray-menu-2026-11-24/README.md). Окно прогревается скрытым при старте, чтобы правый щелчок открывал меню сразу; закрывается по Esc, выбору пункта или потере фокуса. С 0.4.5 (опубликован 25.11) меню своё; в 0.4.4 было нативное.

## Совместимость

Вшитый клиент приходит из exe и не зависит от версии сервера: оболочка открывает данные любого сервера Wynd, который отвечает API клиента, а настольные строки и зона приёма файлов есть всегда. Серверный режим по-прежнему показывает клиент сервера: со старым сервером (0.50.0) окно выберет и откроет его, но настольных строк и зоны не будет; раздел **«Настройки → Приложение → Интерфейс»** требует сервер **0.52.0 или новее**. Такой случай подтверждён владельцем 2026-11-11 в серверном режиме; после выбора обновлённого сервера раздел появился, исправление кода не потребовалось.
