# Wynd для компьютера

Оболочка Windows: своя рамка, постоянный профиль WebView2, выбранный сервер и его интерфейс в окне. Решения — [план 66](../plans/66-desktop-functions.plan.md) (оболочка выпущена), шаги — план 61.

## Сборка

```
scripts\build-desktop.bat
```

Скрипт собирает `cmd/wynd-desktop/frontend` и кладёт `dist\wynd-desktop.exe` (Windows GUI, без консольного окна). Для проверки без установки: `go build -tags "desktop,production" -ldflags "-H windowsgui" ./cmd/wynd-desktop`. Ворота — `scripts\test-desktop.bat`, CI — `.github/workflows/desktop.yaml`.

Выпуски подписываются общим ключом экосистемы через «Wynd Подпись»; в exe вшит открытый ключ, backend самообновления реализован. С 0.3.0 окно предлагает новую версию полосой поверх интерфейса (план 63, принята 2026-11-11). Порядок выпуска — [DEVELOPMENT.md](../DEVELOPMENT.md#wynd-мастерская).

## Данные

- Список серверов и выбранный адрес: `%AppData%\Wynd\desktop\servers.json`. Токенов и паролей там нет.
- Профиль WebView2: `%AppData%\Wynd\desktop\webview`; данные Wynd из системного профиля не используются.
- Сессии (план 66, функция 3): токены учётных записей и панели живут в Credential Manager (`Wynd.Desktop/<origin>`), клиент работает с ними через ручки `/__secrets` локального порта окна; при отказе или старой оболочке — откат в IndexedDB профиля, как у веб-клиента. Очередь и медиа-кэш — в IndexedDB профиля.

## Устройство

- Окно Wails: `cmd/wynd-desktop`, полоса заголовка `$ui/workshop/TitleBar` без отдельной кнопки серверов.
- Оболочка — Svelte под `/__shell/`; интерфейс выбранного сервера — в iframe на `/`.
- `internal/desktop.Proxy` отдаёт оболочку и сервер с одного origin: `/api/v1`, поток событий, медиа и переходы идут в выбранный сервер. Другие добавленные серверы — через `/__srv/<scheme>/<host>`; список разрешённых берётся из `servers.json`, адрес из запроса сам доступа не даёт. `X-Frame-Options` снимается, `frame-ancestors 'none'` заменяется на `'self'`.
- Окно в трее не засыпает: у WebView2 отключён троттлинг фоновых таймеров, очередь отправки планирует повтор сама (после неудачи и для прерванных отправок). Недоступный сервер прокси рвёт соединением, а не ответом 502 — иначе клиент считал бы это ответом API и не ставил запись в очередь. Локальный порт разрешает и открывает странице заголовок `Upload-Offset` для загрузки кусками. Подробности и живой прогон — [протокол](../testing/desktop-background-upload-2026-11-19.md).
- В HTML сервера вставляется `window.__wyndDesktop={"origin":…,"apiBase":…}`; `$lib/desktop/bridge.ts` подставляет настоящий адрес в плашки, ссылки и запросы. `apiBase` — локальный порт окна (`127.0.0.1:<случайный>` с CORS): API и поток событий идут туда обычным TCP, потому что WebView2 через asset-сервер Wails буферизует ответы целиком и SSE не течёт (иначе сервер ложно «не отвечает»).
- У сервера две независимые роли: источник интерфейса (временная, пока клиент не вшит в приложение) и учётная запись с данными (постоянная, как на телефоне; экран «Настройки → Серверы»). Роли хранятся в `servers.json`; записи прежней версии при открытии получают обе роли.
- Структура реализована 2026-11-10: «Серверы» — только учётные записи и действие «Войти на другой сервер»; источник и его смена — «Настройки → Приложение → Интерфейс». Строка смены открывает экран оболочки через `wynd:open-interface`. Смена источника не меняет входы и круги; добавление источника после предварительной проверки не создаёт учётную запись и не переключает окно. У неактивного источника есть крестик с подтверждением удаления; текущий источник удалить нельзя. Удаление источника сохраняет вход и разрешение прокси. Подробности и кадры — план 62 (кадры в истории git).
- Служебный воркер PWA в окне не нужен: оболочка удаляет `webview/EBWebView/Default/Service Worker` при запуске, а клиент не регистрирует SW при наличии моста; иначе окно показывает старый интерфейс из кэша. Окно открывается 760×780 (MinWidth 500) — по ширине интерфейса.
- ПК3 — сохранённый сервер не отвечает; ПК7 — список, добавление и переключение источника интерфейса из «Настройки → Приложение».
- ПК5 — автозапуск: запись `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, значение `Wynd`, путь exe в кавычках и `--from-startup`; строка в «Настройки → Приложение».
- Схема `wynd:open?url=<https-адрес приглашения>` (план 66, функция 4): браузер передаёт приглашение окну; запись обработчика — HKCU при каждом запуске. Свой сервер — интерфейс сразу на экран приглашения, чужой — переключение интерфейса проверкой адреса, отказ — экран «Добавить сервер интерфейса» с адресом и словами об отказе.- ПК6/ПК6а — HTML5 drop внутри интерфейса сервера: на странице круга появляется зона приёма, файлы уходят в существующую подготовку новой записи. Нативный мост Wails не включён; он остаётся запасным путём.
- Общая горячая клавиша `Ctrl+Alt+W` показывает и фокусирует окно из любого места Windows (план 66, функция 1). Ошибки Wails без экрана — в журнал через `ErrorHandler`.
- Вшитый интерфейс (план 66, функция 9, подготовка): exe содержит собранный клиент (`web.Build`); флаг `--embedded-ui` отдаёт страницы из exe, а `/api/`, `/archive/`, `/admin/bootstrap`, `/__srv/…` — через прокси на сервер; origin окна прежний, данные не переносятся. По умолчанию интерфейс — с сервера: переключение отложено до стабилизации интерфейса (решение владельца 23.11).
- Копии архивов по расписанию (план 66, функция 7): настройки — `%AppData%\Wynd\desktopackups.json`; раз в полчаса окно сверяет срок и собирает архивы участника выбранного сервера в папку (`«<круг> ГГГГ-ММ-ДД.zip»`) токеном из Credential Manager — пока приложение запущено, окно может быть закрыто. Ротация — по числу последних или сроку, только свои файлы. Экран — «Настройки → Приложение → Копии по расписанию».
- Системные уведомления Windows (план 66, функция 2): toast от AUMID `com.wynd.desktop` (HKCU-запись с именем и значком при запуске), мост `App.Notify` уведомляет только когда окно спрятано в трей или свёрнуто (`ShouldNotify`); Wails v3.1.0 API уведомлений не имеет — используется go-toast (следить за нативным API v3.2+; при появлении `ShowToast` заменяется одной функцией). Потребители: «Вышла версия X» — периодическая проверка (6 ч) и момент скрытия окна, дедуп по версии; новые записи — живая рамка `event: notify` потока `/sync` (сервер решает тем же правилом, что для пуша), клиент пересылает её оболочке как `wynd:notify`.

## Совместимость

Оболочка открывает интерфейс любого сервера Wynd. Настольные возможности внутри интерфейса — мост адреса, «Войти на другой сервер», смена источника, зона приёма файлов и строка автозапуска — есть только у сервера, собранного с этим изменением клиента. С сервером 0.50.0 окно выберет и откроет его, но этих строк и зоны не будет: клиент сервера их ещё не знает.

В частности, раздел **«Настройки → Приложение → Интерфейс»** требует сервер **0.52.0 или новее**. Оболочка 0.2.0/0.3.0 со старым сервером этот раздел не покажет: он приходит из веб-клиента сервера, а не из exe оболочки. Такой случай подтверждён владельцем 2026-11-11; после выбора обновлённого сервера раздел появился, исправление кода не потребовалось.

## Границы

- Пока Windows; macOS и вшитый интерфейс — позже, Linux после Windows.
- Одновременные серверы: выбранный в корне окна, остальные через `/__srv`; сессии, выход и общий список кругов — в веб-интерфейсе. «Войти на другой сервер» в браузере по-прежнему скрыто (C69), в окне для компьютера работает.
- Не проверены вручную: перенос мышью из Проводника и вход Windows. Ввод в тестовой сессии недоступен; проверка входа — клавиатурой и мышью на обычном рабочем столе.
