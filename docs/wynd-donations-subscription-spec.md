# Wynd: пожертвования и подписка на инфраструктуру

## Цель

Дать администратору instance два независимых механизма для покрытия расходов на инфраструктуру:

1. **Сбор пожертвований** — добровольный, информационный, ни на что не влияет.
2. **Подписка** — обязательный платный доступ к кругам, с ручным подтверждением оплаты админом.

Модели не исключают друг друга: подписка — обязательный шлюз доступа, донат — необязательный жест поддержки поверх подписки.

---

## 1. Подписка

### Правила доступа

- Подписка обязательна для всех, кто хочет пользоваться кругами.
- Без активной подписки доступ к кругам закрыт полностью.
- Грейс-период отсутствует: блокировка наступает сразу после истечения `subscription_expires_at`.

### Флоу оплаты (ручное подтверждение)

1. Юзер без активной подписки видит заглушку «Доступ закрыт» с кнопкой **«Я оплатил»**.
2. По клику открывается форма: обязательно прикрепить **скриншот** оплаты + опциональный текстовый комментарий.
3. Создаётся `PaymentRequest` со статусом `pending`.
4. Админ видит очередь pending-заявок (скриншот + комментарий + юзер).
5. При подтверждении админ вручную вводит, на сколько дней/месяцев продлить подписку.
   `subscription_expires_at = max(now, current_expires_at) + N дней`
6. При отклонении — статус `rejected`, юзер может подать новую заявку.

### Напоминания об истечении

- За `reminder_days_before_expiry` дней до истечения (глобальная настройка, по умолчанию **7 дней**, задаётся админом) — отправляется:
  - in-app уведомление,
  - email (используется существующий SMTP/email-сервис проекта).

### Очистка скриншотов

- Скриншоты — это файлы в файловом хранилище сервиса, привязанные к `PaymentRequest`.
- При истечении `subscription_expires_at` у юзера (`now > expires_at`) — **все** его скриншоты по approved-заявкам удаляются из хранилища, поле `screenshot_url` очищается.
- Сама запись заявки (`PaymentRequest`) остаётся как история, просто без файла.
- Отдельных таймеров хранения на уровне каждой заявки нет — очистка привязана к истечению текущей подписки юзера.

## 2. Баннер пожертвований

### Правила показа

- Показывается в списке кругов, всем пользователям.
- Никак не связан с подпиской и доступом к кругам — чисто информационный блок.
- В системе может быть **только один активный баннер** одновременно.

### Настройки баннера (задаёт админ при создании)

- `text` — текст сообщения (без сумм и прогресс-бара).
- `is_dismissible` — может ли пользователь скрыть баннер.
- `show_until` — до какого момента показывать баннер.
- `is_enabled` — можно выключить баннер вручную раньше срока.

### Скрытие баннера пользователем

- Если `is_dismissible = true`, юзер может скрыть баннер — скрытие постоянное (не появляется снова при новом заходе), пока админ не выпустит новый баннер (новый `id`).
- У нового баннера скрытие сбрасывается для всех — даже для тех, кто скрывал предыдущий.

## 3. Схема данных

### `User` (добавляемые поля)

| Поле | Тип | Описание |
|---|---|---|
| `subscription_expires_at` | datetime, nullable | null = никогда не платил |
| `dismissed_banner_id` | FK → DonationBannerSettings, nullable | какой баннер юзер скрыл |

### `PaymentRequest`

| Поле | Тип | Описание |
|---|---|---|
| `id` | PK | |
| `user_id` | FK → User | |
| `screenshot_url` | string, nullable | файл в хранилище; очищается после истечения подписки |
| `comment` | text, nullable | опциональный комментарий юзера |
| `status` | enum: pending / approved / rejected | |
| `created_at` | datetime | |
| `reviewed_at` | datetime, nullable | |

### `DonationBannerSettings`

| Поле | Тип | Описание |
|---|---|---|
| `id` | PK | |
| `text` | string | текст баннера |
| `is_dismissible` | bool | можно ли скрыть |
| `show_until` | datetime | срок показа |
| `is_enabled` | bool | ручное вкл/выкл |

### `InstanceSettings` (singleton)

| Поле | Тип | Описание |
|---|---|---|
| `reminder_days_before_expiry` | int, default 7 | за сколько дней слать напоминание об истечении подписки |

---

## 4. Ежедневная cron-джоба

1. **Напоминания**: `now == expires_at - reminder_days_before_expiry` → email + in-app.
2. **Блокировка доступа**: `now > expires_at` → доступ к кругам закрыт.
3. **Очистка скриншотов**: при истечении подписки юзера — удалить файлы всех его approved `PaymentRequest.screenshot_url`, обнулить поле.

---

## 5. Логика показа баннера (псевдокод)

```
показывать баннер, если:
  banner.is_enabled == true
  AND now < banner.show_until
  AND (banner.is_dismissible == false OR user.dismissed_banner_id != banner.id)
```

## Открытые вопросы для реализации

- Формат/лимиты загрузки скриншота (макс. размер, форматы файлов).
- Права доступа: один админ обрабатывает все заявки (без разделения ролей на этом этапе).
- UI очереди заявок в админке — сортировка, пагинация при большом количестве pending-заявок.
