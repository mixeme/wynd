# Повторный проход — Мастерская 0.3.1 и «Wynd Подпись»

Дата: 2026-11-03. Область: включение подписанных обновлений в Мастерской 0.3.1 и изменения помощника подписи после `workshop-v0.3.0`. Это проверка настольных приложений, а не новый аудит сервера Wynd.

Прочитаны `internal/installer/selfupdate.go`, вызовы проверки и установки обновления из окна, сценарий сборки и workflow выпуска, изменения `internal/signing/release.go` и экранов «Wynd Подпись». SSH-команды, перенос, права сервера и формат хранения настроек Мастерской после 0.3.0 не менялись.

## Находки и проверенные границы

Новых находок о правах или пользовательских данных нет.

- В сборку включается только открытый ключ Ed25519 из `cmd/wynd-installer/signing-key.pub` (32 байта после base64). Закрытый ключ и пароль не читаются при сборке и не попадают в Git, GitHub Actions или Мастерскую.
- Самообновление проверяет подпись всего скачанного exe встроенным ключом до записи или переименования файлов. Отсутствие подписи, другой ключ или изменение exe не разрешают установку. Предлагаются только более новые опубликованные версии, через 72 часа после публикации.
- «Wynd Подпись» до подписи сверяет сумму exe и удостоверение GitHub Actions для выбранного тега. Ключ из тега, если он есть, обязателен для проверки подписи; ошибка чтения файла или списка файлов блокирует операцию.
- Для старых тегов без открытого ключа разрешена подпись выбранным ключом владельца с проверкой его открытой частью. Окно явно сообщает, что это не включает самообновление в старой сборке. При добавлении подписи опубликованному выпуску описание и дата публикации сохраняются.

## Ограничения

- С 0.1.0–0.3.0 на 0.3.1 нужно перейти вручную: в старых exe нет ключа проверки. Живую проверку обновления из окна 0.3.1 нужно провести со следующим подписанным выпуском; наличие ключа и модульные тесты её не заменяют.
- Подпись и публикацию черновика выполняет владелец в «Wynd Подпись». Проверка на GitHub не получает пароль или закрытый ключ.
- Настоящие SSH-операции и перенос на сервере в этом проходе не выполнялись: их код не менялся.

## Проверки

Успешны `go vet` и `go test` для `internal/installer`, `internal/signing`, `cmd/workshop-sign`; сборка и тесты обоих настольных пакетов с тегом `desktop`; `npm run check` в обоих окнах (0 ошибок и предупреждений); `npm run check:ui`; production-сборка `scripts/build-installer.bat` со встроенным открытым ключом. Тесты помощника проверяют опубликованный выпуск с заметками и без них, старую сборку без ключа, черновик, отказ при чужом ключе, неверной сумме, удостоверении другого тега и ошибках чтения ключа.
