## [Unreleased]

### Добавлено

- Установщик: выбор «собрать на сервере» (план 45, срез 2а). Под планом установки — строка «Сервер скачает Wynd готовым. Собрать самому»; в плане со сборкой названы git и сборка из исходного кода. Есть ли готовый Wynd этой версии, сервер узнаёт при составлении плана: нет — план сразу про сборку, а не отказ посреди установки.
- `scriptsuild-installer.bat` — сборка настольного установщика одной командой (`cmd\wynd-installeruildin\wynd-installer.exe`).
- Установщик: Wynd можно убрать с сервера, где он уже работает, — ссылкой у строки осмотра «Wynd на этом сервере уже стоит» и на экране «Wynd работает»; данные и сертификат удаляются только по галочке. Нужно, например, при переезде на другую машину.
- Установщик: когда данные решили удалить, сертификат сайта сначала отзывается и только потом удаляется вместе с ключом; не вышло отозвать — окно скажет об этом, удаление всё равно пройдёт.
- Установщик: Wynd ставится на сервер, где уже работает чужой nginx или Caddy (план 45, срез 3). Контейнер Wynd слушает только `127.0.0.1:7676`, сайт добавляется веб-серверу отдельным своим файлом; чужие файлы не правятся. Перед тем как просить веб-сервер перечитать настройку — его собственная проверка (`nginx -t`, `caddy validate`); не прошла — свой файл убирается, веб-сервер не трогается. За nginx сертификат получает certbot (ставится, если его нет), за Caddy — сам Caddy. Осмотр останавливает установку, если в чужой настройке уже есть ошибка или Caddy не читает дополнительные файлы, — и говорит, что сделать. За Apache — пока отказ с причиной.
- Установщик: «Убрать Wynd» за чужим веб-сервером убирает свой файл сайта и просит веб-сервер перечитать настройку; когда удаляют данные — отзывает сертификат адреса Wynd (свой, полученный certbot, или из хранилища чужого Caddy). certbot, nginx и Caddy остаются.
- Установщик: после сборки Wynd из открытого кода убирает сборочный кэш Docker (около 2 ГБ) — если до сборки кэш был пуст, то есть весь он наш; чужой кэш не трогает. После неудачной сборки кэш остаётся для повтора, его уберёт удачный повтор или откат.

### Исправлено

- Установщик: при удалении вместе с данными убираются все тома Wynd, а не только названные в нынешнем `compose.yaml`: после смены способа установки на сервере оставался том прежнего Caddy с уже отозванным сертификатом. Сертификат, отозванный раньше, окно больше не называет неотозванным.

### Изменено

- Установщик: план называет Wynd и Caddy контейнерами («Контейнер Wynd», «Контейнер с веб-сервером Caddy», «Docker — он запускает контейнеры») — понятно, зачем Docker и что Caddy в систему не ставится. Строка осмотра про веб-сервер: «Веб-сервера нет: порты 80 и 443 свободны», «Веб-сервер есть: контейнер из папки Wynd (caddy)», «Веб-сервер есть: nginx — …». Откат убирает и образы, которыми пользовались сами контейнеры.

### Документы

- План 45: срез 3 — nginx и Caddy пройдены на пробном сервере, Apache ждёт решения владельца. Макет установщика: кадры 2в, 3г, 3д — черновик.
- Планы 45 и 46: 0.28.9 выложена на рабочий сервер.
- План 45: решения владельца по срезу 3; план 46: C32 — где хранить данные, в томах Docker или в папке.
- Макет установщика: кадры 2б, 5а, 5б — убрать Wynd с сервера.
- План 50: спецификация UnifiedPush сверена (версия для Android `AND_3.0.0`); общий шлюз для запасного пути через Google, похоже, не нужен серверу с VAPID — подтвердить по первоисточнику.
- Макет установщика: кадры 3а–3в — план с выбором «Собрать самому», план со сборкой, план без готового Wynd.

- План 46: вложения в комментариях и открытка дня подтверждены с телефона.

### Оператору

### Изменено

- Образ в реестре GitHub: у сборки под каждую архитектуру своя метка — `<версия>-amd64` и `<версия>-arm64`; `<версия>` и `latest` — оглавление, которое на них ссылается. Версий без меток на странице пакета больше не остаётся: раньше сборки лежали именно там, и их удаление ломало `docker pull`. Подтверждения происхождения (provenance) выключены.

### Добавлено

- Установщик, осмотр: замечание о медленном диске. Если диск сервера в среднем подтверждает запись дольше 200 мс (у SSD это миллисекунды), осмотр говорит об этом заранее: установка и сам Wynd на таком сервере будут медленными. Берётся из счётчиков ядра с момента загрузки — осмотр по-прежнему ничего не пишет на сервер. Ставить не мешает.

### Исправлено

- Установщик: соединение с сервером больше не молчит — каждые 15 секунд идёт проверка живости. Раньше долгая тихая команда (сборка образа) теряла связь через минуту: «Связь с сервером оборвалась», хотя сервер работал.
- Установщик, сборка из открытого кода: клон, подкачка, сборка и уборка — одна команда на сервере под замком. Оборвалась связь — сервер доводит сборку и сам убирает подкачку и исходники; «Повторить» ждёт идущую сборку и берёт её образ, а не запускает вторую. Отказ по месту называет, сколько нужно и сколько есть.

## [0.28.8] — 2026-10-09

Образ Wynd собирается и на маленьком сервере; установщик умеет собирать его на сервере из открытого кода.

### Добавлено

- Настольный установщик, второй срез (план 45): план («поставим», «не тронем») и установка на чистый сервер — Docker, Wynd, свой веб-сервер Caddy с сертификатом, ссылка первого запуска. Шаги видны по одному, каждый можно повторить: сделанное пропускается. Отказ шага объясняется словами и с советом; «Откатить установку» убирает Wynd с сервера, данные — только по отдельной галочке. Сервер с чужим веб-сервером — следующий срез.
- Образ Wynd в реестре GitHub: `.github/workflows/image.yaml` при каждом выпуске (смена `VERSION`) собирает и выкладывает `ghcr.io/mixeme/wynd:<версия>` и `:latest` под x86-64 и ARM64. Установщик берёт Wynd оттуда — сервер скачивает образ сам, в `compose.yaml` стоит его полное имя. Зеркало на GitHub и открытый пакет работают с 2026-10-09; установщику по-прежнему можно дать образ файлом.
- Установщик: сборка Wynd на самом сервере из открытого кода (план 45, срез 2а) — для тех, кому нельзя ставить готовый образ. Сервер клонирует метку выпуска `v<версия>` с GitHub и собирает образ по `deploy/docker/Dockerfile`. Памяти меньше 2 ГБ вместе с подкачкой — на время сборки заводится временный файл подкачки; места под сборку и подкачку нет — отказ до сборки, а не зависший сервер. Пока только в ядре и в сборке разработчика (`WYND_INSTALLER_SOURCE`): выбора в окне ещё нет.
- У выпусков появились метки в git (`v0.28.7` и дальше): по ним установщик берёт исходный код.

### Изменено

- `deploy/docker/Dockerfile`: клиент и бинарь собираются на машине сборки под нужную архитектуру (`$BUILDPLATFORM`, `$TARGETARCH`) — образ под ARM64 выходит без эмуляции. Обычный `docker build` собирает как раньше; нужен BuildKit (в Docker 23 и новее он по умолчанию).
- Установщик: осмотр больше не гадает, хватит ли диска «на первые фотографии», — проверяет только, поместится ли сама установка (2 ГБ, с уже стоящим Docker — 1 ГБ). Прежний порог в 5 ГБ отказывал дешёвому серверу с диском 7 ГБ. Срок подключения по SSH разделён: 15 с на соединение, минута на рукопожатие и вход.

### Исправлено

- `deploy/docker/Dockerfile`: сборка клиента получает явный предел кучи Node (2 ГБ). На сервере с 708 МБ памяти сборка образа без подкачки подвешивала сервер, а с подкачкой падала с «JavaScript heap out of memory»: Node меряет кучу по памяти машины и подкачку не считает. Теперь на таком сервере образ собирается за 8 минут при 1,5 ГБ подкачки.

### Документы

- План 45: срез 2, проба на настоящем сервере, что осталось. Макет установщика: окно «Готово» — настоящая ссылка первого запуска и что именно проверено.
- План 45: срез 2а и замеры сборки на сервере с одним ядром и 708 МБ памяти.

### Оператору

- Миграции нет. Откат на 0.28.7 возможен: схему база не меняет. Бэкап — как обычно.

### Добавлено

- Полоса связи под шапкой круга и над списком кругов. Пока всё работает, знака нет. Нет сети дольше четырёх секунд — «Нет сети.
