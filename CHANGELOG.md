## [0.9.5] — 2026-09-26

Пуши доходят до Firefox.

### Исправлено

- Пуш-уведомления не доходили до Firefox: сервис Mozilla отбивал каждое (413 — слишком большое тело), каким бы коротким ни был сигнал. Теперь тело укладывается в его лимит; Chrome и Safari принимают то же.
- «Проверка»: если тестовый пуш не прошёл, причина видна в строке «Тестовый пуш», а список проверок остаётся на экране — раньше его заменяла одна строка ошибки.

### Оператору

## [0.9.4] — 2026-09-26

Пуш-уведомления показываются; первый запуск без почты; «Проверка» не краснеет зря.

### Исправлено

- **Пуш-уведомления не показывались никому.** Service worker не обрабатывал событие push: сигнал о новой записи, комментарии, реакции или упоминании доходил до браузера и пропадал. Теперь уведомление показывается — без текста журнала, только что случилось и в каком круге; нажатие открывает круг.
- «Тестовый пуш» в «Проверке» отвечал «отправили», хотя слать было некуда: у панели нет подписки. Теперь кнопка спрашивает разрешение на уведомления, шлёт пуш на этот браузер и говорит, если браузер его не принял.
- «Манифест и service worker» в «Проверке» краснел на любом инстансе: манифест запрашивался не по тому адресу.
- «Домен» в «Проверке» в Docker всегда предупреждал «сервер за NAT»: сравнивался адрес контейнера. Теперь домен подтверждает браузер — он пришёл по этому имени и получил ответ именно этого сервера.
- «Доступ» создавал новую многоразовую ссылку на сервер при каждом открытии — на чистом инстансе их копилось столько, сколько раз открыли экран. Теперь экран показывает последнюю живую ссылку и выпускает новую, только если живых нет.
- Панель: подсказки стояли с отступом, которого нет у текста рядом (например, «Реквизиты пока пустые» на «Оплате»); на «Сжатии» поле качества выбивалось из колонки, а подпись «Формат и качество» переносилась.

### Изменено

- Первый запуск: обязателен только пароль администратора. Почту, имя и адрес можно задать позже в панели — и на публичном адресе, не только на loopback. До настройки почты участники не получат код входа, «Проверка» покажет это в строке «Письмо». Адрес сервера подставляется из открытой ссылки, если она по HTTPS. Кнопка сохранения больше не прячется под полосами мобильного браузера (подсказка пароля, панель адреса): под ней есть запас прокрутки.

### Оператору

- Миграций нет, схема v16: откат на 0.9.3 — заменой бинарника или образа.
- После обновления клиент у участников подхватывается со второй загрузки страницы: новый service worker ставится в фоне.

## [0.9.3] — 2026-09-26

Apache как обратный прокси и Docker за прокси хоста; первый запуск с телефона.

### Добавлено

- **Apache** как обратный прокси: шаблон `deploy/proxy/apache.conf` и готовый vhost в панели («Проверка» → прокси → apache). Клиентский `X-Forwarded-For` снимается, адрес клиента дописывает сам Apache; SSE не буферизуется, таймаут 300 с.
- `deploy/docker/compose.own-proxy.yaml` — Wynd в Docker за прокси, который уже стоит на хосте: без Caddy, порт только на `127.0.0.1:7676`, доверенный прокси — один шлюз сети контейнера.

### Исправлено

- Первый запуск с телефона: ошибка (не введён пароль, не заполнен SMTP) показывалась под кнопкой «Сохранить и открыть панель» — за клавиатурой и панелью браузера, и нажатие выглядело как «ничего не произошло». Теперь она над кнопкой, страница прокручивается к ней; на узком экране карточки идут столбиком, поля SMTP не наезжают друг на друга.
- Service worker регистрировался относительно открытой страницы: первый заход по ссылке `/admin/…` или `/join/…` просил `/admin/sw.js` (404), и приложение не ставилось как PWA до захода на главную.

### Оператору

- Apache: vhost из `deploy/proxy/apache.conf` или из панели; нужны модули `proxy`, `proxy_http`, `ssl`, `headers`, `rewrite`, `setenvif`. `WYND_TRUSTED_PROXIES` — адрес, с которого Apache ходит в Wynd (для Docker — шлюз сети контейнера, не весь диапазон).
- Миграций нет, схема v16: откат на 0.9.2 — заменой бинарника или образа.

## [0.9.0] — 2026-09-24

Локальный запуск открывается с телефона в той же сети. Минорная версия —
из-за новой возможности запуска; поведение боевого сервера не менялось.

### Добавлено

- **Локальный запуск открывается с телефона в той же сети:** `scripts\run.bat` по двойному щелчку слушает все интерфейсы и печатает адреса (`run.bat local` — только этот компьютер), на Unix — `make run LAN=1`, для Vite — `npm run dev:lan`. На адресе по обычному HTTP (`http://192.168.…`) клиент больше не ломается: фото загружаются, группа кругов создаётся, ссылки копируются — раньше на этих местах не хватало возможностей браузера, которые есть только под HTTPS и на localhost.

### Оператору

- **Сервер по умолчанию по-прежнему слушает `127.0.0.1:7676`.** Доступ из сети включают только скрипты локального запуска; `listen` и `WYND_LISTEN` не изменились.
- Миграций нет, схема v16: откат на 0.8.2 — заменой бинарника.
